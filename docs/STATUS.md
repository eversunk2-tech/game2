## 3. `main`에 합쳐 올릴 때 할 일 (다음에도 그대로 쓴다)

- 합치기·푸시는 코디네이터만 한다. 트랙의 Review가 통과하면 그 트랙의 `review-*.md`를 트랙 브랜치에 커밋하고 `main`에 `--no-ff`로 합친다. 다른 트랙에 아직 합쳐지지 않은 것이 있으면 트랙 쪽에서 `main`을 `--ff-only`로 맞춰 쓴다.
- 합친 뒤 전체 테스트를 처음부터: `npm test`, `npm run test:e2e`, `E2E_WIDE_TEXT=font npm run test:e2e`. 다른 서브에이전트가 테스트를 돌리는 중이면 컴퓨터가 느려 흔들리는 검사가 실패할 수 있다 — 혼자 다시 돌려 가리고, **새로 합친 것의 검사가 실패하면 올리지 않는다.**
- 합친 화면을 한 번 직접 연다(처음 화면부터 단계 지도까지, 콘솔 오류 0).
- 푸시한 뒤 GitHub Actions의 배포·CI 결과를 확인한다(커밋 해시는 **전체 40자**로 `gh run list --commit`에 넣는다 — 짧은 해시는 빈 결과).
- 이 문서와 [HANDOFF.md](HANDOFF.md)의 "끝난 것"을 고친다.
- **이번에 올릴 때 덧붙일 것**: 인트로 Review 통과 → `track/b0`를 `main`에 합침(그 안에 M3이 들어 있다 — `track/cuboid`도 함께 합쳐짐) → 전체 테스트 → 푸시 → 배포·CI 확인 → 사이트에서 인트로·학년·영역 화면을 직접 열어 본다.
