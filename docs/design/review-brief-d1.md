## Build가 보고한 내용 (직접 확인할 것)

- 단위 80개 통과, e2e 51개 통과·7개 건너뜀(기존 기기별), 기존 e2e는 한 줄도 안 고침
- 글꼴: devDependency `@expo-google-fonts/do-hyeon@0.4.1`, `subset-font@2.9.0`. 게임마다 쓰인 글자만 woff2로 잘라 data: `@font-face`. 게임 파일 net-workshop 126 KB, 예시 93 KB, 허브 63 KB. 400 KB 상한 검사
- 대비 44쌍 통과(최저 4.60)
- 시안과 다른 점: D2 보상 요소 없음(자리만), net-workshop 히어로·단계 그림은 기본 무늬(N1 범위), 결과에 별 개수로 정하는 정적 "참 잘했어요" 도장
- 남은 문제: heroArt·thumb·chip·anchor는 e2e 없이 단위·임시 스크립트로만 확인, 390×844 단계 지도·판별과 1366×680 허브(5px)에 세로 스크롤

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e` 직접 실행. 건너뜀이 정당한지. 기존 테스트를 약하게 만들지 않았는지(`git diff tests/`).
2. **범위**: 바뀐 파일이 build-brief의 허용 목록 안인가. D2 범위(점수·칭호·도장·도감·색종이)가 들어가지 않았는가. 결과 화면의 정적 도장이 D1에 있어도 되는지 의견.
3. **시안과 일치**: 처음 화면·단계 지도·플레이·결과·학습 기록·게임 모음을 시안과 나란히 비교. 사용자가 승인한 모습과 크게 다른 곳.
4. **하위 호환**(spec 5-2·5-3): 예시 게임과 net-workshop이 동작이 바뀌지 않았는가. 템플릿으로 새 게임을 만들어도 새 모습으로 잘 뜨는가. 기존 주소 옵션(`?unlock ?stage ?sound ?seed ?lesson`).
5. **글꼴**: 빌드한 파일에 바깥 참조가 없는가. 화면에 나오는 한글(동적으로 만드는 피드백 문장 포함)이 잘라 넣은 글꼴에 모두 있는가 — 빠진 글자가 있으면 그 글자만 다른 글꼴로 보여 어색하다. 개발 서버에서도 글꼴이 보이는가. OFL 표기. `npm ci`로 새로 설치해도 빌드되는가(저장소 밖 복사본에서).
6. **접근성·교실 기기**: 대비 4.5:1을 직접 계산, 48px, 키보드 초점이 보이는가, `prefers-reduced-motion`, 1366×768·1366×680·820×1180에서 플레이 화면 세로 스크롤 없음, 가로 스크롤 없음(네 크기).
7. **성능**: 저사양을 흉내 내(CPU 느리게, 예: CDP `Emulation.setCPUThrottlingRate` 4~6배) 화면 전환·접기 장면이 끊기지 않는가. 무거운 그림자·필터 남용.
8. **코드 품질**: dev-guide 규칙(`h()`, `innerHTML` 금지), 죽은 코드, 중복, 문서(engine.md·dev-guide.md·README)가 실제 동작과 맞는가.
9. **콘솔 오류**, 정답 노출(net-workshop 답하기 전 DOM).
