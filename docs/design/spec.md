# 공통 디자인·게임 요소 기획서: "종이 공방"

> 범위: 모든 게임이 함께 쓰는 엔진(`src/shared`)의 새 모습과 공통 게임 요소 · 상태: **승인 대기 (2026-10-07 요청)**
>
> 지침: [plan-brief.md](plan-brief.md) · 함께 보는 계획: [net-workshop spec.md 16절](../games/net-workshop/spec.md) (자유 배치 단계, 이 게임만의 요소) · 승인 전에는 구현하지 않는다.

**요약**

- 모든 화면을 "종이 공방"으로 다시 그린다. 따뜻한 종이 바탕에 잉크색 굵은 테두리와 단단한 그림자, 색종이 면, 도장(참 잘했어요)과 마스킹 테이프를 쓴다. 엔진(`base.css`, `app.js`)에 넣으므로 예시 게임도 저절로 새 모습이 된다.
- 공통 게임 요소: **솜씨 점수와 칭호, 연속 맞힘, 다시 일어서기, 도장판(업적), 도감 틀, 도전 주문서 틀, 축하 연출, 새 효과음**. 점수는 모두 학습 행동(정확한 예측, 틀린 뒤 다시 도전, 새로 찾기, 설명)에만 준다. **빨리 푼 것에는 점수를 주지 않는다.** 어떤 보너스도 처음부터 맞힌 것보다 크지 않다. 순위표·친구 비교는 없다.
- 엔진 API는 **추가만** 한다. 기존 `createGameApp`·`ctx`를 쓰는 게임은 고치지 않아도 돌아간다.
- 제목용 글꼴은 **배민 주아(Jua, OFL)를 쓰는 글자만 잘라 파일 안에 넣는 안을 추천한다**. 게임 파일이 약 134 KB 늘어난다(실측). 본문은 기기 글꼴 그대로 쓴다. 9절 1번에서 확인받는다.
- 시안 스크린샷 10장: 맨 끝 "시안" 절.

## 1. 디자인 방향

교실에서 학생은 이미 종이 학습지와 공책, 가위·자·색종이에 익숙하다. 그래서 화면을 **"내 작업대"**처럼 만든다. 바탕은 모눈이 옅게 비치는 종이, 누를 수 있는 것은 잉크로 테두리를 그린 두꺼운 종이 버튼(누르면 내려앉음), 정보 판은 얇은 종이, 칭찬은 선생님 도장으로 보인다. 전개도 게임에서는 이 세계가 그대로 내용이 된다(재단 매트 위에서 색종이 면을 접는다). 다른 교과 게임도 "공방·실험대·탐정 책상"처럼 작업대 위의 종이로 이어 갈 수 있다. 장식은 학습 정보를 가리지 않는 가장자리(테이프, 자, 색종이 조각)에만 둔다.

| 핵심 말 | 뜻 | 왜 |
| --- | --- | --- |
| **종이** | 모든 면은 종이 한 장. 잉크 테두리 + 아래 단단한 그림자 = 누를 수 있다. 옅은 선 + 부드러운 그림자 = 읽을 정보 | 전개도(종이 접기)와 학습지에 바로 이어진다. 누를 수 있는지가 모양만 보고 한눈에 보인다. 흐림 없는 그림자라 저사양 기기에서도 가볍다 |
| **도장** | 보상은 "참 잘했어요" 같은 둥근 도장으로 찍힌다. 도장판에 모인다 | 한국 초등 교실에서 익숙하고, 노력해서 받는 느낌이다(뽑기·카지노 느낌이 아님) |
| **장인** | 칭호는 견습생 → 솜씨꾼 → 장인처럼 "솜씨"가 느는 것으로 오른다 | 빨리가 아니라 정확히·끝까지·여러 가지로 하는 것이 솜씨라는 메시지 |

디자인 규칙 4가지

1. 한 화면에 가장 큰 것은 늘 학습 대상(전개도, 문제)이다. 점수·칭호는 머리 오른쪽에 작게.
2. 잉크 테두리와 단단한 그림자는 누를 수 있는 것에만 쓴다(버튼, 단계 카드, 게임 카드, 면 카드).
3. 틀림은 빨강 경고가 아니라 벽돌색 "까닭 쪽지"로 보인다. 늘 ✗ 표시·글자·무늬와 함께(색만으로 구분 금지).
4. 축하는 짧게(2초 이내), 누르면 바로 넘어간다. 움직임 줄이기면 정지 화면.

### 2-3. 간격·모서리

- 간격(4px 바탕): `--sp-1` 4 · `--sp-2` 8 · `--sp-3` 12 · `--sp-4` 16 · `--sp-5` 24 · `--sp-6` 32 · `--sp-7` 48. 화면 안쪽 여백 20px(휴대폰 16px). 앱 최대 너비 1100px → **1240px**(1366 화면을 더 넓게 씀).

### 2-4. 깊이 (그림자)

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--edge-sm` / `--edge` | `0 3px 0 var(--ink)` / `0 4px 0 var(--ink)` | 버튼·단계 카드. 누르면 `translateY(3px)` + 그림자 0 |
| `--sheet` | `5px 6px 0 rgb(30 33 64 / 10%)` | 작업 지시서·증명서처럼 "종이 한 장"인 판 |
| `--lift` | `0 1px 0 …6%, 0 10px 24px -10px …22%` | 정보 판(흐림 있음, 움직이지 않는 것에만) |

흐림 있는 그림자는 움직이지 않는 판에만 쓴다. 움직이는 것은 단단한 그림자(흐림 0)만.

### 2-6. 아이콘

## 4. 공통 게임 요소 (엔진에 넣는 것)

원칙

1. **학습 행동에만 보상**: 정확히 맞히기·예측하기, 틀린 뒤 까닭을 보고 다시 도전하기, 여러 가지를 새로 찾기, 설명하기.
2. **어떤 보너스도 처음부터 맞힌 것보다 크지 않다** → 일부러 틀리거나 찍어서 이득을 볼 수 없다(단위 테스트로 검사, 7절).
3. **시간 점수 없음**. 시간은 기록에만 남고, 도전 주문서의 "시간 재기"는 학생이 켤 때만 내 기록과 비교한다.
4. 순위표·친구 비교·서버 없음. 모든 기록은 그 기기 `createStorage(game.id)`에만.
5. 틀려도 창피하지 않게: 틀림 소리는 낮고 부드럽게, 문구는 "다시 일어서기 기회".

| 요소 | 무엇에 보상하나 | 규칙 | 저장 |
| --- | --- | --- | --- |
| **솜씨 점수** | 맞히기, 다시 도전, 새로 찾기, 설명 | 아래 점수 표. 단계가 끝날 때 결과 화면에 줄별로 보인다 | `rewards.xp` |
| **칭호** | 쌓인 솜씨 | 기본 5단계, 기준 0·40·100·180·300점. 엔진 기본 이름 새싹 → 탐험가 → 해결사 → 척척박사 → 으뜸 박사. 게임이 `rewards.ranks`로 이름을 바꾼다(전개도: 견습생 → 솜씨꾼 → 접기 장인 → 설계 장인 → 공방 명장). 차시 하나(약 80점)로 한 번은 오르게 맞췄다 | xp에서 계산 |
| **연속** | 처음 시도에 연달아 맞힘 | 머리에 "✦ 연속 n"(2 이상일 때만). 3번마다 +1, 소리 높이가 한 음씩 오름. 틀리면 조용히 0(문구 없음) | 판 안에서만 |
| **다시 일어서기** | 틀린 뒤 까닭을 보고 다음 문항을 맞힘 · 같은 문항을 다시 도전해 맞힘 | 각각 +1 (처음부터 맞힘 +2보다 작음, 아래 점수 표). 틀린 직후 판에 "다음 문제를 맞히면 +1, 도장까지 2/5" 쪽지 | 횟수 `rewards.counters.bounce`, `.retryFix` |
| **도장판(업적)** | 행동 묶음 | 엔진 기본 6개 + 게임 것. 모두 처음부터 "어떻게 받는지" 보인다(숨은 도장 없음). 새로 받으면 결과 화면 카드 + 도장 소리 + 화면 읽기 안내 | `rewards.badges[id] = { at }` |
| **도감 틀** | 여러 가지를 새로 찾기 | 게임이 `collections`(id, 제목, 칸 목록·그림)를 주고 `ctx.collect(id, itemId)`로 등록. 처음이면 "새로!" + +5 | `collections[id][itemId] = { at, stage }` |
| **도전 주문서 틀** | 배운 것을 새 조건에 쓰기 | 단계에 `challenge: true`. 그 차시의 일반 단계를 모두 마치면 열림. 다음 단계 사슬·차시 별 합계에 넣지 않는다(10분 차시를 늘리지 않음). 선택: `timer: 'optional'`이면 시작 전 [⏱ 시간 재기 켜기] 칸, 켜면 머리에 걸린 시간, 결과에 "내 기록 2분 10초(지난번보다 12초 빨라요)" — 점수 없음 | 단계 별 + `rewards.best[stageId].ms` |
| **축하 연출** | — | 결과: 별 하나씩 튐(0.15초 간격, 음 하나씩) → 도장 찍힘(0.45초) → 점수 막대 채움(0.6초) → 칭호·새 도장 카드. 모두 2초 이내, 아무 키·누르기로 끝 상태로 건너뜀. 플레이 중: `ctx.feedback.celebrate({ kind, at })`로 작은 색종이 8~12개 | — |
| **효과음** | — | 아래 소리 표 | 켬/끔 `muted`(지금과 같음) |

**솜씨 점수 표** (`core/rewards.js`, 순수 함수)

| 행동 | 점수 | 근거 |
| --- | --- | --- |
| 맞힘 (그 문항 처음 시도) | +2 | 정확히 하기 |
| 다시 도전해 맞힘 (같은 문항, 틀린 뒤) | +1 | 끝까지 하기. 처음에 맞힌 것(+2)보다 작다 |
| 틀림 | 0 | 벌점 없음 |
| 다시 일어서기 (틀린 문항 바로 다음 문항을 처음에 맞힘) | +1 | 틀린 문항(최대 +1) + 다음 문항(+2) + 1 = 최대 4 ≤ 두 문항 모두 처음에 맞힘(4 + 연속 보너스). 일부러 틀려 이득을 볼 수 없다 |
| 연속 3번마다 | +1 | 작게 |
| 단계 완료 | +5 | 그 단계 별이 **처음 늘었을 때만**(같은 단계 반복으로 쌓기 방지. 답 점수는 연습이므로 늘 준다) |
| 별 | 별 1개당 +2 | 위와 같이 별이 늘어난 만큼만 |
| 새로 찾음 (`ctx.collect`가 처음) | +5 | 여러 가지 찾기 |
| 설명 맞힘 (`ctx.reward.event('explain', { correct: true })`) | +2 | 설명하기. 틀려도 0 |
| 도전 주문서 성공 | +10 | 처음 성공만 |
| 빠르기 | **0** | 시간은 점수에 쓰지 않는다 |

**엔진 기본 도장 6개**

| id | 이름 | 받는 조건 (학습 행동) |
| --- | --- | --- |
| `first-step` | 첫 발걸음 | 첫 단계를 마침 |
| `sharp-eye` | 꼼꼼한 눈 | 한 단계에서 시도 4번 이상, 모두 처음에 맞힘 |
| `try-again` | 끝까지 다시 | 틀린 문항을 다시 도전해 맞힘 3번(누적) |
| `bounce-back` | 다시 일어서기 | 틀린 바로 다음 문항을 맞힘 5번(누적) |
| `lesson-done` | 차시 완주 | 한 차시의 일반 단계를 모두 마침 |
| `all-stars` | 별 부자 | 한 차시의 일반 단계를 모두 별 3개 |

게임 도장은 `rewards.badges: [{ id, title, desc, icon, test(state) }]`로 더한다(`test`는 순수 함수, 상태 = 기록·이벤트 횟수·도감). `explain` 이벤트를 보내지 않는 게임에는 설명 도장이 보이지 않는다.

### 5-2. 바뀌지 않는 것

`createGameApp`의 기존 인자·`ctx`의 기존 이름과 동작, `?unlock ?stage ?sound ?seed ?lesson`, 별 기준(90/70), 잠금 규칙, 학습 기록 저장 모양(`log`), `h()`, `enableDragDrop`, Canvas 도구. 예시 게임·템플릿은 한 줄도 고치지 않아도 새 모습 + 솜씨 점수·도장이 붙는다(예시 게임 `style.css`는 새 토큰으로 조금 다듬는 것을 D1에서 선택으로 한다).

### 5-3. 테스트가 기대하는 글자·선택자 (지킨다)

- 그대로 지킨다: h1, 버튼 이름 "시작하기"·"학습 기록"·"놀이 방법"·"← 단계 선택"·"다음 단계"·"다시 하기"·"단계 선택"·"처음 화면"·"결과 복사", h2 "단계를 골라요"·"학습 기록", h3 "자주 틀린 개념", `.stage-card`(일반 단계가 먼저, 순서 같음, 잠김 = `disabled`), `.lesson-group h3` = 차시 제목만, `.eyebrow` = 차시 제목(학년은 따로 칩), `.play-area`, `.toast-correct/-wrong/-info`, 별 `role="img"` 이름, "n번 중 m번 맞힘", `.report-table tbody tr`, 결과 제목 글자.

## 6. 성능·접근성

**성능 (저사양 크롬북)**

- 움직임은 `transform`·`opacity`만, 흐림 그림자는 정지한 것에만, `backdrop-filter`·`filter: blur` 쓰지 않음. 바탕 모눈·매트 무늬는 CSS 그라디언트(정지).
- 색종이 조각은 한 번에 12개 이하, 1.4초 뒤 DOM에서 지움. 결과 연출 전체 2초 이내.
- 글꼴은 data: 주소 하나(약 100 KB woff2)라 요청이 없고 한 번만 해석한다. `font-display: swap`.
- 3D 무대는 지금 방식(면 버튼 형제 + `matrix3d`) 그대로. 히어로 그림은 정지한 반쯤 접힌 전개도(애니메이션 없음).
- `?fx=low` / 코어 2개 이하 자동: 색종이·떠 있는 장식 끔, 화면 들어오기 움직임 끔.

**접근성**

- 글자 대비 4.5:1 이상(2-1 표), 그림 3:1 이상, 초점은 잉크 3px + 노랑 후광.
- 색만으로 구분하지 않음: ✓/✗ 아이콘·글자, 잠김은 자물쇠 + 글자 + 점선, 고른 답은 "내 답" 꼬리표, 겹침 빗금·빈 자리 점선(지금과 같음), 도감 못 찾은 칸 "?".
- `prefers-reduced-motion`: 축하·화면 움직임 끝 상태로, 색종이 없음, 접기는 지금처럼 3장면.
- 소리 끄기(저장, `?sound=off`). 모든 축하·보상은 소리 없이도 글자로 보인다.
- 화면 읽기: 보상(새 도장, 칭호 오름, 새로 찾음)은 `role="status"` 알림으로 한 번 읽는다. 결과 화면은 지금처럼 제목에 초점.
- 키보드: 새 부품은 모두 `<button>`. 결과 연출은 Enter·Space·Esc로 건너뜀. 자유 배치 판은 방향키 이동(net-workshop 16-1).
- 누르는 곳 48px 이상, 1366×680에서 플레이 화면 세로 스크롤 없음(`max-height: 720px`일 때 머리·간격을 줄이는 규칙을 엔진이 준다. 시안에서 확인).

## 9. 사용자에게 확인할 것 (두 계획서 공통 5개, net-workshop 16-6과 같음)

1. **제목 글꼴** — (가) Jua를 쓰는 글자만 넣기(+약 134 KB/게임, 저장소에 TTF 2.1 MB와 devDependency `subset-font` 추가) **← 추천** / (나) Do Hyeon(+약 54 KB) / (다) 넣지 않음(기기 글꼴 굵게).
2. **보상 요소 범위** — 솜씨 점수·칭호·연속·도장·도감 모두 **← 추천** / 도장·도감만(점수·칭호 없이, 경쟁 느낌 최소).
3. **정육면체 차시 문항 수** — 판별 6→5, 마주 보는 면 5→4, 면 붙이기 4→3 + 자유 배치(전개도 3가지)로 10분 안팎 **← 추천** / 기존 문항 그대로 + 자유 배치(약 12~13분).
4. **자유 배치 단계 위치** — 정육면체 차시의 마지막(4단계, 배운 규칙으로 직접 만들기) **← 추천** / 첫 단계(먼저 마음껏 탐색).
5. **도전 주문서** — 주사위 주문·도감 11가지(차시 밖 선택 활동, 시간 재기는 켜는 학생만) 넣기 **← 추천** / 빼기.
