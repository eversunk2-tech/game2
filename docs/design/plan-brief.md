## 지켜야 할 조건

- **HTML 한 파일·오프라인**: 외부 CDN·웹 글꼴 주소 금지. 그림은 인라인 SVG·CSS로 직접 그린다. 한글 글꼴을 파일 안에 넣는 안(예: OFL 글꼴을 빌드 때 쓰는 글자만 잘라 data:로 넣기)을 제안한다면, 늘어나는 파일 크기·필요한 npm 패키지·빌드 변경을 수치로 적고 "사용자에게 확인할 것"에 올린다.
- **교실 기기**: 1366×768과 실제 크롬북 보이는 높이 1366×680에서 세로 스크롤 없이 플레이, 태블릿 820×1180 터치, 휴대폰은 스크롤 허용. 누르는 곳 48px 이상, 저사양 크롬북에서 부드러울 것(무거운 효과는 피하거나 줄이는 방법).
- **접근성**: 글자 대비 4.5:1 이상, 색만으로 구분 금지, `prefers-reduced-motion`, 소리 끄기, 키보드 조작.
- **개인정보·서버 없음**: 순위표·친구 비교처럼 기기 사이 통신이 필요한 것은 하지 않는다. 기록은 그 기기에만.
- **학습이 먼저**: 게임 요소는 학습 행동(정확히 예측하기, 틀린 까닭 보고 다시 도전, 여러 가지 전개도 찾기, 설명하기)에 보상해야 한다. 찍기·속도만 빠른 것에 큰 보상을 주지 않는다. 느린 학생이 불리하지 않게(시간 압박은 선택). 틀려도 창피하지 않게.
- **엔진 호환**: 공통 디자인은 엔진(`src/shared`)에 넣어 예시 게임도 자동으로 새 모습이 되게 하고, 기존 엔진 API를 쓰는 게임이 깨지지 않게 한다.
- **10분 차시**: 자유 배치 단계·게임 요소를 넣어도 정육면체 차시가 10분 안팎이 되게 단계 구성을 조정한다(필요하면 기존 단계 문항 수 조정 제안).

2. 디자인 토큰: 색(배경·면·글자·강조·정답·오답·별 등, 대비 수치), 글꼴(크기 단계·굵기·줄 간격), 간격, 모서리, 그림자·깊이, 움직임(길이·곡선)
3. 공통 부품의 새 모습: 처음 화면(히어로), 단계 선택(지도·길 형태 등), 플레이 머리, 버튼, 문제 판, 토스트, 결과 화면(축하 연출), 학습 기록, 게임 모음 페이지
4. 공통 게임 요소(엔진에 넣는 것): 예) 연속 정답 콤보, 등급·칭호, 배지·업적, 수집 도감 틀, 도전 모드 틀, 축하 효과, 효과음 다듬기. 각 요소마다 **무엇에 보상하는지(학습 행동)**와 저장 방식
5. 엔진 API 변경점(추가만, 하위 호환) 목록
6. 성능·접근성 처리 방법
7. 빌드 단계 나누기(마일스톤과 "끝났다" 기준)

## net-workshop spec.md `## 16` 절에 담을 것

1. **자유 배치 단계**(정육면체 차시에 추가): 학생이 면 6개를 격자에 마음대로 놓고 [접어 보기] → 놓은 그대로 접히고, 안 되면 입체에서 겹치는 면·비는 곳이 보이는 단계. 조작(놓기·빼기·옮기기, 터치·키보드), 목표와 끝나는 조건(예: 서로 다른 전개도 몇 개 찾기), 기록 tag, 별 기준, 차시 안 위치.
2. **다른 도형에도 같은 원리**: 직육면체(크기가 다른 면 카드), 각기둥(밑면 다각형·옆면 띠), 원기둥(원 2개·직사각형)에서 자유 배치 단계를 어떻게 할지 일반 규칙과 데이터·판정 방법(`fold.js` 확장 방향).
3. **이 게임만의 게임 요소**: 공방 세계관(예: 손님 주문서, 장인 등급, 전개도 도감 11가지 모으기 — 자유 배치에서 새 전개도를 찾으면 도감에 등록, 도전 문제 등). 공통 요소(design/spec.md)와 어떻게 이어지는지.
4. 정육면체 차시의 새 단계 구성 표(단계·문항 수·예상 시간·끝나는 조건)와 10분 안팎 근거.
5. 파일 구조 변경, 테스트 계획(단위·e2e), Build 순서. 사용자가 "직육면체 차시 전에"라고 했으니 이 업그레이드를 2차(직육면체)보다 먼저 한다.
6. 사용자에게 확인할 것(5개 이하, 추천 표시).

## 시안 (스크린샷)

- 최소: 처음 화면, 단계 선택, 플레이(판별 오답 장면), 자유 배치 단계, 결과(축하), 게임 모음 — 1366×768. 그중 두 장면은 태블릿 820×1180도.

- 스크린샷 파일 목록과 경로를 design/spec.md 맨 끝 "시안" 절에 적는다(저장소 밖 경로).
