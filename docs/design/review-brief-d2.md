## 확인할 것

1. **테스트**: 직접 실행, 건너뜀 정당성, `git diff tests/`로 기존 검사가 약해지지 않았는지.
2. **범위**: 허용 파일 안인가. 예시 게임·템플릿·net-workshop(style.css 초점 밖)·package 파일 변경 없음. 전개도 게임 고유 보상(N1·N2)이 들어가지 않았는가.
3. **점수가 학습 행동에만 보상하는가** (가장 중요): 독립적으로 점수 시뮬레이터를 만들어 spec 4절 표와 비교. 일부러 틀리기·같은 단계 반복·다시 하기·새로 고침·지우기 후 재시작·도전 단계 반복으로 점수를 부풀릴 수 있는지 찾는다. 빠르기 점수가 없는지.
4. **D1 review 1~3**: 각각 다시 측정(초점 대비 계산, 제목 글꼴 자리 글자 대조, 악성 cover.svg 예시 여러 개).
5. **하위 호환**: 예시 게임이 코드 수정 없이 보상이 붙고 기존 동작 그대로인가. 템플릿으로 만든 새 게임. `rewards.off`. 기존 주소 옵션.
6. **저장·개인정보**: 저장 키·모양, 이름 저장 없음, 지우기가 점수·도장·도감을 모두 지우는가, 저장이 막힌 환경(사생활 보호 모드 흉내)에서 동작.
7. **접근성·교실 기기**: 축하 연출 건너뛰기(키보드·누르기), `aria-live` 안내 문장, `prefers-reduced-motion`·`?fx=low` 색종이 0, 대비, 48px, 1366×768·1366×680·820×1180 세로 스크롤(플레이·결과), 가로 스크롤 없음(네 크기).
8. **성능**: CPU 4~6배 느리게 해서 결과 연출·색종이가 끊기지 않는가, 연출 후 DOM·타이머가 정리되는가.
9. **코드 품질·문서**: `h()`, `innerHTML` 금지, 순수 함수 분리, 죽은 코드, engine.md 10절이 실제와 맞는가.
10. 콘솔 오류, net-workshop 정답 노출, 효과음이 꺼짐 설정을 지키는가.
