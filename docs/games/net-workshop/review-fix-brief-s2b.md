# Review 서브에이전트 지침: S2 쌓기나무 3·4차시 — 검토 반영 확인 (트랙 "blocks", S2b)

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-fix-brief-s2b.md](build-fix-brief-s2b.md)에 따라 고친 것을 **독립적으로** 확인하고, 지난 검토에서 통과한 것이 깨지지 않았는지 본다. Build와 분리된 검토자다.
- 트랙의 작업 폴더 안 `docs/games/net-workshop/review-blocks-s2.md` **한 파일만** 고친다: 맨 아래에 `## 재검토 (S2b 수정 확인)` 절을 덧붙이고 맨 위 판정·검토일 줄을 고친다. 앞 내용은 지우지 않는다. 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지.
- **트랙의 작업 폴더에서만** 일한다(코디네이터가 프롬프트로 알려 준다). 검증 파일·복사본은 정해 준 scratchpad 폴더에만. Build의 scratchpad는 근거로 삼지 않는다. 지난 검토의 스크립트는 `review-s2/`에 있다 — 같은 스크립트로 다시 재서 지난 값과 나란히 적는다(지금 작업 폴더를 새로 빌드한 것을 여는지 먼저 확인).

## 기준

- `review-blocks-s2.md`의 문제 표(S2-1 ~ S2-12)와 지난 측정값, [build-fix-brief-s2b.md](build-fix-brief-s2b.md)
- [spec-grade6.md](spec-grade6.md) 1-2절("입체 그림에서는 '앞'이 왼쪽 아래, '옆'이 오른쪽 아래에 화살표로"), 2-4절, 4·5절, 15-3·15-4·15-7
- [common-rules.md](common-rules.md) 1~8절

## 검토 대상

`b32cc5d`(지난 검토 대상)와 트랙 브랜치의 마지막 커밋 사이의 변경 전부(`9f92fbd`는 코디네이터가 review 파일만 커밋한 것). **`blocks/**`와 쌓기나무 검사 파일 말고 다른 것이 바뀌었으면 범위 위반**이다. 처음 화면을 거치는 쌓기나무 검사 넷은 바뀌지 않았어야 한다(다음 Build B0c 몫). Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **S2-1 (가장 중요)**: "위, 앞, 옆에서 본 모양 그리기"와 "수만 보고 알아내기"의 답하기 전 입체 그림에 "앞"·"옆" 표시가 있는지(네 크기 스크린샷을 직접 열어 — 학생이 어느 면이 앞인지 바로 알 수 있는가, 교과서의 표시 방식과 같은가), **모든 문항에서 같은 자리·같은 모양**인지(시드 수백 개로 표시의 DOM·자리·글자가 문항과 엮이지 않는지 — 답하기 전 정답 노출 0을 다시), 표시가 쌓기나무를 가리지 않는지, 색만으로 구분하지 않는지, 화면 읽기. 같은 종류로 방향 표시가 빠진 그림이 다른 단계(1·2차시 포함)에 남았는지.
2. **S2-2**: `blocks-flip` 보기 꼴만 보는 두 규칙(지난 값 43.8%·56.2%)과 정답 자리, Build가 바꾼 보기 만들기가 보기의 뜻을 살리는지. 바꾸지 못했다면 까닭이 타당한지.
3. **S2-3**: 960×768·960×680·1000×768에서 칠하는 문항의 세로 스크롤(지난 값 110px)과 [확인하기]까지의 길, 1024×768 쌓기나무 한 변(지난 값 39px). 세 크기·1024×768의 스크롤 0·48px.
4. **S2-4·5·6·7·12**: 뒤집은 그림 ≠ 다른 쪽 그림(시드 1,000개 — 지난 값 그리기 6.4%·수만 보고 11.7%), 까닭 문장 두 가지, 1366×680 이름표 가림(지난 값 7 / 432장면, 10px), 쌓기 틀림의 ✓, 놀이 방법 줄.
5. **깨지지 않았는가(지난 스크립트로 다시)**: 판정 독립 계산(262,144·52,612) 어긋남 0, 정답 노출(360화면) 0과 보기 자리·값 꼴, 별·점수 = 독립 계산(화면에서 여러 판), 네 크기 배치(3,456장면), 기존 차시 불변, 조작(네 수단), 느린 기기 4·8·12배.
6. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`를 직접 실행. `git diff b32cc5d..HEAD -- tests/`로 약해진 검사가 없는지.
7. **합칠 때**: 이 컴퓨터의 `main`과 `git merge-tree --write-tree`로 줄 충돌, 합친 나무에서 처음 화면을 거쳐 깨지는 쌓기나무 검사 목록(판정에는 세지 않음).
8. **새로 생긴 문제**.

## 형식과 끝나면

덧붙이는 절: 판정 줄(통과 = 반드시 수정 0건 / 수정 필요), 테스트 결과 표, 항목별 결과 표(S2-번호 · 지난 값 → 지금 값 · 고쳐짐/남음), 깨지지 않았는지의 표, 발견한 문제 표(심각도, 파일:줄, 재현 방법, 고칠 방향), 확인하지 못한 것.

최종 답변 **10줄 이하**: 판정, S2-1(표시와 정답 노출), S2-2·S2-3 잰 값, 나머지 요약, 깨지지 않았는지의 핵심 수치, 테스트 숫자(보통·글꼴 흉내), 새 문제와 심각도별 개수, "반드시 수정" 목록(파일:줄), 합칠 때 부딪힐 곳, 확인하지 못한 것. 직접 잰 것과 추정을 구분한다.
