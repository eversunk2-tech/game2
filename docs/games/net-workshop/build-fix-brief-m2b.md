# Build 서브에이전트 지침: 직육면체 차시 검토 반영 (트랙 "cuboid")

## 역할

너는 직육면체 차시(2차)를 만든 **Build** 담당이다. 네 작업 폴더의 `docs/games/net-workshop/review-cuboid.md`(Review가 쓴 검토 결과)의 문제와 사용자 결정을 반영한다. Review 판정은 "수정 필요 — 반드시 수정 1 · 고치면 좋음 4 · 참고 6"이었다. 판정(직육면체·정육면체 모두 독립 계산과 불일치 0), 정육면체 불변(6,470장면 차이 0), 정답 노출 0, 점수, 배치는 통과했으니 그대로 둔다. 검증은 별도 Review 서브에이전트가 다시 한다.

## 사용자 결정 (2026-10-11 — 이 폴더의 spec.md에는 아직 없다. 여기 적힌 것이 기준이다. `main`의 spec.md 16-14에 기록됨)

1. **내 맘대로 전개도는 서로 다른 전개도 2가지를 찾으면 끝낼 수 있고, 3가지를 찾으면 별 3개다**(별 = 찾은 가지 수: 2가지 ★2, 3가지 ★3). `cuboid-free`는 네가 만든 그대로다.
   - **정육면체 `cube-free`도 같은 기준으로 맞춘다**(지금은 3가지를 찾아야 끝나 늘 ★3이다). 2가지를 찾으면 [결과 보기]가 나오고 더 찾아 3가지가 되면 별 3개. 결과 화면의 별 기준 안내도 맞춘다(주사위 주문의 `finish({ starNote })` 방식). 도감 주문(`cube-dex`)은 그대로다. **이것은 이미 사이트에 올라가 있는 단계를 일부러 바꾸는 것이다 — 바뀌는 것은 `cube-free`의 끝내기 기준·별·그 안내뿐이어야 한다.**
2. **직육면체 전개도 54가지의 점수에 상한을 둔다**: 이 기기에서 **처음 찾는 10가지까지는 지금처럼**(만들기 성공 +2·연속 등은 엔진 규칙대로 + 새 전개도 +5), **11번째부터는 새로 찾을 때마다 모두 합쳐 +1점**(만들기 성공 점수도 따로 주지 않는다). "찾은 전개도 n / 54"는 계속 오른다. 54가지를 다 찾으면 +407점이 되어 칭호 최고 기준(300점)을 한 단계에서 넘기 때문이다. 정육면체(11가지)는 그대로 둔다.
   - 모양마다 한 번만·바로 저장·화면 = 저장·일부러 틀려 이득 0은 그대로. **어떤 순서로 찾아도·몇 판에 나눠 찾아도 54가지의 등록·만들기 점수 합이 같아야 한다**(10×7 + 44×1 = 114점 + 엔진의 연속·다시 일어서기·단계 점수). 화면의 점수 안내(쪽지 "새 발견 +5" 등)가 11번째부터는 실제 점수와 맞게.
3. 단계 안 도장(정식 도장 대신), 직육면체의 까닭 고르기가 "겹침 탐정" 횟수에 더해지는 것은 **그대로 둔다**. 정식 도장·도감은 나중에 6학년 도장과 함께 정한다.

## 반드시 지킬 것

- 이 폴더의 `common-rules.md` 전부. 통과한 것을 깨지 않는다: 직육면체·정육면체 판정이 독립 계산과 불일치 0, 답하기 전 정답 노출 0(찍기 통계 포함), 점수 = 독립 계산·화면 = 저장·일부러 틀려 이득 0·탭 두 개에서도 한 번만, 세 크기 스크롤 0·판 넘침 0·머리와 매트 움직임 0·판 → 무대 0px.
- **정육면체 차시 불변 — `cube-free` 말고는 한 글자도**: 기준 `3b48260` 빌드와 견줘 `cube-judge`·`cube-opposite`·`cube-complete`·`cube-dice`·`cube-dex`의 화면·점수·기록 차이 0, `cube-free`는 "2가지에서 [결과 보기]가 나오는 것·별·별 기준 안내" 말고 차이 0(전개도 3가지를 찾는 판은 점수까지 지금과 같아야 한다 — 지금 33점). `cube-free`의 기존 검사 가운데 "3가지를 찾아야 끝난다"를 기대하는 것은 새 결정에 맞게 바꾸고 이유를 보고한다(지우지 않는다).
- 점수 상한을 넣으면서 **엔진의 `scored: 'once'`·바로 저장 틀을 깨지 않는다.** 11번째부터의 +1을 어떻게 주는지(엔진의 모음 `xp`, 답 표시 등)는 네가 정하되, 새로 고침·나가기·탭 두 개·`cuboid-free`를 여러 판에 나눠 하기에서 "처음 10가지"가 흔들리지 않아야 한다(10가지의 경계에서 두 번 받거나 못 받는 길 0). 독립 계산과 견주는 무작위 단위 검사에 "순서를 섞어도 총점 같음"을 넣는다.
- 엔진(`src/shared/**`)은 M2-5와 점수 상한에 필요한 만큼만 고치고 줄 번호와 함께 보고한다. **쌓기나무 트랙이 같은 때에 엔진 `app.js`(차시 칩·시간 칩)·`base.css`·`icons.js`·`docs/engine.md`, `main.js`(차시 등록)를 고치고 있다** — 같은 줄을 다시 쓰지 말고 덧붙인다.
- 기존 검사를 지우거나 약하게 만들지 않는다.
- 테스트: `npm test` + `npm run test:e2e -- --workers=4`(보통) + `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`(글꼴 흉내)에서 실패 0.

## 지킬 것

- 작업 폴더·브랜치·포트·scratchpad·`npm install` 금지·e2e 일꾼 수는 지난번과 같다(코디네이터가 프롬프트로 다시 알려 준다). 커밋은 `track/cuboid`에만, `git add`에서 `docs/games/net-workshop/review-cuboid.md`는 뺀다. 최종 상태는 커밋해 둔다.
- 끝났다의 기준: `npm test`, e2e 보통·글꼴 흉내 모두 실패 0(마지막 커밋에서 처음부터). M2-1 문장을 시드 3,000개로 독립 계산과 견준 값(어긋남 0). 54가지 총점을 순서 여러 가지로 잰 값. `cube-free`를 2가지·3가지에서 끝낸 화면과 점수. 정육면체 다섯 단계 불변 수치. 네 크기 스크린샷(바로 선 띠 이름표, 포개지지 않는 표시, `?lesson=cuboid`의 머리, `cube-free` 결과의 별 2개)을 직접 연다.
