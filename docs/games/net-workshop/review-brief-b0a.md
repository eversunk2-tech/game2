# Review 서브에이전트 지침: B0a 영역 고르는 화면 + 앱 이름 "입체도형 공방" (트랙 "b0")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-b0a.md](build-brief-b0a.md)에 따라 만든 것을 **독립적으로** 검증한다. Build와 분리된 검토자다.
- **검토 결과는 새 파일 `docs/games/net-workshop/review-b0a.md`에 쓴다**(트랙의 작업 폴더 안). 맨 위에 판정 줄, 그 아래 기존 review 파일들과 같은 형식의 표.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지.
- **트랙의 작업 폴더에서만** 일한다(코디네이터가 프롬프트로 알려 준다). 검증 파일·스크린샷·기준 빌드는 정해 준 scratchpad 폴더에만. Build의 scratchpad는 근거로 삼지 않는다.

## 검토 대상

기준 커밋 `4e7b216`(사이트에 올라간 것)과 트랙 브랜치의 마지막 커밋 사이의 변경 전부. 커밋 안 된 것이 있으면 그것도 보고 그 사실을 적는다. 고쳐도 되는 파일은 build-brief-b0a.md의 목록이다 — **`scripts/**`·`helpers.js`·`playwright.config.js`, 쌓기나무 폴더·검사, 전개도 플레이 코드가 바뀌었으면 범위 위반**이다. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 실행. `git diff 4e7b216..HEAD -- tests/`로 **지워지거나 약해진 검사**가 없는지 — 처음 화면을 거치게 바꾼 검사는 뜻이 그대로인지 줄마다.
2. **영역 화면 (가장 중요 — 학생·교사가 처음 보는 화면)**: 네 크기(1366×768·1366×680·820×1180·390×844)에서 처음 화면의 영역 카드 둘, 두 영역의 단계 지도와 탭, 탭으로 오가기, [처음 화면]으로 돌아오기를 **마우스·터치·키보드** 각각으로 해 본다. 스크린샷을 직접 열어 카드가 읽히고 어색하지 않은지(빈 자리, 잘린 글, 겹침, 그림), "여기부터!"가 지난번 영역에 붙는지. 세로·가로 스크롤(크롬북 처음 화면 세로 0), 48px, 초점 표시·Tab 순서, 화면 읽기 이름, 대비 4.5:1, 움직임 줄이기·`?fx=low`, 글꼴 흉내.
3. **"6학년 전개도"가 보이지 않는가**(차시가 없으므로), 등록되지 않은 차시 id(`blocks-three`·`blocks-number`)를 영역에 적어 둔 것이 오류 없이 건너뛰어지는가, 그 차시들이 등록되면(복사본에서 가짜 차시로) 저절로 보이는가.
4. **주소**: `?area=` 두 영역·없는 id, `?lesson=` 넷(영역 카드·탭이 안 보이고 그 차시만), `?area=`와 `?lesson=`을 함께, `?stage=`·`?unlock=all`·`?seed=`·`?sound=`·`?fx=` — 기준과 견준다.
5. **기록**: 저장 열쇠·모양이 바뀌지 않았는가. **기준 빌드에서 쌓은 저장 값(별·점수·도감·칭호·도장·학습 기록)을 그대로 옮겨 지금 빌드로 열면 모두 그대로 보이는가.** "지난 영역" 값이 없을 때·이상한 값일 때 오류 없이 첫 영역. 탭 두 개에서 영역 값이 다른 기록을 덮지 않는가.
6. **불변**: 기준 `4e7b216` 빌드와 견줘 ⓐ 네 차시 14단계 + 도전 2의 플레이·결과 화면 DOM·자리·점수·기록 차이 0(앱 이름 글자 말고) ⓑ 예시 게임(처음·단계 지도·플레이·결과) 차이 0 ⓒ `engine-features` 시험 페이지(영역을 쓰지 않는 게임) 차이 0 ⓓ 수업 주소로 연 화면은 앱 이름·놀이 방법 말고 차이 0. 장면 수와 달라진 장면 목록을 적는다.
7. **앱 이름**: "입체도형 공방"이 들어가야 할 곳(처음 화면, 놀이 방법, 표지 `cover.svg`, 게임 모음 카드, `game.json`, `<title>`, 결과 복사 글 등)에 다 들어갔는지, 옛 이름 "전개도 접기 공방"이 남은 곳이 있는지(코드·화면·문서 — 남겨야 할 곳이 있으면 까닭). id·파일 이름·주소는 그대로인지. 표지 그림을 직접 연다.
7-1. **사용자 결정 두 가지(spec.md 16-15)**: 크기형 도움말 "펴서 마주 보는 두 면에 적힌 길이를 견줘 봐요", `cube-free`·`cuboid-free`에서 2가지일 때 놓는 판의 [결과 보기]가 보통 버튼이고 3가지부터 주 버튼인지(두 차시 × 네 크기, 스크린샷). 그 밖의 플레이 화면은 차이 0인지.
8. **놀이 방법**: 처음 화면·각 영역·각 수업 주소에서 보이는 줄이 그 영역에 맞는지(S1b-5가 풀렸는지).
9. **차시 칩**: 영역 안에서의 "1차시"·"2차시", 한 차시 주소·결과·학습 기록에서 어느 영역의 몇 차시인지 헷갈리지 않는지 — Build가 정한 방식에 대한 의견.
10. **엔진 코드**: 영역 기능이 게임 정의의 선택 값으로만 켜지는지, `areas`가 없는 게임의 경로가 바뀌지 않았는지(코드로), `h()`만·`innerHTML` 없음·이모지 없음, 나간 뒤 리스너 0, 콘솔 오류 0. `docs/engine.md` 2·8절 설명이 코드와 맞는지.
11. **느린 기기**: scratchpad 복사본에 CPU 느리게 하기(4·8·12배)를 넣어 Build가 만들거나 고친 검사를 돌려 값 실패 0인지. 새 검사가 움직임이 끝난 뒤에 재는지, 알림을 띄운 조작 바로 뒤에 보는지, 시간 예산.
12. **합칠 때**: 쌓기나무 트랙(`track/blocks`)·작은 수정 트랙(`track/c1`)의 지금 커밋과 `git merge-tree --write-tree`로 합쳐 보아 줄 충돌(특히 `main.js`·`tests/e2e/net-workshop.spec.js`), 그리고 쌓기나무 검사 가운데 처음 화면을 거쳐 가서 영역 카드 때문에 깨질 것(합친 나무에서 쌓기나무 검사를 돌려 본다).
13. **새로 생긴 문제**, 사용자가 정해야 할 것(선택지와 추천).
