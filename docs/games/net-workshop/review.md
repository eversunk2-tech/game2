**계획과 일치**
- 단계 id·제목·문항 수·끝나는 조건: `cube-judge` "접힐까, 안 접힐까?" 6문항(한 번 답하면 다음), `cube-opposite` "마주 보는 면" 5문항(맞힐 때까지), `cube-complete` "한 면을 붙여요" 4문항(맞힐 때까지), 빈 자리 4~6곳.
- `TAGS` 14개를 spec.md 3절 표에서 직접 읽어 비교: 글자까지 같다(14 = 14).
- 판별 구성(시드 701개): 늘 유효 3(1-4-1 하나 + 1-4-1 아닌 꼴 둘) · 무효 3(한 줄 5칸/같은 쪽 날개 겹침 1, 2×2 1, 면 개수 1).

### 확인하지 못한 것 (N1 재검토)

- 실물 크롬북·태블릿·휴대폰과 실제 손가락 터치, Chromium 밖 브라우저(특히 Safari의 `overflow-x: clip` → N1c-6), 화면 읽기 프로그램이 실제로 읽는 순서(알림 영역의 글자 변화만 기록했다), 소리(`sound=off`).
- 태블릿 터치 끌기·마우스 끌기·90초 힌트·대비는 이번에 따로 다시 재지 않았다(관련 파일 `free-board.js`·`style.css`가 안 바뀌었고 e2e의 해당 검사는 통과).
- 점수 규칙의 "16-8만 적용" 칸은 독립 계산(`score-model.mjs`의 `rule: 'once'`)으로만 잰 값이다. 그 규칙을 넣은 엔진은 없으므로 실제 구현 뒤 다시 확인해야 한다.
- Build의 최종 보고 원문은 받지 못했고 코디네이터가 전한 요약만 받았다. 위 수치는 직접 잰 것이다.
