## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-g3a.md](build-brief-g3a.md)(덧붙임 포함)에 따라 만든 것을 **독립적으로** 검증한다. Build와 분리된 검토자다.

- 코드·테스트·다른 문서를 고치지 않는다. 커밋·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다. 작업 폴더에서만, 검증 파일은 정해 준 scratchpad에만. Build의 scratchpad는 근거로 삼지 않는다(사용자가 고른 시안 그림 `build-g3a/shots/*.png`는 기준 모습으로만).

## 확인할 것

1. **테스트**: `npm test`, `E2E_PORT=5363 npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 — 실패 0. 바뀐 기존 `tests/`를 줄마다 읽어 약해진 검사 0(별 합계 57 → 63 · 81 → 87, 원기둥 "준비 중" → 열림처럼 뜻이 바뀐 줄만인지, 준비 중 카드의 동작을 다른 검사가 여전히 지키는지).
2. **계획대로인가**: 1단계(밑면 고르기 2문항 — 선 것 1 · 눕힌 것 1, 1.5배 / 높이 1문항 — 주문서 [가][나][다] 칩(15-35 A), 무대의 길이는 보기만 / 맞힌 뒤 ○△와 펼침 / 옆면 띠 36개가 한 면 — 어느 띠를 눌러도 옆면 전체, Tab·화면 읽기는 한 번), 2단계(5문항 — 되는 것 2 = 흔한 꼴 1 + 낯선 꼴 1 / 안 되는 것 3 = 같은 쪽 · 크기 다름 · 사다리꼴, 판의 절반쯤은 안 되는 것 하나가 낯선 꼴, 예상 → 까닭 → 말기, 사다리꼴은 말지 않고 표시, 까닭 칩의 말), 영역 카드 열림 · 단계 지도 · 놀이 방법 · 학습 기록 tag · 별 합계 · 차시 칩, 사용자가 고른 시안과 같은 모습인지(스크린샷을 직접 열어).
3. **독립 계산**: 저장소 코드를 쓰지 않고 기획서 문장(spec 6-3 · plan 3-0 · 4절)만 보고 짠 판정 — 옆면이 직사각형 하나 · 반지름이 같은 원 둘 · 원이 마주 보는 두 변에 하나씩 · 원이 붙은 변의 길이 = 지름 × 원주율(0.05 cm) · 세워 놓은 꼴 · 엇갈린 자리는 됨 — 과 `checkCylinder`를 무작위 모델 수천 개로 견줌. 말기 기하(원기둥 식으로 셈한 점 vs 화면/`foldNet` 점 — 맞는 전개도가 닫히는지, 틈 · 겹침의 크기), 2단계 문제 만들기(판의 짜임, 낯선 꼴 비율), 점수 · 별(엔진 기본 — 한 번 틀리면 ★2 등, 15-3 기준 해당 없음이 맞는지, 일부러 틀려 이득 0, 화면 = 저장).
4. **정답 노출 0**: 2단계 답하기 전 화면이 되는/안 되는 것에서 같은 방식으로 그려지는지(DOM 속성 · 클래스 · `clip-path` · 띠 수 · 원 요소 수 · 화면 읽기 문장 · 1 cm), 꼴 · 크기 · 자리 · 비율만 보고 맞히는 규칙의 정답률을 시드 3,000개 이상으로 직접 재서 찍기(50%)보다 크게 높지 않은지(높으면 규칙과 수치), 조작판 · 마는 막대 잠금. 1단계 면 색 · 이름 · DOM 차례, 높이 칩의 정답 자리 치우침(시드로).
5. **조작**: 키보드만 · 마우스만 · 터치만으로 두 단계 끝까지, 48px(옆면 가운데 띠 버튼처럼 예외가 있으면 그 까닭이 맞는지), 누르기 · 끌기 8px, 돌려 보기, 화면 읽기 문장 · 알림(알림이 조작을 가리지 않음), 움직임 줄이기 · `?fx=low`(말기 3장면).
6. **배치**: 다섯 크기(1366×768 · 1366×680 · 1024×768 · 820×1180 · 390×844) + 960×768 × 보통 · 글꼴 흉내에서 1 · 2단계 모든 장면(답하기 전 · 말린 뒤 · 까닭 고른 뒤 · 결과)과 6학년 화면 · 단계 지도 스크롤 · 넘침 · 겹침 0(휴대폰 세로 스크롤은 규칙대로) — **움직임이 끝난 뒤에** 잰다.
7. **그리기**: 띠 사이 실금 · 원 가장자리 · 크기 다른 원에서 옆면이 비치는 곳(Build가 손봤다고 한 것) — 2배 화소로 직접 확대해 봄. 말기 움직임의 프레임 간격을 CPU 1 · 4 · 8배로 직접 — Build 보고와 견줌. 실물 기기는 못 봄으로 적는다.
8. **불변**: 기준 빌드(`59b6153`)와 견줘 다른 모든 화면(인트로 · 학년 · 영역 · 정육면체 · 직육면체 · 각기둥 1~4단계 · 도전 · 쌓기나무 1~5차시 · 도전 · 자유 쌓기 · 학습 기록 · 선생님용 안내 · 예시 게임)이 같은지 — 특히 `view3d.js` 기본 갈래에서 바뀐 줄이 정육면체 · 직육면체 · 각기둥의 접기 · 누르기 · 표시를 바꾸지 않는지(같은 시드 · 같은 자세에서 화소 비교). 의도한 차이만: 원기둥 카드 열림 · 6학년 0 / 63 · 내 공방 0 / 87 · 원기둥 단계 지도 · 놀이 방법. 저장 값.
