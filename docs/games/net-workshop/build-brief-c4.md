# Build 서브에이전트 지침: c4 큰 화면에서 [입장하기]도 커진다 (작은 손질 — 트랙 "c1" 작업 폴더)

## 역할

너는 **Build** 담당이다. 사용자의 요청([spec-grade6.md](spec-grade6.md) **15-11**)을 반영한다. 검증은 별도 Review 서브에이전트가 한다.

사용자의 말: "1920 화면에서 selectio game 에서와 마찬가지 크기로 입장하기 크기 키워줘"

## 할 일

1. **배율**: `s = min(화면 CSS 폭 ÷ 1280, 화면 CSS 높이 ÷ 800)`을 **1~1.35로 묶는다**(새 상수 `INTRO_BUTTON_GROW_MAX = 1.35` — 이것 하나로 바꿀 수 있게, 순수 함수 예: `introButtonScale(w, h)`). selectio game의 규칙 그대로다(15-11).
2. **[입장하기]의 모든 크기에 곱한다** — `transform: scale`이 아니라 크기 자체를: 면 높이(`introButtonHeight`의 값 × s — 배율이 1을 넘는 화면에서는 지금 늘 84px이므로 1920×1080에서 약 113px), 그에 따라 이미 따라가는 최소 폭·글자(`--btn-h` 기반), 그리고 지금 px로 고정된 것들 — 금빛 면의 테 6px, 바깥 여백 8px, 반짝임 18px, 잉크 테두리 3px·아래 그림자 7px·흐린 그림자, 누르기·올리기 때 움직이는 거리, **초점 후광**(9px·12px). 화면에 새 CSS 변수(예: `--btn-s`)를 하나 더 준다.
3. **배치**: 꽉 채우기의 버튼 자리·카드의 아래 여백은 이미 버튼 높이를 쓴다 — 커진 크기로 다시 맞는지, 버튼(그림자·초점 후광 포함)이 화면 안이고 화면 밑과 지금 규칙만큼 띄워지는지 확인. **두 아이의 머리(`avoid`)·제목 그림·부제·소리 버튼과 겹침 0.**
4. **기기별 결과표**(실제 함수 + 브라우저에서 잰 값): 1280×800(DPR 1·1.5·2), 1366×768·1, 1366×1024·2, 1440×900(1·2), 1536×864·1.25, 1680×1050·1, 1920×1080(1·2), 1920×1200·1, 2560×1440(1·2), 3840×2160·1 — 각 s, 버튼 면 크기(폭×높이), 글자 px, 화면 밑까지 틈, 겹침. 그리고 **s = 1인 화면**(1024×768·2, 1180×820·2, 820×1180·2, 390×844·3, 844×390·3, 1366×680·1, 1366×768·1, 1280×800·1)은 `cd190ce` 빌드와 **픽셀까지 같아야** 한다(기준 빌드는 작업 트리를 바꾸지 말고 `git archive cd190ce`로 풀어 만든다).
5. 스크린샷: 1920×1080@1·@2, 1440×900@2, 1366×1024@2(멈춘 것, 움직임 줄이기로 연 화면)와 1920×1080의 초점 후광 — 직접 열어 의견.

## 덧붙임 (2026-10-17) — 사용자 결정: 소녀의 손을 피해 왼쪽으로 조금 (spec-grade6 15-11 끝)

사용자의 말: "손 안 가리게 버튼 조금 옮겨줘. 왼쪽으로 약간만. 너무 중심이 흐트러지지는 않도록. 손이 꼭 다보이진 않아도 괜찮아"

1. **손 칸**: 배경 그림에서 소녀가 전개도를 든 손(손가락·손바닥 — 전개도 종이는 빼도 됨)의 자리를 그림 좌표로 직접 재서(확대한 복사본을 scratchpad에 — 그림 파일은 그대로) 게임 인트로 값에 더한다(예: `art.buttonAvoid: [[x0, y0, x1, y1]]` — `main.js`의 INTRO 값 가운데 `avoid` 옆 한 줄. B0b가 `main.js`의 다른 줄을 고치고 있으니 그 한 줄만). 소년 쪽에 같은 일이 없는지도 본다.
2. **옮기기**: [입장하기](면 + 바깥 여백 + 그림자 — 화면에 보이는 버튼 전체)가 손 칸과 겹치면 **왼쪽으로만** 옮긴다 — 겹치지 않을 만큼까지, 다만 **한도 = min(버튼 폭 × 0.2, 무대 폭 × 0.05)**(상수로 — 예: `INTRO_BUTTON_NUDGE_MAX`). 한도 안에서 다 피하지 못하면 한도만큼(손이 조금 가려져도 됨). 위아래 자리·크기는 그대로. 꽉 채우기·카드 두 모드 모두 같은 규칙(카드에서는 카드 안 좌표로). 옮긴 뒤 소년·제목·부제·소리 버튼과 겹침 0, 화면(카드) 밖으로 나가지 않음.
3. 손을 가리지 않는 화면은 그대로 — **배율 1 화면에서 원래 손을 가리던 곳이 있으면 거기도 옮겨지므로** 픽셀 불변 비교는 "옮겨지지 않은 화면은 같다 / 옮겨진 화면은 어디가 몇 px"로 나눠 보고한다.
4. 기기별 결과표에 열을 더한다: 옮긴 거리(px), 옮긴 뒤 손 칸과 겹친 넓이(0이면 다 보임), 버튼 가운데가 화면 가운데에서 벗어난 비율. 1920×1080@1·@2, 1440×900@2, 1366×768@1, 820×1180@2 스크린샷(전·후)을 직접 열어 "중심이 흐트러지지 않았는지" 의견.
5. 검사: 배율 1.35 화면에서 손 칸과 겹침이 줄었는지·옮긴 거리 ≤ 한도·왼쪽으로만, 손이 없는 그림(예시 게임 등 `buttonAvoid` 없음)은 그대로. 고쳐도 되는 줄은 위 1의 `main.js` 한 줄이 더해질 뿐 나머지는 같다(`intro-fit.js`의 버튼 줄·`app.js` vars 줄·`base.css` 버튼 블록·인트로 검사 둘·engine.md 버튼 문장).

## 덧붙임 3 (2026-10-17) — 사용자 요청: 글자는 조금 크게, 버튼은 조금 작게 (spec-grade6 15-11 끝)

사용자의 말: "입장하기 버튼 조금더 작아져도 되겠어. 글자 크기에 비해 여백이 너무 많은거 같아. 글자도 조금더 키우고 버튼 크기도 약간 줄여줘"

1. 지금 비율(면 최소 폭 = 높이 × 3.6, 글자 = 높이 × 0.42, 양옆 안쪽 여백 1.2em, 높이 = min(화면 높이 10.5%, 폭 16%)을 56~84로)을 고친다. 목표: **글자의 화면 크기 약 10~15% 크게, 버튼 폭 약 15~20% 작게, 높이 약 5~10% 작게**(모든 화면에서 — 큰 화면 배율 s와 손 피하기는 그 위에 그대로). 글자 양옆 여백이 글자 크기에 어울리게(예: 글자 높이의 1배 안팎).
2. **시안 셋**: 추천안 하나를 코드에 넣고, 다른 둘(조금 더 작게 / 글자를 더 크게 등)은 같은 화면에서 값만 바꿔 스크린샷만 찍는다. 1366×768@1과 1920×1080@1(@2도 하나) 각각 지금(`023bc61`) · 시안 셋을 나란히 한 장에 붙인 비교 그림을 scratchpad에 만들고 경로를 보고(코디네이터가 사용자에게 보인다). 숫자(면 폭×높이, 글자 px, 글자 양옆 여백 px)를 함께.
3. 버튼이 좁아지므로 손 피하기의 옮긴 거리가 바뀐다(줄거나 0) — 기기별 결과표를 새로. 손 칸·한도·"안 보이면 옮기지 않기"는 그대로.
4. 버튼이 모든 화면에서 달라지므로 "배율 1 화면 픽셀 불변"은 이제 **버튼 둘레 밖만 같음**으로 본다(인트로 밖 화면은 그대로 같아야 함).
5. 검사(단위의 독립 계산·e2e)와 `docs/engine.md` 문장을 새 값으로. 테스트 셋·느린 기기 4·8·12배·`git merge-tree`(main·track/b0·track/b0d) 다시.
