# Build 서브에이전트 지침: c4 큰 화면에서 [입장하기]도 커진다 (작은 손질 — 트랙 "c1" 작업 폴더)

## 역할

너는 **Build** 담당이다. 사용자의 요청([spec-grade6.md](spec-grade6.md) **15-11**)을 반영한다. 검증은 별도 Review 서브에이전트가 한다.

사용자의 말: "1920 화면에서 selectio game 에서와 마찬가지 크기로 입장하기 크기 키워줘"

## 할 일

1. **배율**: `s = min(화면 CSS 폭 ÷ 1280, 화면 CSS 높이 ÷ 800)`을 **1~1.35로 묶는다**(새 상수 `INTRO_BUTTON_GROW_MAX = 1.35` — 이것 하나로 바꿀 수 있게, 순수 함수 예: `introButtonScale(w, h)`). selectio game의 규칙 그대로다(15-11).
2. **[입장하기]의 모든 크기에 곱한다** — `transform: scale`이 아니라 크기 자체를: 면 높이(`introButtonHeight`의 값 × s — 배율이 1을 넘는 화면에서는 지금 늘 84px이므로 1920×1080에서 약 113px), 그에 따라 이미 따라가는 최소 폭·글자(`--btn-h` 기반), 그리고 지금 px로 고정된 것들 — 금빛 면의 테 6px, 바깥 여백 8px, 반짝임 18px, 잉크 테두리 3px·아래 그림자 7px·흐린 그림자, 누르기·올리기 때 움직이는 거리, **초점 후광**(9px·12px). 화면에 새 CSS 변수(예: `--btn-s`)를 하나 더 준다.
3. **배치**: 꽉 채우기의 버튼 자리·카드의 아래 여백은 이미 버튼 높이를 쓴다 — 커진 크기로 다시 맞는지, 버튼(그림자·초점 후광 포함)이 화면 안이고 화면 밑과 지금 규칙만큼 띄워지는지 확인. **두 아이의 머리(`avoid`)·제목 그림·부제·소리 버튼과 겹침 0.**
4. **기기별 결과표**(실제 함수 + 브라우저에서 잰 값): 1280×800(DPR 1·1.5·2), 1366×768·1, 1366×1024·2, 1440×900(1·2), 1536×864·1.25, 1680×1050·1, 1920×1080(1·2), 1920×1200·1, 2560×1440(1·2), 3840×2160·1 — 각 s, 버튼 면 크기(폭×높이), 글자 px, 화면 밑까지 틈, 겹침. 그리고 **s = 1인 화면**(1024×768·2, 1180×820·2, 820×1180·2, 390×844·3, 844×390·3, 1366×680·1, 1366×768·1, 1280×800·1)은 `cd190ce` 빌드와 **픽셀까지 같아야** 한다(기준 빌드는 작업 트리를 바꾸지 말고 `git archive cd190ce`로 풀어 만든다).
5. 스크린샷: 1920×1080@1·@2, 1440×900@2, 1366×1024@2(멈춘 것, 움직임 줄이기로 연 화면)와 1920×1080의 초점 후광 — 직접 열어 의견.

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 검사: 배율 함수의 단위 검사(기획서 문장만으로 짠 기대값 — 1280×800 → 1, 1366×768 → 1, 1366×1024 → 1.0672, 1440×900 → 1.125, 1920×1080 → 1.35, 2560×1440 → 1.35), e2e 1920×1080에서 버튼 크기·화면 안·겹침 0. 기존 검사는 약하게 하지 않는다.
- 움직임 줄이기·`?fx=low`·접근성·[입장하기] 길·숨 쉬는 움직임(`transform`·`opacity`만)은 그대로.
- 브라우저 검사는 느린 기기를 견디게(움직임이 끝난 뒤, 시간 예산), `waitForTimeout`·`retries` 금지. 끝내기 전에 CPU 4·8·12배로 새로 만들거나 고친 검사 값 실패 0.
- 테스트: `npm test`, `npm run test:e2e -- --workers=4`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0. (그림 폴더에 Finder의 `.DS_Store`가 있으면 `tests/unit/engine-intro.test.js` 하나가 실패한다 — 저장소에는 없는 파일이고 B0b가 고친다. 있으면 그 사실만 보고하고 파일은 건드리지 않는다.)
