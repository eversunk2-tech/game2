# Review 재검토 지침: 자유 쌓기 "더 큰 판" — 전체 화면 안내 글 (트랙 "blocks" 작업 폴더)

## 역할과 범위

- 너는 큰 판을 검토한 **Review** 담당이다.
- Build가 [build-fix-brief-big-board.md](build-fix-brief-big-board.md)대로 고친 것을 **직접 재현 · 측정해** 다시 판정한다.
  - 사용자 결정: [spec-grade6.md](spec-grade6.md) 15-41 — B-5만 고친다. B-1 "다음 기회에", B-4 "그대로 두기".
- Build의 보고는 확인 대상이다. 근거로 삼지 않는다.
- 결과: [review-blocks-big.md](review-blocks-big.md)(작업 폴더, `b66b35a`에 커밋됨)에 다음을 한다.
  - 끝에 **"재검토 (날짜)" 절**을 덧붙인다.
  - 맨 위 판정 줄을 재검토 판정으로 바꾼다. 지난 판정은 재검토 절에 남긴다.
- 그 밖의 파일 · 코드 · 테스트는 고치지 않는다. 커밋하지 않는다. 작업 트리를 바꾸는 git 명령을 쓰지 않는다.
- 지킬 것은 [review-brief-big-board.md](review-brief-big-board.md)와 같다.
  - 포트: e2e 5354, 측정 5355
  - scratchpad: `review-big/`
  - 네가 띄운 PID만 내린다.
  - 설치 · 내려받기는 하지 않는다.

## 확인할 것

- 기준과 대상:
  - 기준: `main`의 `571cddc`(올라간 큰 판)
  - 대상: `track/blocks`의 마지막 커밋
  - 이 둘 사이의 변경 전부를 본다.

1. **범위**
   - 바뀐 파일이 지침의 네 파일뿐인지 본다.
   - `play-free-build.js`는 주석만 바뀌었는지 본다.
   - B-1 · B-4 쪽은 손대지 않았는지 본다.
2. **글**
   - 들어갈 때 알림의 화면 글과 화면 읽기 알림이 사용자가 고른 글 그대로인지 직접 본다: "전체 화면을 나가려면 [전체 화면]을 다시 눌러요."
   - 앱 어디에도 옛 글 "Esc를 눌러요"가 남지 않았는지 본다. 빌드 결과에서 찾는다.
   - "처음 한 번" 동작이 그대로인지 본다.
   - 전체 화면을 못 하는 기기에서는 이 글이 뜨지 않는지 본다.
3. **배치**
   - 큰 판 모든 크기 × 보통 · 글꼴 흉내에서 잰다. 크기: 1366×768 · 681 · 680 · 653 · 633, 1280×800, 1536×864, 1920×1080, 1024×768, 1180×820, 820×1180, 768×1024, 683×680
   - 알림이 다 올라온 뒤 다음을 잰다:
     - 알림의 줄 수
     - 띠 · 조작 버튼을 가리는 곳 0
     - 화면 밖 · 잘림 0
   - 683×680에서 펼친 판 칸을 가리는 수를 지난 값(18 · 20)과 견준다. 늘어났으면 몇 칸인지 적는다. 이것은 B-4라 판정에는 넣지 않는다.
   - 그림을 직접 열어 본다.
4. **테스트**
   - 세 가지(`npm test` · 보통 · 글꼴 흉내)를 하나씩 차례로, 처음부터 돌려 실패 0인지 본다.
   - 바뀐 검사를 줄마다 읽어 약해진 곳이 없는지 본다.
   - 고친 검사를 CPU 4 · 8 · 12배로 돌린다.
5. **불변**: 기준 `571cddc`와 견준다.
   - 큰 판 알림 밖의 화면(보통 판, 다른 화면 몇 개)이 같은지 본다.
   - 쌓기나무 늦게 받는 묶음 밖의 처음 받는 크기가 그대로인지 본다.
6. 새로 생긴 문제, 사용자가 정해야 할 것.
