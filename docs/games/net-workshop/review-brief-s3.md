# Review 서브에이전트 지침: S3 쌓기나무 5차시 + 도전 + 쌓기나무 도장 (트랙 "blocks")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-s3.md](build-brief-s3.md)에 따라 만든 것을 **독립적으로** 검증한다. Build와 분리된 검토자다.
- 검토 결과는 새 파일 `docs/games/net-workshop/review-blocks-s3.md`(트랙의 작업 폴더 안) 하나. 맨 위에 판정 줄(통과 = 반드시 수정 0건 / 수정 필요). 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다. 작업 폴더에서만 일하고 검증 파일은 정해 준 scratchpad에만. Build의 scratchpad는 근거로 삼지 않는다.

## 기준

- [spec-grade6.md](spec-grade6.md) 1-2·1-4절, **2-4절의 5차시 `blocks-layer`·도전 `blocks-add`**(문항·돌려 보기·"같은 모양"은 놓인 방향이 같은 것만), 3절, **4절(층별 모양·위층은 아래층 위에·더 붙인 모양)**, **5절(정답 노출 — `blocks-layer-*`·`blocks-add` 줄)**, 6절, **8절(쌓기나무 도장 셋·도전 주문서)**, 15-3(별), **15-8**(앞과 뒤 오개념 보기를 판마다), **15-17**(숨겨진 쌓기나무 도장은 "처음에 맞힌 수 − 2"로 셈 — 사용자 결정)
- [build-brief-s3.md](build-brief-s3.md) 전부, [review-blocks-s2.md](review-blocks-s2.md)의 S2b-1·S2b-2·참고, [common-rules.md](common-rules.md)

## 검토 대상

`0a4b3a6`(= 지금 사이트 `04b589a` + 문서)과 `track/blocks`의 마지막 커밋 사이의 변경 전부. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `E2E_PORT=<네 포트> npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 실행 — 실패 0. `git diff 0a4b3a6..HEAD -- tests/`를 줄마다 읽어 약해진 검사 0(도장 칸 수 13 → 16 네 줄, 그 밖에 뜻이 바뀐 줄).
2. **판정 — 독립 계산**: 기획서 문장만 보고 짠 계산으로 층별 모양 ↔ 쌓기(3×3칸·3층 전부), 1·2개 더 붙여 만들 수 있는가(놓인 방향이 같은 것만 같음 — 돌리거나 뒤집어야 같은 보기는 나오지 않는지), 도전의 수 쓰기, 층별 모양만 보고 개수·앞·옆. Build의 독립 계산 파일을 근거로 삼지 말고 따로 짠다.
3. **정답 노출 0**: 층별 그리기는 답하기 전 높이 값·층 색·층 숫자·벌려 보기 없음, 층별 모양만 보고 알아내기는 답하기 전 입체 요소 0, 도전은 예상 전 처음 모양이 멈춘 그림·내 판 없음·보기 이름이 답을 알리지 않음, 보기 값·자리의 꼴(정답 수·자리 비율, 개수만 세어 맞히는 길)을 시드 여러 개로.
4. **별·점수**: 15-3 기준(어느 단계가 틀린 횟수로 별을 정하는지 — Build는 "층별 모양만 보고 알아내기" 하나), 엔진 점수 = 독립 계산(일부러 틀려 이득 0), 도전은 별 합계 밖.
5. **도장 셋**: 조건이 8절 문장 그대로인지(숨겨진 쌓기나무 찾기는 15-17 결정의 셈 방법), 학습 기록만으로 판정(순수 함수), 이미 조건을 채운 기록으로 열면 한 번만, 도장판 16칸 화면(학습 기록 화면이 길어진 것 포함)이 다섯 크기에서 넘치지 않는지.
6. **15-8**: 앞과 뒤 오개념 보기를 한 번도 못 만나는 판이 0인지, 보기 모양만 보고 맞히는 규칙들의 비율이 찍기(33%)보다 크게 높지 않은지 — 시드 2,000개 이상으로 직접.
7. **S2b-2·참고**: review-blocks-s2.md의 재현 방법대로 960×768·960×680에서 카드와 [확인하기]가 떨어졌는지, 고친 S2b-4, 그대로 둔 것의 값.
8. **배치·접근성**: 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) + 960×768 × 보통·글꼴 흉내에서 새 단계·도전의 스크롤·넘침·겹침 0, 48px, 키보드만으로 5차시·도전 끝까지, 색만으로 구분하지 않음, 움직임 줄이기·`?fx=low`, 화면 읽기 이름·알림. 스크린샷을 직접 열어 의견.
9. **늦게 불러오기**: 새 플레이 코드가 쌓기나무 묶음에 들어갔는지(처음 화면에서 받지 않음), 처음 받는 크기 전·후(Build: 182.6 → 185.1 KB gzip).
10. **불변**: 기준 `0a4b3a6` 빌드와 견줘 정육면체·직육면체·쌓기나무 1~4차시(15-8로 바뀐 `blocks-flip` 문항 말고)·인트로·학년·영역 화면이 같은지, 저장 값 차이 0.
11. **G1과 합칠 때**: 같은 때에 각기둥 G1이 `track/cuboid`에서 끝났다(따로 Review 중). `git merge-tree --write-tree track/blocks track/cuboid`로 줄 충돌, 합친 결과를 scratchpad에 풀어 단위·영역·도장 e2e를 돌려 본다(`E2E_PORT`를 꼭 준다) — 둘 다 `main.js`·`net-workshop-areas.spec.js`를 고쳤다.
12. **느린 기기 검사**: 새로 만들거나 고친 검사를 CPU 4·8·12배로 — 값 실패 0.
13. 새로 생긴 문제, 사용자가 정해야 할 것.
