# Build 서브에이전트 지침: G2r 각기둥 4단계를 직육면체처럼 자유 배치로 (트랙 "cuboid" 작업 폴더)

## 역할

너는 **Build** 담당이다. 사이트에 올라간 각기둥 4단계 "전개도 완성하기"(`prism-free` — G2, `2578b66`)의 조작 방식을 사용자의 요청대로 바꾼다. 검증은 별도 Review 서브에이전트가 한다.

사용자의 말(2026-10-24, [spec-grade6.md](spec-grade6.md) 15-30 — 그대로): "4단계 운영방식을 바꿔야 하겠어. 지금 방식은 불편해. 직육면체 전개도 만들 때처럼 면들을 자유롭게 학생이 직접 끌어와서 배치하고 면을 돌릴수도 있는 방식으로 바꿔줘. 그리고 미리 밑면 중 한개가 고정 배치되는 것도 그렇게 할 필요없어. 직육면체 전개도를 직접 배치해볼 때랑 같은 방식으로 조작할수 있도록 해줘"

## 만들 것

1. `prism-free`를 **직육면체 "내 맘대로 직육면체 전개도"와 같은 조작**으로: 빈 판에서 시작(미리 놓인 면·자물쇠·붙일 자리(+)·주문 1·2 없음), 면 카드(밑면 둘·옆면 n장 — 같은 옆면은 "×n" 묶음이어도 됨)를 끌어 놓기·카드 누르고 판 누르기·옮기기·빼기·되돌리기·모두 빼기, **면 돌리기**(고른 면의 돌리기 손잡이·두 번 누르기·[돌리기]·R 키·끄는 중 돌리기 — 직육면체와 같은 손짓), 키보드만으로도 끝까지. [접어 보기] → 놓은 그대로 접힘 → 맞음 / 안 됨 + "왜 안 될까요?"(고른 까닭 먼저) / 전에 찾은 것. 서로 다른 전개도 3가지까지(2가지부터 [결과 보기], 3가지 ★3).
2. **다각형 밑면을 놓고 돌리는 방법**(삼각형·사다리꼴·육각형은 1 cm 정사각형 칸에 꼭짓점이 맞지 않음)과 **판의 모습**은 시안으로 사용자가 고른다(차례 1). 예: A 1 cm 칸 판 — 옆면(직사각형)은 칸에 맞춰 놓고 90°씩 돌림, 밑면은 놓으면 가까운 면의 같은 길이 모서리(또는 칸 선)에 맞춰 붙고 변마다 돌림 / B 칸 없는 판 — 어느 면이든 끌어 놓으면 가까운 면의 같은 길이 모서리에 자석처럼 붙고, 돌리기는 그 면의 변 방향마다(또는 15°·30°씩) / 그 밖에 네가 더 나은 방법이 있으면. 시안마다 **만들 수 있는 서로 다른 전개도의 수**(962칸 가운데 — 예: 옆면이 육각형의 비스듬한 변에 붙는 전개도를 만들 수 있는지)와 놓기·돌리기에 드는 손짓 수를 적는다.
3. 그대로 둘 것: 나오는 각기둥과 길이, 만들 각기둥을 보이는 창(시안 B — 판을 넓게 써야 하면 자리를 시안에서 다시 보임), 판정(`checkNet`에 해당하는 각기둥 판정)·합동 열쇠·점수(15-29 — 최대 104점)·도장 "기둥 설계사"·저장 값의 모양, 도전 `prism-count`(손대지 않음).
4. 기존 각기둥 4단계 검사는 새 조작에 맞게 다시 쓴다(약해진 검사 0 — 판정·점수·정답 노출·배치·키보드 검사는 같은 강도로). 직육면체·정육면체 자유 배치는 **한 글자도 달라지지 않게** — 공통 부품(`free-board.js` 등)을 넓혀 쓰면 넓히기만 하고 그 화면들의 픽셀·DOM 비교 수치를 보고.

## 차례 — 화면은 시안부터

- **차례 1 = 조작·배치 시안만 만들고 멈춰 보고**: 실제 빌드에 덧씌워(시안 코드는 scratchpad 복사본에 두어도 된다) 지금(G2) + A·B(·C) 비교 한 장을 크롬북 1366×768·세로 태블릿 820×1180·휴대폰 390×844로. 장면은 ① 빈 판 처음 ② 밑면 하나와 옆면 몇 장을 놓은 도중(돌리기 손잡이 보임) ③ 다 놓은 육각기둥 전개도 ④ 접은 모습. 시안마다 2의 수치를 적고 추천을 붙인다. 그림은 scratchpad `build-g2r/shots/`. 보고(10줄 이하)하고 **멈춘다** — 코디네이터가 사용자에게 보이고 "계속"을 메시지로 준다.
- 차례 2~: 고른 시안으로 완성 → 테스트 → 커밋.
