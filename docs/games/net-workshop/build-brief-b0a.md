# Build 서브에이전트 지침: B0a 영역 고르는 화면 + 앱 이름 "입체도형 공방" (트랙 "b0")

## 역할

너는 **Build** 담당이다. 승인된 6학년 계획([spec-grade6.md](spec-grade6.md))의 **B0** 가운데 **학생·교사 눈에 보이는 절반**을 만든다: 엔진의 "영역" 기능, 처음 화면의 영역 카드, 영역별 단계 지도, 수업 주소 `?area=`, 앱 이름 바꾸기. **빌드 구조 바꾸기(여러 파일·늦게 불러오기·로컬 서버 e2e — 계획 7-4절)는 이번 범위가 아니다**(다음 Build "B0b"). 코디네이터가 B0를 둘로 나눴다 — 눈에 보이는 변화와 빌드 바탕의 변화를 따로 검토하려는 것이다. 다른 Build 서브에이전트가 **같은 때에 다른 폴더에서 쌓기나무 3·4차시(S2)**를 만들고 있다. 검증은 별도 Review 서브에이전트가 한다.

## 지금 상태 (2026-10-14)

사이트(`main`)에는 차시 넷이 **한 줄로 이어져** 있다: 1차시 정육면체의 전개도(4단계 + 도전 주문서 2) · 2차시 직육면체의 전개도(4단계) · "쌓기나무 1차시" 어느 방향에서 보았을까(3단계) · "쌓기나무 2차시" 만든 모양과 위에서 본 모양(3단계). 처음 화면은 [시작하기] → 단계 지도. 쌓기나무 차시의 칩("쌓기나무 1차시")·단원 글("6학년 2학기 · 공간과 입체")·시간 칩은 S1이 엔진에 더한 차시 정의의 선택 값으로 보인다. 놀이 방법에는 전개도 6줄 + 쌓기나무 2줄이 한데 있다. 앱 이름은 "전개도 접기 공방"이다.

## 만들 것

### 1. 엔진 "영역" (쓰지 않는 게임은 지금과 한 글자도 같게)

- 게임 정의의 선택 값 `areas: [{ id, title, grades?, note?, lessons: [...] , art? }, …]`. `areas`가 없는 게임(예시 게임, 템플릿으로 만든 게임, `engine-features` 시험 페이지)은 **DOM·자리·저장 값이 지금과 같아야 한다.**
- **처음 화면**: [시작하기] 자리에 영역 카드. 카드마다 작은 그림, 영역 이름, 학년·단원 한 줄, 모은 별(그 영역의 것), 차시 수. 지난번에 하던 영역에 "여기부터!"(처음이면 첫 영역). 카드를 누르면 그 영역의 단계 지도로. 크롬북에서 카드가 한 화면에 들어오고(세로 스크롤 0), 태블릿·휴대폰에서도 넘치지 않는다. 키보드 초점·이름("5학년 전개도, 차시 2개, 모은 별 0 / 24" 같은).
- **단계 지도**: 고른 영역의 차시만 보인다. 위에 **영역 탭**(지금 영역 표시, 다른 영역으로 바로 가기 — `role="tablist"` 또는 그에 맞는 버튼 묶음, 방향키·Tab으로 조작, 48px). "모은 별 n / m"은 그 영역의 것. [처음 화면]으로 돌아가는 길은 그대로.
- **차시 칩**: 한 영역 안에서는 그 영역의 차례대로 "1차시"·"2차시"가 자연스럽다 — 쌓기나무 영역 안에서는 "1차시"·"2차시"(교과서의 차시와 같다 — 7-1절). 지금 S1이 넣은 "쌓기나무 1차시" 칩 값은 영역이 생기면 필요 없어진다. **다만 `?lesson=`으로 한 차시만 연 화면과 결과·기록의 글에서 어느 영역의 몇 차시인지 헷갈리지 않게** 한다(예: 차시 머리의 단원 글 "6학년 2학기 · 공간과 입체"는 그대로 둔다). 어떻게 정했는지 보고한다.
- **주소**: `?area=<id>`(그 영역의 단계 지도로 바로), 없는 id면 처음 화면. `?lesson=`·`?stage=`·`?unlock=all`·`?seed=`·`?sound=`·`?fx=`는 지금과 같게 동작한다. `?lesson=cube`처럼 한 차시만 여는 수업 주소에서는 영역 카드·영역 탭이 **보이지 않는다**(지금처럼 그 차시만). `?area=`와 `?lesson=`이 함께 오면 `?lesson=`이 이긴다.
- **기록**: 저장 열쇠·저장 모양을 바꾸지 않는다(사이트에서 쌓은 별·점수·도감이 그대로 이어져야 한다). "지난번에 하던 영역"을 기억하는 값만 더한다(옛 저장 값에 그 값이 없어도 오류 없이 첫 영역). **옛 저장 값(영역이 없던 때의 것)을 넣고 열어도 별·도감·칭호가 그대로 보이는 것**을 검사로 고정한다.
- 내 공방 카드·칭호·도장판·학습 기록은 게임 하나에 하나 그대로(영역을 넘나들며 쌓임). M2-5에서 넣은 "한 차시만 열면 그 차시의 도감 칩만"은 그대로.
- **다음 단계**: 한 차시의 마지막 단계 결과 화면의 [다음 단계]는 지금처럼 같은 차시 안에서만. 단계 지도로 돌아가면 그 차시가 든 영역의 지도가 보인다.

### 2. 게임에 입히기 (`net-workshop`)

- 영역 둘을 등록한다: **"5학년 전개도"**(`cube`·`cuboid` — "정육면체ㆍ직육면체") · **"쌓기나무"**(`blocks-look`·`blocks-top` — "6학년 2학기 · 공간과 입체"). **"6학년 전개도"(각기둥ㆍ원기둥)는 아직 차시가 없으므로 카드를 보이지 않는다**(코디네이터 결정 — 차시가 하나도 없는 영역은 보이지 않고, 각기둥 차시가 생기면 저절로 나타난다. 엔진이 "차시 없는 영역은 건너뛴다"를 한다). 쌓기나무 트랙이 같은 때에 3·4차시(`blocks-three`·`blocks-number`)를 만들고 있다 — **영역의 `lessons`에 그 id를 미리 적어 두고**, 등록되지 않은 차시 id는 엔진이 조용히 건너뛰게 한다(합친 뒤 저절로 보이게).
- **앱 이름 "입체도형 공방"**: `game.json`의 `title`·`summary`(쌓기나무 한 문장 포함)·`units`("6-2 공간과 입체" 추가, `standards`는 `[]` 그대로), 처음 화면, 놀이 방법, 표지 `cover.svg`(전개도 조각 옆에 쌓기나무 세 개 — 손으로 그린 SVG, 이모지·바깥 그림 없음), 게임 모음 카드의 글. **id(`net-workshop`)·파일 이름·주소·저장 열쇠는 바꾸지 않는다.** 게임 이름 글자를 찾는 기존 검사는 새 이름으로 고친다(뜻은 그대로).
- **놀이 방법을 영역에 맞게**: 처음 화면(영역을 고르기 전)에서는 공통 몇 줄, 영역의 단계 지도나 한 차시 주소에서는 그 영역의 줄만 보인다(지금은 `?lesson=cube`에도 쌓기나무 2줄이 보인다 — S1b-5, 쌓기나무 주소에 전개도 6줄이 보인다). 엔진의 `howTo`를 영역별로 줄 수 있게 넓히거나 게임이 지금 영역을 보고 고르게 — 방식은 네가 정하고 보고한다.
- 영역 카드 그림은 `thumbs.js`에 덧붙인다(전개도 조각 / 쌓기나무 — 지금 단계 그림의 화풍).

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 이번 일에서 특히:
  - **플레이 화면(단계 안)은 한 글자도 달라지지 않는다**: 네 차시 14단계 + 도전 2의 플레이·결과 화면의 DOM·자리·점수·기록이 기준(`main`의 지금 커밋)과 같아야 한다(앱 이름 글자가 들어가는 곳 말고). 수치로 보고한다.
  - **`areas`를 쓰지 않는 게임 불변**: 예시 게임의 처음 화면·단계 지도·결과 화면, `engine-features` 시험 페이지가 기준과 같다.
  - 수업 주소(`?lesson=cube`·`?lesson=cuboid`·`?lesson=blocks-look`·`?lesson=blocks-top`)로 연 화면은 앱 이름과 놀이 방법 말고 기준과 같다.
  - 세 크기(1366×768·1366×680·820×1180)와 휴대폰(390×844)에서 처음 화면·단계 지도에 가로 스크롤 0, 크롬북에서 처음 화면 세로 스크롤 0, 48px, 키보드만으로 영역 고르기 → 단계 시작 → 돌아와 다른 영역, 색만으로 구분하지 않음, 대비 4.5:1, 움직임 줄이기·`?fx=low`, 화면 읽기 이름. 글꼴 흉내에서도.
  - 해요체, "종이 공방" 토큰·아이콘, `h()`만(`innerHTML` 없음), 이모지 없음, 제목 글꼴에 없는 기호를 제목·버튼에 쓰지 않는다(가운뎃점은 `ㆍ`).
- **브라우저 검사는 처음부터 느린 기기를 견디게 쓴다**: 크기·자리는 움직임이 끝난 뒤에(`waitForFunction`으로 `getAnimations`), 사라지는 알림은 띄운 조작 바로 뒤에, 혼자 3초 넘는 검사에는 `test.setTimeout`. `waitForTimeout`·`retries` 금지. 끝내기 전에 scratchpad 복사본에 CPU 느리게 하기(4·8·12배)를 넣어 네가 만들거나 고친 검사를 돌려 값 실패 0을 확인한다.
- 기존 검사를 지우거나 약하게 만들지 않는다. 처음 화면 → [시작하기] → 단계 지도로 걸어가던 검사는 영역 카드를 거치게 고치고(뜻은 그대로), 고친 곳과 이유를 표로 보고한다. 전체 차시 수·별 합계에 기대는 검사는 영역·차시 묶음을 보게 한다.
- 테스트: `npm test` + `npm run test:e2e -- --workers=4`(보통) + `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`(글꼴 흉내)에서 실패 0(다른 일꾼이 도는 상태 그대로에서).

## 동시에 만드는 동안 지킬 것 (common-rules 10절)

- **네 작업 폴더와 브랜치에서만** 일한다(코디네이터가 프롬프트로 알려 준다). `main` 체크아웃과 다른 트랙의 폴더는 고치지 않는다.
- **쌓기나무 트랙(S2)이 같은 때에** `src/games/net-workshop/blocks/**`, `main.js`의 차시·단계 목록 **끝**(3·4차시 등록), 엔진 `icons.js`, `tests/e2e/net-workshop-blocks*.spec.js`·`tests/unit/net-workshop-blocks*.test.js`를 고친다. `main.js`에서 차시·단계 목록의 끝 줄들은 다시 쓰지 않는다(영역 정의는 따로 둔다). 쌓기나무 폴더와 쌓기나무 검사 파일은 **건드리지 않는다** — 쌓기나무 검사가 처음 화면을 거쳐 가는 곳이 있어 영역 카드 때문에 깨지면, 고치지 말고 어느 검사인지 보고한다(코디네이터가 그 트랙에 넘긴다). 단, 깨지는 검사가 있으면 네 트랙의 "실패 0"은 그 검사를 빼고 센 것임을 밝힌다.
- 전개도·쌓기나무의 플레이 코드(`fold.js`·`view3d.js`·`play-*.js`·`cuboid-*.js`·`blocks/**` 등)는 고치지 않는다(위 3번의 두 가지를 넣으라는 말이 있을 때 그 줄만).
- 커밋은 자기 브랜치에만. 푸시·합치기는 하지 않는다. `npm install`·`npm ci`·내려받기 금지. 개발 서버는 정해 준 포트만. 띄운 실행·서버는 모두 내리고 끝낸다.
