# Review 서브에이전트 지침: G1 각기둥의 전개도 1 — 바탕 + 1~3단계 (트랙 "cuboid" 작업 폴더)

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-g1.md](build-brief-g1.md)에 따라 만든 것을 **독립적으로** 검증한다. Build와 분리된 검토자다.
- 검토 결과는 새 파일 `docs/games/net-workshop/review-prism-g1.md`(트랙의 작업 폴더 안) 하나. 맨 위에 판정 줄(통과 = 반드시 수정 0건 / 수정 필요). 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다. 작업 폴더에서만 일하고 검증 파일은 정해 준 scratchpad에만. Build의 scratchpad와 Build가 만든 독립 계산 파일(`tests/unit/net-workshop-prism-indep.js`)은 근거로 삼지 않는다 — 따로 짠다.

## 확인할 것

1. **테스트**: `npm test`, `E2E_PORT=<네 포트> npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 실행 — 실패 0. `git diff 0a4b3a6..HEAD -- tests/`를 줄마다 읽어 약해진 검사 0(지침 밖에서 고친 `build.test.js`·`net-workshop-areas.spec.js` 포함 — 뜻이 바뀐 까닭이 "각기둥이 열림"인지).
2. **판정 — 독립 계산**: 기획서 문장만으로 각기둥 전개도가 되는 조건(면의 수·옆면이 직사각형·두 밑면의 자리·맞닿는 선분의 길이·겹침)을 밑면 종류마다(정삼각형·세 변이 다른 삼각형·직사각형·사다리꼴·정오각형·정육각형), 맞닿는 선분 짝, 서로 다른 전개도 수(알려진 값 — 정삼각기둥 9 등), `pickFace`(입체에서 누른 자리 → 면). 판별 문항의 안 되는 보기가 2-2절의 세 종류인지, 까닭 칩의 정답.
3. **정답 노출 0**(5절): `prism-parts`는 처음·돌린 뒤 모두 면 색·표시·속성·DOM 순서가 밑면을 알리지 않음, `prism-judge`·`prism-edge`는 답하기 전 모습이 한 가지·접기와 조작판 잠금(힌트 동안도), 보기 값·자리의 꼴(시드 여러 개). 화면 읽기 이름이 답을 알리지 않는지.
4. **별·점수**: Build는 틀린 횟수 기준을 쓰지 않았다고 함(3문항을 맞힐 때까지 하는 단계도 한 번 틀리면 75%라 같다) — 15-3·spec 16-13의 뜻과 맞는지 직접 따져 본다. 엔진 점수 = 독립 계산, 일부러 틀려 이득 0, 까닭 고르기 +2·별 밖.
5. **오개념 피드백**(4절 각기둥 줄): 밑면은 바닥 면(눕힌 것 늘 1개), 옆면 수, 옆면은 직사각형, 두 밑면의 위치, 맞닿는 모서리 길이("5 cm ≠ 3 cm"), 만나는 선분(바로 옆 선분 보기) — 틀렸을 때 보여 주는 것이 문장 예와 맞는지.
6. **배치·접근성**: 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) + 960×768 × 보통·글꼴 흉내에서 스크롤·넘침·겹침 0, 48px(입체의 면은 Build가 "예외"로 봄 — 가장 작은 면 40~46px·휴대폰 30px: 받아들일 만한지, [크게 보기]로 풀리는지 의견), 키보드만으로 세 단계 끝까지(면·선분 고르기), 색만으로 구분하지 않음(○·△·무늬), 움직임 줄이기·`?fx=low`. 스크린샷을 직접 열어 의견(다각형 면·이름표·접는 모습).
7. **느린 기기**: 접기·펴기 프레임 간격을 CPU 4·8배로 직접, 새로 만들거나 고친 검사를 CPU 4·8·12배로 — 값 실패 0.
8. **이름표 손질**: 각기둥 길이 이름표가 돌려 본 자세에서 눕지 않는지(직접 여러 자세), 직육면체 이름표·화면은 그대로인지(고치지 않았다고 함).
9. **영역·늦게 불러오기**: 각기둥 영역 카드가 열리고 1~3단계·별 합계·단계 지도·놀이 방법이 맞는지, "여기부터!"가 각기둥(15-17), 원기둥은 "준비 중" 그대로, `?lesson=prism`·`?area=prism`, 각기둥 묶음은 들어갈 때만 받는지, 처음 받는 크기 전·후(Build: 182.6 → 188.5 KB gzip, 여는 파일 9 → 11).
10. **불변**: 기준 `0a4b3a6` 빌드와 견줘 정육면체·직육면체 차시(접기 엔진을 넓혔으므로 접는 모습·판정·점수까지)·쌓기나무·인트로·학년 화면이 같은지(의도한 차이: 6학년 별 합계·영역 탭·카드), 저장 값 차이 0. 기존 전개도 검사 전부가 그대로 통과하는지.
11. **S3와 합칠 때**: 같은 때에 쌓기나무 S3가 `track/blocks`에서 끝났다(따로 Review 중). `git merge-tree --write-tree track/cuboid track/blocks`로 줄 충돌, 합친 결과를 scratchpad에 풀어 단위·영역·도장 e2e를 돌려 본다(`E2E_PORT`를 꼭 준다).
12. **코드**: 엔진 변경 0, 공통 부품(`fold.js`·`view3d.js`·`orbit.js`)을 넓힌 줄이 정육면체·직육면체 경로를 바꾸지 않는지(코드로), `h()`만·`innerHTML` 없음·이모지 없음.
13. 새로 생긴 문제, 사용자가 정해야 할 것.
