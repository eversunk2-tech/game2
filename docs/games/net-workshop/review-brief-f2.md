# Review 서브에이전트 지침: F2 쌓기나무 판 돌리기 조금 느리게 · 자유 쌓기 판에 원근 (트랙 "blocks")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-f2.md](build-brief-f2.md)에 따라 만든 것을 **독립적으로** 검증한다. Build와 분리된 검토자다.
- 결과는 새 파일 `docs/games/net-workshop/review-blocks-f2.md`(트랙의 작업 폴더 안) 하나. 맨 위 판정 줄(통과 = 반드시 수정 0건 / 수정 필요). 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다. 작업 폴더에서만, 검증 파일은 정해 준 scratchpad에만. Build의 scratchpad는 근거로 삼지 않는다(사용자가 고른 시안 그림 `build-f2/shots/sheet-*.png`의 A·"나" 칸은 기준 모습으로만).
- **같은 저장소의 `.worktrees/cuboid`(각기둥 G2 — 사용자가 일시정지)와 그 포트(5301·5361~5364)는 건드리지 않는다.**

## 검토 대상

`b4dc3cc`(지침을 맡긴 `main`)과 `track/blocks`의 마지막 커밋 사이의 변경 전부. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `E2E_PORT=5354 npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 — 실패 0. 바뀐 `tests/`를 줄마다 읽어 약해진 검사 0(0.5° → 0.4°, 원근 투영 기대값 — 뜻이 바뀐 줄만인지, 기대값이 독립 계산인지).
2. **빠르기**: 모든 쌓기나무 판(1~5차시·도전·자유 쌓기)에서 끌기 1px = 0.4°(가로·세로), 8px 문턱·버튼 45°/15°·방향키·크게/작게·처음 보기 그대로. **5학년·6학년 전개도 입체의 끌기는 0.5° 그대로**(직접 끌어 잼).
3. **원근(자유 쌓기만)**: 기획서 문장(눈의 거리 = 판 너비 × 3.0, 위·앞·옆 가까이 15° 안에서 서서히 줄어 딱 그 자세에서는 원근 없음, 판을 내려다보는 높이에 따라 조금 올림 — 옆 0°·바로 위 90°에서 0, 가로 돌림에는 움직이지 않음)만 보고 짠 **독립 투영 계산**과 화면의 판 꼭짓점·쌓기나무 꼭짓점을 견줌(여러 자세·크기). 사용자 그림의 자세(앱 기준 판 돌림 73.7°·높이 27.5°)에서 먼 쪽 ÷ 가까운 쪽 ≈ 0.77, 처음 보기 ≈ 0.90인지. [위]·[앞]·[옆] 자세에서 2D 그림과 같은 네모인지, 그 근처에서 원근이 튀지 않고 이어지는지(끌어서 지나가며 프레임마다).
4. **원근에서도 그대로여야 하는 것**: 돌림판식(판 가운데 축), 수평~바로 위, 처음 크기 꽉 차게(14×14·휴대폰 6×6), 크게·작게, 판 옮기기(결정 9 — 펼친 위에서 본 판과 함께), **누른 칸 = 쌓이는 칸**(마우스·터치·키보드, 판 네 구석과 가운데, 높은 탑 옆), 쌓기나무 앞뒤 가림(높은 탑·바둑판 10층 — 그리는 차례가 틀린 프레임 0), 층별로 벌려 보기, 위에서 본 판·위앞옆 모양, 저장, 화면 읽기 문장.
5. **불변**: 1~5차시·도전 화면이 `b4dc3cc` 빌드와 **픽셀까지 같은지**(끌기 빠르기만 다름 — 같은 자세에서 그림 비교), 5학년·6학년 전개도·인트로·학년·영역·학습 기록·선생님용 안내가 같은지, 저장 값.
6. **배치**: 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) + 960×768 × 보통·글꼴 흉내에서 자유 쌓기 스크롤·넘침·겹침 0(위에서 본 판 펼침·옮기기·알림 포함 — F1 재검토 2 값과 견줌), 스크린샷을 직접 열어 사용자가 고른 시안(A·"나")과 같은 모습인지 의견.
7. **그리는 속도**: 가장 나쁜 꼴(판 전체 바둑판 10층)과 보통 장면을 CPU 1·4·6배로 — F1 값(6배에서 34ms 넘는 프레임 6개)과 견줌.
8. **느린 기기 검사**: 새로 만들거나 고친 검사를 CPU 4·8·12배로 — 값 실패 0.
9. 새로 생긴 문제, 사용자가 정해야 할 것.
