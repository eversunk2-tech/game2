# Review 서브에이전트 지침: S1 쌓기나무 바탕 + 1·2차시 (동시 진행 트랙 "blocks")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-s1.md](build-brief-s1.md)에 따라 만든 쌓기나무 바탕과 두 차시를 **독립적으로** 검증한다. Build와 분리된 검토자다.
- **검토 결과는 새 파일 `docs/games/net-workshop/review-blocks.md`에 쓴다**(트랙의 작업 폴더 안). 다른 트랙과 부딪히지 않게 `review.md`는 고치지 않는다. 맨 위에 판정 줄, 그 아래 기존 review.md와 같은 형식의 표.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci` 금지.
- **트랙의 작업 폴더에서만** 일한다(코디네이터가 프롬프트로 알려 준다). `main` 체크아웃과 다른 트랙의 폴더는 건드리지 않는다. 검증 파일·스크린샷은 정해 준 scratchpad 폴더에만. 개발 서버는 정해 준 포트만. e2e는 `--workers=4`.

## 기준

- **[common-rules.md](common-rules.md)** — 쌓기나무가 정육면체 차시와 **같은 조건**으로 만들어졌는지가 이번 검토의 뼈대다. 1~8절을 하나씩 대조한다.
- **[spec-grade6.md](spec-grade6.md)**: 1-2절(교과서 흐름)·1-4절(용어 표), 2-4절(차시·단계 표), 3절(직접 입체적으로 다루기 — 조작 표), 4절(오개념·피드백), 5절(정답 노출 검토), 6절(기술 설계), 8절(보상), 9절(교실 기기·접근성), 10절(파일 구조), 11절(테스트 계획), 12절 S1 줄, 15절(결정)
- 사용자의 말: "교과서 학습에 맞추어서 **쌓기나무를 직접 입체적으로 다루어볼 수 있도록** 구성해줘"
- [spec.md](spec.md) 17절(보기 조작), [docs/dev-guide.md](../../dev-guide.md), [docs/engine.md](../../engine.md), [docs/design/spec.md](../../design/spec.md)

## 검토 대상

코디네이터가 알려 주는 기준 커밋과 트랙 브랜치의 마지막 커밋 사이의 변경 전부(`git diff <기준>..HEAD`와 커밋 안 된 것이 있으면 그것도). Build가 고쳐도 되는 파일은 build-brief-s1.md의 목록이다 — **전개도 공통 부품(`fold.js`·`geometry.js`·`view3d.js`·`free-board.js`·`play-*.js`·`orbit.js`)이 바뀌었으면 범위 위반**이다. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.** 수치는 모두 직접 실행·측정한 것만 적는다.

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내(`E2E_WIDE_TEXT=font`)로 직접 실행. 건너뜀이 기기 나눔뿐인지. `git diff <기준>..HEAD -- tests/`로 **기존 검사가 지워지거나 약해지지 않았는지**(단계 수를 차시별로 세게 바꾼 것 말고).
2. **직접 입체적으로 다루기 (사용자가 특히 요청 — 가장 중요)**: 3절 조작 표를 한 줄씩, **마우스·터치·키보드·버튼 네 수단으로 각각** 끝까지 해 본다 — 쌓기(바닥 칸·윗면·옆면, 놓일 자리 미리 보기, 3층·판 밖 안내), 빼기, 되돌리기, 모두 치우기, 쌓는 중 돌리기, [위][앞][옆], 크게·작게, 처음 보기로.
   - **누르기와 끌기를 가르기**: 문턱 앞뒤(7·8·9px), 돌리려다 쌓이는 경우·쌓으려다 돌아가는 경우를 여러 속도·방향으로 재서 0인지. 끈 직후의 탭이 먹히는지(관성 스크롤 0 — 터치), 끌기 뒤 따라오는 click이 쌓기로 이어지지 않는지. 끌지 않을 때 페이지 스크롤(휴대폰)과 두 손가락 벌리기.
   - **누른 곳이 가리키는 쌓기나무·면이 정확한지**: 보기 방향 여러 가지 × 모든 보이는 면에서 "누른 점 → 놓인 자리"를 독립 계산(광선)과 견줌. 가려진 면·겹쳐 보이는 가장자리.
   - **그리기**: 깊이 순서 오류 0(무작위 쌓기 × 무작위 보기를 독립 광선 계산과 견줌), [위][앞][옆]에서 2D 그림과 똑같이 보이는지, 돌리는 동안 끊기지 않는지(느린 CPU 흉내), 방향 글자 "앞"·"옆"이 돌려도 읽히는지. 스크린샷을 직접 열어 쌓기나무가 또렷하고 입체로 읽히는지 본다.
   - 교과서 활동과 이어지는지: 두 차시 여섯 단계가 2-4절 표·교과서 흐름(1-2절)과 맞는지, 용어가 1-4절 표와 같은지("만든 모양", "옆"은 오른쪽, 숨겨진 쌓기나무 …).
3. **수학·판정**: 저장소의 `blocks.js`를 쓰지 않는 **독립 계산**으로 3×3칸·3층 높이 지도 262,144개 전부에서 위·앞·옆에서 본 모양, 개수, "같아 보이는가", 문제 후보의 "쌓기가 하나로 정해지는가"를 견준다(계획의 수치 56,478 / 39,041 / 17,437 / 12,636도). 문제 만들기가 시드로 재현되는지, 각 단계 문항의 정답·보기·까닭 문장·오개념 tag가 맞는지(무작위 시드 여러 개). 뜬 쌓기나무가 생길 길이 없는지.
4. **답하기 전 정답 노출 (5절)**: 돌려 보면 답이 보이는 문항(방향 맞히기·"이쪽에서 보면"·개수)에서 답하기 전에 그 그림을 돌릴 수 없는지 — 끌기·휠·키·버튼·[위][앞][옆] 모두. 답하기 전 화면의 글자·속성·클래스·SVG 요소 순서와 좌표·알림에 답(숨겨진 쌓기나무의 자리, 개수)이 드러나지 않는지(멈춘 그림의 DOM에 가려진 쌓기나무가 들어 있지 않은지). 내 쌓기의 2D 그림이 [확인하기] 전에 보이지 않는지. 문항이 달라도 답하기 전 화면 배치·크기가 답과 엮이지 않는지.
5. **점수**: 기획서 문장과 engine.md 점수 표만 보고 짠 독립 계산 ↔ 엔진(무작위 여러 기기·여러 판, 나가기·새로 고침 포함). 놀이터는 채점 없음. 일부러 틀려 이득 0, 되풀이로 쌓이지 않음, 화면 = 저장. 두 차시를 모두 맞힌 학생의 점수와 칭호 기준.
6. **교실 기기·접근성**: 1366×768·1366×680·820×1180 세로·가로 스크롤 0, 판 안쪽 넘침 0·잘린 버튼 0(모든 장면), 플레이 도중 머리·매트 움직임 0, 48px, 알림 겹침 0, 휴대폰 배치. 키보드만으로 두 차시 끝까지(초점 표시, Tab 순서), 색만으로 구분하지 않음, 대비 4.5:1, 움직임 줄이기·`?fx=low`, 화면 읽기 이름·알림(쌓은 개수, 보는 방향, 놓인 자리). 글꼴 흉내에서 세로 여유가 빠듯한 장면 목록.
7. **정육면체 차시 불변**: 기준 커밋을 따로 빌드해 정육면체 4단계 + 도전 2개의 화면·점수·기록을 견준다(달라진 장면 0). 전개도 공통 부품이 바뀌지 않았는지.
8. **화면 문장·디자인·코드**: 해요체, "종이 공방" 토큰·아이콘, `h()`·`innerHTML` 없음·이모지 없음·죽은 코드, 순수 함수와 화면의 나눔, 나간 뒤 리스너·타이머·rAF 0, 콘솔 오류 0. 교과서의 문장·그림·문제 수치를 옮기지 않았는지(코드·문구·주석).
9. **계획의 계산값 확정**: Build가 잰 값으로 확정했다는 것(쌓기나무 한 변의 크기, 화면 배치, 문항 수, 차시 시간)이 타당한지. 차시 시간은 문항당 어림과 견준 의견.
10. **범위·합치기**: 허용 파일 안인지. 같이 쓰는 파일(`main.js` 등록, `style.css`, `icons.js`, `docs/engine.md`, `net-workshop.spec.js`)을 덧붙이기만 했는지, 있는 줄을 다시 쓰거나 옮긴 곳 목록(합칠 때 부딪힐 곳). 엔진 변경이 타당하고 예시 게임에 영향이 없는지. 쌓기나무 코드가 전개도 코드와 떨어져 있어 나중에 영역별로 나눠 불러오기 쉬운지(의견).
11. **새로 생긴 문제**, 사용자가 정해야 할 것(선택지와 추천), Build가 정한 세부에 대한 의견.

## 형식과 끝나면

`review-blocks.md`: 판정 줄, 테스트 결과 표, 발견한 문제 표(심각도: 반드시 수정 / 고치면 좋음 / 참고, 위치는 파일:줄, 재현 방법, 고칠 방향), 조작 수단 × 화면 크기 결과 표, common-rules 대조표(절마다 지킴 / 어김), 확인한 것, 확인하지 못한 것.

최종 답변 **12줄 이하**: 판정(통과 / 수정 필요), 조작(네 수단 결과, 누르기와 끌기 가르기·누른 곳 정확도), 판정·수학 독립 계산 결과, 정답 노출, 점수, 배치·접근성, 정육면체 불변, 테스트 숫자(보통·글꼴 흉내), 새 문제와 심각도별 개수, "반드시 수정" 목록(파일:줄), 합칠 때 부딪힐 곳, 사용자가 정해야 할 것, 확인하지 못한 것. 직접 잰 것과 추정을 구분한다.
