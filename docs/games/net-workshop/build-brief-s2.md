# Build 서브에이전트 지침: S2 쌓기나무 3·4차시 (동시 진행 트랙 "blocks")

## 역할

너는 쌓기나무 영역의 **Build** 담당이다. S1(바탕 + 1·2차시)은 재검토를 통과해 사이트에 올라가 있다. 이번에는 승인된 6학년 계획([spec-grade6.md](spec-grade6.md))의 **S2 — 교과서 3·4차시에 맞춘 두 차시**를 만들고, S1 검토에서 "다음 쌓기나무 Build 때 함께"로 남긴 것을 고친다. 다른 Build 서브에이전트가 **같은 때에 다른 폴더에서 "영역 고르는 화면·앱 이름"(B0a)**을 만들고 있다 — 두 결과는 나중에 코디네이터가 `main`에 합친다. 검증은 별도 Review 서브에이전트가 한다.

## 먼저 읽을 것 (순서대로 — `main` 체크아웃의 것이 최신이다. 네 작업 폴더는 코디네이터가 `main`의 지금 내용으로 맞춰 준다)

1. **[common-rules.md](common-rules.md)** — 공통 규칙. 8절에 **"움직임이 끝난 뒤에 잰다"**가 새로 들어갔다(S1에서 이것 때문에 하루를 붙잡혔다). 처음부터 지킨다.
2. **[spec-grade6.md](spec-grade6.md)** — 1-2절(교과서 흐름)·1-4절(용어 표), **2-4절의 3차시 `blocks-three`·4차시 `blocks-number`**, 3절(조작 — 3-4 "위·앞·옆에서 본 모양을 보여 주는 방법", 3-5 교과서 활동과 잇기), 4절(오개념·피드백), 5절(정답 노출 검토), 6절(6-3 판정 함수의 `maxFill`·`minCount`, 6-4 문제 만들기), 8절(보상), 9절, 10절(파일 구조 — `grid-draw.js`), 11절(테스트 계획), 12절의 **S2 줄**, 15절(결정 — 15-3 쌓는 단계의 별, 15-4)
3. 작업 폴더의 [review-blocks.md](review-blocks.md) — "재검토 (S1b 수정 확인)"의 S1b-1·S1b-3·S1b-4·S1b-8, "재검토 2 (S1c)"의 S1c-1
4. 네가 만든 S1 코드: `src/games/net-workshop/blocks/**`, `tests/unit/net-workshop-blocks*.test.js`, `tests/e2e/net-workshop-blocks.spec.js`(도우미 `calm(page)` — 크기·자리를 재기 전에 부른다)

교과서 PDF는 읽지 않는다. 교과서의 문장·그림·문제 수치를 옮기지 않는다 — 문제와 그림은 모두 새로 만든다. 용어는 1-4절 표 그대로.

## 만들 것

- **3차시 `blocks-three` 위, 앞, 옆에서 본 모양**(교과서 60~63쪽)과 **4차시 `blocks-number` 위에서 본 모양에 수 쓰기**(64~65쪽): 단계 수·내용·문항 수·돌려 보기 잠금·끝나는 조건은 2-4절 표 그대로(차시마다 3단계).
- `grid-draw.js`(10절): 2D 그림(위·앞·옆·수), **모눈 칠하기**(학생이 본 모양을 칸을 눌러 그린다)와 **수 쓰기**(위에서 본 모양의 칸마다 수를 올리고 내린다). 마우스·터치·키보드 각각, 누르는 곳 48px. 판정 순수 함수 `maxFill`·`minCount`(6-3절) 등.
- 지금의 차시 묶음에 **쌓기나무 3차시·4차시**로 등록한다(칩 "쌓기나무 3차시"·"쌓기나무 4차시", 시간 칩은 직접 해 보고 잰 어림, "6학년 2학기 · 공간과 입체"). `?lesson=blocks-three`·`?lesson=blocks-number`로 바로 들어간다. 영역 화면은 B0a의 몫이라 건드리지 않는다.
- 별: 15-3의 기준 그대로 — 맞는 답이 정해진 단계는 답하는 단계다. **한 번만 틀려도 정답률로 바로 ★1이 되는 단계**(문항이 2~3개이고 한 번씩 답하거나 맞힐 때까지 다시 하는 단계)는 틀린 횟수로(0번 ★3 · 1번 ★2 · 2번 이상 ★1, `finish({ stars, starNote })`). 어느 단계에 적용했는지와 까닭을 보고한다(모든 답 순서를 나열해 ★1·★2·★3이 모두 나오는 단위 검사).
- 계획에 적히지 않은 세부는 계획의 뜻과 공통 규칙에 맞게 네가 정하고 까닭을 보고한다. 사용자가 정해야 할 만큼 큰 갈림길은 추측하지 말고 "사용자 결정 필요"로 적는다.

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 특히:
  - **답하기 전 정답 노출 0**: 그림을 보고 본 모양을 그리거나 수를 쓰는 문항에서, 답하기 전에 그 답이 화면의 글자·속성·클래스·SVG 순서·알림·화면 틀에 드러나지 않는다. 돌려 보면 답이 보이는 문항은 답하기 전에 돌릴 수 없다(2-4절의 잠금 표). 보기형 문항은 정답 자리와 **값의 꼴** 모두 답과 엮이지 않는다.
  - 판정을 **독립 계산과 전수 비교**: 3×3칸·3층 262,144개에서 위·앞·옆 모양 → `maxFill`·`minCount`, "세 그림에 맞는 쌓기가 하나로 정해지는가", 수 쓰기의 정답. 계획의 수치와 견준다.
  - 모눈 칠하기·수 쓰기는 **맞힐 때까지 다시 하는 단계**면 같은 틀린 답을 거듭 내도 한 번만 센다(S1-3과 같게). 좌우를 뒤집어 그린 것(옆에서 본 모양의 흔한 오개념 — 4절)은 그 까닭을 말해 준다.
  - 점수는 엔진 규칙 안에서. 독립 계산 ↔ 엔진 무작위 검사(일부러 틀려 이득 0, 화면 = 저장, 되풀이로 쌓이지 않음).
  - 세 크기(1366×768·1366×680·820×1180) 세로·가로 스크롤 0, 판 넘침 0, 머리·매트 움직임 0, 48px, 키보드만으로 두 차시 끝까지, 색만으로 구분하지 않음, 움직임 줄이기·`?fx=low`, 화면 읽기 이름·알림(칠한 칸, 쓴 수).
- **브라우저 검사는 처음부터 느린 기기를 견디게 쓴다**: 크기·자리·겹침은 `calm(page)` 뒤에 잰다. 몇 초 뒤 사라지는 알림은 띄운 조작 **바로 뒤에** 본다. 잠깐만 보이는 상태는 `MutationObserver`로 적어 두고 본다. 혼자 3초 넘게 걸리는 검사에는 `test.setTimeout`(CPU 4배에서 걸린 시간의 3배 이상). `waitForTimeout`·`retries` 금지. **끝내기 전에 scratchpad 복사본에 CPU 느리게 하기(4·8·12배)를 넣어 쌓기나무 검사 파일을 돌려 값이 어긋나는 실패 0을 확인한다**(저장소에는 재현용 코드를 남기지 않는다).
- **이미 사이트에 있는 것(정육면체·직육면체 차시, 쌓기나무 1·2차시)의 화면·점수·기록은 위 표에서 고치는 것 말고 한 글자도 달라지면 안 된다.** 기준(`main`의 지금 커밋)과 견준 수치를 보고한다.
- 테스트: `npm test` + `npm run test:e2e -- --workers=4`(보통) + `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`(글꼴 흉내)에서 실패 0(다른 일꾼이 도는 상태 그대로에서).

## 동시에 만드는 동안 지킬 것 (common-rules 10절)

- **네 작업 폴더와 브랜치에서만** 일한다(코디네이터가 프롬프트로 알려 준다). `main` 체크아웃과 다른 트랙의 폴더는 고치지 않는다(지침·기획서를 읽는 것은 된다).
- 새 코드·스타일·테스트는 쌓기나무 파일에 둔다(`src/games/net-workshop/blocks/**`, `tests/unit/net-workshop-blocks*.test.js`, `tests/e2e/net-workshop-blocks.spec.js` — 길어지면 `net-workshop-blocks2.spec.js`처럼 새 파일). 같이 쓰는 파일(`main.js`의 차시·단계 등록과 놀이 방법, 엔진 `icons.js`, `docs/engine.md`)은 **덧붙이기만, 최소로**. **B0a 트랙이 같은 때에 `main.js`(영역 정의·놀이 방법 나누기)·`game.json`·엔진 `app.js`(처음 화면·단계 지도)·`base.css`를 고친다** — `main.js`에서는 차시·단계 목록의 끝에 덧붙이기만 하고, 놀이 방법 글은 건드리지 않는다(B0a가 영역별로 나눈다).
- 전개도 공통 부품(`fold.js`·`geometry.js`·`view3d.js`·`free-board.js`·`play-*.js`·`orbit.js`·`logic.js`·`cuboid-*.js`)은 고치지 않는다.
- 엔진(`src/shared/**`)은 꼭 필요한 만큼만 고치고 줄 번호와 함께 보고한다.
- 커밋은 자기 브랜치에만. 푸시·합치기는 하지 않는다. `npm install`·`npm ci`·내려받기 금지(`node_modules`는 링크). 개발 서버는 정해 준 포트만. 띄운 실행·서버는 모두 내리고 끝낸다.

## 고쳐도 되는 파일

- `src/games/net-workshop/blocks/**`(새 파일 포함), `src/games/net-workshop/main.js`(덧붙이기), `tests/unit/net-workshop-blocks*.test.js`, `tests/e2e/net-workshop-blocks*.spec.js`

## 끝났다의 기준

`npm test`, e2e 보통·글꼴 흉내 모두 실패 0(마지막 커밋에서 처음부터). 느린 기기 흉내 4·8·12배에서 쌓기나무 검사의 값 실패 0. 두 차시를 브라우저에서 마우스·터치·키보드로 각각 처음부터 끝까지 해 보고 걸린 시간 기록. 판정 전수 비교, 정답 노출 검사(보기의 자리와 값의 꼴 포함), 점수 독립 계산. 네 크기 + 1024×768 스크린샷을 직접 연다(모눈·수 쓰기 판이 또렷하고 누르는 곳이 충분한지, 까닭 그림이 읽히는지). 이미 있는 차시의 불변 수치.

## 최종 보고 (16줄 이하)

만든 것(두 차시 여섯 단계, `grid-draw`)과 직접 확인한 방법·잰 값, 판정 전수 비교, 정답 노출(자리·값의 꼴), 별·점수(어느 단계에 틀린 횟수 기준을 썼는지), 네 크기 배치, S1에서 넘어온 다섯 가지의 결과(잰 값), 느린 기기 흉내 결과, 이미 있는 차시 불변 수치, 테스트 결과(보통·글꼴 흉내), 엔진에서 바꾼 것(줄 번호), 같이 쓰는 파일에서 고친 곳(줄 번호), 차시 시간 어림, 계획과 다른 점, 사용자 결정이 필요한 것, 남은 한계, 마지막 커밋 해시. 직접 실행해 확인한 것과 추정을 구분한다.
