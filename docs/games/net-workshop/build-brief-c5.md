# Build 서브에이전트 지침: c5 "주사위 장인" → "주사위 전개도 장인", "주사위 주문" → "주사위 전개도 주문" (작은 손질 — 트랙 "c1" 작업 폴더)

## 역할

너는 **Build** 담당이다. 사용자의 요청([spec.md](spec.md) **16-18**)을 반영한다. 검증은 별도 Review 서브에이전트가 한다.

사용자의 말: "'주사위 장인'의 의미가 헷갈려. 도전 항목을 말하는 거 맞아? 주사위를 던지지는 않는데 주사위 장신이라 되어 있어서 헷갈리지 않게 이름 수정해줘" → 사용자 결정: 도장 이름 **"주사위 전개도 장인"**, 도전 이름 **"주사위 전개도 주문"**.

## 할 일

1. 도장(`src/games/net-workshop/main.js` `dice-master`): 이름 **`주사위 전개도 장인`**, 설명은 해요체로 무엇을 하면 받는지 분명하게(예: "마주 보는 눈의 합이 7인 주사위 전개도를 2가지 만들어요(도전)" — 도장판 칸에 맞는 길이로 네가 다듬어 보고).
2. 도전 `cube-dice`의 화면에 보이는 이름 "주사위 주문"을 **`주사위 전개도 주문`**으로 — 단계 지도·도전 주문서 칸·주문 칩·결과 화면·학습 기록·놀이 방법·도장 설명·화면 읽기 이름·알림 등 **학생·교사에게 보이는 모든 곳**(코드 전체를 `주사위 주문`·`주사위 장인`으로 찾아 하나씩 — 주석은 맞게 고쳐도 되고 그대로 둬도 됨, 보고).
3. 저장 열쇠·id(`dice-master`, `cube-dice`, 모음 id 등)는 **그대로** — 이미 받은 도장·별이 그대로 이어지는지 검사(옛 저장 값으로 열면 새 이름으로 보임).
4. 긴 이름 때문에 넘치는 곳이 없는지: 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) × 보통·글꼴 흉내에서 도장판·단계 지도(도전 칸)·결과 화면·학습 기록.
5. 그 이름을 찾는 기존 검사는 새 이름으로(줄마다 보고).

## 반드시 지킬 것

- 이름·설명 말고는 한 글자도 바뀌지 않는다(판정·점수·저장·화면 배치). 기준 `main` 빌드와 견줘 바뀐 곳이 이름 자리뿐인지.
- [common-rules.md](common-rules.md), 브라우저 검사는 느린 기기를 견디게, `waitForTimeout`·`retries` 금지.
- 테스트: `npm test`, `E2E_PORT=5305 npm run test:e2e -- --workers=4`, `E2E_PORT=5305 E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0.

## 고쳐도 되는 파일

- 이름이 들어 있는 곳만: `src/games/net-workshop/**`의 그 문자열(쌓기나무 `blocks/**`는 쌓기나무 R1이 다른 작업 폴더에서 고치고 있다 — 거기에 이 이름이 있으면 고치지 말고 보고), 그 이름을 찾는 검사 줄.
- 고치지 않는 것: 저장 열쇠·id, 엔진(`src/shared/**`), `docs/**`, `scripts/**`, package 파일, `.github/**`, `.claude/**`, 그림 파일.

## 지킬 것

- 작업 폴더 `.worktrees/c1` · 브랜치 `track/c1`(코디네이터가 `main`으로 맞춰 둠) · 포트 **5304**·e2e **5305** · scratchpad `build-c5/`(경로는 프롬프트로). 커밋은 `track/c1`에만, 푸시·합치기 금지. `npm install`·`npm ci`·내려받기 금지. **서버·실행을 내릴 때는 네 PID만**.
