# Build 서브에이전트 지침: B0b 빌드 바탕 — 여러 파일 빌드 · 영역을 들어갈 때 불러오기 · 하위 경로 서버 e2e (트랙 "b0")

## 역할

너는 **Build** 담당이다. 승인된 6학년 계획([spec-grade6.md](spec-grade6.md))의 B0 가운데 **빌드 바탕** 절반(B0b — 15-5절)을 만든다. 근거는 **7-3절 안 B(여러 파일)·7-4절·7-5절**과 12절 B0의 "끝났다"의 기준. 검증은 별도 Review 서브에이전트가 한다.

지금 사이트(`cd190ce`)는 게임마다 HTML 한 파일에 엔진·게임 JS·CSS·글꼴(base64)을 넣고, 인트로의 큰 그림 두 장만 B0c2가 먼저 `dist/assets/`로 따로 냈다. 학생은 사이트 주소(`https://eversunk2-tech.github.io/game2/` — **하위 경로**)로만 접속한다(사용자 결정 10-09 — 파일을 내려받아 여는 쓰임은 지원하지 않음).

## 할 일

### 1. 여러 파일 빌드 (7-4절 표)

- `scripts/build.mjs`: esbuild 한 번에 모든 게임을 묶는다 — `format: 'esm'`, `splitting: true`, 이름에 내용 해시(`assets/[name]-[hash]`). HTML은 `<link rel="stylesheet">`·`<script type="module">`의 주소만 해시 이름으로 넣고 `modulepreload`·글꼴 `preload`를 넣는다. **주소는 모두 상대 주소(`./assets/…`)**.
- 글꼴(`scripts/lib/font.mjs`): `data:` 대신 사이트 전체(게임 모음 + 모든 게임의 JS·CSS·HTML)에 쓰인 글자를 모은 **`display-해시.woff2` 하나**. "제목 글꼴에 없는 글자" 검사는 그대로.
- 그림: B0c2가 만든 규칙(16 KB 이상 사진형은 파일로, **바이트 그대로 — md5 같음**, SVG·작은 그림은 `data:`)을 새 빌드에 그대로 옮긴다. 캔바 AI 그림의 출처 정보(C2PA)가 결과물에 남아야 한다(검사 유지).
- 게임 모음(`scripts/lib/hub.mjs`): 링크는 그대로(`<id>.html`), CSS는 인라인 대신 공통 파일. **선생님용 주소 옵션 목록에 `?grade=`·`?area=`를 더한다**(review-b0a.md B0a-6 — 우선순위 `?lesson=` > `?area=` > `?grade=`, [engine.md](../../engine.md) 8절과 같은 설명).
- 빌드 검사: ① 바깥 주소 없음(결과물 전체에서 `http(s)://`·`//` — SVG 이름공간만 허용) ② 가리키는 파일이 모두 있음 ③ `/`로 시작하는 주소 없음 ④ 크기는 **막지 않고 보고**(게임마다 "처음 화면이 받는 크기 gzip", 300 KB를 넘으면 알림). 빌드 로그에 게임마다 처음 받는 크기와 늦게 받는 묶음 크기.

### 2. 영역을 들어갈 때 불러오기 (7-4절 "영역을 들어갈 때 불러오기")

- **바탕 묶음**: 엔진, 모든 영역의 단계 목록(제목·목표·그림 — 단계 지도와 학년·영역 화면에 필요), 5학년 전개도(정육면체·직육면체), `view3d`·`fold`·`orbit`.
- **쌓기나무 묶음**(`src/games/net-workshop/blocks/**`의 문제 만들기·판정·화면)은 그 영역의 **단계에 들어갈 때** `import()`로 받는다. 그러려면 쌓기나무의 "단계 목록"과 "플레이"를 다른 파일로 나눠야 할 수 있다 — 동작·글자·점수·저장 값은 한 글자도 바꾸지 않고 파일만 나눈다. 각기둥·원기둥은 아직 없다 → **다음 Build(G1)가 같은 방법으로 붙일 수 있게** 방법을 `docs/engine.md`에 적는다.
- 처음 화면이 그려진 뒤 한가할 때(`requestIdleCallback`, 없으면 대신할 것) 나머지 묶음을 미리 받아 둔다.
- 엔진(`src/shared/ui/app.js`): ① `playStage`가 Promise를 돌려줘도 된다 — 그동안 "불러오는 중"(짧으면 보이지 않게), 기다리는 사이에 나가면 받은 뒤 아무것도 그리지 않고 정리 ② **불러오기 실패 화면**("새 버전이 올라왔어요" 류 해요체 + [새로 고침]) ③ 처음 스크립트 실패: HTML의 `<script type="module" … onerror>`가 **한 번만** 새로 고침(되풀이 막는 표시는 `sessionStorage`, 막히면 그 안내만). `intro`·`areas`를 쓰지 않는 게임(예시 게임·템플릿)은 지금과 같게.

### 3. 하위 경로 서버로 e2e (7-4절)

- `scripts/serve.mjs`(새): `dist/`를 **하위 경로 `/game2/` 아래**로 주는 작은 서버(gzip, Node 내장 모듈만 — 새 패키지 금지). `/game2/` 밖 요청은 404. `npm run preview`(package.json의 `scripts`에 한 줄).
- `playwright.config.js`: `webServer`(serve.mjs)와 `baseURL`. **포트는 환경 변수(`E2E_PORT`, 기본값은 네가 정해 보고)로 바꿀 수 있게** 하고, 그 포트를 이미 다른 서버가 쓰고 있으면 **재사용하지 말고 실패**하게 한다(여러 트랙이 동시에 e2e를 돌릴 때 남의 `dist/`를 검사하는 일을 막는다). 글꼴 흉내 모드(`E2E_WIDE_TEXT`)는 그 복사본 폴더를 주게. 머리 주석을 사실대로.
- `tests/e2e/helpers.js`: `fileUrl(name, query)`가 서버 주소(`…/game2/<name>`)를 돌려준다(이름은 그대로 — 쓰는 곳이 120군데쯤). `gameFiles()` 그대로. 글꼴 흉내 복사본에 `assets/` 복사(B0c2)는 새 구조에 맞게.
- `tests/e2e/smoke.spec.js`에 더함: 모든 요청이 같은 출처, 응답 400 이상 0, 하위 경로에서 열림, 해시 파일이 모두 받아짐.
- `tests/unit/build.test.js`: 위 빌드 검사 ①~④와 글꼴이 쓰인 글자를 모두 가짐, 그림 md5.
- `.github/workflows/**`는 고치지 않는다 — 명령(`npm test`, `npm run test:e2e`, `npm run build` 후 `dist/` 올림)이 그대로 되는지 이 컴퓨터에서 같은 명령으로 확인하고, 바꿀 일이 생기면 고치지 말고 보고.

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. **지금 있는 단위·브라우저 검사가 한 줄도 약해지지 않고** 새 빌드에서 통과한다(12절 B0의 기준). 검사를 고쳐야 하면 들어가는 길(주소)만 — 고친 줄마다 까닭을 보고.
- **화면 불변**: `cd190ce` 빌드와 견줘 인트로·학년·영역·단계 지도·모든 단계의 첫 화면·놀이 방법·학습 기록·결과 화면, 예시 게임, 게임 모음이 픽셀까지 같다(의도한 차이: 게임 모음의 선생님 옵션 두 줄, 불러오는 중·실패 화면). 저장 열쇠·값 그대로. 주소(`?lesson=`·`?area=`·`?grade=`·`?stage=`·`?unlock=all`·`?seed=`·`?fx=low`)가 모두 그대로 열린다.
- **처음 여는 시간을 7-2절과 같은 방법으로 다시 잰다**(하위 경로 서버 gzip, 새 창 5번의 가운데값: 빠른 망·보통 CPU / 빠른 망·6배 느린 CPU / 느린 망 1.6 Mbps·지연 150ms / 느린 망·6배, 그리고 한 번 연 뒤 `?` 뒤만 바꿔 다시 열기). `cd190ce` 빌드와 나란히. 쌓기나무 단계에 처음 들어갈 때 기다림(미리 받기 전·후).
- 개발 서버(`scripts/dev.mjs`, `npm run dev`)는 그대로 된다(네 포트에서 확인). 사용자가 보는 5183 서버와 5173(다른 프로젝트)·selectio game의 서버(5391·5392·5399 등)는 건드리지 않는다.
- 브라우저 검사는 느린 기기를 견디게(움직임이 끝난 뒤, 사라지는 알림은 조작 바로 뒤, 머무는 시간, 시간 예산), `waitForTimeout`·`retries` 금지. 끝내기 전에 CPU 느리게 하기 4·8·12배로 새로 만들거나 고친 검사 값 실패 0.
- 테스트: `npm test`, `npm run test:e2e -- --workers=4`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0. Playwright 1.56.1 그대로.
