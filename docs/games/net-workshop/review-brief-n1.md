## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e` 직접 실행. 건너뜀 정당성. `git diff tests/`로 기존 검사가 약해지지 않았는지(문항 수·아이콘 글자·예시 게임 다시 하기 검사 변경은 이유가 맞는지).
2. **범위**: 두 지침의 허용 파일 안인가. 범위 밖 엔진 변경(badgeState)이 타당하고 다른 게임에 영향이 없는지. N2(도전 주문서 내용) 미포함.
3. **수학·판정 (가장 중요)**: 자유 배치 판정이 독립 계산(정육면체 감싸기)과 일치하는가 — 35가지 헥소미노 × 8방향 × 판 위치, 떨어진 배치, 7면·5면이 판에 놓일 수 없는지. 같은 모양 판정(`netName`)이 돌림·뒤집기에 불변이고 서로 다른 모양은 다른가. 도감 11칸이 정확히 11가지 전개도와 대응하는가. 힌트 그림자가 늘 아직 못 찾은 유효 전개도인가. 결과 문장·까닭 고르기 정답이 실제 이유와 맞는가.
4. **점수 공정성**: 자유 배치에서 점수를 부풀릴 길(같은 모양 다시 놓기, 돌림·뒤집기, 일부러 틀린 예상, 힌트, 더 찾아보기, 새로 고침)을 직접 찾아본다. 다시 하기 점수 규칙: 별 3개 단계 다시 하기 연습 점수 0, 별 2개 이하는 점수, 이번 판에 처음 3개면 점수, 새로 찾음 +5는 처음 한 번 — 엔진과 독립 시뮬레이터 비교. 일부러 별 3개를 피하며 반복하는 경우의 점수도 재 보고 의견을 적는다.
5. **조작**: 마우스·터치 끌기·키보드만으로 자유 배치 끝까지, 놓인 면 옮기기·빼기, 되돌리기, 떨어진 배치 안내.
6. **교실 기기**: 1366×768·1366×680·820×1180에서 네 단계 모두 세로 스크롤 없음(놓기·접힌 뒤·힌트·결과), 가로 스크롤 없음(네 크기), 48px, 대비 4.5:1, 초점 표시, `prefers-reduced-motion`·`?fx=low`, 토스트가 조작을 가리지 않음(R1·R2 재측정).
7. **정답 노출**: 판별·마주 보는 면·면 붙이기·자유 배치에서 답하기 전 DOM에 정답·힌트가 드러나지 않는가.
8. **시안과 비교**: `build-n1/shots/sbs/` 말고 직접 찍어 비교.
9. **차시 시간**: 시뮬레이션 근거가 타당한지 의견(사람 플레이는 못 하므로 방법만 검토).
10. 코드 품질(`h()`, `innerHTML` 금지, 정리 함수, 죽은 코드), 콘솔 오류, 표지 허용 목록에 새 공격 시도 몇 가지.
