코디네이터가 프롬프트로 알려 주는 기준 커밋 위의 작업 트리 변경 전부(`git status`·`git diff`). Build가 고쳐도 되는 파일은 build-brief-v1.md의 "고쳐도 되는 파일" 목록이다. 그 밖의 파일이 바뀌었으면 범위 위반으로 적는다(코디네이터가 고친 문서는 프롬프트에 적혀 있다).

Build의 최종 보고는 코디네이터가 요약해 전한다. **보고 내용은 확인 대상이지 근거가 아니다.** 수치는 모두 직접 실행·측정한 것만 적는다.

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e` 직접 실행(통과·실패·건너뜀, 건너뜀이 기기 나눔뿐인지). `git diff tests/`로 기존 검사가 약해지지 않았는지(지우거나 바꾼 검사 줄마다 이유).
2. **요청한 기능이 실제로 되는가 (네 크기: 1366×768·1366×680·820×1180 터치·390×844 터치)** — 조작 수단마다 따로, 끝까지:
   - **마우스 끌기**(필수): 접은 입체를 누른 채 끌어 가로·세로로 돌린다. 바로 위(0°)·옆(90°)·바로 아래(180°)·뒤쪽까지 가는가. 한계에서 멈추고 뒤집히지 않는가. 끄는 방향과 입체가 도는 방향이 자연스러운가(잡은 면이 따라옴), 기울기 어디서나 같은가.
   - **터치 끌기**(필수, CDP 터치): 한 손가락 끌기로 같은 것. 끄는 동안 페이지 스크롤 0.
   - **두 손가락 벌리기·오므리기**: 0.5~2배에서 멈춤, 브라우저 화면 배율(`visualViewport.scale`) 1 그대로. 두 손가락 → 한 손가락으로 바뀔 때 튀지 않는가.
   - **마우스 휠**(결정 2): 접은 입체 위에서만 확대, 그 밖·답하기 전에는 페이지 스크롤 그대로. Ctrl+휠.
   - **버튼 7개**: 이름·48px·한계에서 꺼짐·[처음 보기로]. **키보드만**: Tab으로 무대 → ←→↑↓ `+` `-` `0`·Home, 초점이 다른 곳에 있으면 보기가 안 바뀜, 접기 막대에 초점이면 막대만.
   - 버튼만으로, 키보드만으로, 끌기만으로 각각 모든 방향·배율에 갈 수 있는가.
3. **정답 노출 (가장 중요)**: 결정 1대로 답한 뒤에만 되는가. 판별·마주 보는 면·면 붙이기에서 **답하기 전**에 끌기·휠·벌리기·↑↓·`+ − 0`·꺼진 버튼 누르기를 한 뒤의 화면(무대 변환, 면마다의 변환·그늘, 조작판 상태, 속성·클래스)이 문항(정답)과 무관하게 한 가지인가 — 시드 여러 개. 힌트([반만 접어 보기]) 동안에도 잠기는가. 자유 배치: 예상 전 판, 그리고 **까닭을 고르는 동안** 돌리기·기울이기·확대·끌기를 다 해도 까닭 글자·표시가 0인가(안 되는 모양 24가지, 기준 커밋과 견줌). 새 화면 읽기 알림("아래에서 본 모습" 등)이 정답을 말하지 않는가.
4. **기존 조작과 부딪힘**: 마주 보는 면의 면 누르기(맞히기 전 끌어도 기록이 안 생김), 면 붙이기의 빈 자리 누르기·카드 끌어 놓기(마우스·터치), 접기 막대, 자유 배치 판(놓기·옮기기·빼기·키보드). 끌기와 누르기 가르기(문턱 앞뒤, 끌다가 다른 버튼 위에서 떼기, 무대 밖에서 떼기, 끄는 중 `pointercancel`). 끌기 뒤 포인터가 붙잡힌 채 남지 않는가.
5. **펴고 접기·문제 바뀜**: 보기를 바꾼 뒤 [펴기]/막대 0 → 처음 모습, 다시 접으면 내 보기, 다음 문제·[펴서 고치기]·[새로 만들기]·다시 하기 → 처음 보기. 자유 배치 판 → 무대 어긋남 0px(보기를 바꾼 뒤 다시 접어도).
6. **보이는 모습**: 스크린샷을 직접 연다 — 처음 보기·위·옆·아래·뒤·2배·0.5배, 겹치는 모양·2×2 모양·전개도. 면 글자(가~바)와 "✗ 겹쳐요"·"비어요"·● 표시가 거울상이 아니고 읽히는가(특히 아래에서 볼 때, 구멍 안쪽). 면 밝기(빛)가 방향에 따라 어색하지 않은가. "돌려 보면 빈 자리가 보여요" 안내가 실제로 안 보일 때만 나오는가. 2배에서 입체가 조작 버튼·막대·이름표·쪽지를 가리지 않는가(가운데 점 `elementFromPoint`). 새 아이콘 4개가 뜻대로 읽히는가(의견).
7. **교실 기기 배치**: 세 크기 세로·가로 스크롤 0(휴대폰은 가로 0), 자유 배치 오른쪽 판 안쪽 넘침 0, 조작판·도구 48px 이상, 조작판이 이름표·도장·조작 띠·알림과 겹치지 않음, 대비 4.5:1, 초점 표시, 휴대폰 두 줄 띠와 알림 자리.
8. **움직임·정리**: `prefers-reduced-motion`·`?fx=low`에서 끌기·버튼은 바로 반응, 자동 움직임만 줄어듦. 단계에서 나간 뒤 리스너·타이머·rAF가 남지 않는가(여러 번 드나든 뒤 조작 한 번 = 반응 한 번). 빠르게 끄는 동안 콘솔 오류 0. 끄는 동안 한 프레임에 그리기 한 번인가(성능 의견, 저사양은 확인 못 함으로).
9. **회귀**: 판정·수학 그대로(`fold.js` 불변, 독립 계산과 다시 비교), 점수 그대로(돌리기·확대에 점수·`inspect` 없음, 지난 라운드 점수 규칙 유지), 도감 칩, 결과 화면, 예시 게임·게임 모음 동작, 게임 파일 400 KB 이하, 빌드 로그 "알림" 없음.
10. **범위·코드**: 허용 파일 안인가(엔진은 아이콘 4개와 engine.md 한 줄뿐인가). `h()`·`innerHTML` 없음·이모지 없음·죽은 코드. `orbit.js`가 순수 함수이고 단위 테스트가 17-11의 표를 덮는가. Build가 보고한 "계획과 다른 점"이 타당한가.
11. **새로 생긴 문제**, 사용자가 정해야 할 것.
