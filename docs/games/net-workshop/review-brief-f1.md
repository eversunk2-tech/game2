# Review 서브에이전트 지침: F1 쌓기나무 "자유 쌓기" (트랙 "blocks")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-f1.md](build-brief-f1.md)(덧붙임 포함)에 따라 만든 자유 쌓기와 R1-1 손질을 **독립적으로** 검증한다. Build와 분리된 검토자다.
- 결과는 새 파일 `docs/games/net-workshop/review-blocks-f1.md`(트랙의 작업 폴더 안) 하나. 맨 위 판정 줄(통과 = 반드시 수정 0건 / 수정 필요). 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다. 작업 폴더에서만, 검증 파일은 정해 준 scratchpad에만. Build의 scratchpad는 근거로 삼지 않는다(사용자가 본 시안 그림은 기준 모습으로만).

## 기준

[spec-grade6.md](spec-grade6.md) **15-18·15-19(사용자 결정 1~10과 코디네이터가 고른 것)**, [plan-rotate-free.md](plan-rotate-free.md) 5절, [build-brief-f1.md](build-brief-f1.md), [common-rules.md](common-rules.md), spec-grade6 4절(오개념)·5절·8절(점수는 학습 행동에만), [review-blocks-r1.md](review-blocks-r1.md) R1-1.

## 검토 대상

`96cc9a6`(지금 사이트와 같은 코드)과 `track/blocks`의 마지막 커밋 사이의 변경 전부. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `E2E_PORT=<네 포트> npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 — 실패 0. `git diff 96cc9a6..HEAD -- tests/`를 줄마다 읽어 약해진 검사 0(R1-1로 뜻이 바뀐 개수 보기 검사 포함 — 바뀐 뜻이 15-19 아래 "코디네이터가 고른 것"과 맞는지).
2. **사용자 결정대로인가**: 1차시 위 넓은 카드(차시 번호·별·잠금·"여기부터!" 없음, 진도·모은 별·차시 수·도장·학습 기록·점수 어디에도 들어가지 않음 — 저장 값으로 확인), `?stage=` 주소, 한 차시 주소·다른 영역에는 없음, 14×14·10층 / 휴대폰 6×6·6층(짧은 변 600px 기준, 들어갈 때 한 번), 처음 크기 꽉 차게, 돌림판식(판 가운데·수평~바로 위), 저장(판 크기마다 하나·이어서·[모두 치우기]·막힌 저장소에서 오류 0·**[기록 모두 지우기]는 작품을 지우지 않음** — 결정 10), 색 다섯(이름과 함께)·위앞옆 모양·층별로 벌려 보기(층마다 개수), **좁은 세로 띠**(세로 태블릿·휴대폰은 판 아래 가로 줄), **[위에서 본 판] 버튼 하나 → 펼친 판 머리에서 네 쪽 고르기**(결정 8), **펼쳐 가려진 판은 옆으로 옮겨 보기**(결정 9 — 마우스·터치·키보드, 돌리기 끌기와 헷갈림 0, 접으면 제자리, 중심 그대로).
3. **엔진 손질**: 자유 공간 선택을 쓰지 않는 게임·영역의 경로·화면이 그대로인지(코드와 화면 비교), `docs/engine.md`가 코드와 맞는지, `h()`만·`innerHTML` 없음.
4. **조작**: 키보드만·마우스만·터치만으로 14×14의 모든 쪽 끝 칸까지 쌓고 빼기, 10층 한도·알림, 되돌리기, 화면 읽기 문장, 누르기·끌기 8px, 판 옮기기와 돌리기·크게/작게의 헷갈림.
5. **배치**: 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) + 960×768 × 보통·글꼴 흉내에서 스크롤·넘침·겹침 0(휴대폰 세로 스크롤은 규칙대로), 펼친 상태·옮긴 상태·벌린 상태·위앞옆 모양 켠 상태 — 스크린샷을 직접 열어 사용자가 본 시안과 같은 모습인지 의견. 쌓기나무 한 변 px.
6. **그리는 속도**: 계획 5-2의 장면(판 절반 3층, 바둑판 6·10층)을 CPU 1·4·6배로 직접 — Build 보고(가장 나쁜 꼴 6배에서 34ms 넘는 프레임 6개)와 견줌. 실물 기기는 못 봄으로 적는다.
7. **R1-1 손질**: 시드 3,000개 이상으로 2차시·5차시 개수 보기 — 값만 보는 규칙·꼴 규칙이 찍기(25%)보다 크게 높지 않은지(목표 ~30% 이하), 정답 자리 고름, **판마다 함정 보기(2차시 "위에서 본 칸 수", 5차시 "1층 칸 수")를 한 번 이상 만나는지**, 숨은 문항의 "보이는 것만 센 수"·"맨 위층 빠뜨림"이 유지되는지, 정답 노출 0, 점수 그대로.
8. **불변**: `96cc9a6` 빌드와 견줘 다른 모든 화면(인트로·학년·영역·쌓기나무 1~5차시·도전·정육면체·직육면체·각기둥·학습 기록·선생님용 안내·예시 게임)이 같은지(의도한 차이: 쌓기나무 영역 지도의 자유 카드, 놀이 방법 한 줄, 개수 보기 값), 저장 값.
9. **늦게 불러오기**: 자유 쌓기 코드가 쌓기나무 묶음에만 있는지, 처음 받는 크기 전·후.
10. **느린 기기 검사**: 새로 만들거나 고친 검사를 CPU 4·8·12배로 — 값 실패 0.
11. 새로 생긴 문제, 사용자가 정해야 할 것.
