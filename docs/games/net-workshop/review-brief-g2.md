# Review 서브에이전트 지침: G2 각기둥 4단계 `prism-free` + 도전 `prism-count` (트랙 "cuboid" 작업 폴더)

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-g2.md](build-brief-g2.md)(덧붙임 포함)에 따라 만든 것을 **독립적으로** 검증한다. Build와 분리된 검토자다.
- 결과는 새 파일 `docs/games/net-workshop/review-prism-g2.md`(트랙의 작업 폴더 안) 하나. 맨 위 판정 줄(통과 = 반드시 수정 0건 / 수정 필요). 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다. 작업 폴더에서만, 검증 파일은 정해 준 scratchpad에만. Build의 scratchpad는 근거로 삼지 않는다(사용자가 고른 시안 그림은 기준 모습으로만).

## 기준

## 검토 대상

지침을 맡긴 `main` 커밋(Build 프롬프트의 "기준")과 `track/cuboid`의 마지막 커밋 사이의 변경 전부. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `E2E_PORT=5363 npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 — 실패 0. 바뀐 `tests/`를 줄마다 읽어 약해진 검사 0(도장 16 → 17칸처럼 뜻이 바뀐 줄이 맞는지).
2. **`prism-free`가 계획대로인가**: 시드마다 삼각기둥(정삼각형이 아닌 밑면)·사각기둥(직사각형이 아닌 사각형 밑면)·육각기둥, 일부만 놓인 전개도 → 완성 → 다른 모양으로 한 번 더(밑면 하나만 놓임), 예상 없이 [접어 보기](15-2), 길이가 안 맞는 모서리에서 같은 무늬와 "○ cm ≠ △ cm", 모자람·겹침 표시, 끝(2가지 → [결과 보기]), 별 = 찾은 가지 수(3가지면 별 3, 안 되는 모양을 접어도 깎이지 않음), 점수는 처음 만든 모양만(합동 열쇠), 도장 "기둥 설계사"(학습 기록으로 판정).
3. **`prism-count`가 계획대로인가**: 5문항, 모서리·꼭짓점(·면)의 수와 규칙 고르기, 차시를 마치면 열림, 별 합계 밖, 입체를 돌려 셀 수 있음, 흔한 실수 보기가 판마다 한 번 이상, 시드 3,000개 이상으로 보기의 값·자리·꼴만 보고 고르는 규칙이 찍기보다 크게 높지 않은지(목표 ~30% 이하 — 피할 수 없는 한계가 있으면 독립 계산으로 확인해 "사용자에게 물을 거리"로).
4. **독립 계산**: 저장소 코드를 쓰지 않고 기획서 문장만 보고 짠 계산으로 — 완성한 전개도가 각기둥이 되는지(면의 수·옆면 직사각형·두 밑면 자리·맞닿는 선분 길이·겹침)를 밑면 종류마다, 서로 다른 전개도의 수(G1 Review 값과), 모서리·꼭짓점·면의 수와 규칙, 점수(일부러 틀려 이득 0, 같은 모양 두 번 점수 0, 화면 = 저장).
5. **정답 노출 0**: `prism-free`의 붙일 자리·카드 순서·색·DOM·속성이 맞는 모서리를 알려 주지 않는지(맞는 자리와 틀린 자리가 같은 모습 — DOM 비교), 접기 전 결과가 드러나지 않는지. `prism-count`는 답하기 전 수가 보이지 않는지.
6. **조작**: 키보드만·마우스만·터치만으로 두 단계 끝까지(카드 고르기·자리 고르기·돌려 보기), 48px, 누르기·끌기 8px, 화면 읽기 문장·알림(알림이 조작을 가리지 않음), 움직임 줄이기·`?fx=low`.
7. **배치**: 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) + 960×768 × 보통·글꼴 흉내에서 스크롤·넘침·겹침 0(휴대폰 세로 스크롤은 규칙대로) — 스크린샷을 직접 열어 사용자가 고른 시안과 같은 모습인지 의견.
8. **속도**: 접기·펼치기 움직임의 프레임 간격을 CPU 1·4·8배로 직접 — Build 보고와 견줌. 실물 기기는 못 봄으로 적는다.
9. **불변**: 기준 빌드와 견줘 다른 모든 화면(인트로·학년·영역·정육면체·직육면체·각기둥 1~3단계·쌓기나무 1~5차시·도전·자유 쌓기·학습 기록·선생님용 안내·예시 게임)이 같은지(의도한 차이: 각기둥 단계 지도·놀이 방법·영역 카드 별 합계·도전 카드·도장판 17칸), 저장 값. 원기둥은 "준비 중" 그대로.
10. **늦게 불러오기**: 새 코드가 각기둥 묶음에만 있는지, 처음 받는 크기 전·후.
11. **느린 기기 검사**: 새로 만들거나 고친 검사를 CPU 4·8·12배로 — 값 실패 0.
12. 새로 생긴 문제, 사용자가 정해야 할 것.
