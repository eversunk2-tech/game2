# Review 서브에이전트 지침: M3 직육면체 탐구 넓히기 — 검토 반영 확인 (트랙 "cuboid", M3b)

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-fix-brief-m3b.md](build-fix-brief-m3b.md)에 따라 고친 것을 **독립적으로** 확인하고, 지난 검토에서 통과한 것이 깨지지 않았는지 본다. Build와 분리된 검토자다.
- 트랙의 작업 폴더 안 `docs/games/net-workshop/review-m3.md` **한 파일만** 고친다: 맨 아래에 `## 재검토 (M3b 수정 확인)` 절을 덧붙이고 맨 위 판정·검토일 줄을 고친다. 앞 내용은 지우지 않는다. 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다.
- **트랙의 작업 폴더에서만** 일한다. 검증 파일·복사본은 정해 준 scratchpad 폴더에만(지난 검토의 스크립트는 `review-m3/`에 있다 — 같은 스크립트로 다시 재서 지난 값과 나란히). Build의 scratchpad는 근거로 삼지 않는다.

## 기준

- `review-m3.md`의 문제 표(M3-1 ~ M3-11)·D1~D3과 지난 측정값
- [spec.md](spec.md) **16-16·16-17**(사용자 결정 — 완성 도장, 별 0개로 끝낼 때의 글, 놀이 방법 한 줄, 큰 상자 48px 예외), [build-fix-brief-m3b.md](build-fix-brief-m3b.md)
- [common-rules.md](common-rules.md) 1~8절

## 검토 대상

`1049d35`(지난 검토 대상)와 트랙 브랜치의 마지막 커밋 사이의 변경 전부(`97d13b7`은 코디네이터가 review 파일만 커밋). 고쳐도 되는 파일은 build-fix-brief-m3b.md의 목록이다 — 다른 트랙(게임 인트로 B0c)이 같은 때에 처음 화면을 거쳐 가는 검사의 길 찾기 줄을 고치므로, **이 트랙은 기대값 줄(도장 수, 놀이 방법)만** 고쳤어야 한다. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **M3-1 (가장 중요)**: 54가지를 채운 저장 값(기준 빌드에서 실제로 채운 것과 가짜로 만든 것 둘 다)으로 들어가 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) × 보통·글꼴 흉내에서 [도감 보기]가 늘 보이고 54칸이 열리는지, 54번째를 접은 뒤·[펴서 고치기] 뒤·나갔다 다시 들어온 뒤에도.
2. **결정 1~4**: 완성 도장이 도장판 13번째로 보이고 54가지를 채운 순간 찍히는지(이미 채운 저장 값으로 열면 한 번만), 도장 수를 세는 검사 줄 셋(`net-workshop.spec.js`·`net-workshop-areas.spec.js`·`net-workshop-cuboid.spec.js`)이 새 뜻을 고정하는지. 별 0개로 끝낼 때 "오늘은 여기까지!"·"다음에 / 또 찾아요"(스크린샷), 별 1개 이상은 "도전 성공!" 그대로, 점수 0 그대로, **엔진의 새 선택 값(`ctx.finish({ title, stamp })`)을 쓰지 않는 게임·단계는 결과 화면이 한 글자도 달라지지 않는지**(예시 게임·정육면체 도전 2·쌓기나무). 놀이 방법 한 줄과 영역 검사의 새 뜻. 48px 예외의 새 검사가 처음 상자와 48px을 지킬 수 있는 크기에서는 여전히 48px을 요구하는지, 카드·버튼·손잡이는 48px인지.
3. **M3-3**: 상자 보기 이름표 — 64가지 × 세 크기에서 화면 글자 11px 이상, 이름표끼리 겹침 0, 상자 보기 밖 0, 등을 보인 면 이름표 숨김이 맞는지(돌린 자세 여러 개), 거울상 0. 스크린샷을 직접 연다.
4. **M3-5~9**: 휴대폰에서 고를 수 없는 크기와 안내(전개도가 하나도 안 들어가는 상자를 독립 계산으로 다시 셈), 크기 글 한 덩어리, 도감 보기 때 도구 띠 숨김, "직육면체 전개도 n가지"·"정육면체 도감 n / 11"(기존 검사 14줄을 새 뜻으로 바꾼 것이 약해지지 않았는지), 첫 초점 [취소].
5. **깨지지 않았는가(지난 스크립트로 다시)**: 판정·가짓수·표준 이름 독립 계산, 점수 = 독립 계산(크기를 섞어, 탭 두 개, 나가기, 옛 저장 값, 처음 상자 33점), 64가지 크기 × 세 크기 배치, 손잡이(세 수단, 헷갈림 0), 정육면체·직육면체 1~3단계·쌓기나무·영역 화면·예시 게임 불변, 느린 기기 4·8·12배.
6. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`. 알려진 실패(쌓기나무 "단계 지도: 쌓기나무 두 차시가…", 두 기기 — B0c 몫)는 판정에 세지 않는다. `git diff 1049d35..HEAD -- tests/`로 약해진 검사가 없는지.
7. **합칠 때**: 이 컴퓨터의 `main`(쌓기나무 3·4차시가 합쳐져 있다)·`track/b0`(게임 인트로 Build 중)의 지금 커밋과 `git merge-tree --write-tree`로 줄 충돌.
8. **새로 생긴 문제**, 사용자가 정해야 할 것.

## 형식과 끝나면

덧붙이는 절: 판정 줄(통과 = 반드시 수정 0건 / 수정 필요), 테스트 결과 표, 항목별 결과 표(번호 · 지난 값 → 지금 값 · 고쳐짐/남음), 결정 1~4 표, 깨지지 않았는지의 표, 발견한 문제 표(심각도, 파일:줄, 재현 방법, 고칠 방향), 확인하지 못한 것.

최종 답변 **10줄 이하**: 판정, M3-1, 결정 1~4(엔진 선택 값의 불변 포함), M3-3 잰 값, 나머지 요약, 깨지지 않았는지의 핵심 수치, 테스트 숫자(보통·글꼴 흉내), 새 문제와 심각도별 개수, "반드시 수정" 목록(파일:줄), 합칠 때 부딪힐 곳, 확인하지 못한 것. 직접 잰 것과 추정을 구분한다.
