# Review 서브에이전트 지침: 자유 쌓기 "더 큰 판" (트랙 "blocks" 작업 폴더)

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-big-board.md](build-brief-big-board.md)(덧붙임 포함)에 따라 만든 것을 **독립적으로** 검증한다. Build와 분리된 검토자다.
- 결과는 새 파일 `docs/games/net-workshop/review-blocks-big.md` 하나다(트랙의 작업 폴더 안).
  - 맨 위에 판정 줄을 둔다: 통과 = 반드시 수정 0건 / 수정 필요.
  - 커밋하지 않는다.
- 금지:
  - 코드 · 테스트 · 다른 문서를 고치지 않는다.
  - 커밋하거나 작업 트리를 바꾸는 git 명령을 쓰지 않는다(읽기용은 된다).
  - `npm install` · `npm ci` · 내려받기를 하지 않는다.
- 서버 · 실행은 네가 띄운 PID만 내린다.
- 검증 파일은 정해 준 scratchpad에만 둔다.
- Build의 scratchpad는 근거로 삼지 않는다. 사용자가 고른 시안 그림 `build-big/shots/sheet-*.png`는 기준 모습으로만 쓴다.

## 검토 대상

- 기준: Build를 맡긴 `main` 커밋 **`7c47407`**. 다른 화면은 이 빌드와 화소까지 같아야 한다.
- 대상: `track/blocks`의 마지막 커밋.

- Build의 최종 보고는 코디네이터가 요약해 전한다. **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**
   - `npm test`, `E2E_PORT=5354 npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 돌린다(하나씩 차례로). 실패 0이어야 한다.
   - 바뀐 기존 검사는 줄마다 읽는다. 뜻이 바뀐 줄이 띠 버튼 목록 '더 큰 판' · 낮은 창 촘촘한 띠뿐인지, 약해진 검사가 0인지 본다.
2. **계획 · 결정대로인가** — 사용자가 고른 시안 모습과 같은지 스크린샷을 직접 열어 견준다.
   - 큰 판: 20×20 · 10층
   - 같은 화면이 큰 판으로: 맨 위 띠 · 머리 · 양옆 배경 0
   - 전체 화면: 누른 순간 요청, 막혀도 열림, 다시 켜기, Esc 알림
   - [← 보통 판으로]
   - 메뉴 ②: 노랑 바탕 + 가름선, 띠 맨 아래 / 띠 줄 끝
   - 낮은 창에서만 촘촘한 띠
   - 띠 맨 위 "더 큰 판 / 20칸 20줄"
   - 휴대폰 안내 카드: 글 · [알겠어요] · Esc · 바깥 · 초점
   - `?stage=blocks-free&board=big`: 태블릿 · PC에서는 큰 판, 휴대폰에서는 6×6 + 카드 한 번
   - 놀이 방법 한 줄
3. **독립 계산** — 저장소 코드를 쓰지 않고 기획서 문장(15-19 4 · 15-28 · 15-39, plan 7-2)만으로 짠다.
   - 처음 보기 한 변(맞춤 · 원근 A)
   - 휴대폰 판정(창의 짧은 변 600px 미만)
   - 위에서 본 판 칸(18px 안팎 · 13px 아래 0)
   - 이것들을 앱 값과 여러 크기에서 견준다.
4. **저장**
   - 큰 판에서 쌓기 · 빼기 · 되돌리기 · [모두 치우기] → `free-big-20x20`만 바뀌고 `free-14x14` · `free-6x6`은 글자까지 같다.
   - 나갔다 다시 들어오면 이어진다.
   - 학습 기록 [기록 모두 지우기] 뒤에도 남는다.
   - 두 탭에서 같은 큰 판: 한쪽에서 쌓으면 다른 쪽이 따라간다. 서로 덮어쓰는 순서도 본다.
   - 망가진 저장 값 · 다른 크기 값이면 빈 판이 열린다.
   - 막힌 저장소에서는 오류 0.
5. **조작**
   - 키보드만 · 마우스만 · 터치만으로 메뉴 → 큰 판 → 쌓기 · 돌리기 · 위에서 본 판 · 옮기기 → 돌아오기까지 해 본다.
   - 48px, 누르기 · 끌기 8px.
   - 화면 읽기 문장(들어갈 때 알림 · 버튼 이름), Tab 차례.
   - 알림이 띠 · 조작을 가리지 않는다.
   - 움직임 줄이기 · `?fx=low`.
6. **배치** — **움직임이 끝난 뒤에** 잰다.
   - 크기: 1366×768 · 1366×680 · 1366×653 · 1366×633 · 1280×800 · 1920×1080 · 1024×768 · 1180×820 · 820×1180 · 768×1024 · 390×844
   - 보통 · 글꼴 흉내 두 가지로 잰다.
   - 보통 판과 큰 판 모든 장면: 처음 보기 · 위에서 본 판 · 위ㆍ앞ㆍ옆 · 쌓은 뒤 · 알림 · 안내 카드
   - 볼 것: 스크롤 · 띠 넘침 · 잘린 버튼 · 무대 밖 칸 · 겹침이 0인지. 휴대폰 세로 스크롤은 규칙대로.
7. **그리기 · 속도**
   - 판을 많이 채운 장면에서 프레임 간격을 CPU 1 · 4배로 직접 잰다(plan 5절 장면 — 보통으로 쌓은 판 · "도시" · 10층 기둥 200개).
   - 지금 14×14와 나란히 재서 견주고, Build · Plan 값과도 견준다.
   - 잰 조건(시각 · 부하)을 적는다.
   - 실물 기기는 "못 봄"으로 적는다.
8. **불변** — 기준 빌드(`7c47407`)와 견줘 다른 모든 화면이 같은지 본다.
   - 화면: 인트로 · 학년 · 영역 · 5학년 · 각기둥 · 쌓기나무 1~5차시 · 도전 · 학습 기록 · 선생님용 안내 · 예시 게임
   - 자유 쌓기 보통 판(14×14 · 6×6)은 넘치지 않는 창에서 메뉴 버튼 말고 같아야 한다.
   - 의도한 차이만 있어야 한다: 메뉴 버튼, 놀이 방법 한 줄, 낮은 창의 촘촘한 띠.
   - 자유 쌓기에서 나간 뒤 `<html>` 표시가 남지 않는지, 다른 화면의 DOM이 같은지 본다.
   - 엔진 · 원기둥 쪽 파일은 바뀐 줄 0이어야 한다.
9. **늦게 불러오기**: 새 코드가 쌓기나무 묶음에만 있는지 본다. 처음 받는 크기를 바뀌기 전과 뒤로 직접 잰다.
10. **느린 기기 검사**: 새로 만들거나 고친 검사를 CPU 4 · 8 · 12배로 돌린다. 값 실패 0이어야 한다.
11. **공개 저장소**: 교과서 문장 · 그림 · 문제 수치를 옮긴 곳이 없는지 본다.
12. 새로 생긴 문제, 사용자가 정해야 할 것.
