## 할 일

### 1. 지금 모습 목록 (무엇이 "덧붙은 그림자"인가)

- 모든 CSS에서 다음을 찾아 **역할별로** 표를 만든다.
  - 찾을 것: 잉크 테두리 + 흐림 없는 아래 · 옆 그림자(`--edge` · `--edge-sm` · `0 Npx 0 var(--ink)` · `--sheet` · 옆으로 밀린 그림자), 기울인 스티커 · 테이프("여기부터!" 같은 것), 같은 계열의 꾸밈
  - 역할 예: 주 버튼, 보통 버튼, 돌아가기 · 이동 버튼, 큰 카드(학년 · 영역), 단계 카드, 칩 · 배지, 위쪽 띠 · 정보 막대, 놀이 화면의 도구 버튼 · 세로 띠, 알림, 증명서 · 판, 스티커
  - 칸: 선택자, 파일:줄, 누를 수 있는가, 어느 화면에 보이는가
- 토큰으로 바뀌는 곳과 값을 직접 적은 곳의 수를 센다. 이것으로 Build의 크기를 어림한다.
- **범위의 경계를 정해 제안한다**: 놀이 속 물건(전개도 면 · 쌓기나무 · 색종이 카드처럼 "학습 내용 자체"인 것)도 바꿀지, UI 틀(버튼 · 카드 · 띠 · 칩)만 바꿀지. 선택지와 추천을 붙인다.
- 지금 모습을 1366×768로 찍어 둔다. 화면: 인트로, 학년 고르기, 6학년 영역 카드, 단계 지도, 놀이 화면 2~3곳, 결과(별 · 도장), 학습 기록.

### 2. 분석

**(가) 이 모양이 왜 "AI 디자인"으로 읽히는가** — 정직하고 균형 있게 쓴다.

- 이 기법 자체는 사람 디자이너가 먼저 썼다(예: 학습 앱의 두툼한 3D 버튼, 네오 브루털리즘 웹).
- 그런데 생성 AI가 "귀엽고 장난스러운" 화면의 기본값처럼 쓰면서 흔해졌다.
- 어떤 조합이 티를 내는지 짚는다. 예:
  - 모든 요소에 똑같은 검정 테두리 + 똑같은 검정 그림자
  - 크림색 모눈 바탕
  - 기울인 노랑 스티커
  - 테두리 두른 알약 칩
  - 위계 없이 다 같은 깊이
- 이 앱에서 사용자가 짚은 세 곳이 각각 어디에 해당하는지 적는다.

**(나) 사람 전문 디자이너는 메뉴 · 버튼을 밋밋하지 않게 어떻게 만드는가**

- 기법마다 다음을 적는다:
  - 무엇을 하는지
  - 실제 제품 예(이름 · 공개 페이지 수준)
  - 어린이 학습 게임에 맞는지
  - 크롬북 · 태블릿에서 가벼운지
- 기법 예:
  - 역할에 따른 깊이 위계(누르는 것만 두껍게, 정보 판은 얕게)
  - 그림자를 검정이 아닌 **같은 색의 진한 쪽**으로
  - 광원 하나 + 두 겹 그림자(닿는 그림자 + 넓은 확산)
  - 윗면 1px 하이라이트 · 은은한 그라데이션으로 두께
  - 색의 층(바탕보다 조금 밝거나 어두운 면)으로 떠 보이게
  - 제품의 정체성에서 나온 모티프. 이 앱이면 **전개도 · 종이 공작**: 접는 선, 풀칠 날개, 종이 결, 종이가 바닥에서 살짝 뜬 그림자
  - 누를 때의 움직임 · 소리 같은 손맛
  - 글자 · 아이콘 · 간격의 위계
- 인터넷의 공개 글 · 디자인 지침을 **읽기만** 해도 된다(WebSearch · WebFetch를 쓸 수 있으면).
  - 그림 · 글꼴 · 파일은 내려받지 않는다.
  - 다른 제품의 그림 · 캐릭터 · 모양을 따라 하지 않는다. 원리만 가져온다.
  - 참고한 곳은 이름과 주소로만 적는다.

### 3. 메뉴 · 버튼 전반의 방향 셋 (A · B · C) + 지금

- 코디네이터의 출발 가설은 아래와 같다. 더 나은 안이 있으면 까닭을 대고 바꾼다.
  - **A "같은 색 두께"**
    - 검정 테두리 · 검정 그림자를 없앤다.
    - 버튼은 자기 색의 진한 쪽으로 아래 두께를 주고, 윗면에 하이라이트를 준다.
    - 카드 · 판은 부드러운 두 겹 그림자를 쓴다.
    - 칩은 납작하게 한다.
    - 지금과 가장 가깝다.
  - **B "종이 공작"** — 이 앱만의 모습, 전개도 공방다움
    - 종이를 오려 붙인 듯하게 만든다.
    - 테두리 대신 종이 가장자리와 작은 접촉 그림자를 쓴다.
    - 고른 것 · 지금 단계에 접는 선 · 풀칠 날개 모티프를 쓴다.
  - **C "차분한 면"**
    - 색의 층과 글자 위계로 깊이를 만든다.
    - 그림자는 거의 없앤다.
    - 버튼은 채운 색 + 눌림은 색 변화로 보인다.
- 방향마다 적을 것:
  - 토큰 값(CSS 변수)
  - 역할별 모습: 기본 · 올림 · 누름 · 초점 · 비활성
  - 초점 표시: 지금은 잉크 3px + 노랑 후광
  - 진단표 점수: 지금과 견준 것
- **지킬 것**:
  - 아이가 **모양만 보고 누를 수 있는지 안다**. 지금 체계가 그림자로 지키던 것이다. 새 방향에서는 무엇이 대신하는지 적는다.
  - 누르는 곳 48px 이상, 글자 대비 4.5:1(큰 글자 3:1). 새 색은 대비를 직접 잰다.
  - 키보드 초점이 또렷하다. 움직임 줄이기를 존중한다.
  - 성능. 지금 규칙은 "흐림 그림자는 움직이지 않는 것에만"이다.
    - 흐림 그림자를 누르는 것에 쓰는 방향이 있으면 실제 빌드에 덧씌워 잰다. 단계 지도 · 놀이 화면에서 누름 · 올림 · 스크롤의 프레임 간격을 CPU 1 · 4배로 잰다.
    - 그 결과로 규칙을 바꿀지 제안한다.
    - 잴 때 컴퓨터 부하를 확인하고(`uptime`, 다른 실행), 조건을 적는다.
