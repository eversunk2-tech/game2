## 확인할 것

1. **테스트**
   - `npm test`, `E2E_PORT=5584 npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접, 하나씩 차례로 돌린다. 실패 0이어야 한다.
   - 바뀐 기존 `tests/`를 줄마다 읽는다.
     - 뜻이 바뀐 줄(그림자 값 · 지금 탭 · [입장하기] 대비 등)만 바뀌었는지 본다.
     - **약해진 검사가 0인지** 본다. 지금 탭 검사는 "다르다"를 여전히 지키는지 본다.
   - 새 검사 ①②③이 고치기 전 코드(기준)에서 **실패하는지** 직접 본다.
2. **결정대로인가** — 스크린샷을 직접 열어 사용자가 확인한 시안과 견준다.
   - 누를 수 있는 UI 틀(버튼 · 학년 · 영역 · 단계 카드 · 탭 · 도구 버튼 · 답 버튼) 모두:
     - 잉크 테두리 · 아래 · 옆 두께 0
     - 쉴 때 은은한 그림자
     - 마우스 올림에 떠오름(버튼 2px · 단계 카드 3px · 학년 · 영역 카드 4px, 0.2 · 0.3초)과 그림자 커짐
     - 누르면 면이 진해지며 제자리
     - 초점 또렷함
     - 비활성 · 잠김
   - **빠진 곳**: 화면 곳곳을 돌며 잉크 테두리 · 흐림 없는 잉크 두께가 남은 UI 틀이 있는지 계산된 모양으로 전부 센다. 남은 것이 학습 내용(면 카드 · 상자 카드 · 전개도 면 · 쌓기나무 · 판 칸 · 도감 칸 · 도장 · 진행 점)뿐인지 본다.
   - 읽는 판(그림자 거의 없음), 뜨는 것(뜬 그림자), 칩 · "여기부터!"(바로 선 파랑 꼬리표), 테이프 뺌
   - [입장하기]: 위가 조금 밝은 노랑 + 파란 테 6px, 아래 남색 두께 없음, 올리면 떠오름. 크기 · 자리 · 큰 화면 배율 · 손 피하기 · 반짝임은 기준과 같다.
   - 움직임 줄이기 · `?fx=low`: 떠오르지 않음. `?fx=low`는 흐림 없는 그림자만.
3. **자리 · 크기 0px**: 기준 빌드와 견준다.
   - 화면: 모든 화면(인트로 · 학년 · 영역 · 단계 지도 · 모든 놀이 화면 · 결과 · 학습 기록 · 선생님용 안내 · 예시 게임 · 큰 판 · 휴대폰)
   - 크기: 1366×768 · 1366×680 · 1024×768 · 960×768 · 820×1180 · 390×844
   - 볼 것: 모든 요소의 상자 위치 · 크기, 스크롤 · 넘침 · 겹침 0
   - **움직임이 끝난 뒤에** 잰다. 의도한 차이(지금 탭이 더는 내려앉지 않음 등)만 있어야 한다.
4. **대비 · 크기**
   - 새 색 위 글자 대비 4.5 이상(큰 글자 3 이상)을 직접 계산한다.
   - 누르는 곳 48px
   - 누르는 것의 가장자리 대비를 직접 잰다. 사용자에게는 1.3~1.9로 알렸다. 다르면 적는다.
5. **조작**
   - 키보드만 · 마우스만 · 터치만으로 몇 화면을 끝까지 해 본다.
   - 떠오름이 누르기 · 끌기(8px 규칙) · 자석 · 판 돌리기를 방해하지 않는지 본다. 예: 올린 채 끌 때 카드가 흔들리거나, 떠오른 상자 때문에 누를 곳이 어긋나는 일.
   - 알림이 조작을 가리지 않는지 본다.
6. **그리기 · 속도**
   - 단계 지도 · 자유 쌓기 · 큰 판에서 마우스 훑기 · 누르기 · 스크롤의 프레임 간격을 CPU 1 · 4 · 8배로 직접 잰다. Build 보고와 견준다.
   - 부하 조건을 적는다.
   - 2배 화소로 그림자 가장자리 · [입장하기] 테를 확대해 본다.
   - 실물 기기 · Safari는 "못 봄"으로 적는다.
7. **불변**
   - JS가 바뀌지 않았는지 본다(바뀌었으면 까닭).
   - 학습 내용의 모양이 기준과 화소까지 같은지 본다: 전개도 면 · 쌓기나무 · 면 카드 · 상자 카드 · 입체 그림.
   - 저장 값이 같은지 본다.
   - 처음 받는 크기를 기준과 견준다(CSS가 늘어난 만큼만).
8. **느린 기기 검사**: 새로 만들거나 고친 검사를 CPU 4 · 8 · 12배로 돌린다. 값 실패 0이어야 한다.
9. **공개 저장소**: 다른 제품의 그림 · 파일을 가져온 곳이 없는지 본다. "모두의 배움터"에서는 수치 규칙만 옮겼어야 한다.
10. 새로 생긴 문제, 사용자가 정해야 할 것: 선택지와 추천을 붙인다.
