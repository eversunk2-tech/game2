# Build 서브에이전트 지침: N2 도전 주문서 (주사위 주문 · 도감 주문)

## 역할

너는 **Build** 담당이다. [spec.md](spec.md) 16절의 승인된 계획(16-3의 도전 주문서 두 줄, 16-4 단계 표의 "도전" 줄, 16-5의 N2 줄, 16-7 결정 5번 "도전 주문서 넣기")대로 정육면체 차시의 도전 주문서 두 개를 만든다. 이것이 "5학년 앱 완성"의 첫 단계다(다음은 2차 직육면체 — 이번 범위가 아니다). 판정(`fold.js` 결과)은 바꾸지 않는다. 검증은 별도 Review 서브에이전트가 한다.

## 만들 것 (spec 16-3 그대로)

| 단계 | 내용 | 엔진 표시 |
| --- | --- | --- |
| `cube-dice` **주사위 주문** | 면 카드가 주사위 눈 1~6. 마주 보는 두 눈의 합이 7이 되는 전개도를 **서로 다른 모양으로 2개** 만든다. 다 접으면 마주 보는 짝을 같은 무늬로 보이고, 틀리면 "1과 5가 마주 봐요. 마주 보는 두 눈의 합은 7이에요."(tag `마주 보는 면`). 판정은 `oppositeFace`. 별은 접은 시도의 정확도. 선택 시간 재기 | `challenge: true`, `timer: 'optional'`, 주문 칩 "주사위 주문" |
| `cube-dex` **도감 주문** | 자유 배치 판으로 전개도 도감 11칸을 채운다. 여러 번 나눠 해도 도감은 이어진다. [오늘은 여기까지]로 끝내면 별은 도감 수(6칸 ★1, 9칸 ★2, 11칸 ★3), 11칸이면 바로 끝 | `challenge: true`, 주문 칩 "도감 주문" |

- 두 단계는 차시의 일반 단계 4개를 모두 마치면 열리는 **선택 활동**이다(다음 단계를 막지 않고 차시 별 합계에 넣지 않음 — 엔진의 도전 주문서 틀, `docs/engine.md` 4절·10절, `docs/design/spec.md`).
- 게임 도장 "주사위 장인"(`main.js`의 `dice-master`, 주사위 주문 성공)이 이제 받을 수 있게 된다(지난 검토 N1-10).
- 시간 재기: 주사위 주문에서 **켠 학생만** 걸린 시간이 보이고 결과에 내 기록과 견준 말이 나온다. 안 켜면 시간이 어디에도 보이지 않는다. 시간에는 점수가 없다.

## 계획에 적히지 않아 네가 정할 것 (정한 것과 까닭을 보고한다)

계획은 한 줄씩이라 화면의 세부가 비어 있다. 지금 있는 "내 맘대로 전개도"(`cube-free`, `play-free.js`·`free-board.js`)의 흐름·화면·문장을 최대한 물려받아 정하고, **사용자가 정해야 할 만큼 큰 갈림길이면 추측하지 말고 "사용자 결정 필요"로 보고**한다.

- 주사위 주문: 눈 카드의 모습(점 무늬 — 색만으로 구분하지 않기, 화면 읽기 이름 "주사위 눈 3"), 접기 전에 예상을 묻는지(계획에는 예상이 없다 — 놓고 [접어 보기]), 정육면체가 안 되는 모양을 접었을 때(겹침·네 면이 한 점에)와 합이 7이 아닐 때 각각의 피드백·기록·별 계산, "서로 다른 모양 2개"의 뜻(돌림·뒤집기로 같은 모양은 같은 것 — `netName`), 같은 모양을 또 만들었을 때의 안내, 첫 번째를 만든 뒤 두 번째로 넘어가는 흐름, 힌트.
- 도감 주문: `cube-free`와 무엇이 같고 다른가(목표가 3가지 대신 도감 11칸, [오늘은 여기까지]), 이미 도감에 있는 모양을 접었을 때, 이미 11칸인 학생이 들어왔을 때, 별이 도감 수로 정해지므로 다시 들어와 더 채우면 별이 오르는 것.
- 결과 화면의 "오늘의 솜씨" 칸과 문장, 단계 카드 그림(`thumb`), 놀이 방법 문장.

## 반드시 지킬 것

- **점수 규칙은 지금 것을 그대로 따른다** — 새 규칙을 만들지 않는다:
  - 자유 배치의 모양 점수는 이 기기에서 그 모양을 **처음 접을 때만**(spec 16-8), 별 3개 다시 하기와 상관없이 주고 그 자리에서 바로 저장(16-9, 엔진 `scored: 'once'`). 도감 주문은 `cube-free`와 **같은 도감·같은 노트·같은 "접어 본 모양"**을 쓴다 — `cube-free`에서 접은 모양을 도감 주문에서 다시 접어 점수를 또 받는 길, 그 반대의 길이 없어야 한다.
  - 도전 주문서 처음 성공 +10은 엔진이 처음 한 번만 준다. 주사위 주문을 되풀이해 점수를 쌓는 길이 없는지(엔진의 "별 3개 단계 다시 하기 연습 점수 0"·같은 문항 규칙 안에서) 무작위 단위 검사로 확인한다. **일부러 틀려서 이득 보는 길 0**, 모두 맞힌 쪽이 손해 보지 않음.
  - 화면에 보이는 점수 = 저장되는 점수(결과 칸 합 + 점수 줄 = 이번에 모은 솜씨 점수 = 저장 차).
- **답하기 전 정답 노출 0**: 주사위 주문에서 접기 전에는 어느 눈끼리 마주 보는지·합이 맞는지가 화면(글자·무늬·색·클래스·속성·화면 읽기 알림)에 드러나지 않는다. 도감 주문은 `cube-free`와 같은 규칙(예상 전 판, 까닭 고르는 중 노출 0).
- **지금 통과하는 것을 깨지 않는다**: 보기 조작(끌어서 끝없이 돌리기·0.5~2배·조작판은 접힌 뒤에만 — spec 17절·17-15~17-19)이 새 단계의 무대에서도 같은 규칙으로 동작, 끄는 면이 놓을 때까지 보임(16-11), 판 → 무대 어긋남 0px, 1366×768·1366×680·820×1180 세로·가로 스크롤 0, 자유 배치 오른쪽 판 안쪽 넘침 0, 도감 칸은 넘칠 때만 접힘(16-10), 48px, 알림이 조작을 가리지 않음, 움직임 줄이기·`?fx=low`, 나간 뒤 리스너·타이머 0, 콘솔 오류 0. 일반 단계 4개의 화면·점수·기록은 그대로다.
- 단계 지도: 도전 카드 2개는 일반 단계 뒤에 따로 보이고, 차시를 마치기 전에는 잠겨 있다. 차시 도감 칩·"약 10분" 칩은 그대로. `?unlock=all`·`?stage=cube-dice`로 바로 들어갈 수 있다.
- DOM은 `h()`(`innerHTML` 금지), 이모지 대신 `ui/icons.js` 아이콘, 색·간격은 토큰, 화면 문장은 5~6학년 눈높이 해요체 짧은 문장, 제목 글꼴에 없는 기호를 버튼·제목에 쓰지 않는다(빌드 로그 "알림" 확인). 학습 기록의 `tag`는 기획서 오개념 표의 말과 같게.
- 기존 검사를 지우거나 약하게 만들지 않는다. 단계 수가 바뀌어 고쳐야 하는 검사(예: 단계 카드 개수, 도장판)는 이유를 보고에 적는다.

## 덧붙임 1: 직접 만드는 전개도에서 예상하기를 없앤다 (2026-10-10, Build 도중 사용자 결정 — [spec.md](spec.md) 16-12)

이 라운드에 함께 넣는다. 기준은 spec 16-12 전체다. 요약:

- `cube-free`와 `cube-dex` 모두 **예상 버튼 없이 [접어 보기] 하나**로 접는다. 예상 안내·[될 거예요]·[안 될 거예요]·"예상과 달랐어요"·"예측 적중" 문구와 그 점수·쪽지를 없앤다. 안 되는 모양이면 지금처럼 까닭 고르기(고르기 전 무대에 까닭 글자·표시 0) → 표시.
- **`cube-free`의 별 = 이번 판에 찾은 서로 다른 전개도 수**(1·2·3가지 → ★1·★2·★3). 안 되는 모양은 별에 영향이 없다. `cube-dex`의 별은 도감 수.
- 점수: 되는 모양 처음 = 만들기 성공 +2(+ 엔진의 연속·다시 일어서기) + 도감 +5, 안 되는 모양 처음 = 노트 +1 + 까닭 맞히면 +2, 접어 본 모양 0. 모두 `scored: 'once'`·바로 저장의 지금 틀 안에서. **한 모양의 점수는 어떤 길로도 한 번만**, 되는 전개도 하나의 점수 > 안 되는 모양 하나의 점수, 화면 = 저장. 35가지 탐구 총점(전에는 219)이 달라지므로 엔진으로 재서 보고하고, 단위 검사의 기댓값을 새 규칙의 독립 계산에 맞춘다(지우지 말고 바꾼다). 모두 맞히는 학생의 첫 차시 점수와 칭호 기준(0·40·100·180·300)도 재서 보고한다.
- 기록: 접은 것 하나 = 학습 기록 하나(되면 맞음, 안 되면 오개념 tag). 이 단계의 쪽지·결과 화면에는 정답률·"틀림" 느낌의 말을 쓰지 않는다("찾은 전개도 n가지 · 접어 본 모양 n가지"). 엔진의 결과 화면을 그렇게 바꾸려면 필요한 만큼만 고치고(다른 단계·예시 게임은 그대로) 보고한다.
- 도장 "예측 명수"·"겹침 탐정"의 조건을 새 흐름에 맞게 정하고(이름을 바꿔야 하면 바꾸고) 정한 것과 까닭을 보고한다. 이미 받은 학생의 도장이 사라지지 않게 한다.
- 놀이 방법·단계 설명·힌트·알림 문장에서 "예상"이 남지 않게 한다(판별 단계의 예상은 그대로). 키보드 흐름(6장 놓은 뒤 [접어 보기]에 초점)과 1366×680 판 안쪽 넘침 0을 다시 잰다(버튼이 둘에서 하나가 되어 자리가 달라진다).
- 테스트: 예상 버튼을 누르던 단위·e2e 검사를 새 흐름으로 바꾼다. "접기 전 화면에 정답이 드러나지 않음", "까닭 고르는 중 노출 0(24가지)", "같은 모양 다시 접기 0점", "새로 고침·나가기 뒤 점수" 검사는 뜻을 살려 남긴다.
