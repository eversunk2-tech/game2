- 이 저장소는 **공개 저장소**다. 교과서는 저작물이다. **PDF·쪽 그림·삽화·등장인물·문제의 수치·문장을 저장소에 옮기지 않는다**(spec-grade6.md에도, 나중의 게임에도). 교과서에서 가져오는 것은 "무엇을 어떤 순서로 배우는가"(차시 흐름·개념·활동의 종류)뿐이고, 게임의 문제·문장·그림은 모두 새로 만든다.

- 교과서의 용어(각기둥, 밑면, 옆면, 모서리, 꼭짓점, 높이, 전개도, 쌓기나무, 위·앞·옆에서 본 모양, 층별로 나타낸 모양 등)는 교과서와 **같은 말**을 쓴다 — 용어가 교과서에서 어떻게 쓰이는지 확인해 표로 정리한다.

## spec-grade6.md에 반드시 담을 내용

1. **교과서 흐름 정리** — 세 단원 각각: 차시(소단원)별 쪽 범위, 배우는 개념, 학생이 하는 활동의 종류(자기 말 요약). 이번 범위(각기둥의 전개도 / 쌓기나무 단원 전체 / 원기둥의 전개도)에 해당하는 차시를 표시하고, 범위 밖(각뿔, 원뿔, 구 등)은 "다루지 않음"과 까닭. 용어 표. PDF에 성취기준이 있으면 쪽과 함께.
2. **앱 차시 구성** — 교과서 차시 ↔ 앱 차시·단계 **대응표**. 차시마다(10분 안팎) 단계 목록, 끝나는 조건, 별 기준, 문항 수. 지금 정육면체 차시의 흐름(판별 → 구조 이해 → 만들기 → 내 맘대로)과 어떻게 이어지는가.
   - 각기둥의 전개도: 교과서가 다루는 각기둥의 종류(삼각기둥·사각기둥·오각기둥·육각기둥 등 — 직접 확인), 전개도에서 익히는 것(밑면 2개·옆면 수 = 밑면의 변의 수, 맞닿는 모서리 길이, 겹치는 면 등), 전개도 그리기 활동을 화면에서 어떻게 하는가.
   - 원기둥의 전개도: 옆면이 직사각형, 옆면의 가로 = 밑면의 둘레(원주), 세로 = 높이. 교과서가 원주율을 어떻게 쓰는지(3, 3.1, 3.14 등 — 직접 확인)에 맞춘다. 곡면을 접는(마는) 모습을 화면에서 어떻게 보이는가.
   - **쌓기나무(공간과 입체)**: 교과서 단원의 차시 흐름(어느 방향에서 본 것인지 알기, 쌓은 모양과 쌓기나무의 개수, 위·앞·옆에서 본 모양, 위에서 본 모양에 수를 써서 나타내기, 층별로 나타낸 모양, 여러 가지 모양 만들기 등 — 직접 확인한 대로)에 맞춘 차시·단계.
3. **쌓기나무를 "직접 입체적으로 다루기" 설계 (사용자가 특히 요청)** — 학생이 쌓기나무를 **직접 쌓고·빼고·돌려 보는** 조작을 중심에 둔다.
   - 조작 표: 쌓기(어디를 누르면 어디에 놓이는가 — 바닥 칸, 쌓기나무의 윗면·옆면), 빼기, 되돌리기, 모두 치우기, 돌려 보기(지금의 `orbit.js` 방식 그대로), 크게·작게. 마우스 / 터치 / 키보드 각각. 누르기(쌓기)와 끌기(돌리기)를 어떻게 가르는가(지금 무대는 "답한 뒤에만 돌리기"로 갈랐다 — 쌓기나무는 쌓는 중에도 돌려 봐야 한다).
   - 교과서 활동과 잇는 방법: 위·앞·옆에서 본 모양을 보고 쌓기 / 쌓은 모양을 위·앞·옆에서 보면 어떤 모양일지 예상하고 돌려서 확인하기 / 위에서 본 모양에 수 쓰기 ↔ 쌓기 / 층별 모양 ↔ 쌓기 / 개수 세기(보이지 않는 쌓기나무) / 조건에 맞게 여러 가지로 쌓기. "위·앞·옆에서 본 모양"을 화면에서 어떻게 보여 주는가(버튼으로 그 방향에서 보기, 2D 그림과 나란히).
   - 실물 쌓기나무와 다른 점을 어떻게 다루는가(공중에 뜬 쌓기나무를 허용할지, 보이지 않는 뒤쪽 등).
   - 판 크기·최대 높이·최대 개수와 그 까닭(교과서 문제의 크기, 1366×680 화면, 그리기 성능).

12. **Build 단계 나누기와 순서** — "5학년 완성(N2 도전 주문서 → 2차 직육면체) 뒤 6학년"이라는 사용자 순서 안에서, 6학년 세 영역을 어떤 순서로 몇 번의 Build·Review로 나눌지(각 Build는 Review 한 번으로 볼 수 있는 크기). 영역끼리 기대는 것(예: 각기둥은 2차의 자유 배치 어댑터에 기댐), 먼저 만들면 좋은 것. 각 Build의 예상 작업량.
13. **사용자에게 확인할 것** — 사용자가 골라야 하는 것만(**5개 이하**), 각각 선택지 2~3개와 **추천**. 초등 교사가 읽고 고를 수 있게 기술 용어 없이. 예: 한 앱에 다 넣기 vs 나누기(크기 문제가 있을 때만), 6학년 세 영역을 만드는 순서, 쌓기나무에서 공중에 뜬 쌓기나무 허용 여부, 앱 이름.
14. **확인한 것과 확인하지 못한 것** — 교과서에서 직접 읽은 것 / 시제품으로 잰 것 / 추정을 구분.

## 형식

- 한국어, spec.md와 같은 문체·표 형식. 학생에게 보이는 화면 문장은 5~6학년 눈높이 해요체 짧은 문장.
- 길어도 되지만 한 절이 한 화면을 넘으면 표로 줄인다. 맨 위에 "요약"(10줄 이하)을 둔다.

## 최종 답변 (14줄 이하)

교과서에서 확인한 차시 흐름 요약(세 단원), 추천하는 앱 차시 구성(영역별 단계 수), 쌓기나무 조작 방식 요약, 파일 크기·앱 구조 결론, Build 순서, **사용자에게 확인할 것**(선택지와 추천), 확인하지 못한 것. 직접 확인한 것과 추정을 구분한다.

## 덧붙임: 전제 변경 (2026-10-09, Plan 진행 중 사용자 결정)

> "단일 html로 하지 않아도 돼. 처음에 설정을 잘못 했던거 같아. js 환경으로 자유로운 용량으로 만들어줘"
