## 0. 사용자에게 보일 요약 (쉬운 말)

- **지금 모습이 왜 "AI 같다"는 말을 듣는가**: 버튼 · 카드 · 이름표 · 판 어디에나 **똑같은 진한 남색 테두리와 똑같은 남색 "덧붙은 두께"**가 있고, 노랑 스티커가 기울어 붙어 있습니다. 이 모양 자체는 사람 디자이너들이 먼저 쓴 방법인데, 요즘 AI가 "귀엽고 장난스러운 화면"을 만들 때 거의 늘 이 묶음을 그대로 내놓아서 사람들이 "AI 화면"의 표시로 알아보게 되었습니다. 이 앱에서는 누르지 않는 것(접는 정도 막대, 도구 띠, 이름표)에도 같은 두께가 붙어 있어 더 그렇게 보입니다.
- **사람 디자이너는 어떻게 하나**: ① 누르는 것만 입체로, 읽는 판은 납작하게(높낮이 차례) ② 그림자를 검정이 아니라 그 물건 색의 진한 쪽이나 바닥 색으로 ③ 빛은 위에서 하나 ④ 그 제품만의 모양을 하나 정해 되풀이 — 이 앱이라면 **종이 공작(풀칠 날개 · 접는 선 · 오릴 점선)**.
- **시안 셋** (모두 실제 화면에 덧씌워 찍음, 글자 · 자리 · 크기는 그대로 — 직접 잼):
  - **A 같은 색 두께** — 남색을 걷고, 누르는 것만 "파랑 계열의 두께"를 남깁니다. 지금과 가장 가깝습니다.
  - **B 종이 공작 (추천)** — 덧붙은 두께를 아예 없앱니다. 판은 책상에 놓인 종이, 누르는 것은 책상에서 살짝 뜬 두꺼운 색지처럼 보입니다. "여기부터!"는 기울인 스티커 대신 카드 위에 붙은 **풀칠 날개**, 학년 카드의 색 칸과 흰 칸 사이는 **접는 선**입니다.
  - **C 차분한 면** — 그림자를 거의 없애고 색 면으로만 구분합니다(교과서처럼 평평하게).
- **B를 추천하는 까닭**: 사용자가 짚은 "덧붙은 부분"이 하나도 남지 않으면서, 이 앱이 "전개도 공방"이라는 것이 모양으로 드러납니다. 버튼 가장자리가 바탕과 구분되는 정도도 셋 가운데 가장 또렷합니다(직접 잼 3.6~4.1배 — A 2.9~3.3 · C 1.1~1.6).
- **[입장하기]**: 지금도 제목 그림(금빛 글자 + 남색 외곽선)과 한 벌이라 괜찮습니다. 다만 금빛 제목과 금빛 버튼이 둘 다 주인공이 되려고 합니다. 시안 셋 — A 금빛 두께(남색만 걷음) · B 입장권(종이 표 모양) · **C 리본 파랑(추천 — 제목 아래 파랑 리본과 같은 색, 흰 글자)**. 크기 · 자리 · 손 피하기는 네 가지 모두 똑같습니다(직접 잼).
- **고르실 것**: ① 메뉴 · 버튼 방향(A · B · C · 지금) ② [입장하기](지금 · A · B · C) ③ 어디까지 바꿀지(버튼 · 카드 같은 틀만 — 추천 / 전개도 면 · 쌓기나무까지) ④ 바탕 모눈은 그대로 둘지(추천: 그대로).

### (가) 이 모양이 왜 "AI 디자인"으로 읽히는가

- **기법 자체는 사람이 먼저 썼다.** 굵은 검정 테두리 + 옆 · 아래로 밀린 단단한 그림자는 2020년대 초 웹의 "네오 브루털리즘" 유행에서, 두툼한 아래 두께는 학습 앱의 3D 버튼(Duolingo — 버튼 색의 진한 쪽으로 3~4px 두께, 누르면 납작)에서 널리 쓰였다. 그 자체는 나쁜 기법이 아니고, "누를 수 있다"가 모양으로 보이는 장점이 있다(지금 체계를 고른 까닭 — design/spec.md 1절).
- **흔해진 까닭**: 생성 AI가 "귀엽고 장난스러운 · 어린이용" 화면을 만들 때 거의 늘 같은 **묶음**을 내놓으면서, 사람들이 이 묶음을 "AI가 만든 화면"의 표지로 알아보게 되었다. 한 가지 기법이 아니라 아래가 **한꺼번에, 모든 요소에 똑같이** 있을 때 티가 난다.

| 티 내는 조합 | 이 앱에서 (직접 모은 수) |
| --- | --- |
| ① 모든 요소에 똑같은 검정(잉크) 테두리 + 똑같은 검정 그림자 | 화면마다 잉크 테두리 7~31개, 덧붙은 그림자 5~20개. 버튼 · 카드 · 탭 · 칩 · 판 · 알림 · 막대 모두 `#1e2140` 한 색 |
| ② 크림색 모눈 바탕 | `body` 28px 모눈(base.css:115~118) |
| ③ 기울인 노랑 스티커 · 테이프 | "여기부터!" 3°, 테이프 −3°, 주문 도장 −3°, 쪽지 −1~−4° |

- **사용자가 짚은 세 곳**
  - ① **6학년 카드**: ①+⑤ — 파랑 2px 테두리 + 짙은 파랑 아래 4px + 옅은 파랑 4px 고리(이것이 "옆으로 덧붙은 것")를 한꺼번에, 거기에 ③ 기울인 노랑 스티커와 ④ 테두리 알약(별 칩), 색 칸과 흰 칸 사이의 잉크 2px. "지금 할 곳"을 세 겹(두께 · 고리 · 스티커)으로 강조한다.
  - ② **[← 처음으로]**: ①의 가장 전형적인 모양(잉크 2px + 아래 잉크 3px). 화면 맨 위의 작은 이동 버튼인데 주 버튼과 같은 무게다(⑤).
  - ③ **[입장하기]**: 금빛 + 파란 테 + 잉크 3px 외곽 + 아래 잉크 7px + 흐린 그림자 + 반짝임. 이것은 웹의 AI 문법이라기보다 **모바일 게임 버튼 문법**이고, 캔바에서 받은 제목 그림 자체가 남색 외곽선 + 금빛 두께라 그림과는 한 벌이다 — 셋 가운데 AI 티가 가장 약하다(사용자 느낌과 같다). 다만 금빛 제목과 금빛 버튼이 둘 다 주인공이 되려고 한다.

## 3. 메뉴 · 버튼 전반의 방향 — 지금 + A · B · C

- 코디네이터의 출발 가설(A 같은 색 두께 · B 종이 공작 · C 차분한 면)을 그대로 두되, **셋이 "깊이를 무엇으로 보이는가"에서 확실히 갈리게** 다듬었다: **A = 두께(단단한 같은 색 띠)**, **B = 뜸(종이가 바닥에서 뜬 그림자 — 덧붙은 띠 없음)**, **C = 면의 색(그림자 없음)**. 처음 가설의 B는 A와 거의 같은 두께에 무늬만 더한 것이었는데, 그러면 사용자가 짚은 "덧붙은 부분"이 B에도 남는다.
- 공통: **테두리 두께(px)는 지금과 같게 두고 색만 바꾼다(투명 포함)** → 자리 · 크기 변화 0. 초점 표시(잉크 3px + 노랑 후광 7px)는 셋 다 그대로. 도장은 셋 다 그대로(진짜 도장은 기울어 찍힌다). 학습 내용(1-3 (가))은 그대로.
- **자리 · 크기를 직접 잼**(`tools/layoutdiff.mjs` → `out/layoutdiff.json`): 8화면 × 4크기(1366×768 · 820×1180 · 1366×680 · 390×844)에서 요소 61~155개의 자리 · 크기를 지금과 견줌 → **A · C 0px**, **B는 "여기부터!" 하나만**(풀칠 날개 모양이라 폭이 16~20px 넓음 — 의도, 떠 있는 꼬리표라 다른 것을 밀지 않음). 남는 스크롤도 지금과 같다(학습 기록 · 휴대폰 화면의 세로 스크롤만 — 지금도 있는 것). 몇 군데 2px로 나온 것은 눌린 탭의 `transform` 때문에 잰 기준(offsetParent)이 바뀐 것으로, 화면의 자리는 같다(확인함).
- **"여기부터!"가 다른 것과 겹치는가**(`tools/flagcheck.mjs`, 6크기 × 학년 고르기 · 6학년 · 단계 지도 둘): 네 방향 모두 학년 고르기의 "공부할 학년을 골라요" 줄 상자에 4~7px 걸치는 것뿐(지금도 7px — 글자가 아니라 줄 상자의 오른쪽 빈 곳). B의 풀칠 날개를 처음에 카드 밖으로 더 올렸더니 차시 제목 · "약 n분" 칩과 2~9px 겹쳐서, 지금 깃발과 같은 높이로 되돌렸다.
- **덧붙은 두께가 얼마나 남는가**(`tools/audit.mjs`, 1366×768 화면 9곳 합 — 흐림 없는 2px 이상 그림자가 있는 요소): 지금 **87**(그 가운데 잉크색 76) → A 61(모두 파랑 계열 · 잉크색 0 — 주 버튼 · 지금 할 곳의 짙은 파랑 5 포함) → **B 0** → **C 0**. UI 틀에 남은 잉크 테두리: 셋 다 0(남은 것은 "지금 할 곳" · 주 버튼의 파랑 테두리와 학습 내용 — 전개도 면 · 색 견본).

### 3-1. A "같은 색 두께"

- 생각: 남색을 걷고, 누르는 것만 **자기 색의 진한 쪽으로** 아래 두께를 준다. **누르는 것은 파랑 계열**(주 버튼 = 파랑 면 + 짙은 파랑 두께, 보통 버튼 = 흰 면 + 옅은 파랑 테 + 파랑 두께), 읽는 판은 따뜻한 종이(두께 없음, 부드러운 두 겹 그림자). 칩은 납작, 스티커는 바로 세움, 테이프는 뺌.
- 덧씌운 CSS: `css/A.css`.

### 3-2. B "종이 공작" ← 추천

- 생각: 이 앱은 "종이를 오려 접는 공방"이다. 진짜 종이에는 검은 테두리도, 옆으로 밀린 검은 그림자도 없다.
  - **읽는 판 = 책상에 놓인 종이**: 테두리 없이 아주 얇은 종이 가장자리(따뜻한 갈색 15%) + 바로 밑의 닿는 그림자.
  - **누르는 것 = 책상에서 살짝 뜬 두꺼운 색지**: 종이 가장자리 + 바로 밑 1px 닿는 그림자 + 넓은 퍼짐(빛은 위에서 하나). 올리면 조금 더 뜨고(2px), 누르면 책상에 붙는다(그림자가 줄고 1px 내려앉음). **덧붙은 띠는 없다.**
  - 그림자 색은 남색이 아니라 **종이 밑의 따뜻한 갈색**(`rgb(70 52 24 / …)`), 파랑 종이 밑은 파랑.
  - **이 앱만의 표시** — 화면마다 1~2곳만: "여기부터!" = 카드 위 가장자리에 붙은 **풀칠 날개**(사다리꼴 + 아래 접는 점선, 기울이지 않음, 자리 · 높이는 지금 깃발과 같게), 학년 카드의 색 칸과 흰 칸 사이 = **접는 선**(점선), 잠긴 카드 · 비활성 버튼 = **아직 오리지 않은 종이(오릴 점선)** — 지금의 점선을 따뜻한 색으로. 모서리는 종이처럼 조금 덜 둥글게(판 14px · 버튼 12px).
  - 테이프는 작업 지시서 · 증명서 · 내 공방에 그대로(종이 공작의 재료 — 조금 옅게). 칩은 납작한 종이 꼬리표.
- 덧씌운 CSS: `css/B.css`.

| --- | --- | --- |
| `--tint` (새) | `70 52 24` | 종이 밑 그림자의 색(따뜻한 갈색) — rgb 세 값 |
