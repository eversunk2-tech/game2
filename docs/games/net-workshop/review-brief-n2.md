## 확인할 것

### A. 예상하기 삭제 (16-12) — 사용자가 직접 요청한 것

1. `cube-free`와 `cube-dex`에 예상 버튼·예상 안내·"예상과 달랐어요"·"예측 적중" 같은 말이 **화면·쪽지·결과·놀이 방법·학습 기록·화면 읽기 알림 어디에도 남아 있지 않은가**(네 크기 스크린샷을 직접 열고, DOM 글자·`aria-label`도 훑는다). 6장을 이어 놓으면 [접어 보기] 하나로 접히는가(마우스·터치·키보드, 키보드 초점 흐름). 판별 단계(`cube-judge`)의 예상은 그대로인가.
2. 안 되는 모양: 까닭 고르기가 나오고, **고르기 전에는 무대에 까닭 글자·표시가 0**인가(안 되는 모양 24가지 모두, 돌려 보고 크게 본 뒤에도) — 지난 검토와 같은 방법. 고른 뒤·넘어간 뒤에는 표시가 나오는가.
3. **별**: `cube-free`의 별이 이번 판에 찾은 서로 다른 전개도 수(1·2·3 → ★1·★2·★3)인가. 안 되는 모양을 여러 번 접어도 별이 그대로인가. 같은 모양을 돌려 다시 접은 것은 세지 않는가. 다시 하기에서 별이 줄지 않는가(엔진의 "가장 좋은 별" 규칙). 결과 화면의 별 기준 안내 문장이 새 기준과 맞는가.
4. **점수(독립 계산과 견줌)**: 기획서 문장(16-8·16-9·16-12, engine.md 점수 표)만 보고 짠 독립 계산 ↔ 엔진, 무작위 여러 기기·여러 판(나가기·새로 고침·별 3개 다시 하기 포함). 되는 모양 처음 +2(+연속·다시 일어서기)·도감 +5, 안 되는 모양 처음 노트 +1·까닭 +2, 접어 본 모양 0. 한 모양의 점수는 어떤 길로도 한 번(탭 두 개, 처음에 까닭을 틀린 모양을 나중에 맞히기, `cube-free` ↔ `cube-dex`를 오가며 같은 모양 접기 포함). 되는 전개도 하나의 점수 > 안 되는 모양 하나의 점수. 화면 = 저장(결과 칸 합 + 점수 줄 = 이번에 모은 솜씨 점수 = 저장 차). 35가지 탐구 총점, 모두 맞히는 학생의 첫 차시 점수와 칭호 기준(0·40·100·180·300)을 견준 의견. **안 되는 모양을 일부러 접는 것이 이득이 되는 정도**(탐구 보상으로서 적당한가, 연속·다시 일어서기 보너스를 일부러 끊고 이어 더 받는 길이 있는가).
5. 기록·화면의 말: 접은 것 하나가 학습 기록 하나로 남는가(되면 맞음, 안 되면 오개념 tag). 이 단계의 쪽지·결과에 정답률·"틀림" 느낌의 말이 없는가. 학습 기록 화면의 "자주 틀린 개념"에 어떻게 보이는가(의견). 엔진 결과 화면을 고쳤다면 다른 단계·예시 게임의 결과 화면이 기준 커밋과 같은가.
6. 도장 "예측 명수"·"겹침 탐정"의 새 조건이 화면에 적힌 말과 실제 판정이 같은가, 받을 수 있는가, 이미 받은 기록이 사라지지 않는가.

### B. 도전 주문서 (16-3)

7. **주사위 주문 `cube-dice`**: 눈 카드(색만으로 구분하지 않음, 화면 읽기 이름), 마주 보는 눈의 합이 7인 전개도를 서로 다른 모양으로 2개. 판정을 독립 계산(정육면체 감싸기로 마주 보는 면을 구함)과 견준다 — 전개도 11가지 × 눈 놓는 방법 전부에서 "합이 7" 판정과 틀렸을 때 문장("○과 ○이 마주 봐요…")의 눈이 맞는가. 정육면체가 안 되는 모양을 접었을 때, 같은 모양을 또 만들었을 때의 처리. 다 접으면 마주 보는 짝이 같은 무늬로 보이는가. **접기 전 화면에 어느 눈끼리 마주 보는지가 드러나지 않는가**(글자·무늬·색·클래스·속성·알림). 별·점수·"도전 성공 +10은 처음 한 번"·되풀이해 점수 쌓기 불가.
8. **시간 재기**: 켠 학생만 걸린 시간이 보이고 결과에 내 기록과 견준 말이 나오는가. **안 켜면 시간이 화면·결과·학습 기록·결과 복사 어디에도 보이지 않는가.** 시간에 점수가 없는가.
9. **도감 주문 `cube-dex`**: 도감 11칸을 채우는 흐름, [오늘은 여기까지], 별 = 도감 수(6·9·11칸), 11칸이면 바로 끝. **새로 고침·나갔다 들어오기·여러 번에 나눠 하기에서 도감이 이어지는가.** `cube-free`와 같은 도감·노트를 쓰는가. 이미 11칸인 학생이 들어왔을 때. 전개도 11가지를 실제로 모두 만들어 끝까지 가 본다(독립 계산의 11가지로).
10. 잠금: 일반 단계 4개를 모두 마치기 전에는 도전 카드가 잠겨 있고 마치면 열리는가. 도전이 다음 단계·차시 별 합계에 들어가지 않는가. `?unlock=all`·`?stage=`로 바로 들어가기. 게임 도장 "주사위 장인"을 실제로 받는가.

### C. 공통

11. **테스트**: `npm test`, `npm run test:e2e` 직접 실행(통과·실패·건너뜀, 건너뜀이 기기 나눔뿐인지). `git diff tests/`로 기존 검사가 약해지지 않았는지 — 예상 버튼을 누르던 검사가 새 흐름의 검사로 **바뀌었는지(지워지기만 한 것이 없는지)** 줄 단위로 본다. 계획의 세 테스트(주사위 판정 단위, 도감 이어 하기 e2e, 시간 재기를 안 켜면 안 보임 e2e)가 있는가.
12. **CI 검사 수정(덧붙임 2)**: 1px 차이로 실패하던 3건을 고친 방법이 검사의 뜻(답하기 전 조작 띠·칸 크기가 V1 이전과 같다, 조작판 때문에 줄지 않는다)을 살렸는가 — 허용 폭이 지나치게 넓어 실제 회귀(예: 칸을 다시 줄이는 것, 5px 이상 어긋남)를 놓치지 않는가. 일부러 값을 어긋나게 한 복사본에서 검사가 실패하는지 확인한다. 글자 폭에 기대는 픽셀 상수가 다른 검사(기존·새 것)에 더 있는지 찾아 목록으로 적는다(리눅스 CI에서 깨질 후보). 리눅스에서의 실제 통과는 여기서 확인할 수 없으니 "CI에서 확인 필요"로 적는다.
13. **교실 기기**: 새 단계와 바뀐 `cube-free`에서 1366×768·1366×680·820×1180 세로·가로 스크롤 0, 자유 배치 오른쪽 판 안쪽 넘침 0·잘린 버튼 0(모든 장면), 48px, 알림이 조작을 가리지 않음, 휴대폰 배치. 보기 조작(끌어서 끝없이 돌리기·0.5~2배·조작판은 접힌 뒤에만)·끄는 면 보이기·판 → 무대 어긋남 0px이 새 단계에서도 같은가.
14. **회귀**: 판정·수학 그대로(`fold.js` 불변), 나머지 세 일반 단계의 화면·점수·기록이 기준 커밋과 같은가, 예시 게임·게임 모음, 움직임 줄이기·`?fx=low`, 나간 뒤 리스너·타이머 0, 콘솔 오류 0.
15. **범위·코드**: 허용 파일 안인가. 엔진을 고쳤다면 무엇이 모자랐는지가 타당하고 다른 게임에 영향이 없는가. `h()`·`innerHTML` 없음·이모지 없음·죽은 코드(쓰지 않게 된 예상 관련 코드가 지워졌는가). 앱 이름·빌드 구조·6학년 영역은 건드리지 않았는가.
16. **새로 생긴 문제**, 사용자가 정해야 할 것(선택지와 추천).
