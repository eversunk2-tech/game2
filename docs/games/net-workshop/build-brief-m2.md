# Build 서브에이전트 지침: 2차 직육면체 차시 (동시 진행 트랙 "cuboid")

## 역할

너는 **Build** 담당이다. 승인된 계획대로 5학년 **직육면체의 전개도 차시**(`cuboid`)를 만든다. 이것으로 "5학년 앱"이 완성된다. 다른 Build 서브에이전트가 **같은 때에 다른 폴더에서 쌓기나무 영역**을 만들고 있다 — 두 결과는 나중에 코디네이터가 `main`에 합친다. 검증은 별도 Review 서브에이전트가 한다.

1. **[common-rules.md](common-rules.md)** — 정육면체 차시를 만들며 정한 공통 규칙. 이 차시도 **같은 조건**으로 만든다(직접 만드는 단계에는 예상이 없다, 정답 노출 0, 점수는 모양마다 한 번, 보기 조작, 끌기, 화면 배치, 테스트 기준, 동시에 만들 때 지킬 것).
2. [spec.md](spec.md) — 2절 차시 표의 `cuboid` 줄과 단계 표(`cuboid-edge` → `cuboid-face` → `cuboid-judge`), 3절 오개념 표(만나는 선분 · 맞닿는 모서리 길이 · 마주 보는 면은 합동), 4~6절(놀이·조작·피드백), 11절 기술 설계(다각형 면 전개도, `unfold(cuboid(a, b, c), tree)`, `hingeAngle`, 직육면체 전개도 54가지 실험값, 문제 만들기), 13절 테스트 계획, 14절의 "2차 직육면체" 줄, **16-2**(모든 차시의 마지막 단계 "내 맘대로 전개도" — `cuboid-free`), 16-8~16-13(점수·예상 삭제·N2에서 정한 세부), 17절(보기 조작)
3. [docs/dev-guide.md](../../dev-guide.md), [docs/engine.md](../../engine.md), [docs/design/spec.md](../../design/spec.md)

## 만들 것

| 단계 | 내용 (spec 2절·16-2) |
| --- | --- |
| `cuboid-edge` 만나는 선분 | 전개도에서 한 선분과 접었을 때 만나는 선분 고르기(보기 4). 꼭짓점 이름(ㄱㄴㄷ…), 접는 장면에서 두 선분을 같은 무늬로 |
| `cuboid-face` 알맞은 면 고르기 | 크기가 다른 면 카드 가운데 빈 자리에 맞는 것 붙이기(마주 보는 면은 합동) |
| `cuboid-judge` 길이까지 살펴요 | 길이가 적힌 직육면체 전개도 판별(무효: 길이 · 겹침 · 마주 보는 면 크기) → 접어 확인 → 까닭 |
| `cuboid-free` 내 맘대로 전개도(직육면체) | 16-2: a×b · b×c · a×c 직사각형 2장씩을 1 cm 격자에 놓아 전개도 만들기. **예상 버튼 없이 [접어 보기] 하나**(16-12), 별은 찾은 가지 수, 안 되면 까닭 고르기 |

- 기술(spec 11절·14절): 부분 겹침 경첩·`edge-length` 판정, `unfold`, 꼭짓점 이름, 길이 이름표, 크기가 다른 직사각형 면의 무대 표시와 자동 맞춤. **뒤이어 6학년 각기둥 차시가 이 부품(부분 겹침 경첩·`edge-length`·`unfold`·길이 이름표·자동 맞춤·자유 배치 어댑터)을 물려받는다** — 직육면체에만 맞춘 지름길 대신, 계획대로 "다각형 면 전개도 공통"으로 넓혀 둔다(각기둥 자체는 만들지 않는다).
- 단계 지도에 `cuboid` 차시가 `cube` 차시 다음에 보이고, `?lesson=cuboid`로 바로 들어간다. 차시는 10분 안팎(문항 수는 계획대로, 손으로 한 번 해 보고 시간을 적는다).
- 계획에 적히지 않은 세부(화면 배치, 문장, `cuboid-free`의 판 크기·카드 돌리기·도감을 둘지, 점수 세부)는 정육면체 차시의 같은 종류 단계를 물려받아 네가 정하고 까닭을 보고한다. 사용자가 정해야 할 만큼 큰 갈림길은 추측하지 말고 "사용자 결정 필요"로 적는다.

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 특히: 답하기 전 화면이 정답과 무관하게 한 가지(길이 이름표·면 크기·자리 포함 — 판별 문항에서 무효 전개도만 다르게 보이지 않게), 점수는 엔진 규칙 안에서(직접 만드는 단계는 `scored: 'once'`), 일부러 틀려 이득 0·화면 = 저장을 독립 계산과 견주는 무작위 검사, 판정을 독립 계산(직육면체 감싸기)과 전수·큰 표본으로 견줌(전개도 54가지 포함), 1366×768·1366×680·820×1180 스크롤 0·판 안쪽 넘침 0, 플레이 도중 머리·매트 움직임 0, 보기 조작·끌기는 지금 것을 그대로.
- **정육면체 차시와 도전 주문서의 화면·점수·기록은 한 글자도 달라지면 안 된다**(공통 부품을 넓히면서 깨지기 쉽다). 기준 커밋을 따로 빌드해 견준 값을 보고한다. 지금 있는 단위·브라우저 검사는 고치지 않고 통과해야 한다 — 단, **전체 단계 수·차시 수를 세는 기존 검사는 차시별로 세도록** 고쳐 다른 트랙이 차시를 더해도 깨지지 않게 한다(이유를 보고).
- 테스트: `npm test` + `npm run test:e2e -- --workers=4`(보통) + **글꼴 흉내 모드**(`E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`)에서 실패 0. 글자 폭에 기대는 픽셀 상수를 쓰지 않는다.

## 동시에 만드는 동안 지킬 것 (common-rules 10절)

- **네 작업 폴더와 브랜치에서만** 일한다(코디네이터가 프롬프트로 알려 준다). `main` 체크아웃(`/Users/sungchul/Desktop/play2/game2`의 맨 위 폴더)과 다른 트랙의 폴더는 읽기도 고치기도 하지 않는다.
- 새 코드는 **새 파일**에(예: `src/games/net-workshop/cuboid-*.js`, `tests/unit/net-workshop-cuboid*.test.js`, `tests/e2e/net-workshop-cuboid.spec.js`). 같이 쓰는 파일(`main.js`·`logic.js`의 등록, `style.css`, `tests/e2e/net-workshop.spec.js`, `docs/engine.md`)은 **덧붙이기만, 최소로** — 있는 줄의 순서를 바꾸거나 다시 쓰지 않는다. 공통 부품(`fold.js`·`geometry.js`·`view3d.js`·`free-board.js`·`play-*.js`)은 이 트랙만 고친다(쌓기나무 트랙은 건드리지 않는다).
- 엔진(`src/shared/**`)은 꼭 필요한 만큼만 고치고 무엇을 왜 바꿨는지 보고한다(쌓기나무 트랙도 아이콘 등을 더할 수 있다 — 아이콘·목록은 끝에 덧붙인다).
- 커밋은 **자기 브랜치에만** 한다(작업 단위마다 커밋해도 된다). `git push`·`main`에 합치기·다른 브랜치 바꾸기는 하지 않는다. 최종 상태는 커밋해 둔다(Review가 그 커밋을 본다).
- 이 폴더에서 `npm ci`는 처음 한 번 해도 된다(의존성이 없는 새 폴더다). Playwright 브라우저는 이미 깔려 있다(1.56.1).
- 개발 서버는 정해 준 포트만. 5173·5183은 건드리지 않는다. e2e는 `--workers=4`. 시간 제한으로 실패한 검사는 혼자 다시 돌려 부하 탓인지 가린다.
- 임시 파일·스크린샷은 정해 준 scratchpad 폴더에만. 작업 폴더 안에 임시 파일을 남기지 않는다.

## 끝났다의 기준

`npm test`, e2e 보통·글꼴 흉내 모두 실패 0(마지막 커밋에서 처음부터). 직육면체 54가지 테스트·만나는 선분 테스트·`?lesson=cuboid` e2e(계획 14절). 네 단계를 브라우저에서 처음부터 끝까지 직접 해 보기(마우스·터치·키보드만), 네 크기 스크린샷을 직접 열어 확인. 정육면체 차시가 기준 커밋과 같음을 수치로.
