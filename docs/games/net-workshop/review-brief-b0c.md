# Review 서브에이전트 지침: B0c 게임 인트로 화면 (트랙 "b0")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-b0c.md](build-brief-b0c.md)(맨 아래 덧붙임 포함)에 따라 만든 게임 인트로 화면과, 처음 화면을 거쳐 가는 검사의 손질을 **독립적으로** 검증한다. Build와 분리된 검토자다.
- **검토 결과는 새 파일 `docs/games/net-workshop/review-b0c.md`에 쓴다**(트랙의 작업 폴더 안). 맨 위에 판정 줄, 그 아래 기존 review 파일과 같은 형식의 표. 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다.
- **트랙의 작업 폴더에서만** 일한다. 검증 파일·스크린샷·기준 빌드는 정해 준 scratchpad 폴더에만. Build의 scratchpad는 근거로 삼지 않는다.

## 검토 대상

기준 `95b7647`(이 컴퓨터의 `main` — 영역 화면·쌓기나무 3·4차시·작은 수정이 들어 있다)과 트랙 브랜치의 마지막 커밋 사이의 변경 가운데 **B0c의 것**. 이 가지에는 직육면체 M3 트랙(`track/cuboid`)이 합쳐져 있다(코디네이터의 `40b076b` — M3은 따로 재검토 중이니 **M3의 기능은 이번 검토 대상이 아니다**). 합친 뒤 Build가 인트로 때문에 깨지는 직육면체 검사의 길 찾기 줄을 고쳤다 — 그 줄들은 이번 검토 대상이다. 그림 파일 `img/intro-bg.jpg`·`img/intro-title.webp`는 바뀌지 않았어야 한다. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 실행. 실패 0이어야 한다(옛 처음 화면 탓이던 쌓기나무 실패도 이제 0). `git diff 95b7647..HEAD -- tests/`에서 B0c가 고친 줄을 줄마다 읽어 **들어가는 길만 바뀌고 뜻은 그대로인지**(약해진 검사 0) — 특히 쌓기나무 "단계 지도: 쌓기나무 네 차시가…"를 다시 쓴 것, 차시 칩 검사 셋, 처음 화면 그림 검사의 "두 프레임 기다림".
2. **인트로 (가장 중요 — 학생이 처음 보는 화면)**: 네 크기(1366×768·1366×680·820×1180·390×844)와 1024×768·1180×820에서 — 스크롤 0, 제목·부제·버튼·소리 버튼이 잘리지 않고 겹치지 않음, 버튼·제목이 두 아이의 얼굴을 가리지 않음, 부제가 리본 안(글꼴 흉내 포함). 스크린샷(멈춘 것·움직이는 중)을 **직접 열어** "진짜 게임 인트로 느낌"(사용자 참고 이미지의 분위기: 밝고 반짝이며 큰 입체 제목, 눈에 띄는 버튼)이 나는지, 어색한 곳(빈 자리, 흐린 그림, 늘어난 그림, 이음매, 하늘색과 그림의 경계)이 없는지 의견을 적는다.
3. **움직임**: 차례(제목 떨어짐 → 부제 → 버튼)와 그 뒤 계속 도는 움직임이 `transform`·`opacity`만 쓰는지, 느린 CPU(4·8배)에서 끊기지 않는지(프레임 간격), 움직임 줄이기·`?fx=low`에서 처음부터 제자리이고 도는 움직임 0인지, 다른 화면으로 가면 움직임·타이머·리스너가 남지 않는지(나간 뒤 rAF·애니메이션 0).
4. **언제 보이나·길**: 주소에 `?stage=`·`?lesson=`·`?area=`·`?grade=`가 없을 때만 인트로, 있으면 바로 그 화면. [입장하기](마우스·터치·Enter·Space) → 학년 고르기, [← 처음으로] → 인트로. 소리 끔이면 소리 0. 인트로 동안 머리 처리. 새로 고침·뒤로 가기에서 이상한 화면이 없는지.
5. **접근성**: h1(그림의 대체 글), 부제는 글자, [입장하기]가 진짜 버튼이고 처음 초점, 꾸밈은 화면 읽기에서 숨김, 대비(부제·버튼 글자), Tab 순서.
6. **불변**: 기준 `95b7647` 빌드와 견줘 학년 고르기 뒤의 모든 화면(학년·영역·단계 지도·플레이·결과·학습 기록)과 수업 주소 화면, 예시 게임, 저장 열쇠·값이 같은지(의도한 차이: 학년 고르기의 [← 처음으로] 줄, 차시 하나뿐인 영역의 칩 없음). 예시 게임 파일이 168 → 184 KB가 된 까닭(엔진 CSS·JS)을 확인하고, 예시 게임 화면 차이 0.
7. **차시 칩·B0a-1**: 정육면체·직육면체 영역 지도에서 칩 없음, 쌓기나무 1~4차시, 수업 주소 화면 그대로. 960×680·1024×600 글꼴 흉내에서 학년 고르기 넘침 0.
8. **처음 여는 시간**: Build가 잰 값(HTML 516 → 1,067 KB, 느린 망 1.6 Mbps에서 첫 그림 1.09 → 2.96초, 그동안 빈 화면)을 같은 방법으로 다시 잰다. 이것은 다음 Build(B0b — 여러 파일 빌드)에서 다루기로 했다 — **이번 판정에는 "고치면 좋음" 이하로 두되**, 학교 교실(학생 30명이 같은 때에 여는 경우)에서 어떤 영향이 있을지 의견을 적는다.
9. **코드**: 엔진 선택 값 `intro`가 없는 게임(예시 게임, 템플릿, 시험 페이지)의 경로가 바뀌지 않았는지(코드로), `h()`만·`innerHTML` 없음·이모지 없음, 디자인 토큰 밖의 색(하늘색)의 까닭, `docs/engine.md` 설명이 코드와 맞는지.
10. **느린 기기 검사**: 새로 만들거나 고친 검사를 CPU 4·8·12배로 돌려 값 실패 0, 움직임이 계속되는 화면에서 배치를 어떻게 재는지(움직임 줄이기로 연 화면에서 재는지).
11. **새로 생긴 문제**, 사용자가 정해야 할 것(선택지와 추천).
