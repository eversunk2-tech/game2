# Build 서브에이전트 지침: F2 쌓기나무 판 돌리기 조금 느리게 · 자유 쌓기 판에 원근 (트랙 "blocks")

## 역할

너는 **Build** 담당이다. 사용자의 수정 요청 둘을 만든다. 검증은 별도 Review 서브에이전트가 한다.

사용자의 말(2026-10-23, [spec-grade6.md](spec-grade6.md) 15-27 — 그대로 옮김): "쌓기나무 자유쌓기 수정 요청이야. 1. 쌓기나무 판 돌리는 빠르기 약간만 더 느리게 수정 2.자유쌓기 바탕 판이 캡쳐화면과 같이 각도에 따라 정사각형 판이 좀 찌그러진 모양이 됨. 모양이 좀더 정확하도록 수정". 사용자가 보낸 그림: scratchpad `user-f2-skew.png`(경로는 프롬프트로).

## 만들 것

1. **판 돌리기 약 20% 느리게 — 모든 쌓기나무 판**(1~5차시·도전·자유 쌓기): 끌기 1px = 0.5° → **0.4°**(가로·세로 같이). `orbit.js`의 `DRAG_DEG`는 **5학년·6학년 전개도 입체도 쓰므로 바꾸지 않는다** — 쌓기나무 쪽(`turn-view.js`)에 따로 값을 둔다. 버튼의 판 45°·높이 15° 눈금, 8px 문턱, 크게·작게, 처음 보기·[위][앞][옆] 자세는 그대로. 키보드 방향키 한 번의 각도도 끌기와 같은 비율로 줄일지는 지금 값을 보고 정해 보고(바꾸면 까닭).
2. **자유 쌓기 판에만 원근**: 먼 쪽이 작아 보이게 그린다(사용자 그림의 자세 — 판 돌림 약 16°·높이 약 27.5° — 에서 정사각형 판이 바른 정사각형으로 읽히게). **1~5차시·도전의 판(3×3)은 원근 없이 지금 그대로** — 그 화면은 픽셀까지 같아야 한다.
   - 원근이 들어가도 그대로여야 하는 것: 판 가운데를 중심으로 도는 돌림판식, 수평~바로 위, 처음 크기 꽉 차게(14×14·휴대폰 6×6 모두), 크게·작게, 판 옮기기(옆으로 옮겨 보기 — 결정 9), 칸 누르기·쌓기·빼기의 정확도(누른 칸 = 쌓이는 칸 — 원근에서도 화면 좌표로 거꾸로 셈), 세로 모서리(원근으로 기울어 보이는 정도를 재서 보고), 쌓기나무의 앞뒤 가림(그리는 차례가 원근에서도 맞는지 — 높은 탑·바둑판 10층에서), 층별로 벌려 보기, 위에서 본 판·위앞옆 모양(2D 그림은 그대로), 저장.
   - [위] 자세(바로 위)에서 원근이 있으면 높은 탑의 옆면이 보인다. 이것을 그대로 둘지, 바로 위·정면 자세에서는 원근을 줄일지 시안에 함께 보이고 "사용자 결정 필요"로 올린다(추천을 붙여).
   - 그리는 속도: 가장 나쁜 꼴(판 전체 바둑판 10층)을 CPU 1·4·6배로 재서 F1 값(6배에서 34ms 넘는 프레임 6개)보다 나빠지지 않게.

## 차례 — 화면은 시안부터

- **차례 1 = 시안만 만들고 멈춰 보고**: 실제 빌드에 원근을 넣어(코드는 커밋하지 않아도 된다 — 시안용이면 scratchpad에) **지금(원근 없음) + 원근 세기 A(약하게)·B(알지오매스와 비슷하게)·C(강하게)**를 같은 쌓기나무·같은 자세로 한 장에 견준다. 자세는 ① 사용자 그림과 같은 자세(돌림 약 16°·높이 약 27.5°, 노란 쌓기나무 3개) ② 처음 보기 ③ [위] 자세(높은 탑 하나 포함) ④ 크롬북 1366×768과 세로 태블릿 820×1180. 세기마다 "먼 쪽 변 ÷ 가까운 쪽 변"과 구석 세로선의 기울기(°)를 적는다. 그림은 scratchpad `build-f2/shots/`. 보고(10줄 이하)하고 **멈춘다** — 코디네이터가 사용자에게 보이고 "계속"을 메시지로 준다.
- 차례 2~: 고른 세기로 완성 → 테스트 → 커밋.

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 1~5차시·도전 화면은 **끌기 빠르기 말고 한 글자·한 픽셀도 달라지지 않는다**(그림 비교 — 기준은 코디네이터가 맞춰 준 `main` 커밋). 5학년·6학년 전개도 입체의 끌기는 그대로(0.5°).
- 판정·점수·저장은 바뀌지 않는다(자유 쌓기는 점수 밖 — 그대로).
- 바뀌는 검사는 뜻이 바뀐 줄만(0.5° → 0.4°, 자유 쌓기의 투영 기대값) — 독립 계산(기획서 문장으로 짠 원근 투영)으로 고친다. 약해진 검사 0.
- 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) + 960×768 × 보통·글꼴 흉내에서 자유 쌓기 배치(스크롤·넘침·겹침 0, 위에서 본 판 펼침·옮기기 포함)가 F1과 같게.
- 브라우저 검사는 처음부터 느린 기기를 견디게, `waitForTimeout`·`retries` 금지. 끝내기 전에 CPU 4·8·12배로 새로 만들거나 고친 검사 값 실패 0.
- 테스트: `npm test`, `E2E_PORT=5352 npm run test:e2e -- --workers=4`, `E2E_PORT=5352 E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0.
