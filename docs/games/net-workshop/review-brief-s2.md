# Review 서브에이전트 지침: S2 쌓기나무 3·4차시 (트랙 "blocks")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-s2.md](build-brief-s2.md)에 따라 만든 두 차시와 S1에서 넘어온 다섯 가지를 **독립적으로** 검증한다. Build와 분리된 검토자다.
- **검토 결과는 새 파일 `docs/games/net-workshop/review-blocks-s2.md`에 쓴다**(트랙의 작업 폴더 안). 맨 위에 판정 줄, 그 아래 `review-blocks.md`와 같은 형식의 표.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지.
- **트랙의 작업 폴더에서만** 일한다(코디네이터가 프롬프트로 알려 준다). 검증 파일·스크린샷·기준 빌드는 정해 준 scratchpad 폴더에만. Build의 scratchpad는 근거로 삼지 않는다.

## 검토 대상

기준 커밋 `4e7b216`(사이트에 올라간 것)과 트랙 브랜치의 마지막 커밋 사이의 변경 전부. 커밋 안 된 것이 있으면 그것도 보고 그 사실을 적는다. 고쳐도 되는 파일은 build-brief-s2.md의 목록이다 — **전개도 공통 부품·`cuboid-*`·`game.json`·`cover.svg`·`scripts/**`가 바뀌었거나 `main.js`의 놀이 방법 글을 고쳤으면 범위 위반**이다. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 실행. `git diff 4e7b216..HEAD -- tests/`로 지워지거나 약해진 검사가 없는지(뜻이 바뀐 검사는 새 뜻을 고정하는지).
2. **수학·판정 (가장 중요)**: 저장소 코드를 쓰지 않는 **독립 계산**으로 3×3칸·3층 262,144개에서 위·앞·옆에서 본 모양 → `maxFill`·`minCount`, "세 그림에 맞는 쌓기가 하나로 정해지는가", 위에서 본 모양의 수 쓰기 정답, 모눈 칠하기 판정(좌우 뒤집힌 그림을 어떻게 판정하는지 포함)을 견준다. 계획의 수치와 견준다. 문제 만들기가 시드로 재현되는지, 각 단계 문항의 정답·보기·까닭 문장·오개념 tag가 맞는지(시드 수백 개).
3. **교과서 활동과 잇기**: 두 차시 여섯 단계가 2-4절 표·1-2절 흐름과 맞는지, 용어가 1-4절 표와 같은지, 교과서의 문장·그림·문제 수치를 옮기지 않았는지.
4. **조작**: 모눈 칠하기·수 쓰기·쌓기를 **마우스·터치·키보드·버튼** 각각으로 두 차시 끝까지. 누르기와 끌기 가르기(잘못 칠함·잘못 돌아감 0), 누르는 곳 48px, 수 올리고 내리기의 한계(0~3), 되돌리기·모두 지우기.
5. **답하기 전 정답 노출 0**: 답하기 전 화면의 글자·속성·클래스·SVG 순서와 좌표·알림·화면 틀에 답이 없는지, 돌려 보면 답이 보이는 문항은 답하기 전에 돌릴 수 없는지(끌기·휠·키·버튼·[위][앞][옆]), 보기형 문항은 **정답 자리와 값의 꼴** 모두 답과 엮이지 않는지(값만 보는 규칙들 — 가장 큰/작은/가운데, 이어진 수 묶음, 큰 간격의 어느 쪽, "가장 큰 수 − 3 이상 가운데 가장 작은 것" — 로 맞히는 비율, 시드 1,000개 이상).
6. **별·점수**: 15-3의 기준대로 틀린 횟수 기준을 쓴 단계가 맞는지(한 번만 틀려도 정답률로 바로 ★1이 되는 단계인지 직접 계산), 모든 답 순서에서 ★1·★2·★3, 안내 문장. 기획서 문장과 engine.md 점수 표만 보고 짠 독립 계산 ↔ 엔진(무작위 여러 판, 나가기·새로 고침), 일부러 틀려 이득 0, 같은 틀린 답 거듭 내기는 한 번만, 화면 = 저장.
7. **S1에서 넘어온 다섯 가지**: S1b-1(값의 꼴 — 위 5번), S1b-8(큰 수를 고르면 tag·까닭), S1b-4(1366×768 글꼴 흉내 + 글자 110%의 넘침 — 지난 값 20px), S1b-3(폭 901~1000px 세로 스크롤 — 지난 값 960×768 확인 뒤 189px), S1c-1(시간 예산 360초). 지난 값 → 지금 값.
8. **교실 기기·접근성**: 세 크기 세로·가로 스크롤 0, 판 넘침 0·잘린 버튼 0(모든 장면), 머리·매트 움직임 0, 1024×768, 휴대폰 배치, 키보드만으로 두 차시, 색만으로 구분하지 않음(칠한 칸·안 칠한 칸), 대비, 움직임 줄이기·`?fx=low`, 화면 읽기 이름·알림(칠한 칸, 쓴 수). 네 크기 + 1024×768 스크린샷을 직접 연다(모눈·수 판이 또렷한지, 까닭 그림이 읽히는지). 글꼴 흉내에서 세로 여유가 빠듯한 장면 목록.
9. **이미 있는 차시 불변**: 기준 `4e7b216` 빌드와 견줘 정육면체·직육면체 차시, 쌓기나무 1·2차시의 화면·점수·기록 차이 0(위 표에서 고친 것 말고 — 고친 것은 무엇이 어떻게 달라졌는지).
10. **느린 기기**: scratchpad 복사본에 CPU 느리게 하기(4·8·12배)를 넣어 쌓기나무 검사 파일 전부를 돌려 값 실패 0, 새 검사가 `calm` 뒤에 재는지, 알림은 띄운 조작 바로 뒤에, 잠깐 보이는 상태는 머문 시간까지, 시간 예산.
11. **화면 문장·디자인·코드**: 해요체, 토큰·아이콘, `h()`만, 이모지 없음, 죽은 코드, 순수 함수와 화면의 나눔, 나간 뒤 리스너·타이머·rAF 0, 콘솔 오류 0.
12. **합칠 때**: 영역 화면 트랙(`track/b0`)·작은 수정 트랙(`track/c1`)의 지금 커밋과 `git merge-tree --write-tree`로 줄 충돌(특히 `main.js`), 합친 나무에서 쌓기나무 검사 가운데 처음 화면을 거쳐 가서 깨지는 것.
13. **차시 시간**: Build의 어림과 문항당 어림을 견준 의견. **새로 생긴 문제**, 사용자가 정해야 할 것(선택지와 추천).
