# Build 서브에이전트 지침: 이미 있던 검사의 흔들리는 곳 2건 + 긴 검사의 시간 예산 (트랙 "c1"의 후속 "c2")

## 역할

너는 트랙 c1의 **Build** 담당이다. c1은 Review를 통과해 `main`에 올라갔다(`d6371ad`). 그 Review가 **`main`에 이미 있던 검사**에서 느린 기기에서 흔들리는 곳 2건과 시간 제한이 빠듯한 검사를 찾았다(작업 폴더의 `docs/games/net-workshop/review-c1.md` 6절·8절). 이번에는 그것을 고친다. 검증은 별도 Review 서브에이전트가 한다. 앱 코드는 고치지 않는다.

## 기준

- `review-c1.md` 6절("느린 기기에서만 실패하는 다른 검사")과 8절 문제 표의 1·2, 참고 3
- [common-rules.md](common-rules.md) 8절 "움직임이 끝난 뒤에 잰다"(`main` 체크아웃의 것이 최신이다)

## 직접 확인할 것

- scratchpad에 푼 복사본의 검사 파일 맨 위에 CPU 느리게 하기(`Emulation.setCPUThrottlingRate`)를 넣어 —
  - 고치기 **전**(`d6371ad`): C2-1·C2-2의 실패가 재현되는지(16배 `--repeat-each=10`, 그리고 Review가 쓴 "재는 때를 40ms 늦추기").
  - 고친 **뒤**: 그 검사들이 4·8·16배 × `--repeat-each=10`에서 실패 0인지. 그리고 **전체 브라우저 검사를 4·8배로 한 번씩** 돌려 값이 어긋나는 실패 0인지(시간 제한만 넘긴 것은 따로 표시).
  - 저장소의 검사 파일에는 재현용 코드를 남기지 않는다.
- 고친 검사가 여전히 앱의 회귀를 잡는지: 복사본의 스타일을 일부러 망가뜨려(조작판 버튼을 44px로, 알림을 조작 버튼 위에 뜨게) 그 검사가 실패하는지.
- `npm test`, `npm run test:e2e -- --workers=3`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=3` 모두 실패 0(마지막 커밋에서 처음부터). 다른 일꾼 둘이 같은 때에 브라우저 테스트를 돌린다 — 그 상태 그대로에서 실패 0이어야 하고, 실패하면 부하 탓으로 넘기지 말고 원인을 본다.
- 빌드 결과물(`dist/*.html` 세 파일)의 해시가 고치기 전과 같다(검사 파일만 바뀐다).

## 덧붙임 (2026-10-13): 느린 기기에서 실패하는 정육면체 검사 더

직육면체 트랙의 재검토(`review-cuboid.md` M2b-4)가 `main`에 이미 있는 정육면체 검사 가운데 느린 기기(CPU 4·8·12배)에서 실패하는 것을 더 찾았다. C2-4에 넣어 함께 고친다. 모두 `tests/e2e/net-workshop.spec.js`이고 **검사 이름으로 찾는다**(줄 번호는 가지마다 어긋난다).

1. "주사위 주문 배치(네 크기)" — C2-2와 같은 것(4·8·12배 모두에서 실패)
2. "자유 배치: 알림이 조작(칸·카드·접어 보기·접기 도구·다음 버튼)을 가리지 않는다"
3. "도감 주문 배치(네 크기)"
4. "자유 배치: 칸을 눌러 십자 → [접어 보기] → 접혀 도감에 …"(`.toast-correct`를 읽는 곳)
5. "주사위 주문 보기 조작·정리"
6. "답하기 전 힌트(반만 접어 보기) …"

- 그 Review의 진단(확인 대상): 1~4는 알림이 스스로 사라진 뒤에 `.toast`를 읽는다(도우미 `expectToastClear`). 5·6은 원인을 적지 않았다 — 느리게 하기로 재현해 원인을 밝힌다.
- 고치는 법: 알림은 띄운 조작 바로 뒤에 "보임"과 "자리 읽기"를 한 번의 `evaluate`로 묶어 잰다(**알림이 없으면 통과가 아니라 실패**). 잠깐만 보이는 상태(움직임 줄이기에서 550ms만 보이는 `data-fold="half"` 등)를 단언하는 곳은 "움직임 줄이기 › 접기 애니메이션 대신 …" 검사처럼 `MutationObserver`로 지나간 값을 적어 두고 본다.
- 최종 보고에 이 여섯 검사의 고치기 전·후 배수별 결과(4·8·12배 × `--repeat-each=5` 이상)와 5·6의 원인을 더한다.
