# Review 서브에이전트 지침: G1 각기둥 1 — 검토 반영 확인 (G1b)

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-fix-brief-g1b.md](build-fix-brief-g1b.md)에 따라 고친 것을 **독립적으로** 확인하고, 지난 검토에서 통과한 것이 깨지지 않았는지 본다. Build와 분리된 검토자다.
- 트랙 작업 폴더의 `docs/games/net-workshop/review-prism-g1.md` **한 파일만** 고친다: 맨 아래에 `## 재검토 (G1b 수정 확인)` 절을 덧붙이고 맨 위 판정·검토일 줄을 고친다. 앞 내용은 지우지 않는다. 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다. 작업 폴더에서만, 검증 파일은 정해 준 scratchpad에만(지난 검토의 스크립트 `review-g1/`를 같은 방법으로 다시 돌려 지난 값과 나란히). Build의 scratchpad는 근거로 삼지 않는다.

## 기준

review-prism-g1.md의 문제 표(G1-1~G1-7·참고)와 지난 측정값, [spec-grade6.md](spec-grade6.md) **15-20**(사용자 결정 셋), [build-fix-brief-g1b.md](build-fix-brief-g1b.md), [common-rules.md](common-rules.md).

## 확인할 것

1. **G1-1 (가장 중요)**: 태블릿·휴대폰 터치로 면 안쪽 점을 지난번과 같은 방법·수(태블릿 144번 등)로 눌러 이웃 면이 골라지는 일 0, 면 가장자리 가까이·작은 면·돌린 자세도. 마우스·키보드 그대로, 누르기·끌기 가르기 8px 그대로.
2. **G1-2**: 독립 계산 두 방법(대칭 궤도 수, 허용 오차 합동)으로 모든 밑면의 서로 다른 전개도 수와 열쇠 수가 같은지(세 변이 다른 삼각기둥 42, 정삼각기둥 9, 직육면체 54·29, 정육면체 11 등), 합동인 두 전개도의 열쇠가 같고 다른 것은 다른지.
3. **G1-3·G1-6**: 밑면 고르기의 면에 들어가는 원 지름을 지난번과 같은 방법으로 다시 재고(크롬북·680·태블릿·휴대폰), 입체가 무대 밖으로 나가지 않는지, ✓·✗ 표시 크기.
4. **G1-4·G1-5**: 꼴만 보는 규칙들이 맞히는 비율(판별), 바로 옆 선분이 정답인 문항의 비율과 오개념 보기가 남는지(선분) — 시드 2,000개 이상으로 직접. 정답 노출 0 그대로.
5. **G1-7·참고**: 고쳤으면 확인, 못 했으면 그대로인지.
6. **깨지지 않았는가(지난 스크립트로 다시)**: 판정·까닭 칩·선분 독립 계산, 점수 = 독립 계산(64점), 정답 노출(답하기 전 한 가지 모습·잠금), 여섯 크기 × 두 모드 배치, 키보드만으로 세 단계, 접기 프레임 CPU 1·4·8배, 이름표, 정육면체·직육면체·쌓기나무 불변, 엔진 0줄.
7. **테스트**: `npm test`, `E2E_PORT=<네 포트> npm run test:e2e -- --workers=4`, 글꼴 흉내 같은 방법 — 실패 0. `git diff <지난 검토 대상 커밋>..HEAD -- tests/`로 약해진 검사 0. 새·고친 검사 CPU 4·8·12배.
8. **합칠 때**: `git merge-tree --write-tree`로 `track/blocks`(S3 — 지금 커밋)·`main`과 충돌, 합친 결과에서 단위·영역·도장 e2e.
9. 새로 생긴 문제, 사용자가 정해야 할 것.

## 형식과 끝나면

덧붙이는 절: 판정 줄, 테스트 결과 표, 항목별 결과 표(번호 · 지난 값 → 지금 값 · 고쳐짐/남음), 깨지지 않았는지의 표, 발견한 문제 표, 확인하지 못한 것. 최종 답변 **10줄 이하**. 직접 잰 것과 추정을 구분한다.
