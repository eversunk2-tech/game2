# Build 서브에이전트 지침: M3 직육면체 탐구 넓히기 — 검토 반영 (트랙 "cuboid", M3b)

## 역할

너는 M3를 만든 **Build** 담당이다. 네 작업 폴더의 `docs/games/net-workshop/review-m3.md`(Review가 쓴 검토 결과)와 사용자 결정([spec.md](spec.md) **16-17**)을 반영한다. 판정은 **"수정 필요 — 반드시 수정 1건"**(M3-1)이었고, 수학·판정·표준 이름(독립 계산), 점수(탭 하나·두 개), 64가지 크기 배치, 손잡이(세 수단), 불변, 느린 기기는 통과했다 — 그대로 둔다. 검증은 별도 Review 서브에이전트가 다시 한다.

## 사용자 결정 (2026-10-17, spec.md 16-17 — 모두 추천안)

1. **"직육면체 도감 완성" 도장을 도장판에 넣는다**(12칸 → 13칸). 네가 만들어 둔 `CUBOID_BADGES`의 정의를 등록하고, 도장 수를 세는 검사 두 줄(`tests/e2e/net-workshop.spec.js:2166`의 12, `tests/e2e/net-workshop-areas.spec.js:327`의 "도장 2 / 12")을 13으로 고친다. 54가지를 다 찾은 저장 값으로 그 도장이 찍히는지 검사.
2. **도감 주문의 [오늘은 여기까지]는 하나라도 접었으면 언제든**(지금대로). 다만 10가지 전에 끝냈을 때 결과 제목 "도전 성공!"과 도장 "다시 해 봐요"가 함께 나오는 어색함을 고친다(M3-4 — 코디네이터 결정): 별이 0개면 **"오늘은 여기까지!"류의 제목과 "다음에 또 찾아요"류의 글**(해요체, 정확한 글은 네가 정해 보고)로, 별이 1개 이상이면 지금처럼. 엔진에 작은 선택 값이 필요하면 최소로 더하고 줄 번호와 함께 보고(그 값을 쓰지 않는 게임·단계는 한 글자도 달라지지 않게). 점수는 지금대로(별이 있을 때만 도전 성공 +10).
3. **직육면체 영역의 놀이 방법에 도감 주문 한 줄**(해요체 — 예: "도전 주문서에서 직육면체 전개도 54가지 도감을 채워 봐요."). 그 줄이 없어야 한다고 보던 `tests/e2e/net-workshop-areas.spec.js:410·441`을 새 뜻으로 고친다.
4. **큰 상자의 판 칸 48px 예외**: 1~4 cm를 모두 고를 수 있게 그대로 두고, 큰 상자에서 1 cm 칸이 48px보다 작아지는 것을 받아들인다(M3-2). `net-workshop-cuboid.spec.js:1227`의 "1 cm 칸 48px 이상" 검사는 **처음 상자(1·2·3 cm)와 48px을 지킬 수 있는 크기에 대해서는 그대로** 두고, 큰 상자에 대해서는 "면 카드·버튼·손잡이는 48px 이상, 칸은 정해 둔 아래 한계(예: 24px) 이상"으로 새 뜻을 고정한다. 이유를 보고.

## 반드시 지킬 것

- 통과한 것을 깨지 않는다: 판정·가짓수·표준 이름 독립 계산 어긋남 0, 점수 = 독립 계산(크기를 섞어, 탭 두 개, 나가기), 64가지 크기 × 세 크기 배치, 손잡이(누르기·끌기와 헷갈림 0), 정육면체 차시·직육면체 1~3단계·쌓기나무·영역 화면·예시 게임 불변, 옛 저장 값, 처음 상자로만 하는 판의 점수·기록.
- **다른 트랙이 같은 때에 `tests/e2e/net-workshop-areas.spec.js`·`net-workshop.spec.js`·`net-workshop-blocks.spec.js`의 "처음 화면을 거쳐 가는 줄"(길 찾기)을 고친다(게임 인트로 B0c).** 너는 위에 적은 **기대값 줄(도장 수, 놀이 방법)만** 고친다 — 길 찾기 줄은 건드리지 않는다.
- 엔진(`src/shared/**`)은 결정 2에 필요한 만큼만, 줄 번호와 함께 보고.
- 브라우저 검사는 느린 기기를 견디게(움직임이 끝난 뒤, 사라지는 알림은 조작 바로 뒤, 머무는 시간, 시간 예산), `waitForTimeout`·`retries` 금지. 끝내기 전에 CPU 느리게 하기 4·8·12배로 이 트랙 검사 값 실패 0.
- 테스트: `npm test`, `npm run test:e2e -- --workers=4`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`. 알려진 실패(쌓기나무 "단계 지도: 쌓기나무 네 차시가…" — 지금 `main`에서는 두 기기 실패, B0c가 고친다)는 보고만 하고, 그 밖은 실패 0.
