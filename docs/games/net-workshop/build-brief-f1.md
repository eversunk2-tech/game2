# Build 서브에이전트 지침: F1 쌓기나무 "자유 쌓기" (트랙 "blocks")

## 역할

너는 쌓기나무 영역의 **Build** 담당이다. 사용자의 수정 요청([spec-grade6.md](spec-grade6.md) **15-18·15-19**)의 둘째 — 넓은 판에 쌓기나무를 마음대로 쌓으며 혼자 탐구하는 **"자유 쌓기"**를 만든다. 계획은 [plan-rotate-free.md](plan-rotate-free.md) **5절·6절(F1)**. 돌림판식 돌리기(R1)는 이미 `main`에 합쳐졌다 — 그것을 그대로 쓴다. 검증은 별도 Review 서브에이전트가 한다.

사용자의 말: "알지오매스처럼 넓은 받침 판에 쌓기나무를 자유롭게 쌓아보면서 혼자 탐구해볼 수 있는 공간이 추가되면 좋겠어. <자유 쌓기>라고 이름 붙여서 1차시 위쪽에 넣어줘"

## 사용자 결정 (15-19 — 그대로 따른다)

1. 돌기의 중심 = 판 가운데, 위아래 = 수평 ~ 바로 위(R1의 돌림판식 그대로).
2. 자리 = 쌓기나무 영역 단계 지도의 **1차시 위에 넓은 카드 한 장** — 차시 번호·별·잠금·"여기부터!" 없음, "모은 별"·"차시 n개"·도장에 들어가지 않음. 차시 번호는 교과서 그대로(1~5차시). `?lesson=…` 한 차시 주소에는 보이지 않고, `?stage=blocks-free`(이름은 네가 정함)로 바로 열림.
3. 판 = **크롬북·태블릿 14×14칸·10층**(알지오매스와 같은 넓이), **휴대폰 6×6칸·6층**(화면의 짧은 변 600px 미만 — 들어갈 때 한 번 정함). 처음 크기 = **판이 꽉 차게**(처음 보기에서 판과 3층 높이가 무대를 채움 — 크롬북 쌓기나무 한 변 약 34~36px, 계획 시안 기준), [작게 보기]로 전체.
4. 저장 = **이 기기에 하나 자동 저장**(판 크기마다 열쇠 하나 — 쌓기나무 높이 + 색), 다시 들어오면 이어서, [모두 치우기]로 새로. 점수·별·도장·학습 기록 없음.
5. 기능 = 쌓기·빼기·되돌리기·모두 치우기·돌리기·[위][앞][옆]·처음 보기·크게/작게·개수·층별로 벌려 보기(층마다 개수) + **색 고르기**(5가지) + **위·앞·옆에서 본 모양(평면 그림) 켜고 끄기**.
6. **화면 배치(사용자 요청 — 14×14 시안을 보고)**: "오른쪽의 패널을 작게 만들면 쌓기나무 보드를 더 크게 화면에 나타나게 할수 있지 않아? <쌓기, 빼기, 왼쪽 앞 보기 등>을 세로로 한줄로 나타나게 하고, 넓은 보드판은 처음엔 보이지 않다가 그것을 선택하면 앞에서 본 모습의 보드판이 펼쳐지는 것과 같은 방식으로 해줘" → 오른쪽은 버튼을 **세로 한 줄**로 세운 **좁은 띠**, "위에서 본 판"(칸마다 수 — 14×14는 네 쪽 7×7로 나눔, 48px 칸)은 **처음에는 숨김** → 쪽 버튼(왼쪽 앞·오른쪽 앞·왼쪽 뒤·오른쪽 뒤)을 누르면 그 쪽이 **앞쪽이 아래로 오게 놓인 모습으로 펼쳐지고**, 다시 누르면 접힘. 남는 자리는 모두 무대에 — 쌓기나무가 시안보다 커진다(잰다). 휴대폰처럼 좁은 화면에서 세로 띠를 판 아래 가로 줄로 바꿔야 하면 그렇게 하고 보고.

## 일하는 차례

1. **먼저 배치 시안만**(실제 코드 위에 만들어도 되고 scratchpad 시제품이어도 됨): 1366×768·1366×680·1024×768·820×1180·390×844에서 처음 화면, 위에서 본 판 한 쪽을 펼친 화면, 층별로 벌려 본 화면 — 스크린샷과 쌓기나무 한 변 px. **여기서 멈추고 보고**한다(코디네이터가 사용자에게 보여 확인받는다). 코디네이터가 메시지로 "계속"을 주면 2부터.
2. 엔진: 자유 카드(영역 단계 지도 맨 위, 진도·별·도장에서 빼기), `docs/engine.md`. 이 선택을 쓰지 않는 게임·영역은 한 글자도 그대로.
3. 게임: 계획 6절 F1 줄의 파일들(새 `blocks/play-free-build.js` 등) — 판 크기를 무대마다, 처음 보기 맞춤, 쌓기나무마다 색, 10층 벌려 보기, N×N 판·네 쪽 나누기·펼치기/접기, 저장. 늦게 불러오는 쌓기나무 묶음에 넣는다(처음 화면이 받는 크기는 거의 그대로).
4. 놀이 방법에 자유 쌓기 한 줄.

## 함께 고칠 것 (작게)

- **R1-1**(review-blocks-r1.md, 고치면 좋음): 5차시 "층별 모양만 보고 알아내기"의 개수 보기에서 값의 크기만 보고 "10에 가장 가까운 보기"를 고르면 52 → 56%(찍기 25%), 2차시 "모두 몇 개일까?"도 52.7%. 보기 값만으로 맞히는 길을 줄인다(정답 값의 범위와 보기 값의 분포가 엮이지 않게). `blocks-logic.js:1581`의 주석도 사실대로. 시드 2,000개 이상으로 꼴·값 규칙 여러 개의 비율을 전·후 보고.

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 키보드·터치만으로 모든 칸에 쌓을 수 있음(위에서 본 판 48px — 펼친 상태), 색만으로 구분하지 않음(색 고르기는 색 이름도), 움직임 줄이기·`?fx=low`, 화면 읽기("2줄 3칸에 쌓았어요. 모두 17개").
- 그리는 속도: 계획 5-2의 장면들(판의 절반을 3층, 바둑판 6·10층)을 CPU 1·4·6배로 다시 재서 보고 — 가장 나쁜 꼴에서 끄는 손을 늦게 따라가면 끄는 동안 면 수를 줄이는 등의 방법을 써도 된다(보고).
- **불변**: 쌓기나무 1~5차시·도전, 정육면체·직육면체·각기둥, 인트로·학년·영역 화면(쌓기나무 영역 지도에 자유 카드가 더해지는 것 말고), 저장 값이 기준(`main`) 빌드와 같다.
- 브라우저 검사는 느린 기기를 견디게, `waitForTimeout`·`retries` 금지. 끝내기 전에 CPU 4·8·12배로 새로 만들거나 고친 검사 값 실패 0.
- 테스트: `npm test`, `E2E_PORT=5352 npm run test:e2e -- --workers=4`, `E2E_PORT=5352 E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0.
