# Build 서브에이전트 지침: N2 검토 반영 + CI 실패 2건 (N2-1 · N2-3 · 터치 뒤 누르기)

## 역할

너는 N2를 만든 **Build** 담당이다. N2는 Review를 통과해 `main`(`673f871`)에 올라갔고 사이트에 배포됐다. 그런데 **GitHub 자동 테스트(리눅스)가 2건 실패**했다(188 통과). 그 2건과 [review.md](review.md) "N2 검토"의 N2-1·N2-3을 고친다. 판정(`fold.js` 결과)·점수 규칙은 바꾸지 않는다(N2-3의 별 계산 말고). 검증은 별도 Review 서브에이전트가 다시 한다.

## 리눅스 CI에서 또 깨지지 않게 (이번에 함께)

지금까지 세 번, 로컬(macOS)에서 통과한 e2e가 CI(리눅스)에서 글자 폭 차이로 실패했다. N2 Review가 **본문에 글자 사이 0.25px를 넣으면 `a137a40`이 실제 CI와 똑같이 3건만 실패한다**는 것을 확인했다(스크립트·기록: `scratchpad/review-n2/`의 `emu/` 등 — 읽어서 방법을 가져온다).

- e2e를 **"글자 폭 넓힘" 모드**로도 돌릴 수 있게 한다: 환경 변수 하나(예: `E2E_WIDE_TEXT=1`)를 주면 모든 테스트 페이지에 글자 사이를 넓히는 스타일이 들어가게(`tests/e2e/helpers.js`나 `playwright.config.js`에서 — 앱 코드에는 넣지 않는다). 보통 실행은 지금과 한 글자도 다르지 않아야 한다.
- 이번 수정의 "끝났다의 기준"에 **넓힘 모드에서도 실패 0**을 넣는다. 넓힘 값은 Review가 맞춘 0.25px을 기본으로 하고, 0.5px(약 +4.6%)에서도 돌려 실패하는 검사가 있으면 목록으로 보고한다(이번에 다 고치지 않아도 되지만 CI-1은 0.5px에서도 통과해야 한다).
- 실제 리눅스 통과는 코디네이터가 `main`에 올린 뒤 CI로 확인한다. 보고에 "CI에서 확인 필요"라고 적는다.

## 반드시 지킬 것

- 머리(엔진) 배치를 바꾸므로 **모든 단계와 예시 게임의 화면이 달라질 수 있다**: 네 크기에서 머리·매트·판의 자리가 `673f871`과 어떻게 달라졌는지 재서 보고하고(달라진 곳은 의도한 것만), 세 크기 세로·가로 스크롤 0, 자유 배치 판 안쪽 넘침 0, 판 → 무대 어긋남 0px(연속 칸이 생기는 순간 포함), 48px, 알림 자리, 답하기 전 화면 불변 검사(조작 띠 = V1 이전)가 그대로 통과해야 한다. 예시 게임 e2e(`sample-divisor-sort.spec.js`·`smoke.spec.js`)는 고치지 않고 통과.
- 지금 통과하는 것을 깨지 않는다: 예상 관련 말 0, 까닭 고르는 중 노출 0, 주사위 접기 전 노출 0, 점수 독립 계산 일치, 도감 이어 하기, 끄는 면 보이기, 보기 조작.
- 기존 검사를 약하게 만들지 않는다. 바꾼 검사는 이유를 보고한다.
