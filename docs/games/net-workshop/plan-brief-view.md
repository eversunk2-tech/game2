## 17절에 반드시 담을 내용

1. **무엇을 만드는가** — 한 문단. 학생이 접은 입체를 여러 방향(위·아래·옆·뒤)에서 보고 크게·작게 볼 수 있게 한다. 이것이 어떤 학습(마주 보는 면 찾기, 겹침·빈 자리 확인, 까닭 설명)에 도움이 되는지.
2. **조작 표** — 돌리기(가로·세로)와 확대·축소를 마우스 / 터치 / 키보드 / 화면 버튼으로 각각 어떻게 하는지. 후보를 견주어 추천한다: 무대 끌기(한 손가락·마우스), 두 손가락 벌리기(핀치), 마우스 휠, 버튼([+][−][처음 보기로] 등, 48px 이상), 방향키 ←→↑↓, `+`·`−`·`0`. 다음 충돌을 하나씩 따져 적는다.
   - 무대 위의 다른 조작과 겹침: 마주 보는 면 단계의 **면 누르기**, 면 붙이기 단계의 **빈 자리 누르기·면 카드 끌어 놓기**(`enableDragDrop`), 접기 막대. 끌기와 누르기를 어떻게 가르는가(움직인 거리 기준 등).
   - 브라우저 기본 동작: 태블릿 화면 스크롤·브라우저 확대(핀치), 마우스 휠 페이지 스크롤, 크롬북 터치패드 두 손가락. `touch-action` 등으로 어디까지 막는가. 휠을 쓸지(무대 위에서만? 아예 안 씀?).
   - 키보드: 방향키가 이미 쓰이는 곳(접기 막대 `<input type="range">`, 자유 배치 판)과의 관계, 초점이 어디 있을 때 동작하는가.
3. **범위와 한계 값** — 어느 단계의 무대에 적용하는가(네 단계 모두 같은 무대이므로 공통이 기본), 펼친 상태·접는 중·다 접힌 뒤 가운데 언제 되는가. 세로 기울기 범위(뒤집혀 헷갈리지 않게 위·아래 한계를 둘지, 밑면까지 볼 수 있어야 하는지), 확대 최소·최대, 확대했을 때 입체가 무대 밖 조작(버튼·쪽지·판)을 가리지 않게 자르는 방법, [처음 보기로] 되돌리기, 문제가 바뀌거나 [펴기]를 누르면 보기가 어떻게 되는가.
4. **정답 노출 검토 (중요)** — 답하기 전에 돌리거나 확대해서 정답이 드러나는 길이 없는지 단계마다 따진다(판별: 펼친 상태, 마주 보는 면: 접기 전·후, 면 붙이기: 빈 자리, 자유 배치: 예상 전 판·까닭 고르기 중). 지난 검토에서 "펼친 상태의 회전·그늘이 문항과 무관하게 같다"가 확인돼 있다 — 기울기를 바꿀 수 있게 되면 그 성질이 유지되는지, 답하기 전에는 잠그거나 처음 보기로 고정할지 정한다.
5. **기존 기능과의 맞춤** — 빛 계산(면 밝기)이 기울기·돌림을 따라가는가, "돌려 보면 빈 자리가 보여요" 안내의 조건, 2×2로 막힌 모양의 보기, 자유 배치 판 → 무대 이어 접기(어긋남 0px 유지: 접기 시작은 처음 보기에서), 결과 이름표·"✗ 겹쳐요" 글자의 방향과 읽기 쉬움(뒤집히거나 거울상이 되지 않게), 휴대폰 배치와 알림 위치, `prefers-reduced-motion`·`?fx=low`(끌기는 즉시 반응, 자동 움직임만 줄임).
6. **화면 스케치** — 1366×768(실제 높이 약 680)·태블릿 820×1180·휴대폰 390×844에서 새 버튼이 놓일 자리. 지금도 1366×680에서 오른쪽 판과 도구 줄이 빠듯하다(N1c-2) — 스크롤 0·판 안쪽 넘침 0·48px를 지키면서 버튼을 어디에 둘지(무대 모서리에 겹쳐 놓기 등)를 글자 그림으로 그린다. 디자인은 "종이 공방" 토큰·`ui/icons.js` 아이콘(이모지 금지, 새 아이콘이 필요하면 엔진에 추가할 것을 적는다).
7. **보상·기록** — 돌리기·확대에는 점수를 주지 않는다(보상은 학습 행동에만). 이미 있는 살펴보기 횟수(`inspect`)가 무엇을 세는지 확인하고, 새 조작을 거기에 넣을지 의견.
8. **접근성** — 버튼 이름(화면 읽기), 초점 표시, 키보드만으로 모든 방향·확대, 지금 보는 방향을 글로 알릴지(예: "위에서 본 모습").
9. **2~4차 도형** — 직육면체·각기둥·원기둥 차시에도 같은 무대를 쓸 때 그대로 통하는가(도형 크기가 다를 때 확대 한계 등).
10. **파일 구조·엔진 변경** — 바꿀 파일과 까닭. 게임 폴더 안에서 끝나는지, 엔진(`src/shared`)에 넣을 것이 있는지(아이콘, 끌기 도우미).
11. **테스트 계획** — 단위(보기 각도·확대 계산을 순수 함수로 떼어 검사: 한계 값, 처음 보기, 빛 방향), 브라우저(마우스 끌기·휠, 터치 끌기·핀치(CDP), 키보드, 버튼, 네 크기 스크롤 0·넘침 0·48px, 누르기와 끌기가 헷갈리지 않음, 답하기 전 정답 노출 0, 움직임 줄이기).
12. **Build 단계 나누기** — 한 번에 할지 나눌지, 예상 작업량.
13. **사용자에게 확인할 것** — 사용자가 골라야 하는 것만(5개 이하), 각각 선택지 2~3개와 **추천**을 붙인다. 초등 교사가 읽고 고를 수 있게 기술 용어 없이 쓴다. 예: 답하기 전에도 돌려 볼 수 있게 할지, 마우스 휠 확대를 쓸지, 버튼을 어디에 둘지.
