## V1b-1에서 반드시 맞출 것

- **어느 접는 정도에서나 같다**: 접는 정도 1·5·10·20·24·25·30·60·100%에서 — 한 방향으로 750° 넘게 끌어도 걸음마다 같은 각도(1px = 0.5°)로 돌고 튀는 걸음 0, 360°마다 같은 모습, 여덟 방향, 뒤집힌 자세에서도 끄는 방향 = 앞면이 움직이는 방향. 좌우 버튼 12번·위아래 버튼 24번·방향키 24번이면 제자리, 한 번 = 정확히 한 단계. 배율 단계도 같은 값.
- **0을 지날 때**: 막대를 0으로 가져가면 처음 모습(무대 변환이 답하기 전과 같은 `scale3d(1, 1, 1) rotateX(0deg) rotateZ(…)` — 펼친 채 돌린 것만 남음), 다시 올리면 내 자세. 그 사이를 약 0.2초의 움직임으로 잇고, 한 프레임에 크게 튀지 않는다. 막대를 0 근처에서 빠르게 왔다 갔다 하거나, 잇는 움직임 도중에 끌기·버튼·[접어 보기]·[펴기]·다음 문제·나가기가 들어와도 끝 상태가 맞고 남는 타이머·rAF가 없다. 움직임은 `transform`만.
- **[접어 보기]·[펴기] 움직임과 함께**: 내 자세가 있는 채로 [펴기]를 누르면 접힌 입체가 내 자세에서 펴지고 끝에서 처음 모습으로 돌아가는 것이 자연스럽게 보이는가(끊기거나 두 번 튀지 않게). 반대로 [접어 보기]도. 움직임 줄이기(3장면)·`?fx=low`에서는 끝 상태로 바로.
- **깨지면 안 되는 것**: 답하기 전 화면 = `bf86e8c`(넓은 화면·태블릿·폭 561~640 각 144/144, 답하기 전에 새 조작을 해도 그대로), 힌트([반만 접어 보기]) 동안 잠김, 까닭 고르는 중 노출 0(24가지), 자유 배치 판 → 무대 어긋남 0px(처음 접기와 [펴서 고치기] 뒤), 글자 거울상 0, "돌려 보면 빈 자리가 보여요" 안내, 화면 읽기 알림, 멈췄을 때 또렷하게 다시 그리기, 끌기와 누르기 가르기, 벌리기·휠.
- **검사**: 단위 — "t = 0.01·0.05·0.1·0.2에서 한 방향으로 750° 끌어도 걸음마다 같은 각도·튐 없음", "접는 도중 버튼 한 번 = 한 단계", "t > 0이면 배율이 그대로", "t = 0은 처음 모습". 브라우저 — 접는 정도 10%·20%에서 위로 880px 끌기(440°, 튀는 걸음 0), 좌우 버튼 12번 제자리, 0을 지나는 움직임(보통·움직임 줄이기), 0 근처 빠르게 왔다 갔다. 지난 검사 가운데 "25% 미만에서 줄어든다"를 기대하던 것이 있으면 새 결정에 맞게 바꾸고 이유를 보고한다(지우지 않는다).
