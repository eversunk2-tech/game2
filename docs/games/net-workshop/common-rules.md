# 공통 규칙: 정육면체 차시를 만들며 정한 것

> 2026-10-10 정리. 정육면체 차시(판별·마주 보는 면·면 붙이기·내 맘대로 전개도·도전 주문서)를 만들고 고치는 동안 사용자가 정했거나 Review가 찾아낸 것을 한곳에 모았다.
> **직육면체·각기둥·원기둥·쌓기나무를 만드는 모든 Plan·Build·Review 서브에이전트는 이 문서를 먼저 읽고 같은 조건으로 만든다.** 여러 영역을 동시에 만들어도 화면·점수·조작이 한 앱처럼 보이게 하려는 것이다.
> 자세한 까닭은 괄호 안의 출처([spec.md](spec.md) · [spec-grade6.md](spec-grade6.md) · [review.md](review.md) · [docs/engine.md](../../engine.md) · [docs/dev-guide.md](../../dev-guide.md))에 있다. 이 문서와 영역 기획서가 어긋나면 **더 나중에 정한 사용자 결정**이 이긴다 — 어긋남을 발견하면 추측하지 말고 보고한다.

## 1. 단계의 뼈대

| 단계의 종류 | 흐름 | 별 |
| --- | --- | --- |
| **주어진 것을 보고 답하는 단계** (판별, 마주 보는 면, 만나는 선분, 개수, 보기 고르기 …) | 먼저 답한다(예상) → 접거나 돌려서 확인한다 → 까닭을 본다. 답하기 전에는 접을 수도 돌려 볼 수도 없다 | 엔진 기본(정답률 90%↑ ★3, 70%↑ ★2, 틀린 시도도 셈) |
| **직접 만드는 단계** (내 맘대로 전개도, 도감 주문, 전개도 완성하기, 쌓기 …) | **예상 버튼이 없다.** 만들고 확인 버튼 하나([접어 보기]·[확인하기]) → 결과. 안 되면 "왜 안 될까요?" 까닭 고르기(넘어가기 가능) → 표시 | 찾은(완성한) 가지 수. **안 되는 것을 만들어도 별이 깎이지 않는다** (spec 16-12) |

- 직접 만드는 단계의 화면(쪽지·결과)에는 "틀렸다"는 느낌의 말(정답률, 예상과 달랐어요)을 쓰지 않는다. 결과는 "찾은 전개도 n가지 · 접어 본 모양 n가지"처럼 보인다. 학습 기록에는 접은 것 하나가 기록 하나로 남는다(안 되면 오개념 tag) — 선생님이 볼 수 있게.
- 문항 수가 적어 정답률이 어색한 단계(예: 2개만 만드는 주사위 주문)는 **틀린 횟수**로 별을 정한다(0번 ★3 · 1번 ★2 · 그 이상 ★1, spec 16-13).
- 까닭 고르기: 고르기 전에는 무대에 까닭 글자·표시가 없다. 고른 뒤(맞든 틀리든·넘어가도) 표시와 까닭 문장이 나온다(review N1-1).
- 차시 하나는 10분 안팎. 도전 주문서는 차시의 일반 단계를 모두 마치면 열리는 선택 활동이고(`challenge: true`), 시간 재기는 켠 학생에게만 화면에 보인다(기록에는 남는다).

## 2. 답하기 전에 정답이 드러나지 않는다 (가장 자주 잡힌 문제)

- 답하기(접기·확인하기) 전 화면은 **정답과 무관하게 한 가지 모습**이어야 한다: 글자, 무늬, 색, 그늘, 크기, 자리, 클래스, `data-*`·`aria-*` 속성, 숨은 글자, 화면 읽기 알림까지. e2e로 "문항이 달라도 답하기 전 화면이 같다"를 고정한다.
- **크기나 자리가 답과 엮여도 노출이다.** 조작판을 피하려고 넓은 전개도만 작게 그렸더니 "작게 나온 문제는 안 돼요"가 77~94% 맞았다(review V1-1). 문항에 따라 화면 배치를 바꾸지 않는다.
- 접기 전에 막는 안내("떨어진 면이 있어요", "이미 만든 모양이에요")가 답을 알려 주지 않게 한다. 막는 조건은 학생이 이미 본 것(접어 본 것)뿐이어야 한다.
- 안내 문장·버튼 이름에 까닭 낱말이 섞이지 않게 한다(review N2: "모여"가 접기 안내에 들어 있었다).
- 돌려 보면 답이 보이는 문항은 답하기 전에 돌리기를 잠근다. 쌓기나무처럼 쌓는 중에 돌려야 하는 무대는 [spec-grade6.md](spec-grade6.md) 3절·5절(내 판은 늘 돌림, 답이 드러나는 문항의 그림만 잠금)을 따른다.

## 3. 점수·별·보상 (엔진이 준다 — [docs/engine.md](../../engine.md) 10절)

- 보상은 학습 행동(정확히 맞히기, 틀린 뒤 다시 도전, 새로 찾기, 설명하기)에만. **빠르기·시간에는 점수가 없다.** 순위표·목숨·뽑기 없음.
- 게임은 점수를 직접 만들지 않는다. `ctx.log.answer`·`ctx.collect`·`ctx.reward.event`로 행동을 알린다.
- **직접 만드는·탐구하는 단계의 점수는 대상(모양)마다 이 기기에서 한 번만**(`scored: 'once'`). 별 3개 다시 하기와 상관없이 주고, 그 자리에서 바로 저장한다(판 중간에 나가도 남는다). 이미 해 본 것은 0점(spec 16-8·16-9).
- 반드시 지킬 네 가지 — 무작위 단위 검사로 고정한다:
  1. **한 대상의 점수는 어떤 길로도 한 번**: 새로 고침, 나갔다 들어오기, 탭 두 개, 돌리거나 뒤집어 다시 만들기, 처음에 틀린 것을 나중에 맞히기, 두 단계를 오가기.
  2. **일부러 틀려서 이득 보는 길 0.** 모두 맞힌 쪽이 손해 보지 않는다.
  3. **되풀이해서 쌓이지 않는다.**
  4. **화면에 보이는 점수 = 저장되는 점수**: 결과 칸 합 + 점수 줄 = 이번에 모은 솜씨 점수 = 저장된 점수 차.
- 검사는 **독립 계산**(저장소의 `rewards.js`·`fold.js`를 쓰지 않고 기획서 문장만 보고 짠 것)과 엔진을 무작위 여러 기기·여러 판으로 견준다. 판정(접힘, 마주 보는 면, 위·앞·옆 모양, 개수)도 독립 계산과 전수 또는 큰 표본으로 견준다.
- 도감: 대표 도감은 "도감 n / m", 곁들이는 모음(노트 등)은 `label`을 주어 따로 센다. 등록 점수도 한 번만.
- 새 차시를 더하면 모두 맞히는 학생의 차시 점수와 칭호 기준(0·40·100·180·300)을 재서 보고한다.

## 4. 입체 보기 조작 ([spec.md](spec.md) 17절 — `orbit.js`를 그대로 쓴다)

- 끌어서(마우스·한 손가락) **어느 방향으로든 끝없이** 돌린다: 1px = 0.5°, 문턱 8px, 관성 없음, 어떤 자세에서도 끄는 방향 = 보이는 면이 움직이는 방향. 버튼·방향키도 화면 기준으로 끝없이.
- 크게·작게 0.5~2배: 두 손가락 벌리기, 무대 위 휠(Ctrl+휠 포함), 버튼, `+` `-`. [처음 보기로]·`0`·Home.
- 조작판(방향 넷·크게·작게·처음 보기로, 48px)은 무대 오른쪽 위, 휴대폰은 아래 띠 두 줄. **답하기 전에는 조작판을 숨긴다**(17-16).
- 접는 도중에도 다 접었을 때와 같은 정도로 돈다. 다 편 전개도는 처음 모습이고 0.2초 움직임으로 잇는다(17-18).
- 면 글자는 거울상이 되지 않게 한다. 보통 면 글자는 입체와 함께 뒤집히고(17-19), 읽어야 하는 표시("겹쳐요" 등)는 바로 세운다.
- 돌리기·확대에는 점수가 없다.

## 5. 끌기·터치

- 끄는 것은 **집은 순간부터 놓는 순간까지 화면에 보인다**(spec 16-11). 끌어다 놓기는 엔진 `enableDragDrop`(복제를 옮김)을 쓴다 — 따로 만들지 않는다.
- 끄거나 돌리는 동안에는 브라우저가 그 움직임을 화면 쓸기로 받지 않게 한다(관성 스크롤이 생기면 크롬북·태블릿에서 끈 직후 첫 누르기가 안 먹힌다 — N2 재검토에서 확인 중). 끌지 않을 때의 페이지 스크롤은 그대로여야 한다.
- 끌기와 누르기는 8px 문턱으로 가른다. 끌기 뒤 따라오는 click은 한 번만 막고, 새로 누르면 반드시 풀린다.
- 모든 조작은 마우스만·터치만·키보드만으로 끝까지 할 수 있다. 누르는 곳은 48px 이상, 초점 표시가 보인다.

## 6. 화면 배치 (교실 기기)

- 1366×768 · 1366×680 · 820×1180: **세로·가로 스크롤 0**(결과 화면 포함). 휴대폰 390×844: 가로 0.
- 오른쪽 판 안쪽 넘침 0 · 잘린 버튼 0 — **모든 장면**에서(목표 전·후, 맞힘·틀림, 까닭 고른 뒤). 접는 것은 넘칠 때만(spec 16-10).
- **플레이 도중 머리와 매트가 움직이지 않는다**(연속 칸이 생겨도 — N2 재검토에서 확인 중). 판 → 무대 이어 접기 어긋남 0px.
- 알림이 조작을 가리지 않는다. 조작판·이름표·도장·조작 띠가 서로 겹치지 않는다. 2배로 키워도 버튼이 가려지지 않는다.
- **글자 폭이 다른 기기에서도 버틴다**: 이 맥에서 맞아도 리눅스·크롬북에서는 글자가 조금 넓다. 세로 여유가 10~20px뿐인 배치는 넘친다.

## 7. 화면 문장·디자인·코드

- 5~6학년 눈높이 해요체 짧은 문장. 교과서 용어를 그대로 쓴다(6학년 용어 표: spec-grade6 1-4절). 숫자 뒤 조사는 `josa()`.
- 디자인 "종이 공방": `base.css` 토큰만, 새 색을 만들지 않는다(대비 4.5:1). 이모지 대신 `ui/icons.js` 아이콘. 색만으로 구분하지 않는다. 제목·버튼에 제목 글꼴(Do Hyeon)에 없는 기호를 쓰지 않는다(빌드 로그 "알림" 확인).
- DOM은 `h()`로(`innerHTML` 금지). 움직임은 `transform`·`opacity`만, `prefers-reduced-motion`·`?fx=low`면 끝 상태로. 단계에서 나가면 리스너·타이머·rAF가 남지 않는다. 콘솔 오류 0.
- 규칙·판정·문제 만들기는 순수 함수(`logic.js` 계열)에 두고 시드(`ctx.rng`)로 재현되게 한다.
- 학생 개인정보를 저장·전송하지 않는다. 바깥 CDN·웹 글꼴 주소·바깥 요청 없음. 교과서의 문장·그림·문제 수치를 옮기지 않는다(공개 저장소). 성취기준은 확인된 것만.
- "게임은 HTML 파일 하나·400 KB 이하" 규칙은 없어졌다. 학생들은 사이트 주소로 접속한다.

## 8. 테스트와 "끝났다"의 기준

- `npm test`(단위) + `npm run test:e2e`(크롬북 1366×768·태블릿 820×1180 터치, 검사 안에서 1366×680·390×844도) 모두 통과.
- **글꼴 흉내 모드에서도 실패 0**: `E2E_WIDE_TEXT=font npm run test:e2e`(본문 글꼴을 한글 폭이 넓은 글꼴로 바꾸고 글자 사이 0.25px — 지난 GitHub CI 실패 목록을 그대로 다시 낸 유일한 방법). 글자 사이만 넓히는 `E2E_WIDE_TEXT=1`(0.25px)은 줄 넘김을 못 잡고, `0.5`는 헛경보가 있다. e2e에 **글자 폭에 기대는 픽셀 상수를 쓰지 않는다**(이 맥에서 잰 버튼 너비 같은 것) — 세 번 연속 GitHub CI에서 깨졌다. 자세한 것은 [docs/engine.md](../../engine.md) 11절.
- 기존 검사를 지우거나 약하게 만들지 않는다. 결정으로 뜻이 바뀐 검사는 새 뜻을 고정하는 검사로 바꾸고 이유를 보고한다. 실패를 기다림(`waitForTimeout`)으로 덮지 않는다 — 원인을 밝힌다.
- 네 크기 스크린샷을 **직접 열어** 확인한다. 마우스·터치·키보드만으로 각각 끝까지 해 본다.
- 직접 실행해 확인한 것과 추정을 구분해 보고한다. 확인하지 못한 것(실물 기기, Safari, 리눅스 CI)은 못 했다고 적는다.

## 9. 절차

- [CLAUDE.md](../../../CLAUDE.md): Plan → Build → Review → Embed. Build와 Review는 다른 서브에이전트. 서브에이전트마다 지침 파일. 지침에 적힌 범위만 고친다. 사용자가 정해야 할 것은 추측하지 말고 "사용자 결정 필요"로 보고한다.
- Review가 통과시킨 것만 `main`에 올린다(올리면 사이트에 자동 배포). 올린 뒤 코디네이터가 GitHub CI 결과를 확인한다.

## 10. 여러 영역을 동시에 만들 때

- 트랙마다 **자기 작업 폴더(worktree)와 브랜치**에서만 일한다. 다른 트랙의 폴더와 `main` 체크아웃은 건드리지 않는다. 커밋은 자기 브랜치에만 하고 푸시하지 않는다(합치기는 코디네이터가 한다).
- **같이 쓰는 파일은 덧붙이기만, 최소로**: `main.js`(단계·차시 등록), `logic.js`(`STAGES`), `style.css`, 엔진(`src/shared/**`), `tests/e2e/net-workshop.spec.js`. 새 영역의 코드·스타일·테스트는 **새 파일**에 둔다(예: `tests/e2e/net-workshop-cuboid.spec.js`). 있는 줄의 순서를 바꾸거나 다시 쓰지 않는다 — 합칠 때 부딪힌다.
- 엔진을 바꿔야 하면 최소로 하고, 무엇을 왜 바꿨는지 보고한다(다른 트랙도 같은 곳을 바꿨을 수 있다).
- 같은 컴퓨터에서 여러 트랙이 브라우저 테스트를 함께 돌린다. e2e는 `npm run test:e2e -- --workers=4`처럼 일꾼 수를 줄여 돌리고, 시간 제한으로 실패한 검사는 혼자 다시 돌려 부하 탓인지 가린다.
- 개발 서버는 트랙마다 정해 준 포트만 쓴다. 5173(다른 프로젝트)·5183(사용자가 보는 서버)은 건드리지 않는다.
