# Review 재검토 지침: G3a 원기둥 1·2단계 고친 것 (트랙 "cuboid" 작업 폴더)

## 역할과 범위

- 너는 G3a를 검토한 **Review** 담당이다. Build가 [build-fix-brief-g3a.md](build-fix-brief-g3a.md)대로 고친 것을 **직접 재현·측정해** 다시 판정한다.
- Build의 보고는 확인 대상이다. 근거로 삼지 않는다.
- 결과는 [review-cylinder-g3a.md](review-cylinder-g3a.md)(작업 폴더, `a2f424d`에 커밋됨) 끝에 **"재검토 (날짜)" 절**을 덧붙인다. 맨 위 판정 줄은 재검토 판정으로 바꾼다(지난 판정은 재검토 절에 남김).
- 그 밖의 파일·코드·테스트는 고치지 않는다. 커밋하지 않는다. 작업 트리를 바꾸는 git 명령은 쓰지 않는다.
- 지킬 것은 [review-brief-g3a.md](review-brief-g3a.md)와 같다: 포트 e2e 5363·측정 5364, scratchpad `review-g3a/`, 네가 띄운 PID만 내림, 설치·내려받기 금지.

## 확인할 것

1. **테스트 셋 처음부터 실패 0**: `npm test`, 보통, 글꼴 흉내(하나씩 차례로). 바뀐 검사는 줄마다 읽어 약해진 것이 없는지 본다. 새로 만들거나 고친 검사는 CPU 4·8·12배로 돌린다.
2. **G3a-1**: 높이 문항 답하기 전 DOM(칩·길이 표시·이름표·화면 읽기·숨은 글·클래스·DOM 차례)에 정답이 없는지 본다. `tools/expose.mjs`처럼 시드 20개 이상으로 직접 재고, 정답 자리 치우침도 다시 잰다. 새 노출 검사가 고치기 전 코드(`bea877f`)에서 실패하는지 직접 확인한다.
3. **G3a-3**: 사다리꼴 위·아래 원의 띠 번호가 같은지(시드 500개 이상), 다른 꼴의 띠 번호가 바뀌지 않았는지(독립 계산과 견줌) 본다. 꼴 규칙 정답률은 네 4,000판 계산으로 다시 잰다.
4. **G3a-4**: 휴대폰 390×844(보통·글꼴 흉내)에서 [다음 문제] 뒤·판별 뒤 알림 × 조작 겹침을 잰다. 알림이 너무 일찍 지워져 결과 문장을 못 읽게 되지 않았는지도 본다(화면 읽기 알림 포함).
5. **G3a-5**: 더한 검사가 그 동작을 실제로 지키는지 본다(일부러 깨면 실패하는지).
6. **G3a-2**: 960×768·1024×768 결과 화면 넘침을 다시 재고, Build가 찾은 까닭이 맞는지 직접 확인한다. 예외를 남겼다면 그 까닭이 맞는지도 본다.
7. **불변**: 기준 `59b6153`과 견줘 다른 화면이 그대로인지 본다(지난 불변 비교를 고친 빌드로 다시). 원기둥 1·2단계 모습이 사용자가 고른 시안과 같은지 스크린샷을 직접 열어 본다.
8. 새로 생긴 문제, 사용자가 정해야 할 것.

## 끝나면

- 재검토 절의 형식: 판정, 테스트 표, 고친 것마다 "직접 잰 값 · 판단", 새 문제 표.
- 최종 답변은 **13줄 이하**. 직접 잰 것과 추정을 구분한다.
