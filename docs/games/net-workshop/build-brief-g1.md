# Build 서브에이전트 지침: G1 각기둥의 전개도 1 — 바탕 + 1~3단계 (트랙 "cuboid" 작업 폴더)

## 역할

너는 **Build** 담당이다. 승인된 6학년 계획([spec-grade6.md](spec-grade6.md))의 **G1 — 각기둥의 전개도 차시의 바탕과 앞 세 단계**를 만든다. 6학년 영역의 "각기둥의 전개도" 카드가 지금 "준비 중"인데, 이 Build로 처음 열린다. 4단계 `prism-free`(전개도 완성하기)와 도전 `prism-count`(후보)는 다음 Build G2의 몫이다. 검증은 별도 Review 서브에이전트가 한다.

사용자의 말(2026-10-18): 원기둥을 먼저 하자고 했다가 원기둥이 각기둥 부품에 기댄다는 설명을 듣고 "그럼 원래 계획대로 각기둥부터 해줘"(spec-grade6 15-16).

## 만들 것

1. **각기둥 바탕**: `solids.js`(순수 — 각기둥 입체·전개도 펼치기·이면각), 다각형 면(삼각형·사다리꼴·오각형·육각형 밑면 — 2-2절의 "나오는 각기둥"), 각기둥 전개도의 접기(면 사이 각도가 직각이 아닌 경첩 — 밑면 다각형의 내각에 맞는 옆면 사이 접힘), 입체 상태의 면 누르기(`pickFace` — 누르기와 끌기는 8px로 가름, 5절). 정육면체·직육면체 차시의 접기·화면은 **한 글자도 달라지지 않게** 넓힌다(기존 전개도 검사 전부 그대로 통과).
2. **차시 `prism` 각기둥의 전개도 1~3단계**(2-2절 표 그대로):
   - `prism-parts` 밑면과 옆면(살펴보기 주문): 입체(선 것·눕힌 것 — 눕힌 것 늘 1개, 4절 "밑면은 바닥 면")에서 밑면 두 개를 눌러 고르고 [확인] → 이름("오각기둥")과 "옆면은 5개" → 펼쳐지며 밑면(○)·옆면(△)이 전개도의 어디로 갔는지. 3문항, 사각기둥은 사다리꼴 밑면만.
   - `prism-judge` 각기둥이 될까?(검사 주문): 예상 → 접어 확인 → 안 되는 것을 맞혔으면 까닭 고르기(8절 보기 — 면의 수가 달라요 / 옆면이 직사각형이 아니에요 / 면이 겹쳐요 / 맞닿는 선분의 길이가 달라요, 맞으면 +2·별 밖). 5문항(되는 것 2: 띠 꼴 1 + 낯선 꼴 1 / 안 되는 것 3: 옆면의 수 · 두 밑면이 같은 쪽 · 길이가 다른 선분 또는 직사각형이 아닌 옆면). 되는 전개도는 접힌 뒤 이름.
   - `prism-edge` 맞닿는 선분(짝 찾기 주문): 표시된 선분과 접었을 때 맞닿는 선분을 누름(선분이 버튼, 48px 누를 자리) → 맞히면 접히며 두 선분이 같은 무늬로 만남. 보기에 바로 옆 선분(4절 "만나는 선분"). 3문항, 힌트(반만 접기) 동안에도 잠금.
3. **영역 등록**: 6학년의 "각기둥의 전개도" 영역에 차시 `prism`(칩 "6학년 1학기 · 각기둥과 각뿔"·시간 칩은 직접 해 보고 잰 어림)을 1~3단계로 등록 → 영역 카드가 "준비 중"에서 열린다. 4단계는 G2에서 더한다(지금은 3단계만 — 단계 지도·놀이 방법·영역 카드의 별 합계가 3단계에 맞게). `?lesson=prism`·`?area=prism`.
4. **늦게 불러오기**: 각기둥의 문제 만들기·판정·화면은 들어갈 때 받는 묶음(10절의 `grade6/` — 원기둥도 나중에 여기에)에, 단계 목록·그림은 처음 묶음에. B0b의 쌓기나무 나눔과 같은 방법. 처음 화면이 받는 크기(gzip)가 크게 늘지 않는지 빌드 로그로 보고.
5. 별: 엔진 기본(정답률). 다만 15-3·spec 16-13의 기준 — **한 번 틀리면 정답률로 바로 ★1이 되는 단계**(문항 3개이고 맞힐 때까지 다시 하는 단계 등)는 틀린 횟수로(0번 ★3 · 1번 ★2 · 그 이상 ★1). 어느 단계에 썼는지 보고.

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 특히:
  - **답하기 전 정답 노출 0**(5절): `prism-parts`는 돌려 봐도 어느 면이 밑면인지 화면이 알려 주지 않는다(면 색·표시·DOM 순서·속성이 모두 같음), `prism-judge`는 펼친 전개도가 늘 처음 모습·접기 막대·조작판 잠금(spec 17-16), `prism-edge`는 맞히기 전에는 접히지 않음. 멈춘 그림·잠근 무대의 모습이 문항과 무관(지금 전개도 무대의 "답하기 전 36화면이 한 가지 모습" 검사를 각기둥에도).
  - 판정을 **독립 계산과 비교**: 기획서 문장만 보고 짠 계산으로 — 각기둥이 되는 전개도의 조건(면의 수, 옆면이 직사각형, 두 밑면의 자리, 맞닿는 선분의 길이, 겹침)을 밑면 종류마다, 맞닿는 선분 짝을 모든 문항 꼴에서. 계획의 수치와 견준다.
  - 점수는 엔진 규칙 안에서(독립 계산 ↔ 엔진 무작위 검사 — 일부러 틀려 이득 0, 화면 = 저장).
  - 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) + 960×768 × 보통·글꼴 흉내에서 스크롤·넘침·겹침 0, 48px, 키보드만으로 세 단계 끝까지(면 고르기·선분 고르기도), 색만으로 구분하지 않음(○·△ 표시, 무늬), 움직임 줄이기·`?fx=low`, 화면 읽기 이름·알림.
  - 느린 기기: 각기둥 접기·펼치기 움직임의 프레임 간격(CPU 4·8배)을 재서 보고.
- **이미 사이트에 있는 것(정육면체·직육면체·쌓기나무, 인트로·학년·영역 화면, 선생님용 안내)의 화면·점수·기록은 위 표에서 고치는 것과 영역 카드가 열리는 것 말고 한 글자도 달라지면 안 된다.** 기준(`main` `7a9eaed`) 빌드와 견준 수치를 보고한다.
- 브라우저 검사는 처음부터 느린 기기를 견디게(움직임이 끝난 뒤에 잼, 사라지는 알림은 조작 바로 뒤, 머무는 시간, 시간 예산), `waitForTimeout`·`retries` 금지. 끝내기 전에 CPU 4·8·12배로 새로 만들거나 고친 검사 값 실패 0.
- 테스트: `npm test`, `E2E_PORT=5361 npm run test:e2e -- --workers=4`, `E2E_PORT=5361 E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0. **같은 때에 쌓기나무 S3 Build가 다른 작업 폴더에서 돈다** — 값이 어긋나는 실패는 혼자 다시 돌려 가린다.
