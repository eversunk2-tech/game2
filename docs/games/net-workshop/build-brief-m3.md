# Build 서브에이전트 지침: M3 직육면체 전개도 탐구 넓히기 (트랙 "cuboid")

## 역할

너는 **Build** 담당이다. 사용자의 수정 요청과 결정([spec.md](spec.md) **16-16**)에 따라 직육면체 차시의 "직접 만드는" 활동을 넓힌다: ① 학생이 **상자 크기(가로·세로·높이)를 정하면** 그 상자의 면 6장이 나오고 ② 세 길이가 모두 다른 직육면체의 전개도 **54칸 도감을 채우는 도전 주문서**가 생기고 ③ 놓을 면을 고른 상태에서 **손잡이로 돌린다**. 검증은 별도 Review 서브에이전트가 한다. 다른 Build가 같은 때에 다른 폴더에서 일할 수 있다(코디네이터가 프롬프트로 알려 준다).

## 만들 것

### 1. 상자 크기 정하기 (`cuboid-free`)

- 면을 놓기 전에 **가로·세로·높이를 각각 1~4 cm에서 고른다**(± 버튼 또는 숫자 칩 — 48px, 키보드, 화면 읽기 "가로 2 cm"). 처음 값은 지금과 같은 1·2·3 cm.
- 고르면 **그 직육면체가 옆에 작게 나타난다**(지금의 입체 보기 부품으로, 끌어서 돌려 볼 수 있음 — 답을 알려 주는 것이 아니므로 언제든 돌려도 된다). 길이 이름표(가로·세로·높이 cm)를 붙인다.
- 그 상자의 **면 6장(크기가 같은 면 두 장씩, 세 쌍)**이 면 카드로 나온다. 카드에는 가로×세로 cm가 보인다. 놓는 판은 고른 크기에 맞춰 칸 크기를 정해 **1366×680에서도 스크롤 0·판 넘침 0**이어야 한다(4·4·4처럼 큰 상자도). 상자 크기를 바꾸면 판에 놓인 면을 모두 거둔다(확인을 한 번 묻는다 — 놓인 면이 있을 때만).
- 세 길이가 같으면(정육면체) "세 모서리의 길이가 모두 같으면 정육면체예요"를 알려 주고 그대로 만들 수 있다(정육면체도 직육면체다).
- 끝내기·별은 지금 그대로(서로 다른 전개도 2가지에서 끝낼 수 있고 3가지면 ★3 — 16-14). 이번 판에서 "서로 다른"은 **상자 종류별로** 센다(같은 모양을 크기만 바꿔 다시 접으면 새로 세지 않는다 — 아래 2절의 "같은 전개도").
- 접기·까닭 고르기·힌트·도장은 지금의 규칙을 그대로 쓴다(16-12: 예상 없음, 안 되는 것을 접어도 별이 깎이지 않음, 까닭은 고른 뒤에만).

### 2. "같은 전개도"와 도감·점수

- **상자 종류**: 세 길이가 모두 다름(54가지) / 두 길이가 같음(29가지) / 셋이 같음(정육면체, 11가지). 같은 종류 안에서는 **실제 길이가 달라도 같은 모양이면 같은 전개도**다(예: 1·2·3 cm와 2·3·4 cm에서 짧은·가운데·긴 모서리의 자리가 같은 전개도). 길이 순서로 맞춘 표준 모양으로 이름(id)을 정한다. 돌리기·뒤집기는 지금처럼 같은 모양.
- **모음(도감)**: 세 길이가 다른 것 → 지금의 직육면체 전개도 모음(54칸, `CUBOID_NETS_ID`). 두 길이가 같은 것 → **새 모음(29칸, 조용한 모음 — 도감 화면은 없어도 된다)**. 정육면체 → **1차시의 정육면체 전개도 도감(11칸)**에 넣는다(정육면체 차시에서 이미 찾은 것이면 점수 없음 — 모양마다 한 번).
- **점수(16-14 그대로, 코디네이터가 정한 세부)**: 이 기기에서 처음 찾는 직육면체 전개도(세 길이가 다른 것 + 두 길이가 같은 것을 **합쳐서**) 10가지까지는 만들기 +2 · 새 전개도 +5, 11번째부터는 +1. 정육면체 상자로 찾은 것은 정육면체 도감의 규칙대로. 같은 전개도는 `cuboid-free`와 도전(3절)에서 **합쳐 한 번만**. 어떤 순서·어떤 판 나눔·탭 두 개에서도 "처음 10가지"의 경계가 흔들리지 않는다(지금의 `xpAfter` 방식을 넓혀 쓴다).

### 3. 도전 주문서 "직육면체 도감 주문" (새 단계 `cuboid-dex`)

- 2차시(직육면체)의 도전 주문서로 등록한다(정육면체 차시의 도감 주문과 같은 틀 — 차시의 일반 단계를 마치면 열리고, 별 합계에 넣지 않고, 시간 재기는 켜는 학생만).
- **세 길이가 모두 다른 상자만**(크기 고르기는 1절과 같되 같은 길이를 고르면 "도감 주문은 세 모서리의 길이가 모두 달라야 해요"). 찾은 전개도가 **54칸 도감**에 차곡차곡 쌓이고, **여러 번에 나눠 해도 이어진다**(정육면체 도감 주문처럼). [오늘은 여기까지]로 언제든 끝낸다.
- **별 = 지금까지 도감에 찾은 가지 수**: 10가지 ★1 · 20가지 ★2 · 30가지 ★3(결과 화면에 별 기준 안내 — `finish({ stars, starNote })`). **54가지를 다 찾으면 "완성" 도장**(엔진 도장 — 이름과 그림은 네가 정해 보고). 20가지·30가지에도 무대 도장(지금의 5·10가지째 무대 도장처럼)을 둘지 네가 정해 보고.
- **도감 화면(54칸)**: 찾은 칸은 그 전개도의 작은 그림, 못 찾은 칸은 "?" — 1366×680·820×1180·390×844에서 넘치지 않게(접기·넘기기·작게 — 정육면체 도감 칸의 "넘칠 때만 접기" 방식, 16-10). 학습 기록 글에도 "직육면체 전개도 n / 54".
- 힌트: 안 되는 모양을 연달아 접으면 [힌트] → **아직 못 찾은** 전개도의 그림자(지금 규칙).

### 4. 면 돌리기 손잡이 (`free-board.js` — 직사각형 면이 있는 판)

- 판에 놓인 면이나 카드를 **눌러 고르면** 그 면의 모서리에 **↻ 손잡이**가 생긴다. 손잡이를 잡고 돌리면 면이 손가락·마우스를 따라 돌다가, 놓으면 **가장 가까운 90°**로 맞춰진다(가로·세로가 바뀐 면이 판에 들어가지 않으면 제자리로 돌아가고 까닭을 알림으로).
- 면을 **끄는 중에는** 다른 손가락으로 톡(태블릿) · 마우스 오른쪽 버튼 · **R 키**로 90° 돌린다.
- 지금의 두 번 누르기·[돌리기] 버튼·키보드 돌리기는 그대로 둔다. 정사각형 면만 있는 판(정육면체 `cube-free`·도감 주문)에서는 손잡이를 보이지 않는다(돌려도 모양이 같다) — **정육면체 단계의 화면은 달라지지 않아야 한다**.
- 누르기·끌기·손잡이 돌리기를 헷갈리지 않는다(8px 문턱, 끈 뒤 따라오는 click, 끄는 동안 `touchmove` 막기 — common-rules 5절). 손잡이는 48px, 초점 표시, 화면 읽기("돌리기 손잡이, 지금 0°").

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 직접 만드는 단계의 규칙(1절), 정답 노출 0(답이 정해진 문항은 없지만 힌트·도감 칸에 아직 못 찾은 전개도가 드러나지 않는지), 점수 = 기획서 문장만 보고 짠 **독립 계산**과 일치(무작위 여러 기기·여러 판·크기를 섞어·탭 두 개), 세 크기 세로·가로 스크롤 0·판 넘침 0·머리와 매트 움직임 0(1~4 cm 모든 크기 조합 64가지에서), 48px, 키보드만으로 크기 고르기·놓기·돌리기·접기·도감 주문 끝까지, 색만으로 구분하지 않음, 움직임 줄이기·`?fx=low`.
- 판정은 **독립 계산**(저장소의 `fold.js`를 쓰지 않는 직육면체 감싸기)과 견준다: 크기 64가지 × 무작위 배치에서 되는/안 되는 판정, 상자 종류별 가짓수(54·29·11), 표준 모양 id가 크기를 바꿔도 같은지.
- **이미 있는 것은 그대로**: 정육면체 차시(4단계 + 도전 2)의 화면·점수·기록 차이 0. 직육면체 1~3단계 차이 0. `cuboid-free`를 처음 값(1·2·3 cm)으로만 하는 학생의 점수·기록은 지금과 같다. 이미 사이트에서 쌓은 직육면체 도감 기록이 그대로 이어진다(저장 열쇠·id 바꾸지 않음 — 옛 저장 값으로 열어 보는 검사).
- 브라우저 검사는 처음부터 느린 기기를 견디게: 크기·자리는 움직임이 끝난 뒤, 사라지는 알림은 띄운 조작 바로 뒤, 잠깐 보이는 상태는 머문 시간까지(지금 파일들에 있는 도우미를 쓴다), 혼자 3초 넘는 검사에 `test.setTimeout`. `waitForTimeout`·`retries` 금지. 끝내기 전에 scratchpad 복사본에 CPU 느리게 하기(4·8·12배)를 넣어 네가 만들거나 고친 검사의 값 실패 0.
- 기존 검사를 지우거나 약하게 만들지 않는다. 결정으로 뜻이 바뀐 검사는 새 뜻을 고정하는 검사로 바꾸고 이유를 보고한다.
- 테스트: `npm test`, `npm run test:e2e -- --workers=4`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0.

## 지킬 것

- 작업 폴더·브랜치·scratchpad·포트는 코디네이터가 프롬프트로 알려 준다. 그 폴더에서만 일한다. 커밋은 그 브랜치에만(작업 단위마다 해도 된다), 푸시·합치기는 하지 않는다. `npm install`·`npm ci`·내려받기 금지. 띄운 실행·서버는 모두 내리고 끝낸다.
- 계획에 적히지 않은 세부는 16-16의 뜻과 공통 규칙에 맞게 네가 정하고 까닭을 보고한다. 사용자가 정해야 할 만큼 큰 갈림길은 추측하지 말고 "사용자 결정 필요"로 선택지와 추천을 붙여 적는다.

## 끝났다의 기준

세 가지 테스트 실패 0(마지막 커밋에서 처음부터), 느린 기기 흉내 값 실패 0, 판정·가짓수·표준 id 독립 계산 일치, 점수 독립 계산 일치(크기를 섞은 무작위 여러 판), 64가지 크기 × 세 크기 화면 배치 0, 손잡이를 마우스·터치·키보드로, 정육면체 차시·직육면체 1~3단계 불변 수치, 옛 저장 값으로 연 화면, 네 크기 스크린샷(크기 고르기와 작은 입체, 큰 상자의 판, 54칸 도감, 손잡이로 돌리는 중)을 직접 연다. 도감 주문을 브라우저에서 직접 해 보고 10가지를 찾는 데 걸린 시간 기록.

## 최종 보고 (16줄 이하)

만든 것(크기 고르기·작은 입체·면 카드, 상자 종류와 표준 id, 모음 셋과 점수, 도감 주문·별·도장·도감 화면, 손잡이)과 직접 확인한 방법·잰 값, 판정·가짓수 독립 계산, 점수 독립 계산(경계·순서·판 나눔·탭 두 개), 배치(64가지 크기 × 세 크기), 손잡이(세 수단, 잘못 돌아감·잘못 놓임 0), 정육면체·직육면체 1~3단계 불변, 옛 저장 값, 느린 기기, 테스트 결과(보통·글꼴 흉내), 엔진에서 바꾼 것(줄 번호), 같이 쓰는 파일에서 고친 곳(`main.js`·`free-board.js` 줄 번호), 고친 기존 검사와 이유, 네가 정한 세부, 사용자 결정이 필요한 것, 남은 한계, 마지막 커밋 해시. 직접 실행해 확인한 것과 추정을 구분한다.
