- 너는 F1을 검토한 **Review** 담당이다. Build가 [build-fix-brief-f1b.md](build-fix-brief-f1b.md)(덧붙임 포함)에 따라 고친 것을 독립적으로 다시 확인한다.

## 확인할 것

1. **F1-1~F1-3**: 지난번 잰 크기(960×768·1000×768·1000×700·900×700·960×600·1024×600 + 다섯 크기)에서 넘침 0·못 보는 칸 0(옮기기의 모든 자리를 합쳐), 휴대폰 390×844·360×780 [위·앞·옆 모양]·위에서 본 판 잘림 0, 세로 태블릿·휴대폰 알림 밑 버튼(차시 단계와 견줌). 펼치는 칸의 자리가 사용자가 본 두 모습(크롬북 왼쪽 위·세로 태블릿 아래)에서 벗어나지 않았는지 그림을 직접 열어 본다. 칸 크기가 24px 아래로 줄었으면 그 크기와 누르기 정확도.
2. **F1-4~F1-6·R-f**(·R-b): 키보드 초점·Escape·`aria-*`, 조사, 글꼴에 없는 기호(빌드 알림 기준과 견줌), `docs/engine.md`가 코드와 맞는지.
3. **테스트**: 셋 다 직접 실행 — 실패 0. 지난 검토 뒤 바뀐 `tests/`를 줄마다 읽어 약해진 검사 0, 새 배치·알림·초점 검사가 지난번 실패를 실제로 잡는지(고치기 전 커밋 `b8d73c1`에서 새 검사가 실패하는지 scratchpad 복사본으로 확인하면 좋다). 새로 만들거나 고친 검사를 CPU 4·8·12배로 — 값 실패 0.
4. **불변**: 지난번처럼 다른 모든 화면이 `96cc9a6`과 같은지(의도한 차이만), 자유 쌓기의 다른 조작(쌓기·빼기·돌리기·옮기기·저장·벌리기)이 그대로인지, 개수 보기(`blocks-logic.js`)는 덧붙임으로 바꾸라고 한 것 말고는 그대로인지.
5. 새로 생긴 문제.
