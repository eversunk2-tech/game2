# Review 서브에이전트 지침: G2r 각기둥 4단계를 직육면체처럼 자유 배치로 (트랙 "cuboid" 작업 폴더)

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-g2r.md](build-brief-g2r.md)(덧붙임 포함)에 따라 바꾼 각기둥 4단계 `prism-free`를 **독립적으로** 검증한다. Build와 분리된 검토자다.
- 결과는 새 파일 `docs/games/net-workshop/review-prism-g2r.md`(트랙의 작업 폴더 안) 하나. 맨 위 판정 줄(통과 = 반드시 수정 0건 / 수정 필요). 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다. 검증 파일은 정해 준 scratchpad에만. Build의 scratchpad는 근거로 삼지 않는다(사용자가 고른 시안 `build-g2r/shots/compare-*.png`의 B 줄은 기준 모습으로만).

## 기준

[spec-grade6.md](spec-grade6.md) **15-30·15-31**(사용자의 말·결정·그대로인 것), 15-2·15-29(+ 그 아래 코디네이터가 고른 것), 2-2·4·5·8절, [spec.md](spec.md) 16-2·16-8·16-9·16-12·16-14·16-15·16-16·17절, [common-rules.md](common-rules.md), [review-prism-g2.md](review-prism-g2.md)(지난 잰 값).

## 검토 대상

지침을 맡긴 `main` 커밋(Build 프롬프트의 "기준")과 `track/cuboid`의 마지막 커밋 사이의 변경 전부. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `E2E_PORT=5363 npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 — 실패 0. 바뀐 `tests/`를 줄마다 읽어 약해진 검사 0(G2의 4단계 검사가 새 조작에 맞게 다시 쓰였는지 — 판정·점수·정답 노출·배치·키보드가 같은 강도인지).
2. **사용자 결정대로인가**: 빈 판에서 시작(미리 놓인 면·자물쇠·+ 자리·주문 1·2 없음), 면 카드를 끌어 놓기·카드 누르고 판 누르기·옮기기·빼기·되돌리기·모두 빼기, 같은 길이 모서리 가까이 놓으면 자석처럼 붙음, 돌리기는 직육면체와 같은 손짓(↻ 손잡이·두 번 누르기·[돌리기]·R·끄는 중 돌리기)으로 30°씩·놓으면 가까운 모서리 방향으로 맞춤, [접어 보기] → 놓은 그대로 접힘, 서로 다른 전개도 3가지까지(2가지부터 끝, 3가지 ★3), "왜 안 될까요?"·고른 까닭 먼저, 점수(처음 10가지·11~30번째 +1·31번째부터 0, 최대 104점), 도장 "기둥 설계사", 만들 각기둥 창. **직육면체 "내 맘대로 직육면체 전개도"를 함께 열어 손짓이 같은지** 견준다.
3. **만들 수 있는 전개도**: 962가지(이등변삼각 23·사다리꼴 104·정육각 354 × 2) 모두 이 조작으로 만들 수 있는지(독립 계산 — 각 전개도를 놓는 차례를 직접 셈하거나 학생처럼 끌어 놓아 봄), 같은 모양은 합동 열쇠로 한 번만.
4. **판정·점수 독립 계산**: 저장소 코드를 쓰지 않고 기획서 문장만 보고 짠 계산으로 — 학생처럼 놓은 판 수천 개의 판정(면의 수·옆면·두 밑면 자리·맞닿는 선분 길이·겹침), 점수(일부러 틀려 이득 0, 같은 모양 두 번 점수 0, 화면 = 저장).
5. **정답 노출 0**: 자석이 맞는 자리에만 붙어 정답을 알려 주지 않는지(같은 길이의 틀린 모서리에도 붙는지 — Build의 판단과 까닭을 함께 봄), 판·카드·DOM·속성이 접기 전에 결과를 드러내지 않는지.
6. **조작**: 키보드만·마우스만·터치만으로 끝까지(첫 면 놓기·자석 자리 고르기·돌리기·빼기), 48px, 누르기·끌기 8px, 화면 읽기 문장·알림(알림이 조작을 가리지 않음), 움직임 줄이기·`?fx=low`. 끌어 놓은 면이 겹치거나 판 밖으로 나갈 때의 동작.
7. **배치**: 여섯 크기(1366×768·1366×680·1024×768·960×768·820×1180·390×844) × 보통·글꼴 흉내에서 스크롤·넘침·겹침 0(휴대폰 세로 스크롤은 규칙대로), 다 놓은 육각기둥 꽃 꼴이 판에 들어가는지 — 스크린샷을 직접 열어 사용자가 고른 시안 B와 같은 모습인지 의견.
8. **속도**: 끌기·자석 붙기·돌리기·접기 움직임의 프레임 간격을 CPU 1·4·8배로.
9. **불변**: 기준 빌드와 견줘 다른 모든 화면(정육면체·직육면체 자유 배치 — 픽셀·DOM, 각기둥 1~3단계·도전, 쌓기나무·자유 쌓기, 인트로·학년·영역·학습 기록·선생님용 안내)이 같은지, 저장 값의 모양. 처음 받는 크기 전·후.
10. **느린 기기 검사**: 새로 만들거나 고친 검사를 CPU 4·8·12배로 — 값 실패 0.
11. 새로 생긴 문제, 사용자가 정해야 할 것.

## 형식과 끝나면

`review-prism-g2r.md`: 판정 줄, 테스트 결과 표, 발견한 문제 표(심각도, 파일:줄, 재현 방법, 고칠 방향), 결정 대조표(15-30·15-31), 직육면체와 손짓 비교 표, 만들 수 있는 전개도 표, 독립 계산 표, 정답 노출 표, 조작 표, 배치 표, 속도 표, 불변 표, 고친 검사 표, 확인한 것, 확인하지 못한 것. 최종 답변 **13줄 이하**. 직접 잰 것과 추정을 구분한다.
