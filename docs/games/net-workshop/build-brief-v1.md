# Build 서브에이전트 지침: V1 입체 여러 방향으로 돌려 보기·확대 축소

## 역할

너는 **Build** 담당이다. [spec.md](spec.md) **17절**(17-1~17-12)과 **17-15 결정**(2026-10-08 사용자 승인)대로 접은 입체를 여러 방향으로 돌려 보고 크게·작게 보는 기능을 만든다. 판정(`fold.js` 결과)·점수 규칙은 바꾸지 않는다. 검증은 별도 Review 서브에이전트가 한다.

## 사용자 요청과 결정 (기준)

- 요청 원문: "전개도 접은 입체 화면은 다양한 방향으로 돌려보거나 확대 축소 할수 있도록 해줘"
- 결정(17-15): ① **답한 뒤, 접힌 입체에서만** 된다(답하기 전 화면은 지금과 같다) ② **마우스 휠 확대를 쓴다**(접은 입체 위에서만) ③ 버튼은 **오른쪽 위 십자 조작판**(휴대폰은 아래 띠 두 줄), 그리고 사용자가 덧붙인 말 "마우스(pc)나 터치 누름(태블릿)을 통해 화면을 원하는대로 돌리기도 가능하게 해줘" → **끌어서 돌리기(마우스로 누른 채 끌기, 손가락으로 누른 채 끌기)는 필수**다. 버튼·키보드와 끌기·벌리기·휠을 모두 만든다. 어느 하나를 다음으로 미루지 않는다.
- Plan이 정한 값: 기울기 0°(바로 위)~180°(바로 아래, 밑면까지), 배율 0.5~2배(단계 0.5·0.64·0.8·1·1.25·1.6·2), 끌기 문턱 8px·1px = 0.5°, 관성·옮기기·비틀어 돌리기 없음, 안쪽 면 글자는 거울상이 되지 않게, 점수·`inspect` 없음, [처음 보기로].

## 만들 것 (17절 그대로, 순서는 17-12)

1. `orbit.js`(새, 순수 함수) + 단위 테스트 — 보기 값의 한계·한 단계·끌기/벌리기/휠 → 값, 펼친 상태와 잇기, 빛 방향, 뒷면 판정, 글자 바로 세우기, 보는 방향 말(17-10·17-11 단위 표)
2. 조작판(버튼 7개, 48px, 이름 = `aria-label`·`title`)·키보드(←→↑↓ `+` `-` `0`·Home)·네 크기 배치(17-6)
3. 끌기(마우스·한 손가락)·두 손가락 벌리기·휠(Ctrl+휠 포함) — 17-2의 "부딪히는 곳" 표를 하나씩 지킨다
4. 브라우저 테스트(17-11)·스크린샷

## 반드시 지킬 것 (지금 통과하는 성질을 깨지 않는다)

- **답하기 전 화면은 지금과 한 가지 모습**: 판별·마주 보는 면·면 붙이기에서 답하기 전에 끌기·휠·↑↓·`+ − 0`·꺼진 버튼 누르기를 해도 무대 변환·면 그늘·조작판 상태가 문항과 무관하게 같다(힌트로 반만 접힌 동안도). 자유 배치에서 까닭을 고르는 동안 돌리고 키워도 까닭 글자·표시는 0(N1-1에서 고친 것, 지금 e2e의 `expectNoReasonShown`).
- 면 누르기·빈 자리 누르기·면 카드 끌어 놓기·접기 막대·자유 배치 판의 조작이 지금과 같다. 끌기와 누르기를 헷갈리지 않는다(문턱 8px, 끌기 뒤 따라오는 click 삼키기).
- 자유 배치 판 → 무대 이어 접기 어긋남 0px, 1366×768·1366×680·820×1180 세로·가로 스크롤 0, **자유 배치 오른쪽 판 안쪽 넘침 0**(바로 앞 라운드에서 고친 것), 누르는 곳 48px 이상, 알림이 조작(새 조작판 포함)을 가리지 않음, 이름표·도장·조작 띠와 조작판이 겹치지 않음.
- 움직임은 `transform`·`opacity`만. `prefers-reduced-motion`·`?fx=low`에서 끌기·버튼은 바로 반응하고 자동 움직임만 줄인다. 나간 뒤 남는 리스너·타이머·`requestAnimationFrame` 0(정리 함수).
- DOM은 `h()`(`innerHTML` 금지), 이모지 대신 `ui/icons.js` 아이콘(새 아이콘 `up`·`down`·`zoomin`·`zoomout` 4개를 엔진에 더하고 `docs/engine.md`에 적는다), 색·간격은 `base.css` 토큰, 제목 글꼴에 없는 기호를 버튼·제목에 쓰지 않는다(빌드 로그의 "알림" 확인), 게임 파일 400 KB 이하.
- 화면 문장(버튼 이름·안내 칩·화면 읽기 알림·놀이 방법)은 5~6학년 눈높이 해요체 짧은 문장. 17절에 정해 둔 말을 쓴다.
- 기존 검사를 지우거나 약하게 만들지 않는다. 바꿔야 하는 검사(예: [↺][↻]를 찾는 자리)는 이유를 보고에 적는다.
- 17절과 다르게 만들어야 하는 곳이 생기면(시제품은 앞 라운드 이전 코드 위에서 만든 것이다) 그렇게 한 까닭을 "계획과 다른 점"으로 보고한다. 사용자가 정해야 할 것이 새로 보이면 추측하지 말고 "사용자 결정 필요"로 적는다.
