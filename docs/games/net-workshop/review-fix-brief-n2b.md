## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e` 직접 실행(보통). Build가 만든 **글자 폭 넓힘 모드**로도 e2e 전체를 직접 실행(0.25px, 그리고 0.5px) — 실패 수와 목록. `git diff tests/`로 약해진 검사가 없는지.
2. **넓힘 모드가 믿을 만한가**: ⓐ 보통 실행이 넓힘 모드 추가 전과 한 글자도 다르지 않은가(환경 변수를 안 주면 스타일이 안 들어감) ⓑ `673f871`을 따로 풀어 그 넓힘 모드(0.25px)로 돌리면 **실제 CI와 같은 2건이 실패하는가**(CI-1은 그래야 한다. CI-2도 재현되는지) — 즉 이 모드가 CI를 미리 알려 주는가 ⓒ 앱 코드에 넓힘 스타일이 새어 들어가지 않았는가.
3. **CI-1 = N2-1 (머리 높이)**: 태블릿 세로 주사위 주문에서 두 번째를 연달아 맞히는 순간 머리 높이·매트 자리가 0px 움직이는가(지난 값 75 → 117px, 42.7px). 그 장면의 세로 여유(지난 값 11px)와 넓힘 0.25·0.5px에서의 값, 세로 스크롤 0. `cube-free` 태블릿의 18.8px도 0이 됐는가. **네 크기 × 모든 단계(일반 4 + 도전 2)에서** 연속 칸이 생기는 순간·사라지는 순간·[시간 재기]를 켜는 순간 매트가 움직이는 장면 0인가. 판 → 무대 어긋남 0px.
   - 머리를 바꾸면서 **`673f871`과 달라진 화면**: 네 크기에서 머리·매트·판·무대의 자리와 크기를 견줘 달라진 곳을 표로. 의도한 변화뿐인가, 무대가 작아지거나 판이 빠듯해진 곳은 없는가(1366×680 판 안쪽 여유: 지난 값 주사위 53px·도감 14px·free 36px). 스크린샷을 직접 열어 머리가 어색하지 않은지(빈 자리가 덩그러니 남는지) 본다. 예시 게임의 머리도 본다.
4. **CI-2 (터치 뒤 누르기) — Build가 밝힌 원인이 맞는가**: Build의 설명을 그대로 믿지 말고 직접 재현한다. `673f871`에서: 터치로 카드를 끈 직후 0·50·100·200·400·800ms에 다른 버튼([접어 보기], 칸, 다음 버튼)을 탭했을 때 먹히지 않는 경우가 있는가 — CPU 늦춤(4~6배)·넓힘 모드·태블릿과 휴대폰. 마우스 끌기 뒤 클릭도. 작업 트리에서 같은 것을 재서 0이 됐는가. **실제 태블릿에서 "카드를 끈 직후 첫 누르기가 안 먹힘"이 일어날 수 있었는지**에 대한 판단. Build가 "검사 문제"라고 했다면 검사가 왜 CI에서만 실패했는지 설명이 재현과 맞는가. 끌기 뒤 따라오는 click을 삼키는 처리가 여전히 필요한 곳에서는 동작하는가(끌어 놓은 자리의 요소가 눌리지 않음).
5. **N2-3 (주사위 별)**: 0번 틀림 ★3·1번 ★2·2번 이상 ★1인가(브라우저에서 세 경우 모두). 결과 화면의 별 기준 안내가 맞는가. 점수를 독립 계산과 견줌: 한 번에 성공, 한 번 틀리고 고침(이제 ★2), 그 뒤 완벽 재도전, ★1·★2에 머물며 되풀이, ★3 뒤 다시 — 지난 값(20 / 16 / +8 / 판마다 +4 / 0)과 나란히. 일부러 틀려 이득 0(틀린 쪽이 늘 덜 받음), 화면 = 저장.
6. **깨지지 않았는가(지난 스크립트로 다시)**: 예상 관련 말 0, 까닭 고르는 중 노출 0(24가지), 주사위 접기 전 노출 0, `cube-free`·`cube-dex` 점수 독립 계산 일치, 도감 이어 하기, 끄는 면 보이기, 답하기 전 화면 = V1 이전(조작 띠 검사), 보기 조작, 세 크기 스크롤 0·판 넘침 0·48px, 예시 게임, 콘솔 오류 0.
7. **범위·코드**: 허용 파일 안인가. `drag-drop.js`를 고쳤다면 예시 게임과 면 붙이기의 끌기가 나빠지지 않았는가. 넓힘 모드 코드가 테스트 바탕에만 있는가. `h()`·`innerHTML` 없음.
8. **새로 생긴 문제**, 리눅스 CI에서 여전히 깨질 수 있는 검사 목록(넓힘 0.5px·부하에서 실패한 것).
