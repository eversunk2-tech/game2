# Build 서브에이전트 지침: S1 쌓기나무 검토 반영 (트랙 "blocks")

## 역할

너는 S1(쌓기나무 바탕 + 1·2차시)을 만든 **Build** 담당이다. 네 작업 폴더의 `docs/games/net-workshop/review-blocks.md`(Review가 쓴 검토 결과)의 문제와 사용자 결정을 반영한다. Review 판정은 "수정 필요 — 반드시 수정 1건, 그 밖은 통과 수준"이었다. 판정(위·앞·옆·개수)·조작의 뼈대는 통과했으니 그대로 둔다. 검증은 별도 Review 서브에이전트가 다시 한다.

## 사용자 결정 (2026-10-11 — 이 폴더의 spec-grade6.md에는 아직 없다. 여기 적힌 것이 기준이다)

1. **맞는 답이 정해진 쌓기 단계는 답하는 단계다.** [확인하기]는 답을 내는 행동이고 틀린 [확인하기]는 별에 든다(자유 탐구가 아니므로 "안 되는 것을 만들어도 별이 깎이지 않는다"는 해당하지 않는다).
2. **한 번만 틀려도 정답률 기준으로 바로 ★1이 되는 단계의 별은 틀린 횟수로 정한다**: 틀린 답 0번 ★3 · 1번 ★2 · 2번 이상 ★1(주사위 주문과 같은 기준). **`blocks-copy`(2문항)와 `blocks-scene`(3문항)에 적용한다.** `blocks-hidden`은 지금 그대로(엔진 정답률). 결과 화면에 별 기준 안내를 보인다(주사위 주문의 `finish({ starNote })` 방식).
3. **놀이터(`blocks-play`)의 점수(단계 완료 +5 · 별 +6, 처음 한 번)는 그대로 둔다.**

## 사이트에 올라갔을 때 헷갈리지 않게 (Review 계획과 다른 점 ⑧)

영역 고르는 화면(B0)은 아직 없지만, 이 트랙이 `main`에 합쳐지면 바로 사이트에 올라간다. 지금은 단계 지도에 쌓기나무 차시가 정육면체 뒤에 "2차시·3차시"·"약 10분"으로 이어져 보이고 놀이 방법은 전개도 이야기뿐이다. **최소한으로** 고친다:

- 쌓기나무 차시의 칩이 "쌓기나무 1차시"·"쌓기나무 2차시"로 보이게(전개도 차시의 자동 번호 "1차시"는 그대로). 엔진에 차시 정의의 선택 값(예: `chip`, `minutes`)을 더하는 식으로 — 값을 주지 않는 차시와 예시 게임은 한 글자도 달라지지 않아야 한다. 시간 칩은 이 차시의 어림(1차시 약 6분, 2차시 약 8분 — Review의 어림 5~7분·7~10분)으로.
- 차시 제목 옆이나 아래에 "6학년 2학기 · 공간과 입체"임을 알 수 있는 짧은 말.
- 놀이 방법에 쌓기나무 줄을 덧붙인다(쌓기·빼기·돌려 보기 한두 문장, 해요체).
- 영역 화면·앱 이름·`game.json`·처음 화면의 큰 구조는 건드리지 않는다(B0의 몫).
- **직육면체 트랙이 같은 때에 `main.js`·`logic.js`의 차시 목록과 엔진 `app.js`(821–822·1080행 근처)·`collection.js`를 고쳤다.** 같은 줄을 다시 쓰지 말고 덧붙인다. 엔진을 고친 곳은 줄 번호와 함께 보고한다.

## 반드시 지킬 것

- 이 폴더의 `common-rules.md` 전부. 통과한 것을 깨지 않는다: 누르기와 끌기 가르기(잘못 쌓임·잘못 돌아감 0), 누른 곳 = 광선 계산, 판정 전수 비교 어긋남 0, 답하기 전 정답 노출 0, 점수 = 독립 계산·화면 = 저장·일부러 틀려 이득 0, 세 크기 스크롤 0·판 넘침 0·머리와 매트 움직임 0, 정육면체 차시 불변, 전개도 공통 부품 0줄.
- 보기의 자리·순서를 바꾸면서 **답하기 전 화면이 답과 엮이지 않는지** 다시 본다(보기 값의 크기 순서, 그림의 차례).
- 기존 검사를 지우거나 약하게 만들지 않는다. 뜻이 바뀐 검사(별 기준)는 새 뜻을 고정하는 검사로 바꾸고 이유를 보고한다.
- 테스트: `npm test` + `npm run test:e2e -- --workers=4`(보통) + `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`(글꼴 흉내)에서 실패 0.
