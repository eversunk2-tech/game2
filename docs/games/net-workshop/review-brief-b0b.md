# Review 서브에이전트 지침: B0b 빌드 바탕 (트랙 "b0")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-b0b.md](build-brief-b0b.md)에 따라 만든 여러 파일 빌드·영역을 들어갈 때 불러오기·하위 경로 서버 e2e를 **독립적으로** 검증한다. Build와 분리된 검토자다.
- **이 일은 사이트 전체가 열리느냐가 걸린 일이다** — 빌드가 틀리면 학생이 아무 화면도 못 본다. 화면 하나하나보다 "어떤 주소로 어떤 순서로 열어도 열리는가"를 먼저 본다.
- 검토 결과는 새 파일 `docs/games/net-workshop/review-b0b.md`(트랙의 작업 폴더 안) 하나에 쓴다. 맨 위에 판정 줄(통과 = 반드시 수정 0건 / 수정 필요), 그 아래 기존 review 파일과 같은 형식의 표. 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지. 서버·실행은 네가 띄운 PID만 내린다.
- **트랙의 작업 폴더에서만** 일한다. 검증 파일·스크린샷·기준 빌드는 정해 준 scratchpad 폴더에만. Build의 scratchpad는 근거로 삼지 않는다.

## 검토 대상

기준 `7d512a4`(= 사이트에 올라간 `cd190ce` + 문서)와 트랙 브랜치의 마지막 커밋 사이의 변경 전부. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `E2E_PORT=<네 포트> npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 실행 — 실패 0. `git diff 7d512a4..HEAD -- tests/`를 줄마다 읽어 **약해진 검사 0**(지운 검사, 느슨해진 기대값, 건너뛰기 늘어남, 주소 말고 뜻이 바뀐 줄). 건너뛴 수가 전과 같은지(지금 94).
2. **열리는가 (가장 중요)**:
   - 하위 경로 `/game2/` 서버(Build의 `serve.mjs`와 **네가 따로 짠 작은 서버** 둘 다 — 저장소에 더하지 않고 scratchpad에)에서 게임 모음, 입체도형 공방, 예시 게임이 열리고 모든 요청이 같은 출처·응답 400 이상 0·콘솔 오류 0.
   - 주소 옵션 모두(`?lesson=` 각 차시, `?area=` 다섯, `?grade=5|6`, `?stage=`, `?unlock=all`, `?seed=`, `?fx=low`, 섞은 것)가 그대로 열린다.
   - 결과물의 모든 주소가 상대 주소이고 `/`로 시작하는 주소·바깥 주소 0(결과물 전체를 직접 훑는다), 가리키는 파일이 모두 있다. 해시가 내용에 따라 바뀌는지(파일 하나를 고친 복사본으로 빌드해 견줌 — scratchpad에서).
   - GitHub Pages와 같은 조건인지: `dist/` 전체를 그대로 올리는 구조, `.nojekyll`이 필요한 파일 이름(밑줄로 시작 등)이 없는지, 대소문자.
   - 개발 서버(`npm run dev`)가 그대로 되는지(네 포트에서).
3. **바이트 그대로**: 인트로 그림 두 장의 md5가 저장소·결과물에서 같고(`a0ca1de662f43b43b63964d18f635e0c`·`aa28acc246cf72c99d8a9a5a1367777f`) 출처 정보(C2PA)가 남아 있는지.
4. **영역을 들어갈 때 불러오기**: 처음 화면에서 쌓기나무 묶음을 받지 않는지(네트워크로), 쌓기나무 단계에 들어갈 때·미리 받은 뒤에 기다림, 받는 사이에 나가면 아무것도 그려지지 않고 남는 것이 없는지, 한 번 받은 뒤 다시 받지 않는지. **불러오기 실패**(묶음 요청을 막아 재현): 실패 화면 글이 해요체이고 [새로 고침]이 되는지, 처음 스크립트 실패 때 새로 고침이 **한 번만**인지(되풀이 0). 파일을 나눈 쌓기나무 코드가 내용 그대로 옮겨졌는지(`git diff -M`으로 옮김 확인).
5. **화면 불변**: `cd190ce` 빌드(작업 트리를 바꾸지 말고 `git archive`로 풀어 만든다)와 새 빌드를 같은 서버 조건에서 네 크기(1366×768·1366×680·820×1180·390×844) × 보통·글꼴 흉내로 픽셀 비교 — 인트로(움직임 줄이기), 학년, 영역 다섯, 단계 지도, 모든 단계의 첫 화면, 놀이 방법, 학습 기록, 결과 화면 하나 이상, 예시 게임, 게임 모음(의도한 차이: 선생님 옵션 두 줄). 저장 열쇠·값 그대로, 옛 저장 값으로 연 화면도 같게.
6. **처음 여는 시간**: Build가 잰 표를 같은 방법(7-2절: 하위 경로 서버 gzip, 새 창 5번 가운데값, 네 조건 + `?` 뒤만 바꿔 다시 열기)으로 다시 잰다. `cd190ce`와 견줘 **느린 망에서 더 늦어지지 않았는지**(7-2절이 "여러 파일은 느린 망에서 0.26초 늦을 수 있다"고 적었다 — 실제 값을 적고, 늦어진 만큼이 받아들일 만한지 의견). 게임마다 처음 받는 크기 gzip.
7. **e2e 바탕**: `E2E_PORT`가 다른 두 실행을 동시에 돌려 서로 섞이지 않는지, 포트를 이미 다른 서버가 쓰고 있으면 실패하는지(남의 서버를 재사용하지 않음), 글꼴 흉내 모드가 복사본을 주는지, CI 명령(`npm test`, `npm run test:e2e`, `npm run build`)이 환경 변수 없이 그대로 되는지.
8. **지난 검토 몫**: 숨김 파일(`.DS_Store`)을 그림 폴더에 놓고 단위 검사가 통과하는지(복사본에서), B0c-1을 어느 쪽에 맞췄고 문서·코드가 맞는지, B0c-2(제목 그림 실패 때 글자 제목)·B0c-12, 게임 모음 선생님 옵션의 `?grade`·`?area` 설명이 engine.md와 맞는지.
9. **코드·문서**: 빌드 검사 ①~④가 실제로 잡는지(복사본에서 일부러 깨 봄 — 바깥 주소, 없는 파일, `/` 주소, 그림 바이트), `h()`만·`innerHTML` 없음, 새 패키지 0(`package.json` 의존성·`package-lock.json` 그대로), `docs/dev-guide.md`·`engine.md`·`README.md`가 코드와 맞는지("파일 하나" 문장이 남지 않았는지), README의 "수업 시간에는 올리지 않는다".
10. **느린 기기 검사**: 새로 만들거나 고친 검사를 CPU 4·8·12배로 돌려 값 실패 0.
11. **새로 생긴 문제**, 사용자가 정해야 할 것(선택지와 추천).
