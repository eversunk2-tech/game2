## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e`를 보통과 **글꼴 흉내 모드**로 직접 실행(통과·실패·건너뜀). 0.25px·0.5px도 돌려 지난 값과 나란히. `git diff tests/`로 약해진 검사가 없는지.
2. **N2b-1 (가장 중요)**: 1366×768·1366×680 주사위 주문에서 [시간 재기]를 켜는 순간 — 머리 높이·매트 자리·세로 스크롤·목표 글 줄 수를 보통, 글꼴 흉내(한글 1em + 0.25px), Noto 폭 흉내(0.92em), 한글 0.96·1.0·1.1em에서 잰다. 지난 값(0.96em부터 두 줄, 글꼴 흉내에서 머리 56 → 74.8px·세로 스크롤 15px)과 나란히. **어느 글자 폭에서도 [시간 재기]·연속 칸으로 머리와 매트가 움직이지 않는가, 머리가 두 줄이 되는 글꼴이 있다면 그때도 페이지 스크롤 0인가.** 글꼴 흉내에서 지난번 실패한 2건이 통과하는가. 켠 시계가 보이고 읽히는가(스크린샷), 시간이 흐르는 동안 정보 칸 폭이 흔들리지 않는가(자릿수가 바뀔 때).
3. **머리가 달라진 화면**: 여섯 단계 + 예시 게임 × 네 크기에서 머리·매트·판·무대의 자리와 크기를 `673f871`·지난 재검토 때와 견줘 달라진 곳을 표로. 크롬북에서 제목·목표 글이 한 줄이고 잘리지 않는가. 스크린샷을 직접 열어 머리가 어색하지 않은지(빈 자리, 좁아진 글, 겹침) 본다. 폭을 여러 가지로(지난번 21가지 폭 × 8단계) 연속 칸·시간 재기로 매트가 움직이는 장면 수(지난 값: 연속 칸 0, 시간 재기는 561·900~960px에서 움직임 = N2b-2).
4. **글꼴 흉내 모드가 믿을 만한가**: ⓐ 소스 파일·보통 실행·`dist/`를 바꾸지 않는가(실행 앞뒤 `git status`·diff·해시) ⓑ `673f871`과 `a137a40`을 따로 풀어 이 모드로 돌리면 **실제 CI의 실패 목록과 같은가**(`673f871`: [tablet] 주사위 주문 배치 1건 + 터치 검사는 관성 문제라 여기서는 안 잡힘 / `a137a40`: 조작 띠 2건 + 돌린 전개도 칸 크기 1건) ⓒ 그 글꼴이 없는 환경에서 어떻게 되는가(코드로 확인) ⓓ `helpers.js` 머리말·`docs/engine.md`의 설명이 사실과 맞는가.
5. **새 터치 검사**: 플랫폼에 따라 달라질 정확한 제스처 개수에 기대지 않게 됐는가. 옛 코드(끄는 동안 `touchmove`를 막지 않는 것, click 삼키기를 풀지 않는 것)로 되돌린 복사본에서 여전히 실패하는가(뜻이 살아 있는가). 리눅스에서 달라질 수 있는 부분이 남았는지 코드로 판단(추정으로 적는다).
6. **깨지지 않았는가(지난 스크립트로 다시)**: CI-1(태블릿 주사위 두 번째 완성: 머리 고정·어긋남 0px·세로 여유 67·67·43px), CI-2(빠른 터치 끌기 뒤 관성 0, 끈 직후 탭이 먹힘, 끌지 않을 때 페이지 스크롤·두 손가락 벌리기 그대로), N2-3(주사위 별 0·1·2번, 점수 독립 계산 일치), 예상 관련 말 0, 까닭 노출 0, 주사위 접기 전 노출 0, 도감 이어 하기, 답하기 전 화면 = V1 이전(조작 띠), 보기 조작, 세 크기 스크롤 0·판 넘침 0·48px·판 → 무대 어긋남 0px, 예시 게임, 콘솔 오류 0.
7. **범위·코드**: 허용 파일 안인가(`drag-drop.js`가 지난 재검토 때와 같은가). 넓힘·글꼴 흉내 코드가 테스트 바탕에만 있는가. `h()`·`innerHTML` 없음.
