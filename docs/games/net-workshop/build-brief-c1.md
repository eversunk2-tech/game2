# Build 서브에이전트 지침: 파일 크기 검사 걷어내기 + 흔들리는 CI 검사 고치기 (트랙 "c1")

## 역할

너는 **Build** 담당이다. 게임 코드가 아니라 **빌드 스크립트·검사·문서의 작은 손질 두 가지**를 한다. 검증은 별도 Review 서브에이전트가 한다. 지침에 적힌 범위만 고친다.

## 배경

1. **"게임 파일 하나는 400 KB 이하" 규칙은 사용자 결정(2026-10-09)으로 없어졌다**("단일 html로 하지 않아도 돼… 자유로운 용량으로 만들어줘", 학생들은 사이트 주소로 접속한다 — `docs/dev-guide.md` 37행의 결정 메모). 그런데 `scripts/build.mjs`는 아직 400 KB를 넘으면 빌드를 멈춘다. 지금 따로 만들고 있는 두 영역(직육면체, 쌓기나무)을 `main`에 합치면 `net-workshop.html`이 약 421 KB가 되어 빌드가 멈춘다. 합치기 전에 검사를 걷어낸다.
   - **이번에 하지 않는 것**: 여러 파일로 내보내기, 영역별로 나눠 불러오기(다음 단계 "B0"의 몫). 지금은 "HTML 한 파일로 묶는 것"은 그대로 두고 **크기 상한만** 없앤다. 바깥 참조 검사(`findExternalRefs`), 제목 글꼴 넣기는 한 글자도 바꾸지 않는다.
2. **GitHub CI(리눅스)에서 흔들리는 검사 1건**: 문서만 바꾼 커밋 `cd6a39c`(코드는 통과했던 `3b48260`과 같다)의 CI가 실패했다 — `tests/e2e/engine-features.spec.js:177` "플레이 머리 높이는 판을 하는 동안 바뀌지 않는다 …"가 [chromebook]·[tablet] 모두 `ch1 시간 재기를 끔`에서 `.timer-toggle`의 위 자리가 78 대신 77.47.
   - 코디네이터가 찾은 원인(네가 다시 확인한다): `.btn`은 포인터가 올라가면 1px 들뜨고(`base.css` 195행 `translateY(-1px)`) 0.12초에 걸쳐 가라앉는다(193행 `transition: transform var(--dur-1)`). 검사는 [시간 재기]를 누른 뒤 `page.mouse.move(0, 0)`으로 포인터를 떼고 **가라앉는 움직임이 끝나기를 기다리지 않고** 자리를 잰다. 빠른 기기에서는 들뜨기도 전에 포인터가 떠나 어긋남이 없지만, 느린 기기에서는 도중에 재게 된다. **앱 문제가 아니라 검사의 기다림 문제**다.
   - 코디네이터의 재현(임시 복사본, 크롬의 CPU 느리게 하기 `Emulation.setCPUThrottlingRate`를 검사 앞에 넣어서): 고치기 전 6배 느리게에서 6번 중 6번 같은 자리(`시간 재기를 끔`)에서 실패. 버튼과 그 안의 움직임이 끝날 때까지 기다리는 줄을 세 번의 누르기 뒤에 넣으니 12배·20배 느리게에서 16번 중 16번 통과. "켬" 쪽은 `.timer-label`의 움직임만 기다리고 있어 12배 느리게에서 드물게(12번 중 1번, 61.99 ≠ 62) 실패했다 — 버튼 자신의 움직임도 기다려야 한다.

## 할 일

### 1. 크기 상한 없애기

- `scripts/build.mjs`: 400 KB를 넘어도 빌드가 멈추지 않게 한다. `MAX_FILE_BYTES`와 그 오류는 없앤다(쓰는 곳을 모두 찾아 함께 — `scripts/**`, `tests/**`). 파일 크기를 로그에 찍는 것(`✓ dist/…  (… KB, …)`)은 그대로 둔다. 파일 머리말 주석의 옛 문장도 고친다.
- `tests/unit/build.test.js`: 49행 근처 검사 이름과 `MAX_FILE_BYTES` 단언을 새 뜻에 맞게(크기 상한 단언만 빼고 **나머지 단언은 그대로**), 161–164행 "400 KB를 넘으면 빌드가 멈춘다"는 **"400 KB를 넘어도 빌드가 되고, 그 파일이 열리는 내용 그대로 나온다"**를 고정하는 검사로 바꾼다(지우지 않는다 — 뜻이 바뀐 검사를 새 뜻으로).
- 문서의 옛 문장: `docs/engine.md` 302행(400 KB 이하 문장), `README.md` 93행의 "파일 크기(400 KB 이하)를 검사", `docs/dev-guide.md` 37–38행(37행 결정 메모의 "빌드 스크립트의 크기 검사 … 아직 옛 규칙 그대로다"를 사실에 맞게 — 크기 검사는 걷어냈고, 한 파일로 묶기는 B0에서 바꾼다 / 38행 끝의 "게임 파일 하나는 400 KB 이하(빌드가 검사)"). "HTML 파일 하나로 빌드된다"는 문장들은 아직 사실이므로 그대로 둔다. 다른 곳에 같은 옛 문장이 남았는지 `grep`으로 훑는다(`docs/games/**`·`docs/STATUS.md`·`docs/HANDOFF.md`·`CLAUDE.md`는 코디네이터의 것이라 고치지 않는다 — 남은 곳은 보고만).

### 2. 흔들리는 검사 고치기

- `tests/e2e/engine-features.spec.js`의 그 검사 하나에서, [시간 재기]를 누르고 포인터를 뗀 **세 곳 모두**(켬 · 끔 · 다시 켬) 자리를 재거나 다음 행동으로 넘어가기 전에 **버튼과 그 안(`.timer-label`)의 움직임이 끝날 때까지** 기다리게 한다(예: `document.querySelector('.timer-toggle').getAnimations({ subtree: true }).every((a) => a.playState === 'finished')`를 `waitForFunction`으로). 정해 둔 시간(`waitForTimeout`)으로 기다리지 않는다.
- **검사의 뜻을 약하게 만들지 않는다**: 기대값은 여전히 "처음 자리와 0.01px까지 같음"(`toEqual(start)`)이다. 허용 오차를 넣거나 재는 항목을 빼지 않는다.
- 같은 종류(포인터를 올렸다 뗀 직후, 또는 `.btn`을 누른 직후에 **그 버튼의 자리**를 0px로 견주는 곳)가 이 파일과 `tests/e2e/net-workshop.spec.js`에 더 있는지 훑어 목록으로 보고한다. 분명히 같은 문제인 곳만 같은 방법으로 고치고, 애매한 곳은 고치지 말고 보고한다.
- 앱 코드(`src/**`)는 고치지 않는다.

## 직접 확인할 것

- 고치기 **전** 상태에서 느리게 하기로 실패가 재현되는지, 고친 **뒤** 6배·12배·20배 느리게에서 `--repeat-each=8` 이상으로 실패 0인지. 느리게 하기는 scratchpad에 푼 복사본에서만 넣는다(저장소의 검사 파일에 재현용 코드를 남기지 않는다). 복사본은 `git archive HEAD | tar -x -C <scratchpad 안 폴더>` + `node_modules` 링크로 만든다.
- 400 KB를 넘는 게임이 실제로 빌드되고 브라우저에서 열리는지(임시 폴더의 시험용 게임으로 — 단위 검사가 하는 방식).
- `npm test`, `npm run test:e2e -- --workers=3`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=3` 모두 실패 0(마지막 커밋에서 처음부터). 다른 트랙들이 같은 때에 브라우저 테스트를 돌리므로 시간 제한 실패는 혼자 다시 돌려 부하 탓인지 가린다.
- 빌드 결과물이 달라지지 않았는지: 고치기 전·후의 `dist/*.html` 세 파일의 해시가 같다(크기 검사는 내용을 바꾸지 않는다).

## 고쳐도 되는 파일

- `scripts/build.mjs`, `tests/unit/build.test.js`, `tests/e2e/engine-features.spec.js`(그 검사와, 분명히 같은 문제인 곳), `tests/e2e/net-workshop.spec.js`(분명히 같은 문제인 곳만)
- `docs/engine.md`·`README.md`·`docs/dev-guide.md`의 위에 적은 문장
- 고치지 않는 것: `src/**`, `scripts/` 의 다른 파일(`MAX_FILE_BYTES`를 쓰는 곳이 있으면 그 줄만), `docs/games/**`, `docs/STATUS.md`·`docs/HANDOFF.md`·`docs/design/**`, `CLAUDE.md`, `tests/e2e/helpers.js`·`playwright.config.js`, package 파일, `.github/**`, `.claude/**`

## 지킬 것

- 작업 폴더·브랜치·scratchpad는 코디네이터가 프롬프트로 알려 준다. 그 폴더에서만 일한다. `npm install`·`npm ci`·내려받기 금지(`node_modules`는 링크). 커밋은 그 브랜치에만, 푸시·합치기는 하지 않는다. 최종 상태는 커밋해 둔다.
- 다른 두 트랙이 `docs/engine.md`(187행 근처, 그리고 모음·점수 절)를 고치고 있다 — **302행의 그 문장만** 고치고 둘레의 줄은 건드리지 않는다.
- 공개 저장소다. 이모지 없음, 주석은 한국어로 짧게(둘레의 주석 밀도에 맞춘다).

## 최종 보고 (10줄 이하)

크기 상한(무엇을 없앴고 무엇을 그대로 뒀는지, 바뀐 검사와 새 뜻, 빌드 결과물 해시), 흔들리는 검사(원인을 다시 확인한 결과, 고치기 전·후 느리게 하기 배수별 실패 수/횟수, 넣은 줄), 같은 종류로 더 찾은 곳 목록(고친 곳·안 고친 곳), 고친 문서 문장(파일:줄)과 고치지 않고 남은 옛 문장, 테스트 결과(단위·보통·글꼴 흉내), 못 한 것, 마지막 커밋 해시. 직접 실행해 확인한 것과 추정을 구분한다.
