## 고칠 것

1. **R4 (반드시)**: 학습 기록 [기록 모두 지우기] → "한 번 더 누르면 지워져요"(`.btn.is-confirm`, 벽돌 글자 16px)
   - 지금 문제: 마우스를 올리면 대비 4.34, 누르면 3.70이다. `.btn:hover` · `:active`가 면을 옅은 파랑으로 덮어서다.
   - 고칠 방향: 올림 · 누름에서도 **벽돌 계열 면**을 지켜 글자 대비 4.5 이상으로 한다. 기준 빌드는 올림 5.81 · 누름 4.95였다.
   - 같은 원인이 `.edge-opt.is-wrong`(직육면체 "만나는 선분"의 틀린 보기, 벽돌 글자 20px 굵게)에도 있다. 지금은 큰 글자라 통과하지만 함께 지킨다.
   - **비슷한 곳을 더 찾는다**: 색 글자(벽돌 · 초록 · 흐린 글자 등)를 쓰는 `.btn` · 답 버튼 · 칩 버튼에 올림 · 누름 면 색이 덮여 대비가 떨어지는 곳. 계산된 색으로 전부 잰다.
   - 검사를 더한다: 이 버튼들의 쉼 · 올림 · 누름 글자 대비가 기준 이상인지 본다. 고치기 전 코드에서 실패하는지 직접 확인한다.
2. **R1**: 아래 가장자리를 누르면 안 눌리는 띠가 넓어졌다.
   - 버튼 · 탭 · 답 · 조작판 2px, 단계 카드 3px, 학년 · 영역 카드 4px이다. 기준은 1~2px였다.
   - 떠오른 만큼 마우스 밑에서 빠져 click이 가지 않는다.
   - 고칠 방향: **모양은 그대로 두고, 누르는 자리만 남긴다.** 예: 떠오를 때 아래로 그 거리만큼 누르는 자리를 늘리는 투명한 가상 요소를 둔다. 가상 요소가 이미 쓰이는 부품은 다른 방법을 쓴다.
   - 볼 것:
     - 쓰는 방법이 레이아웃 · 겹침 · 이웃 버튼의 누르는 자리를 침범하지 않는지 본다. 간격이 좁은 도구 띠 · 탭 · 숫자 칸에서 특히 본다.
     - 가만히 둔 동안 오르내림(깜빡임)이 생기지 않는지 본다.
   - 검사를 더한다: 아래 끝 1~4px에서 눌러도 click이 가는지 본다(움직임 켬). 고치기 전 코드에서 실패하는지 직접 확인한다.
   - Review가 쓴 재는 방법: `.worktrees/_saved-scratchpad-2026-11-19/review-depth/`의 `tools/edgejitter.mjs`(읽기만, 복사해서 써도 됨)
3. **R2**: 토큰 없이 적은 새 색을 토큰으로 옮긴다. 모양은 그대로 둔다.
   - `base.css`(`.xp-bar` `#e6dece`), `cuboid.css`(`.dex-meter` `#e6dece`), `style.css`(`.answer-btn:hover` `#f3f6ff`)
   - 예: `--track`, `--answer-up`
