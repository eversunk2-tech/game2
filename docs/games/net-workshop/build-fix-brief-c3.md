# Build 서브에이전트 지침: 끌기 안내가 가끔 숨는 앱 문제 + "머무는 시간" 검사 (트랙 "c1"의 후속 "c3")

## 역할

너는 트랙 c1의 **Build** 담당이다. c2(이미 있던 검사의 흔들리는 곳)는 Review를 통과해 `main`에 합쳐졌다. 그 Review가 `main`에 이미 있던 **앱의 작은 문제 하나**(c2-1)와, c2·M2c에서 "지나간 값을 적어 두고 보기"로 바꾸며 생긴 **검사의 약한 곳**(c2-2, 직육면체 M2c-1)을 찾았다. 이번에 그 둘을 고친다. 검증은 별도 Review 서브에이전트가 한다. 다른 Build 둘(영역 화면 B0a, 쌓기나무 3·4차시 S2)이 같은 때에 다른 폴더에서 일한다.

- 작업 폴더의 `docs/games/net-workshop/review-c1.md` 맨 아래 "재검토 (c2: …)" 절 — "새로 찾은 앱의 흔들림 (c2-1)", 문제 표의 c2-1·c2-2·c2-3·c2-5, "정할 것"

## 반드시 지킬 것

- **앱 변경은 C3-1뿐이다.** 그 밖의 앱 코드는 고치지 않는다. C3-1 뒤 정육면체·직육면체 차시의 플레이 화면(움직임 줄이기·`?fx=low` 포함)이 기준(`main`의 지금 커밋)과 같은지 수치로 보인다(접기 장면의 DOM·자리·저장 값. 움직임이 끝난 뒤의 장면을 견준다).
- C3-1을 고친 것을 **결정적으로** 보인다: Review가 쓴 방법(첫 프레임 시각을 일부러 앞당기기)을 scratchpad 복사본에 넣어 고치기 전 매번 숨고, 고친 뒤 0번 숨는지. 저장소에는 재현용 코드를 남기지 않는다.
- C3-2의 새 단언이 **회귀를 잡는지** 보인다: 복사본의 앱에서 반 접힘 머무는 시간을 0·50ms로, 알림 시간을 300ms로 줄이면 실패하고, 앱 값 그대로면 CPU 4·8·12배에서도 통과(`--repeat-each=10` 이상).
- 기대값·재는 항목·장면 수를 줄이거나 느슨하게 하지 않는다. `waitForTimeout`·`retries` 금지.
- 테스트: `npm test`, `npm run test:e2e -- --workers=4`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0(마지막 커밋에서 처음부터). 다른 일꾼이 같은 때에 테스트를 돌린다 — 값이 어긋나는 실패는 부하 탓으로 넘기지 않는다.

- `src/games/net-workshop/view3d.js`(C3-1), 같은 꼴이 분명한 다른 앱 파일(그 줄만, 보고), `tests/e2e/net-workshop.spec.js`, `tests/e2e/net-workshop-cuboid.spec.js`, `tests/e2e/net-workshop-free-finish.spec.js`

## 합칠 때 부딪히지 않게

영역 화면 트랙(B0a)이 같은 때에 `tests/e2e/net-workshop.spec.js`에서 **처음 화면 → [시작하기] → 단계 지도로 걸어가는 검사**와 **게임 이름 글자**를 찾는 곳을 고친다. 그 검사들(처음 화면·단계 지도·놀이 방법·게임 이름이 나오는 검사)은 건드리지 않는다. 도우미를 더할 때는 파일 맨 위 도우미 묶음의 끝에 덧붙인다.

## 지킬 것

- 작업 폴더·브랜치·scratchpad는 코디네이터가 프롬프트로 알려 준다. 커밋은 그 브랜치에만, 푸시·합치기는 하지 않는다. `npm install`·내려받기 금지. 띄운 실행·서버는 모두 내리고 끝낸다.
