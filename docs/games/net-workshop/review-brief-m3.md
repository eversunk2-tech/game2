# Review 서브에이전트 지침: M3 직육면체 전개도 탐구 넓히기 (트랙 "cuboid")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-m3.md](build-brief-m3.md)에 따라 만든 것을 **독립적으로** 검증한다. Build와 분리된 검토자다.
- **검토 결과는 새 파일 `docs/games/net-workshop/review-m3.md`에 쓴다**(트랙의 작업 폴더 안). 맨 위에 판정 줄, 그 아래 기존 review 파일과 같은 형식의 표. 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지.
- **트랙의 작업 폴더에서만** 일한다(코디네이터가 프롬프트로 알려 준다). 검증 파일·스크린샷·기준 빌드는 정해 준 scratchpad 폴더에만. Build의 scratchpad는 근거로 삼지 않는다.

## 검토 대상

기준 커밋 `55c7053`(이 컴퓨터의 `main` — 영역 화면 B0a와 작은 수정 c3가 들어 있다)과 트랙 브랜치의 마지막 커밋 사이의 변경 전부. 고쳐도 되는 파일은 build-brief-m3.md의 목록이다 — **`blocks/**`·정육면체 단계(`play-judge.js`·`play-pick.js`·`play-place.js`·`play-dice.js`)·`scripts/**`가 바뀌었으면 범위 위반**이다. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내로 직접 실행. 알려진 실패 2건(쌓기나무 "단계 지도: 쌓기나무 두 차시가…", 옛 처음 화면 탓 — 다음 Build B0c 몫)은 이 트랙의 판정에 세지 않는다. `git diff 55c7053..HEAD -- tests/`로 약해진 검사가 없는지.
2. **수학·판정 (가장 중요)**: 저장소의 `fold.js`·`cuboid-logic.js`를 쓰지 않는 **독립 계산(직육면체 감싸기)**으로 — 크기 64가지(1~4 cm × 3) × 무작위 배치에서 되는/안 되는 판정, 상자 종류별 가짓수(54·29·11), **표준 모양 이름(id)이 크기를 바꿔도 같은 모양이면 같고 다른 모양이면 다른지**(예: 1·2·3과 2·3·4, 1·1·2와 2·2·3, 길이의 차례를 바꾼 상자), 돌리기·뒤집기를 같은 모양으로 보는지.
3. **점수(독립 계산)**: 기획서 문장과 지침만 보고 짠 모형 ↔ 엔진 — 크기를 섞은 무작위 여러 기기·여러 판(`cuboid-free`와 도감 주문 섞어), 나가기·새로 고침·**탭 두 개**에서 "처음 10가지"(세 길이 다름 + 두 길이 같음 합쳐)의 경계가 흔들리지 않는지, 같은 전개도를 두 단계에서 두 번 받지 않는지, 정육면체 상자로 찾은 것이 정육면체 도감의 규칙대로인지(이미 찾은 것이면 0), 일부러 틀려 이득 0, 화면 = 저장. 사이트에 이미 있는 직육면체 도감 기록(옛 저장 값)이 그대로 이어지는지.
4. **상자 크기 정하기**: 네 크기에서 크기 고르기(± 또는 칩, 48px, 키보드, 화면 읽기), 작은 입체(돌려 보기, 길이 이름표가 바로 서는지), 면 카드 6장의 크기 표시, 크기를 바꿀 때 놓인 면 거두기와 확인 묻기, 정육면체 안내. **64가지 크기 × 1366×768·1366×680·820×1180**에서 스크롤 0·판 넘침 0·면이 판에 들어감·머리와 매트 움직임 0(큰 상자 4·4·4도). 끝내기·별(2가지 끝냄, 3가지 ★3)이 크기와 관계없이 맞는지, "서로 다른"을 상자 종류별 표준 모양으로 세는지.
5. **도감 주문(`cuboid-dex`)**: 도전 주문서로 등록(일반 단계를 마치면 열림, 별 합계에 안 넣음, 시간 재기는 켜는 학생만), 세 길이가 다른 상자만(같은 길이를 고르면 안내), 여러 번에 나눠 해도 이어짐, [오늘은 여기까지], 별 10·20·30(결과 화면 안내), 54가지 "완성" 도장(가짜 저장 값으로 54가지를 채워 확인), 54칸 도감 화면이 세 크기와 휴대폰에서 넘치지 않음, 학습 기록 "n / 54", 힌트는 아직 못 찾은 전개도만, 도감 칸·힌트에 못 찾은 전개도가 드러나지 않음.
6. **돌리기 손잡이**: 마우스·터치·키보드 각각 — 고르면 손잡이, 끌어 돌리면 따라 돌고 놓으면 90° 맞춤, 판에 들어가지 않으면 제자리와 알림, 끄는 중 둘째 손가락 톡·오른쪽 버튼·R 키로 90°. **누르기·끌기·손잡이 돌리기를 헷갈리는 일 0**(8px 문턱, 끈 뒤 따라오는 click, `touchmove` 막기, 끈 직후 탭 — 여러 속도·방향으로 재서), 두 번 누르기·[돌리기]·키보드 돌리기 그대로, 48px·초점·화면 읽기. **정육면체 `cube-free`·도감 주문에서는 손잡이가 보이지 않고 화면이 기준과 같음**.
7. **불변**: 기준 `55c7053` 빌드와 견줘 정육면체 차시(4단계 + 도전 2), 직육면체 1~3단계, 쌓기나무 차시, 영역·학년 화면, 예시 게임의 화면·점수·기록 차이 0. `cuboid-free`를 처음 값(1·2·3 cm)으로만 하는 판의 점수·기록이 기준과 같음.
8. **교실 기기·접근성·코드**: 세 크기 + 휴대폰 + 1024×768, 키보드만으로 크기 고르기 → 놓기 → 돌리기 → 접기 → 도감 주문 끝까지, 색만으로 구분하지 않음, 대비, 움직임 줄이기·`?fx=low`, 해요체, `h()`만·이모지 없음, 나간 뒤 리스너·타이머 0, 콘솔 오류 0. 네 크기 스크린샷을 직접 연다.
9. **느린 기기**: scratchpad 복사본에 CPU 느리게 하기(4·8·12배)를 넣어 이 트랙의 검사를 돌려 값 실패 0, 새 검사가 움직임이 끝난 뒤에 재는지·사라지는 알림을 조작 바로 뒤에 보는지·머무는 시간·시간 예산.
10. **범위·합치기**: 허용 파일 안인지, 엔진·`main.js`·`free-board.js`에서 고친 줄, 쌓기나무 트랙(`track/blocks`)과 `git merge-tree --write-tree`로 줄 충돌.
11. **새로 생긴 문제**, 사용자가 정해야 할 것(선택지와 추천), Build가 정한 세부에 대한 의견. 도감 주문 10가지를 찾는 데 걸리는 시간에 대한 의견(Build의 기록과 직접 해 본 것).
