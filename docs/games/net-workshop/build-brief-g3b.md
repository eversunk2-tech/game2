## 만들 것 (G3b)

1. **3단계 `cylinder-size` "옆면의 가로와 세로"**(plan 3-3):
   - 앞 2문항 — 카드:
     - 옆면 카드 셋을 빈 자리에 놓고 [말아 보기]. 한 번 틀린 뒤 [굴려 재기].
     - 카드 묶음 손질 ①: 판의 한 문항은 지름 카드를 꼭 넣는다. "가장 긴 것" · "가운데 것" 규칙이 찍기(33%)보다 크게 높지 않게 시드로 재서 단위 검사로 고정한다.
   - 뒤 2문항 — 계산: 숫자판으로 답한다. 틀린 값으로 까닭을 알리고, 두 번 틀리면 [힌트]로 식을 보인다.
   - 4문항. 길면 3문항으로 — 시간을 재서 정하고 까닭을 보고한다.
2. **숫자판 부품** `grade6/number-pad.js`(plan 3-3 · 5-6):
   - 0~9 · 소수점 · 지우기 · [확인하기], 칸 48px
   - 키보드 숫자 키 · 소수점 · Backspace · Enter, 화면 읽기
   - 입력 칸 길이는 늘 같다(답의 자리 수를 드러내지 않음).
   - "18.84"와 "18.840"을 같은 값으로 맞게 본다. cm는 칸 밖에 고정한다.
3. **4단계 `cylinder-free` "전개도 완성하기"**(plan 3-4 · ④ (가)):
   - 판 · 배치: 각기둥 4단계와 같은 판 · 배치 · 손짓(15-26 시안 B · 15-30~15-32). 주문 3개, 9가지 원기둥.
   - 카드: 옆면 3장(둘레 · 지름 · 반 바퀴, 길이 글). 원 두 묶음, **둘 다 ×2**.
   - 붙기:
     - 원은 옆면 변 가까이 1 cm 안이면 접하게 붙는다.
     - 붙은 채 끌면 변을 따라 미끄러지고 끝에서 멈춘다.
     - 길이가 맞든 안 맞든 같은 모습 · 소리 · 안내로 붙는다.
   - 조작:
     - 돌리기는 옆면만 90°씩이다.
     - [말아 보기] 결과: 꼭 맞음 / 틈 / 겹침 / 안 맞는 원 / 자리가 안 맞는 원
     - 안 되면 → "왜 안 될까요?"(고른 까닭 먼저) → [펴서 고치기]
   - 끝 · 별: 2개면 끝, 3개면 ★3. 안 되게 말아도 별이 안 깎인다.
   - 점수: 처음 완성한 원기둥 +2 · 등록 +5, 보이지 않는 모음 9칸, `scored: 'once'`, 바로 저장.
   - 엇갈린 자리로 완성하면 쪽지를 보인다. 점수는 없다.
   - 자석 판의 처리:
     - `magnet-board.js`에 규칙 묶음을 넘기는 자리를 만든다. 기본값 = 지금 각기둥 규칙 그대로.
     - 그것이 각기둥 판을 한 픽셀이라도 흔들면 `cylinder-board.js`를 새로 만든다. 어느 쪽을 골랐는지 까닭을 보고한다.
4. **도장 "원기둥 설계사"**(⑥): "원기둥의 전개도를 주문대로 3개 완성해요" — 4단계 기록으로 판정하는 순수 함수로, 여러 판을 합쳐 센다. 도장판 18칸.
5. **원주율** `?pi=3` · `3.1` · `3.14`(⑤ 5-2):
   - 한 판의 계산 거리 다섯에 두 가지 이상의 값이 나오게 한다.
   - 그 밖의 값은 무시한다.
   - 선생님용 안내(`scripts/lib/hub.mjs` `URL_OPTIONS`)에 한 줄을 넣는다.
6. **영역 둘레**(⑥ G3b 몫):
   - 차시 `cylinder`에 단계 3 · 4를 더한다.
   - 단계 그림, 놀이 방법 나머지 줄
   - 학습 기록 tag `원주 계산`
   - 6학년 · 내 공방 별 합계 — 단계 넷만큼, 네가 세어 보고한다.
   - 차시 시간 칩 — 네 단계를 자동으로 해 본 시간으로 정하고 까닭을 보고한다.

## 차례 — 화면은 시안부터

- **차례 1 = 시안만 만들고 멈춰 보고한다**(plan ⑦ G3b 차례 1).
  - 실제 빌드에 덧씌워 찍는다. 시안용 코드는 scratchpad에 둔다.
  - 시안 목록:
    1. **4단계 조작 "지금(각기둥 4단계) + A · B · C" 한 장**:
       - A 붙은 원이 변을 따라 끊김 없이 미끄러짐(plan 추천)
       - B 0.5 cm 눈금마다 딱딱 붙음
       - C 놓으면 변의 가운데에 붙고 붙은 채 끌면 옮겨짐
       - 함께 보일 것: 카드 칸(옆면 3장 · 원 두 묶음 ×2), 판에 셋보다 많이 놓으려 할 때의 모습
    2. 4단계 말아 본 결과(꼭 맞음 · 지름 카드 · 반 바퀴 카드 · 크기 다른 원 · 같은 변 · 짧은 변), 결과 화면, 만든 원기둥 칸

       - 카드 판(원 둘 고정 + 빈 자리 + 카드 셋)

## 반드시 지킬 것

- **공통 규칙과 공개 저장소**
  - [common-rules.md](common-rules.md) 전부를 지킨다.
  - **공개 저장소**다 — 교과서의 문장 · 그림 · 문제 수치를 옮기지 않는다. 생활 장면 · 예시 수는 새로 만든다.
- **바뀌면 안 되는 화면**
  - 원기둥 1 · 2단계 · 각기둥 · 정육면체 · 직육면체 · 쌓기나무(자유 쌓기 큰 판 포함) 화면은 한 글자 · 한 픽셀도 바뀌지 않는다.
  - 기준은 지침을 맡긴 `main` 커밋이다(프롬프트로 알려 준다).
  - 의도한 차이만 있어야 한다: 원기둥 단계 지도에 3 · 4단계 · 6학년 · 내 공방 별 합계 · 도장 0 / 18 · 도장판 18칸 · 원기둥 놀이 방법 줄 · 안내의 `?pi=` 한 줄 · 차시 시간 칩.
- **정답 노출 0**(plan 3-3 · 3-4 "정답 노출" 줄)
  - 카드 · 원 묶음 · 숫자판의 DOM 속성 · 클래스 · `aria-*` · 화면 읽기 이름 · DOM 차례에 정답과 관련된 값이 없다.
  - 정답을 찾는 검사는 같은 시드로 logic을 불러 셈한다. DOM에 숨기지 않는다.
  - 새 노출 검사는 일부러 노출을 넣으면 실패하는지 확인한다.
  - 짐작 규칙("가장 긴 카드" · "가운데" · 원 묶음 모양)의 정답률을 시드 수백 개로 재서 단위 검사로 고정한다.
- **독립 계산**
  - 판정 · 점수 · 별 · 도장 · 원주율 답을 기획서 문장만으로 짠 독립 계산과 견준다(plan ⑧ 테스트 계획 G3b 몫).
  - 일부러 틀려 이득 0, 화면 = 저장.
- **브라우저 검사**
  - 처음부터 느린 기기를 견디게 짠다. `waitForTimeout` · `retries`는 쓰지 않는다.
  - **움직임이 끝난 뒤에 잰다.**
  - 끝내기 전에 새로 만들거나 고친 검사를 CPU 4 · 8 · 12배로 돌려 값 실패 0이어야 한다.
  - 말기 · 굴려 재기 · 끌기의 프레임 간격을 CPU 1 · 4 · 8배로 재서 보고한다.
- **배치**
  - 여섯 크기 × 보통 · 글꼴 흉내에서 3 · 4단계 모든 장면(답하기 전 · 말린 뒤 · 까닭 고른 뒤 · 굴려 재기 · 숫자판 · 2 · 3개 완성 · 결과)을 잰다.
  - 스크롤 · 넘침 · 겹침 0(휴대폰 세로 스크롤은 규칙대로), 누르는 곳 48px, 알림이 조작을 가리지 않음, 판 → 무대 어긋남 0px.
- **조작**
  - 키보드만 · 마우스만 · 터치만으로 3 · 4단계 끝까지 갈 수 있다.
  - 화면 읽기 문장, 움직임 줄이기 · `?fx=low`도 본다.
- **기존 검사**
  - 바뀌는 기존 검사는 뜻이 바뀐 줄만 고친다(별 합계 · 도장 칸 수 등) — 줄마다 까닭을 보고한다. 약해진 검사 0.
  - **지침에 없는 기존 검사를 바꿔야 하면 바꾸기 전에 보고한다.**
- **테스트**: 세 가지 모두 실패 0이어야 한다(마지막 커밋에서 처음부터, 하나씩 차례로).
  - `npm test`
  - `E2E_PORT=5361 npm run test:e2e -- --workers=4`
  - `E2E_PORT=5361 E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`
  - CPU 배수 실행은 다른 실행과 기록 폴더가 겹치지 않게 한다.

  - 다른 화면 픽셀이 같음
- 보고에 담을 것:
  - 만든 것(3 · 4단계 · 숫자판 · 도장 · `?pi=`), 고른 시안대로인지

  - 불변 비교 수치, 바꾼 기존 검사 줄과 까닭
