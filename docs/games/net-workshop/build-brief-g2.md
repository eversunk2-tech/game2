# Build 서브에이전트 지침: G2 각기둥의 전개도 2 — 4단계 `prism-free` + 도전 `prism-count` (트랙 "cuboid" 작업 폴더)

## 역할

너는 **Build** 담당이다. 승인된 6학년 계획([spec-grade6.md](spec-grade6.md))의 **G2 — 각기둥 차시 4단계 "전개도 완성하기"(`prism-free`)와 각기둥 도전 "모서리와 꼭짓점"(`prism-count`)**을 만든다. 1~3단계는 G1에서 사이트에 올라가 있다. 검증은 별도 Review 서브에이전트가 한다.

사용자의 말(2026-10-20, spec-grade6 15-25): 멈춰 두었던 각기둥 4단계를 **"각기둥 4단계 시작 (추천)"**, 후보였던 도전을 **"함께 넣기 (추천)"**. 원기둥(G3)은 여전히 멈춤 — 원기둥 파일·등록은 건드리지 않는다.

## 만들 것

1. **4단계 `prism-free` 전개도 완성하기(설계 주문)** — 2-2절 표와 그 아래 문단 그대로:
   - 그 판의 시드가 삼각기둥(밑면이 정삼각형이 아님) → 사각기둥(밑면이 **직사각형이 아닌** 사각형) → 육각기둥 가운데 하나를 고른다. 각기둥 입체(길이 적힘)를 보여 주고, **일부만 놓인 전개도**에 남은 면 카드를 모서리에 붙여 완성 → 예상 없이 [접어 보기](15-2) → **다른 모양으로 한 번 더**(이번에는 밑면 하나만 놓여 있음).
   - 면 카드를 고르면 빈 모서리마다 48px "붙일 자리"(5학년 방식). 옆면 카드는 가로가 서로 다르다(밑면의 변 길이) — 길이가 안 맞는 모서리에 붙이면 접었을 때 맞닿는 두 선분에 같은 무늬와 "5 cm ≠ 3 cm"(4절, `wrong-hinge`). 면이 모자라면 점선 "비어요", 겹치면 겹침 표시(4절).
   - 끝: 서로 다른 전개도 2가지 → [결과 보기]. 별은 찾은 가지 수(15-2·spec 16-14·16-15 — 3가지면 별 3개). 안 되는 모양을 접어도 별이 깎이지 않는다. 점수는 이 기기에서 처음 만든 모양만(`scored: 'once'`, 모양의 같음은 G1b의 합동 열쇠 — 8절).
   - 도장 **"기둥 설계사"**(각기둥 전개도를 서로 다른 모양으로 2가지 완성 — 8절, 학습 기록으로 판정하는 순수 함수). 도장판이 16칸 → 17칸.
2. **도전 `prism-count` 모서리와 꼭짓점(셈 주문)** — 2-2절 줄·8절 "도전 주문서": 한 밑면의 변의 수를 보고 모서리·꼭짓점(필요하면 면)의 수 맞히기 → 규칙 고르기(예: "모서리 = 한 밑면의 변의 수 × 3"을 보기에서). 5문항. 각기둥 차시를 마치면 열리고 별 합계에 넣지 않는다(정육면체 도전·쌓기나무 `blocks-add`와 같은 방식). 입체를 돌려 보며 셀 수 있게(G1의 입체 무대). 보기의 함정은 4절·공통 규칙(값만 보고 고르기가 찍기보다 크게 높지 않게, 흔한 실수 — 예: 꼭짓점을 한 밑면만 셈, 모서리를 옆면 모서리만 셈 — 판마다 한 번 이상). 정답 노출 0(답하기 전 입체 무대에 수 표시 없음).
3. **등록**: 각기둥 차시를 4단계로(단계 지도·놀이 방법·영역 카드의 별 합계·시간 칩이 4단계에 맞게), 도전을 각기둥 영역에 등록, 도장 하나. `?stage=prism-free`·`?stage=prism-count`. 늦게 불러오기: 문제 만들기·판정·화면은 각기둥 묶음(`grade6/`)에, 단계 목록·그림만 처음 묶음에. 처음 화면이 받는 크기(gzip) 전·후를 보고.
4. G1 Review가 남긴 것은 할 수 있는 만큼(거의 옆으로 선 가는 면, 비스듬한 면의 ✓) — 못 하면 잰 값만.

## 차례 — 화면은 시안부터 (CLAUDE.md "화면을 바꾸는 요청은 시안부터")

- **차례 1 = 배치 시안만 만들고 멈춰 보고**: `prism-free` 판(입체 그림·놓인 전개도·남은 면 카드·붙일 자리·[접어 보기]·찾은 가지)과 `prism-count` 화면을 **실제 빌드에 덧씌워** 크롬북 1366×768·세로 태블릿 820×1180·휴대폰 390×844에서 찍는다. 5학년 "내 맘대로 전개도"를 바탕으로 한 시안 하나를 기본으로, 배치가 갈릴 만한 곳이 있으면 다른 시안 1~2개(지금 + A·B·C 비교 한 장). 그림은 scratchpad `build-g2/shots/`. 보고(10줄 이하)하고 **멈춘다** — 코디네이터가 사용자에게 보이고 "계속"을 메시지로 준다.
- 차례 2~: 고른 시안대로 완성 → 테스트 → 커밋.

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 특히:
  - **답하기 전 정답 노출 0**(5절): `prism-free`는 붙일 자리·카드 순서·색·DOM이 "어느 모서리가 맞는지"를 알려 주지 않는다(맞는 자리와 틀린 자리가 같은 모습), 접기 전 무대에 결과가 드러나지 않는다. `prism-count`는 답하기 전 수가 보이지 않는다.
  - 판정을 **독립 계산과 비교**: 기획서 문장만 보고 짠 계산으로 — 완성한 전개도가 각기둥이 되는지(면의 수, 옆면이 직사각형, 두 밑면의 자리, 맞닿는 선분의 길이, 겹침)를 밑면 종류마다, 서로 다른 전개도의 수(G1b 열쇠 — 정삼각 9·세 변이 다른 삼각 42·사다리꼴 104·정육각 354 등 G1 Review 값), 모서리·꼭짓점·면의 수와 규칙.
  - 점수는 엔진 규칙 안에서(독립 계산 ↔ 엔진 무작위 검사 — 일부러 틀려 이득 0, 같은 모양 두 번 점수 0, 화면 = 저장).
  - 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) + 960×768 × 보통·글꼴 흉내에서 스크롤·넘침·겹침 0(휴대폰 세로 스크롤은 규칙대로), 48px, 키보드만으로 두 단계 끝까지(카드 고르기·자리 고르기도), 색만으로 구분하지 않음, 움직임 줄이기·`?fx=low`, 화면 읽기 이름·알림(알림이 조작을 가리지 않음).
  - 느린 기기: 접기·펼치기 움직임의 프레임 간격(CPU 4·8배)을 재서 보고.
- **이미 사이트에 있는 것(정육면체·직육면체·각기둥 1~3단계·쌓기나무·자유 쌓기, 인트로·학년·영역 화면, 선생님용 안내)의 화면·점수·기록은 4단계·도전·도장 등록으로 생기는 차이(각기둥 단계 지도·영역 카드 별 합계·도장판 17칸·학습 기록) 말고 한 글자도 달라지면 안 된다.** 기준(`main` — 코디네이터가 맞춰 준 커밋) 빌드와 견준 수치를 보고한다.
- 브라우저 검사는 처음부터 느린 기기를 견디게(움직임이 끝난 뒤에 잼, 사라지는 알림은 조작 바로 뒤, 머무는 시간, 시간 예산), `waitForTimeout`·`retries` 금지. 끝내기 전에 CPU 4·8·12배로 새로 만들거나 고친 검사 값 실패 0.
- 테스트: `npm test`, `E2E_PORT=5361 npm run test:e2e -- --workers=4`, `E2E_PORT=5361 E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0. 도장 수를 세는 기존 검사(16칸)는 17칸으로 뜻이 바뀌는 줄만 고친다.
