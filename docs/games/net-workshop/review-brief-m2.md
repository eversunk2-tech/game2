# Review 서브에이전트 지침: 2차 직육면체 차시 (동시 진행 트랙 "cuboid")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-brief-m2.md](build-brief-m2.md)에 따라 만든 직육면체 차시를 **독립적으로** 검증한다. Build와 분리된 검토자다.
- **검토 결과는 새 파일 `docs/games/net-workshop/review-cuboid.md`에 쓴다**(트랙의 작업 폴더 안). 다른 트랙과 부딪히지 않게 `review.md`는 고치지 않는다. 맨 위에 판정 줄, 그 아래 기존 review.md와 같은 형식의 표.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci` 금지.
- **트랙의 작업 폴더에서만** 일한다(코디네이터가 프롬프트로 알려 준다). `main` 체크아웃과 다른 트랙의 폴더는 건드리지 않는다. 검증 파일·스크린샷은 정해 준 scratchpad 폴더에만. 개발 서버는 정해 준 포트만. e2e는 `--workers=4`.

## 기준

- **[common-rules.md](common-rules.md)** — 이 차시가 정육면체 차시와 **같은 조건**으로 만들어졌는지가 이번 검토의 뼈대다. 1~8절을 하나씩 대조한다.
- [spec.md](spec.md): 2절 `cuboid` 차시·단계 표, 3절 오개념 표, 4~6절, 11절 기술 설계, 13절 테스트 계획, 14절 "2차 직육면체", 16-2(`cuboid-free`), 16-8~16-13, 17절
- [docs/dev-guide.md](../../dev-guide.md), [docs/engine.md](../../engine.md), [docs/design/spec.md](../../design/spec.md)

## 검토 대상

코디네이터가 알려 주는 기준 커밋과 트랙 브랜치의 마지막 커밋 사이의 변경 전부(`git diff <기준>..HEAD`와 커밋 안 된 것이 있으면 그것도). Build가 고쳐도 되는 파일은 build-brief-m2.md의 목록이다. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.** 수치는 모두 직접 실행·측정한 것만 적는다.

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내(`E2E_WIDE_TEXT=font`)로 직접 실행. 건너뜀이 기기 나눔뿐인지. `git diff <기준>..HEAD -- tests/`로 **기존 검사가 지워지거나 약해지지 않았는지**(단계 수를 차시별로 세게 바꾼 것 말고). 계획의 테스트(직육면체 전개도 54가지, 만나는 선분, `?lesson=cuboid` e2e)가 있는지.
2. **수학·판정 (가장 중요)**: 저장소의 `fold.js`를 쓰지 않는 **독립 계산(직육면체 감싸기)**으로 — 서로 다른 세 길이의 직육면체 전개도 수(54), 1×1×2(29), 만나는 선분 짝, 마주 보는 면, 길이 판정(`edge-length`), 겹침, 판별 문항의 정답과 까닭 문장·오개념 tag, `cuboid-face`의 맞는 카드, `cuboid-free`의 판정(되는 배치·안 되는 배치·같은 모양 판정)을 전수 또는 큰 표본으로 견준다. 문제 만들기가 시드로 재현되는지, 무효 문항의 종류가 계획대로인지.
3. **정육면체 차시 불변**: 기준 커밋을 따로 빌드해 정육면체 4단계 + 도전 2개의 화면(글자·속성·자리·크기)·점수·기록·답하기 전 화면을 견준다. 달라진 장면 0이어야 한다. 정육면체의 판정을 독립 계산과 다시 견줌(공통 부품을 넓혔으므로).
4. **답하기 전 정답 노출**: 네 단계에서 답하기(접기) 전 화면이 정답과 무관하게 한 가지인지 — 글자·길이 이름표·면 크기와 자리·그늘·클래스·속성·알림·화면 배치(문항에 따라 크기가 달라지며 답과 엮이지 않는지 통계로). 까닭 고르기 전 표시 0. 접기 전에 막는 안내가 답을 알려 주지 않는지.
5. **직접 만드는 단계(`cuboid-free`)**: 예상 버튼·예상 관련 말 0, [접어 보기] 하나, 별은 찾은 가지 수, 안 되는 것을 접어도 별이 깎이지 않음, 결과에 정답률·"틀림" 말 없음(common-rules 1절).
6. **점수**: 기획서 문장과 engine.md 점수 표만 보고 짠 독립 계산 ↔ 엔진(무작위 여러 기기·여러 판, 나가기·새로 고침 포함). 모양마다 한 번, 일부러 틀려 이득 0, 되풀이로 쌓이지 않음, 화면 = 저장. 차시를 모두 맞힌 학생의 점수와 칭호 기준. 정육면체 차시와 오가며 점수를 두 번 받는 길.
7. **조작·보기**: 마우스·터치·키보드만으로 네 단계 끝까지. 보기 조작(끌어서 끝없이 돌리기·0.5~2배·조작판은 답한 뒤만·접는 도중에도 같은 정도)이 직육면체 무대에서도 같은지, 글자·길이 이름표가 거울상이 아닌지. 끄는 면이 놓을 때까지 보이는지, 끈 직후 탭이 먹히는지. 크기가 다른 면 카드의 누르는 곳 48px.
8. **교실 기기**: 1366×768·1366×680·820×1180 세로·가로 스크롤 0, 오른쪽 판 안쪽 넘침 0·잘린 버튼 0(모든 장면), 플레이 도중 머리·매트 움직임 0, 판 → 무대 어긋남 0px, 알림·조작판 겹침 0, 휴대폰 배치, 긴 직육면체가 무대 안에 들어오는지(자동 맞춤). 글꼴 흉내에서 세로 여유가 빠듯한 장면 목록.
9. **화면 문장·디자인·코드**: 해요체·교과서 용어(선분 ㄱㄴ, 모서리, 면), 길이 단위 표기, 색만으로 구분하지 않음, `h()`·`innerHTML` 없음·이모지 없음·죽은 코드, 움직임 줄이기·`?fx=low`, 나간 뒤 리스너·타이머 0, 콘솔 오류 0. 스크린샷을 직접 열어 본다.
10. **각기둥이 물려받을 부품**: 공통 부품을 "다각형 면 전개도 공통"으로 넓혔는지, 직육면체에만 맞춘 지름길인지(의견 — 다음 트랙이 쓸 수 있는지).
11. **범위·합치기**: 허용 파일 안인지. 같이 쓰는 파일(`main.js`·`logic.js` 등록, `style.css`, `icons.js`, `docs/engine.md`, `net-workshop.spec.js`)을 덧붙이기만 했는지, 있는 줄을 다시 쓰거나 옮긴 곳이 있는지 목록으로(합칠 때 부딪힐 곳). 엔진 변경이 타당하고 예시 게임에 영향이 없는지.
12. **새로 생긴 문제**, 사용자가 정해야 할 것(선택지와 추천), Build가 정한 세부에 대한 의견.
