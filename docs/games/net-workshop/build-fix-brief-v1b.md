# Build 서브에이전트 지침: V1 검토 반영 (V1-1 ~ V1-3) + 도감 칸 접기 (N1d-5)

## 역할

너는 V1(입체 돌려 보기·확대 축소)을 만든 **Build** 담당이다. [review.md](review.md) 맨 아래 "V1 검토"의 V1-1~V1-3과 "N1 재검토 2"의 N1d-5를, 사용자 결정 [spec.md](spec.md) **17-16**과 **16-10**(둘 다 2026-10-09)대로 고친다. 판정(`fold.js` 결과)·점수 규칙은 바꾸지 않는다. 검증은 별도 Review 서브에이전트가 다시 한다.

## 반드시 맞출 것

- **답하기 전 화면은 `bf86e8c`와 같다.** 판별·마주 보는 면·면 붙이기에서 답하기 전 화면(무대 변환, 칸 크기, 면마다의 변환·그늘·화면 자리, 아래 조작 띠의 버튼 자리와 막대 길이)이 `bf86e8c`를 따로 빌드한 것과 같아야 한다 — 세 단계 × 시드 12 × 모든 문항 × 네 크기(1366×768·1366×680·820×1180·390×844). 지금은 133·129·114·144 / 144인데 넓은 화면·태블릿에서 **144 / 144**가 되어야 한다. 휴대폰은 아래 "휴대폰" 항목.
- 답하기 전에 새 조작(끌기·휠·벌리기·↑↓ `+ − 0`·Home)을 해도 화면이 그대로이고, 답하기 전에 조작판 버튼이 DOM에 있더라도 보이지 않고 눌리지 않고 Tab으로 가지 않아야 한다(숨기는 방법은 네가 정한다). 힌트([반만 접어 보기]) 동안에도 조작판은 없다.
- **답한 뒤는 지금과 같다**: 조작판 7버튼·끌기·벌리기·휠·키보드, 한계, [처음 보기로], 글자 바로 세우기, 화면 읽기 알림, "끌어서 돌려 봐요" 칩. 조작판이 나타날 때 무대 크기·입체 자리가 흔들리지 않는다(판 → 무대 어긋남 0px 유지). 답한 뒤에는 아래 띠의 좌우 돌리기를 조작판으로 옮길지(지금처럼 막대가 길어짐) 두 곳에 다 둘지는 네가 정하고 까닭을 보고한다 — 같은 이름의 버튼이 화면에 두 번 보이지 않게 한다.
- 답하는 순간 초점이 사라지는 버튼 위에 있었다면 초점을 잃지 않게 한다(무대나 조작판의 같은 버튼으로).
- 답한 뒤 다 편 상태(막대 0)·자유 배치에서 접기 시작하는 순간에 조작판이 전개도 위에 겹쳐 보이는 것은, 그때 눌러야 할 면·빈 자리가 없으면 허용한다. 눌러야 할 것이 가려지는 장면이 있으면 보고한다.
- **휴대폰(조작 버튼이 아래 띠 두 줄, 무대 위에 겹치지 않음)**: 가리는 문제가 없다. 답하기 전에도 두 줄을 그대로 둘지(지금: 무대는 `bf86e8c`와 같고 매트만 48px 높음), 답하기 전에는 한 줄로 두고 답하면 두 줄이 될지(답하는 순간 화면이 48px 밀림)를 견줘, **화면이 덜 흔들리고 학생이 덜 헷갈리는 쪽**으로 정하고 스크린샷과 함께 까닭을 보고한다. 꺼진 버튼 다섯 개를 답하기 전에 보일지도 함께 정한다.
- **도감 칸 접기**: 고정 높이 하나로 가르지 말고 "접지 않으면 넘칠 때만"이 되게 한다. 1366×680·700·720·740·768, 820×1180, 390×844에서 자유 배치의 모든 장면(목표 전·후 × 겹침·2×2 × 예상 맞힘·틀림 × 까닭 맞힘·틀림·넘어가기) 오른쪽 판 안쪽 넘침 0, 잘린 버튼 0. 접힘이 풀린 화면에서 "도감 ③번과 같은 모양" 칸 강조·방금 들어간 노트 칸이 보인다. 장면이 바뀔 때 접혔다 펴졌다 깜빡이지 않는다.
- 지금 통과하는 것을 깨지 않는다: 까닭 고르는 중 노출 0(24가지), 세 크기 세로·가로 스크롤 0, 48px, 알림·이름표·도장과 조작판 겹침 0, 2배에서 버튼이 가려지지 않음, 나간 뒤 리스너·타이머·rAF 0, 움직임 줄이기·`?fx=low`.
- 기존 검사를 약하게 만들지 않는다. 이번 결정으로 뜻이 바뀌는 검사(답하기 전 조작판 상태 "켜짐 2·꺼짐 5", 조작판 피하기·칸 줄이기 검사 등)는 새 결정에 맞게 고치고 이유를 보고한다. 쓰지 않게 된 코드(조작판 피하기 계산 등)는 지운다.
