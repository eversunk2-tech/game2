# Review 서브에이전트 지침: 전개도 접기 공방 1차 (정육면체 차시)

## 역할과 범위

- 너는 **Review** 단계 담당이다. Build 서브에이전트가 만든 1차 결과를 **독립적으로** 검증하고 `docs/games/net-workshop/review.md` **한 파일만** 쓴다.
- 코드·테스트·다른 문서를 **고치지 않는다.** 문제를 찾으면 review.md에 재현 방법과 고칠 방향을 적는다 (수정은 Build 쪽이 한다).
- `git commit`, `git push`, `git stash`, `git checkout -- <파일>`처럼 작업 트리를 바꾸는 명령을 쓰지 않는다. 읽기용 `git diff`, `git status`, `git show`는 된다.
- 검증용 스크립트·스크린샷은 저장소 밖 `/tmp/claude-0/-home-user-game2/51527575-3484-5179-b863-3acfe59f4ca9/scratchpad/review-m1/`에만 둔다.
- Build 보고를 그대로 믿지 말고 직접 실행·계산해서 확인한다.

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e`를 직접 돌려 통과·실패·건너뜀 개수를 적는다. 건너뜀이 정당한지 본다.
2. **범위**: 바뀐 파일이 build-brief의 "고쳐도 되는 파일" 안에만 있는가. 1차 범위 밖 기능(다른 차시 등)이 화면에 나오지 않는가.
3. **계획과 일치**: 단계 id·제목·문항 수·끝나는 조건(spec 5절), 오개념 tag 글자(spec 3절), 피드백(6절), 학습 기록 값(7절), game.json(결정 표: `mode: "개인"`, `standards: []`). Build가 보고한 "계획과 다른 점"이 타당한지도 판단한다.
4. **수학적 정확성** (가장 중요): 직접 독립적인 방법으로 다시 계산해 본다.
   - 헥소미노 35개 중 정육면체로 접히는 것이 11개이고 `CUBE_NETS`와 같은 집합인가
   - 11개 전개도 모두에서 `oppositeFace`가 맞는가 (직접 다른 방법으로 계산해 비교)
   - `completionSlots`의 정답/오답 자리가 맞는가
   - 여러 seed로 만든 모든 문항에서 정답과 `checkNet` 판정·의도한 이유가 일치하는가
   - 화면 설명 문장의 내용이 수학적으로 맞고, 면 이름(가~바)이 화면의 면과 일치하며, 조사가 맞는가
5. **엔진 변경**: 차시 묶음을 안 쓰는 예시 게임이 전과 같게 동작하는가. `?lesson=`, `?stage=`, `?unlock=all`, `?seed=` 조합, 차시 끝 결과 화면, 학습 기록 화면이 맞는가. 잘못된 `?lesson=` 값일 때 어떻게 되는가.
6. **브라우저에서 직접 플레이**: 빌드한 `dist/net-workshop.html`을 크롬북(1366×768)·태블릿(820×1180 터치)·휴대폰(390×844)에서 세 단계 모두 끝까지 해 보고 스크린샷을 직접 본다. 확인: 가로 스크롤 없음, 1366×768·820×1180에서 세로 스크롤 없음, 키보드만으로 진행 가능, 터치 끌기, `prefers-reduced-motion`, 색만으로 정답·오답을 구분하지 않음, 콘솔 오류 없음, 토스트가 조작을 가리지 않음.
7. **정답 노출**: DOM(속성, 클래스, 숨긴 글자)에 정답이 드러나 학생이 개발자 도구 없이도 알 수 있는 곳이 있는가.
8. **코드 품질**: dev-guide 규칙(`h()` 사용, `innerHTML` 금지, 외부 파일 없음), 단계를 나가거나 다시 할 때 타이머·애니메이션·이벤트가 정리되는가(`cleanup`), 같은 단계를 여러 번 다시 해도 문제없는가, 죽은 코드·중복, 빌드 파일 크기.
9. **테스트 품질**: 테스트가 의미 있는 것을 검사하는가, 빠진 중요한 경우가 있는가.

- 추측은 쓰지 않는다. 직접 재현하거나 계산한 것만 쓰고, 확인 못 한 것은 따로 적는다.
