# Build 서브에이전트 지침: B0d 첫 화면은 인트로 · 게임 모음은 "선생님용 안내"로 (트랙 "b0d")

## 역할

너는 **Build** 담당이다. 사용자의 요청([spec-grade6.md](spec-grade6.md) **15-13**)을 반영한다. 검증은 별도 Review 서브에이전트가 한다.

사용자의 말: "인트로 페이지가 아니라 캡쳐한 이 화면이 계속 제일 먼저 나오네. 이 화면은 이제 딱히 필요 없는거 같아. 인트로 화면에서 입장하면 학년 선택하는 페이지의 한쪽 구석에 '선생님용 안내' 버튼을 하나 만들고, 선생님용 안내 페이지로 설정해줘. '입체도형 공방'을 누르면 인트로 페이지로 가는게 아니라 학년 선택 페이지로 가도록 하는거야" (캡처한 화면 = 지금 사이트 맨 위 주소의 게임 모음 `dist/index.html`)

이 가지는 **B0b 빌드 바탕**(`track/b0` `20770eb` — 여러 파일 빌드, 하위 경로 서버 e2e, 늦게 불러오기, Review 중) 위에서 시작한다. B0b의 Review가 고칠 것을 내면 코디네이터가 합쳐 주고 알려 준다.

## 할 일

1. **사이트 맨 위 주소 = 인트로**: `dist/index.html`로 들어오면 입체도형 공방의 인트로가 **바로**(다른 화면이 번쩍 보이지 않게) 나온다. 방법은 네가 정해 까닭과 함께 보고한다 — (가) 빌드가 게임 페이지를 `index.html`로도 내보냄(추천 — 넘겨 주기 0번) / (나) 곧바로 넘겨 주기(주소 뒤 `?…`·`#…`를 그대로 넘김). 어느 쪽이든: 옛 주소 `net-workshop.html?…`는 그대로 열리고, 저장 열쇠·값은 같고(같은 출처라 기록이 이어진다), 맨 위 주소에 수업 주소 옵션(`/?lesson=cube` 등)을 붙여도 맞게 열린다.
2. **`?intro=0`**: 인트로를 건너뛰고 학년 고르기를 연다(다른 옵션 `?lesson`·`?area`·`?grade`·`?stage`는 지금처럼 그 화면으로 — 우선순위 그대로, `?intro=0`은 그 밖일 때만 뜻이 있다). 학년 고르기의 [← 처음으로]는 그대로 인트로로 간다.
3. **[선생님용 안내] 버튼**: 학년 고르기 화면에만, 한쪽 구석에 작고 눈에 덜 띄게(학년 카드보다 앞서 보이지 않게 — 자리는 네가 정해 스크린샷으로 보고). 누르면 같은 탭에서 선생님용 안내 페이지로. 손가락으로 누를 수 있는 크기(공통 규칙의 작은 버튼 기준), 키보드 Tab 순서는 학년 카드 뒤. 엔진에는 게임이 주는 선택 값(예: `teacherGuide: './teacher.html'`)으로 — 그 값을 주지 않는 게임(예시 게임·템플릿)은 한 글자도 달라지지 않게.
4. **선생님용 안내 페이지**(예: `dist/teacher.html` — 이름은 영어 소문자로 네가 정함): 지금 게임 모음(`scripts/lib/hub.mjs`)을 고쳐 쓴다.
   - 제목은 "선생님용 안내"류(앱 이름이 함께 보이게), 맨 위에 학년 고르기로 돌아가는 링크(`net-workshop.html?intro=0`).
   - **"입체도형 공방" 카드 → `net-workshop.html?intro=0`(학년 고르기)**.
   - **예시 게임 카드는 뺀다**(사용자 결정 15-13 — 파일은 그대로 만들고 주소로만 열림. 목록에서 빼는 방법은 `game.json`의 표시 값 등 네가 정함).
   - 선생님용 주소 옵션 목록: 지금 것 + B0b가 더한 `?grade`·`?area` + **`?intro=0`**. 설명이 `docs/engine.md` 8절과 같게.
   - 기록 안내(지금 초록 상자)에 한 줄: **학생 기록은 사이트 주소마다 따로**(같은 게임이 두 주소 — GitHub Pages와 Cloudflare Pages — 에 올라가 있음. 반에는 한 주소만 나눠 주기). 주소 자체를 쓸지는 네가 정함(쓴다면 두 주소 모두 정확히).
   - 짧은 안내글(15-12의 "학생은 이 사이트 주소로 열어요" 뜻은 유지 — 맨 위 주소로 열면 인트로가 나온다는 것으로).
5. **두 사이트에서**: GitHub Pages(하위 경로 `/game2/`)와 Cloudflare Pages(맨 위 경로 `/`, `/teacher.html` → `/teacher`처럼 `.html`을 뺀 주소로 308 넘겨 줌 — 쿼리 그대로)에서 모두 맞게 열리는지: 맨 위 주소 → 인트로, `teacher(.html)` → 안내, 카드 → 학년 고르기, 학년 고르기의 버튼 → 안내. B0b의 `scripts/serve.mjs`로 하위 경로를, scratchpad의 작은 서버로 맨 위 경로·`.html` 빼기를 흉내 낸다(저장소에 서버를 더하지 않는다).
6. 검사: 게임 모음 검사를 안내 페이지 검사로(뜻이 바뀐 줄마다 까닭), 맨 위 주소가 인트로, `?intro=0`, 버튼(마우스·터치·키보드), 카드 링크, 예시 게임이 목록에 없음·주소로는 열림, 저장 값 그대로. 약하게 하는 검사 0.
7. 문서: `README.md`(사이트 주소로 열면 인트로, 선생님용 안내 주소), `docs/engine.md`(`?intro=0`, 선생님용 안내 선택 값), `docs/dev-guide.md`(게임 모음 → 안내 페이지).

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. **화면 불변**: 학년 고르기(버튼 하나 더해진 것 말고)와 그 뒤의 모든 화면, 인트로, 수업 주소 화면, 예시 게임이 `track/b0`(`20770eb`) 빌드와 픽셀까지 같다. 저장 열쇠·값 그대로.
- **c4 트랙과 줄 몫**: 같은 때에 c4(큰 화면에서 [입장하기] 키우기·소녀의 손 피하기)가 먼저 `main`에 올라간다. c4 몫 줄 — `src/shared/core/intro-fit.js`의 버튼 줄, `src/shared/ui/app.js`의 인트로 CSS 변수 `vars` 줄과 `planIntro`의 `buttonAvoid` 2줄, `src/shared/styles/base.css`의 [입장하기] 블록, `src/games/net-workshop/main.js` INTRO `art`의 `buttonAvoid` 줄 — 은 건드리지 않는다. c4가 올라가면 코디네이터가 `main`을 이 가지에 합쳐 준다.
- 브라우저 검사는 느린 기기를 견디게(움직임이 끝난 뒤, 시간 예산), `waitForTimeout`·`retries` 금지. 끝내기 전에 CPU 4·8·12배로 새로 만들거나 고친 검사 값 실패 0.
- 테스트: `npm test`, `E2E_PORT=5326 npm run test:e2e -- --workers=4`, `E2E_PORT=5326 E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0. 다른 트랙의 Review가 같은 때에 돌아 컴퓨터가 느릴 수 있다 — 값이 어긋나는 실패는 혼자 다시 돌려 가린다.
