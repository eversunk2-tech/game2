# Build 서브에이전트 지침: S3 쌓기나무 5차시 + 도전 (트랙 "blocks")

## 역할

너는 쌓기나무 영역의 **Build** 담당이다. S1(바탕 + 1·2차시)과 S2(3·4차시)는 Review를 통과해 사이트에 올라가 있다. 이번에는 승인된 6학년 계획([spec-grade6.md](spec-grade6.md))의 **S3 — 교과서 5차시(층별로 나타내기)와 도전 "더 붙여서 만들기"**를 만들고, 앞 검토가 S3로 넘긴 것을 함께 고친다. 이것으로 쌓기나무 영역(6-2 3단원)이 다 갖춰진다. 사용자가 "6학년은 현재 2학기니깐 바로 쓸수 있게"라고 했다(2026-10-18) — 교실에서 곧 쓴다. 검증은 별도 Review 서브에이전트가 한다.

## 먼저 읽을 것 (순서대로)

1. **[common-rules.md](common-rules.md)** — 공통 규칙 전부(8절 "움직임이 끝난 뒤에 잰다"·느린 기기 흉내).
2. **[spec-grade6.md](spec-grade6.md)** — 1-2절(교과서 흐름)·1-4절(용어 표), **2-4절의 5차시 `blocks-layer`와 도전 `blocks-add`**(표·"같은 모양" 약속·짝 활동), 3절(조작), 4절(오개념·피드백), 5절(정답 노출), 6절(데이터·판정·문제 만들기), **8절(보상 — 쌓기나무 도장 셋, 도전 주문서)**, 15-3(쌓는 단계의 별), 15-4·15-7(예상 문항), **15-8**(앞과 뒤 오개념 보기), 15-13~15-15(지금 앱 구조 — 학년 고르기·영역 화면).
3. [review-blocks-s2.md](review-blocks-s2.md) — 맨 아래 재검토(S2b)의 **S2b-1·S2b-2**와 참고 S2b-3~6.
4. 네가(쌓기나무 Build가) 만든 코드: `src/games/net-workshop/blocks/**`(B0b 빌드 바탕이 **`blocks-stages.js`(단계 목록 — 처음 묶음)와 `blocks-play.js`(플레이 — 쌓기나무 단계에 들어갈 때 늦게 받는 묶음)**로 나눠 두었다 — 새 단계도 이 나눔을 지킨다), `tests/unit/net-workshop-blocks*.test.js`, `tests/e2e/net-workshop-blocks*.spec.js`(도우미 `calm(page)`), [docs/engine.md](../../engine.md) 2절(영역·늦게 불러오기)·11절(테스트 — 하위 경로 서버, `E2E_PORT`).

교과서 PDF는 읽지 않는다. 교과서의 문장·그림·문제 수치를 옮기지 않는다 — 문제와 그림은 모두 새로 만든다. 용어는 1-4절 표 그대로.

## 만들 것

1. **5차시 `blocks-layer` 층별로 나타내기**(교과서 66~67쪽): `blocks-layer-draw`(층별 모양 그리기 — 만든 모양과 1층 모양을 보고 2층·3층 모양을 모눈에 칠함 → [확인하기] → 층별로 벌어져 내 그림과 견줌) · `blocks-layer-build`(층별 모양을 보고 쌓기) · `blocks-layer-views`(층별 모양만 보고 개수·앞·옆 — 답하기 전에는 입체 없음). 문항 수·돌려 보기·끝나는 조건은 2-4절 표 그대로. 이미 있는 부품(`grid-draw.js` 모눈 칠하기, `block-view.js` 층별로 벌려 보기, `block-pad.js`)을 쓴다.
2. **도전 `blocks-add` 더 붙여서 만들기**(68~69쪽 — 도전 주문서): 주어진 모양에 1개(뒤 문항은 2개)를 더 붙여 만들 수 있는 모양을 보기에서 **모두** 고르기(예상) → 내 판에서 직접 붙여 확인 → 만든 모양 하나를 위에서 본 모양에 수를 써서 나타내기. 보기는 **놓인 방향이 같은 것만**(돌려야 같은 보기는 내지 않는다 — 2-4절). 차시를 마치면 열리고 별 합계에 넣지 않는다(8절 도전 주문서 — 정육면체 도전과 같은 엔진 방식).
3. 차시 묶음에 **쌓기나무 5차시**로 등록(칩·시간 칩은 직접 해 보고 잰 어림, "6학년 2학기 · 공간과 입체"), `?lesson=blocks-layer`. 쌓기나무 영역의 단계 지도·놀이 방법·영역 카드("차시 5개"·별 합계)가 새 차시를 반영.
4. **쌓기나무 도장 셋**(8절 — 지금 도장판에 아직 없다): 숨겨진 쌓기나무 찾기 · 세 방향의 눈 · 층층이 쌓기. 조건은 8절 문장 그대로(학습 기록으로 판정하는 순수 함수, 숨은 도장 없음). 도장판 칸 수가 13 → 16이 된다 — 도장 수를 세는 기존 검사(`net-workshop.spec.js`·`net-workshop-areas.spec.js`·`net-workshop-cuboid.spec.js` 등의 "/ 13")를 새 뜻으로 고치고 줄마다 보고. 이미 쌓은 학습 기록으로 조건을 채운 학생에게 처음 열 때 한 번만 찍힌다.
5. 별: 15-3의 기준 그대로(한 번 틀리면 정답률로 바로 ★1이 되는 단계는 틀린 횟수로). 어느 단계에 썼는지 보고.

## 반드시 지킬 것

- [common-rules.md](common-rules.md) 전부. 특히 **답하기 전 정답 노출 0**(층별 모양만 보고 알아내는 문항은 답하기 전에 입체가 없다), 판정을 **독립 계산과 전수 비교**(3×3칸·3층 모든 쌓기에서 층별 모양 ↔ 쌓기, 1·2개 더 붙인 모양의 모든 경우, 방향이 같은 같음), 점수는 엔진 규칙 안에서(독립 계산 ↔ 엔진 무작위 검사), 맞힐 때까지 다시 하는 단계에서 같은 틀린 답은 한 번만 센다.
- 다섯 크기(1366×768·1366×680·1024×768·820×1180·390×844) + 960×768 × 보통·글꼴 흉내에서 스크롤·넘침·겹침 0(휴대폰 세로 스크롤은 지금 규칙대로), 48px, 키보드만으로 5차시·도전 끝까지, 색만으로 구분하지 않음, 움직임 줄이기·`?fx=low`, 화면 읽기 이름·알림.
- **늦게 불러오기**: 새 단계의 플레이 코드는 쌓기나무 묶음(`blocks-play.js` 쪽)에, 단계 목록·그림은 `blocks-stages.js` 쪽에. 처음 화면이 받는 크기(gzip)가 크게 늘지 않는지 빌드 로그로 보고.
- **이미 사이트에 있는 것(정육면체·직육면체, 쌓기나무 1~4차시, 인트로·학년·영역 화면)의 화면·점수·기록은 위 표에서 고치는 것과 도장판 칸 수 말고 한 글자도 달라지면 안 된다.** 기준(`main` `7a9eaed`) 빌드와 견준 수치를 보고한다.
- 브라우저 검사는 처음부터 느린 기기를 견디게(`calm` 뒤에 잼, 사라지는 알림은 조작 바로 뒤, 머무는 시간, 시간 예산), `waitForTimeout`·`retries` 금지. 끝내기 전에 CPU 4·8·12배로 새로 만들거나 고친 검사 값 실패 0.
- 테스트: `npm test`, `E2E_PORT=5352 npm run test:e2e -- --workers=4`, `E2E_PORT=5352 E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4` 모두 실패 0. **같은 때에 각기둥 G1 Build가 다른 작업 폴더(`.worktrees/cuboid`, 포트 5301·5361·5362)에서 돈다** — 건드리지 말고, 값이 어긋나는 실패는 혼자 다시 돌려 가린다.

## 동시에 만드는 동안 — G1과 줄 몫

- G1(각기둥 1)은 `solids.js`·`grade6/**`(새), 전개도 공통 부품, `main.js`의 **각기둥 영역·차시 등록 줄**을 고친다. 너는 `main.js`의 **쌓기나무 차시·도전·도장 등록 줄**만 고치고 각기둥 줄은 건드리지 않는다. 도장 수를 세는 기존 검사의 칸 수 줄은 네 몫이다(G1은 도장을 더하지 않는다).
