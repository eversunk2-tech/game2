# Review 서브에이전트 지침: 이미 있던 검사의 흔들리는 곳 2건 + 시간 예산 확인 (트랙 "c1"의 후속 "c2")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-fix-brief-c2.md](build-fix-brief-c2.md)에 따라 고친 **검사 파일들**을 **독립적으로** 확인한다. Build와 분리된 검토자다.
- 트랙의 작업 폴더 안 `docs/games/net-workshop/review-c1.md` **한 파일만** 고친다: 맨 아래에 `## 재검토 (c2: 이미 있던 검사의 흔들리는 곳)` 절을 덧붙이고, 맨 위 "판정" 줄 아래에 c2 판정 한 줄을 더한다. 앞 내용은 지우지 않는다. 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지.
- **트랙의 작업 폴더에서만** 일한다(코디네이터가 프롬프트로 알려 준다). 검증 파일·복사본은 정해 준 scratchpad 폴더에만. Build의 scratchpad는 근거로 삼지 않는다.

## 검토 대상

`d6371ad`(`main`에 올라간 c1)와 `track/c1`의 마지막 커밋 사이의 변경 전부. **`tests/e2e/` 아래 허용된 검사 파일 말고 다른 것이 바뀌었으면 범위 위반**이다(`src/**`·`scripts/**`·`helpers.js`·`playwright.config.js`가 한 줄이라도 바뀌면 안 된다). Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **범위**: `git diff d6371ad..HEAD --stat`. 저장소의 검사 파일에 재현용 코드가 남지 않았는지. 빌드 결과물(`dist/*.html` 세 파일)의 해시가 `d6371ad`와 같은지.
2. **C2-1(조작판 48px)·C2-2(주사위 주문의 알림)**: scratchpad의 **`d6371ad` 복사본**에서 실패가 재현되는지(CPU 16배 `--repeat-each=10`, 재는 때 40ms 늦추기), **지금 것의 복사본**에서 4·8·16배 × `--repeat-each=10` 이상으로 실패 0인지(두 기기).
   - **덧붙임의 여섯 검사**(수정 지침 맨 아래 "덧붙임 (2026-10-13)" — "주사위 주문 배치", "자유 배치: 알림이 조작…을 가리지 않는다", "도감 주문 배치", "자유 배치: 칸을 눌러 십자…", "주사위 주문 보기 조작·정리", "답하기 전 힌트(반만 접어 보기)…")도 같은 방법으로: `d6371ad` 복사본에서 4·8·12배로 실패가 재현되는지, 지금 것에서 0인지, Build가 밝힌 5·6의 원인이 맞는지.
3. **검사의 뜻이 그대로인지**: `git diff d6371ad..HEAD -- tests/`를 줄마다 읽는다 — 기대값·재는 항목·장면 수가 줄거나 느슨해지지 않았는지, `waitForTimeout`·`retries`가 없는지, 기다림이 끝나지 않을 길이 없는지. C2-1에서 반올림을 썼다면 "48px 미만을 잡는다"가 그대로인지(47.99 같은 실제 미달은 여전히 실패하는가). C2-2에서 순서를 바꿨다면 "알림이 떠 있는 동안 조작을 가리지 않는다"가 그대로인지(**알림이 아예 없으면 통과가 아니라 실패**인가). 복사본의 스타일을 일부러 망가뜨려(조작판 버튼 44px, 알림을 조작 버튼 위에) 그 검사들이 실패하는지.
4. **시간 예산(C2-3)**: 예산 말고 바뀐 것이 없는지. 예산을 적은 검사의 혼자 돌린 시간(보통·CPU 4배)을 표본으로 재서 Build의 표와 견주고, 예산이 4배 시간의 3배 이상인지, 지나치게 크지 않은지. 예산이 없는데 3초 넘게 걸리는 검사가 남았는지(전체 목록의 걸린 시간으로).
5. **전체 느리게 하기**: 지금 것의 복사본에서 전체 브라우저 검사를 4·8배로 한 번씩 — 값이 어긋나는 실패 0인지(시간 제한만 넘긴 것은 따로 표시). 실패가 있으면 어느 검사·어느 줄·어떤 움직임인지.
6. **합칠 때**: 직육면체 트랙(`track/cuboid`)·쌓기나무 트랙(`track/blocks`)의 지금 커밋과 `git merge-tree --write-tree`로 합쳐 보아 `tests/e2e/net-workshop.spec.js`에 줄 충돌이 없는지(읽기만).
7. **테스트**: `npm test`, `npm run test:e2e -- --workers=3`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=3`을 직접 실행(통과·실패·건너뜀). 다른 일꾼과 겹쳐 느려졌을 때의 실패는 혼자 다시 돌려 가리되, **값이 어긋나는 실패는 부하 탓으로 넘기지 않는다.**
8. **새로 생긴 문제**.
