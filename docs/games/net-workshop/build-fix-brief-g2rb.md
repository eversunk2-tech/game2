# Build 수정 지침: G2rb 각기둥 4단계 자유 배치 고치기 (트랙 "cuboid" 작업 폴더)

## 역할과 범위

- 너는 G2r을 만든 **Build** 담당이다. [review-prism-g2r.md](review-prism-g2r.md)(작업 폴더 `track/cuboid`에 코디네이터가 커밋 — 고치지 말 것)의 판정 "수정 필요"와 사용자 결정(spec-grade6 15-31 덧붙임 — 빈 판 누르기)을 반영한다. 고칠 수 있는 파일은 [build-brief-g2r.md](build-brief-g2r.md)의 "고쳐도 되는 파일"과 같다.

## 반드시 고칠 것

1. **G2r-1** (`prism-free-logic.js:423·486-490`, `play-pfree.js:356`): 길이가 같은 두 변이 어긋나게 맞닿은 곳을 "4 cm와 4 cm로 달라요"라고 말하고 이름표도 4 cm·4 cm로 붙는다(학생처럼 놓은 18,000판 가운데 34판). 직육면체처럼 "어긋나게 붙어 있어요" 문장을 쓰고, 길이 까닭을 보일 때는 길이가 정말 다른 곳을 먼저 고른다. 판정·까닭 고르기(참인 까닭)·독립 계산·검사를 함께 맞춘다.
2. **G2r-2 — 사용자 결정 "직육면체처럼 놓이게 (추천)"** (`magnet-board.js:495-512`): 카드를 고르지 않고 빈 판을 누르면 남은 카드 가운데 앞의 것이 그 자리에 놓인다(가까운 모서리가 있으면 자석처럼 붙음). 직육면체 `free-board.js`의 빈 칸 누르기와 같은 뜻·같은 알림. 휴대폰 안내 띠 "판 누르기: 놓기"와 맞게. 키보드도 직육면체와 같은지 확인.

## 고치면 좋음 (함께)

3. **G2r-3** 육각기둥 옆면 폭이 39~47px로 48px보다 좁다(1366×680만 50px) — 누르는 곳 48px(common-rules): 면 자체를 키울 수 없으면 누르는 자리(투명 테두리 등)를 48px로, 또는 판의 1 cm 크기를 맞춤. 잰 값을 보고.
4. **G2r-4** 빗변에 붙일 면은 30° 두 단계 가운데 한쪽에서만 자석이 붙는다 — 두 단계 모두에서 가까운 모서리 방향으로 맞춰 붙게.
5. **G2r-5** 빗변에서는 가운데에 놓아도 끝 맞춤으로 붙는 때가 많다(삼각 20/40, 사다리꼴 54/92만 가운데) — "덜 움직이는 쪽" 규칙이 빗변에서도 예상대로 되게.
6. (참고 — 되면) G2r-6 "떨어짐" 꼬리표가 작은 면에서 안 보임, G2r-7 판 가장자리에 걸치게 놓으면 직육면체와 달리 놓이지 않음.

## 검사·끝나면

- 각 고침에 검사를 더하고(고치기 전 커밋에서 실패하는지 확인), 테스트 셋 처음부터 실패 0: `npm test`, `E2E_PORT=5361` 보통·글꼴 흉내. 고친 검사는 CPU 4·8·12배로.
- 같은 작업 폴더·포트(5301, e2e 5361~5362)·scratchpad `build-g2r/`(그림 `shots-g2rb/`). 테스트가 통과한 단위마다 커밋, 띄운 서버는 네 PID만 내린다.
- 보고(12줄 이하): 고친 것마다 방법과 잰 값, 테스트 수치, 남은 것, 사용자에게 물을 것.
