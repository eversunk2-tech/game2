# Plan 서브에이전트 지침: 원기둥의 전개도 G3 (spec-grade6 15-33)

## 역할

너는 **Plan** 담당이다. 저장소 코드는 고치지 않는다(시제품·측정은 scratchpad에서만). 원기둥 영역(G3)의 계획을 **지금 앱과 그 뒤 사용자 결정에 맞춰 다시 보고**, 사용자가 정해야 할 갈림길을 **선택지와 추천**으로 정리한다. 사용자가 승인·선택하면 다음 Build가 만든다.

사용자의 말(2026-11-07): **"원기둥 시작해줘"**.

## 배경 — 왜 다시 보나

- 원기둥 4단계는 [spec-grade6.md](spec-grade6.md) **2-3절**에 확정안으로 있고 2026-10-09에 승인됐다(15-1 — 원주율은 문제마다 값을 알려 주고 3 · 3.1 · 3.14를 섞음, 수업 주소로 한 값에 고정 가능).
- 그 뒤 바뀐 것:
  - **15-2**: 직접 만드는 단계에는 예상하기가 없다([접어 보기] 하나, 별은 찾은 가지 수, 안 되는 모양을 접어도 별이 깎이지 않음). 2-3절의 `cylinder-free`("될지 예상하고 말기", "일부러 안 되는 전개도 2가지를 만들어 '안 될 거예요'로 맞히기")는 이 결정과 부딪힌다.
  - **15-30~15-32**: 사용자가 각기둥 4단계를 "직육면체 전개도를 직접 배치해볼 때랑 같은 방식"으로 바꾸게 했다 — 빈 판(초록 판 전체)에 면 카드를 끌어 놓고·옮기고·빼고·돌리며, 모서리 가까이 놓으면 자석처럼 붙고(길이가 달라도 붙음 — 접으면 어긋나는 것을 학생이 봄), 만들 입체 창에 가린 곳은 [◀][▶]로 판을 옆으로 옮겨 봄. 사용자는 이 조작이 편하다고 했다.
  - 각기둥에는 도전 "모서리와 꼭짓점"(`prism-count`)과 도장 "기둥 설계사"가 생겼다(15-25·15-29). 쌓기나무에는 자유 쌓기가 생겼다.
- 그래서 2-3절의 각 단계가 **지금 앱의 부품·조작·규칙과 맞는지**, 바꿔야 할 곳은 어디인지, 사용자에게 물어야 할 갈림길은 무엇인지를 정리하는 것이 이번 일이다.

## 할 일

### A. 2-3절 단계마다 — 그대로 / 바꿈 / 사용자에게 물음

네 단계(`cylinder-parts`·`cylinder-judge`·`cylinder-size`·`cylinder-free`) 각각에 대해: 지금 앱의 어떤 부품을 물려받는지(파일·함수), 새로 만들 것, 2-3절 이후 결정(15-2·15-30~15-32 등)과 부딪히는 곳, 문항 수·끝나는 조건·별(15-3의 "답하는 횟수가 3번 이하" 기준이 해당하는지)·점수·시간.

특히:

- **`cylinder-free`(전개도 완성하기)**: 15-2와 15-30~15-32에 맞는 안을 2~3개 만들어 견준다. 생각할 것: 각기둥처럼 빈 판(초록 판 전체)에 옆면 카드·원 카드를 끌어 놓고 원이 옆면 가장자리에 자석처럼 붙는(변을 따라 미끄러짐) 방식, 카드에 섞을 것(가로가 둘레 · 지름 · 반 바퀴인 옆면, 크기가 다른 원 — 2-3절), [말아 보기] 뒤 틈·겹침·안 맞는 원의 모습, 원기둥은 되는 꼴이 사실상 한 가지라(원의 자리만 다름) "찾은 가지 수"로 별을 줄 수 없다는 점 — 그러면 무엇으로 끝·별·점수를 정할지(예: 원기둥 여러 개를 주문받아 만들기, 되는 꼴의 자리 바꿔 보기 — 흔한 꼴 · 세워 놓은 꼴 · 엇갈린 자리, 안 되는 것은 15-2대로 별을 깎지 않고 "왜 안 될까요?"로 까닭). 원 카드의 크기와 "1 cm" 크기, 다섯 크기에서 판에 들어가는지(각기둥 4단계 1 cm 값과 견줌), 돌리기가 필요한지(원은 돌릴 필요가 없음 — 옆면은 90°?).
- **원주율**(15-1): 어느 문항에 값을 적는지, 3 · 3.1 · 3.14를 어떻게 섞는지, `?pi=` 주소, 답이 깔끔하게 떨어지게 반지름을 고르는 방법, 계산을 화면 안에서 어떻게 하게 할지(보기 고르기 / 수 쓰기 — 지금 앱에 수 쓰기 부품이 있는지 확인), 둘레 = 지름 × 원주율을 배웠다고 볼 수 있는지(6-1 원주율 단원 — 1-3절 메모).
- **말기·굴려 재기 움직임**(2-3절 "곡면을 마는 모습", 6-1절 시제품 값): 지금 `view3d.js`·`fold.js`에 어떻게 넣을지, 움직임 줄이기·`?fx=low`.
- 정답 노출(5절)·까닭 고르기(8절, 4절 끝)·오개념 표(4절 원기둥 줄)가 각 단계에서 어떻게 지켜지는지.

### B. 영역 둘레

- 원기둥 영역 카드("준비 중" → 열림)·단계 지도·학년 화면의 별 합계·"여기부터!"·학습 기록·선생님용 안내에서 바뀌는 것.
- **도장**: 원기둥 도장을 넣을지(각기둥 "기둥 설계사"처럼), 넣으면 무엇으로 받는지 — 도장판 칸 수(지금 17칸)가 늘면 학습 기록 화면 길이(7절 남은 것).
- **도전**: 각기둥처럼 원기둥 도전을 넣을지 — 후보(예: 1-3절 "생활 장면: 물건이 꼭 맞게 들어가는 통"을 넓힌 주문)와 넣지 않는 안. 넣는다면 언제 열리는지·별 합계 밖인지·보기의 값·자리·꼴만 보고 맞히는 규칙이 찍기보다 크게 높지 않게 하는 방법(각기둥 도전에서 겪은 것 — review-prism-g2.md).
- 시간(차시 카드의 "약 ○분" — 각기둥은 약 11분).
- 늦게 불러오기(새 코드가 원기둥 묶음에만), 처음 받는 크기.

### C. 화면 — Build 차례 1의 시안 목록

- 화면을 바꾸는 일은 시안부터다(CLAUDE.md). Build 차례 1에서 무엇을 시안으로 만들어 사용자에게 보일지(단계마다 화면 배치, `cylinder-free` 조작 안 둘 이상 등), 크기(1366×768 · 1366×680 · 1024×768 · 820×1180 · 390×844 + 960×768).
- 필요하면 갈림길을 사용자에게 설명할 **간단한 그림**(scratchpad — 손그림 수준의 SVG/HTML 스크린샷이면 충분, 지금 앱에 덧씌우지 않아도 됨)을 만든다. 선택지가 그림 없이 분명하면 만들지 않아도 된다.

### D. Build 나누기

- 한 Build(차례 1 시안 → 차례 2~)로 할지, 둘(예: 1~2단계 / 3~4단계 + 둘레)로 나눌지 — 크기 어림(줄 수), 각 Build의 Review, 작업 폴더(`.worktrees/cuboid` · `track/cuboid`를 이어 쓰는 것이 기본), 고칠 파일과 고치지 않을 파일(각기둥 화면은 한 픽셀도 바뀌지 않게 — 같이 쓰는 부품을 넓힐 때 방법).
- 테스트 계획: 판정 독립 계산(기획서 문장만으로 짠 `checkCylinder` 대응), 원주율 값마다 답, 차시 흐름 e2e, 배치, 느린 기기, 불변 비교.

## 결과물

- 새 파일 **`docs/games/net-workshop/plan-cylinder.md`**(작업 폴더 안): ① 한 문단 요약 ② 2-3절 이후 바뀐 결정과 부딪히는 곳 표 ③ 단계마다 계획(A — 그대로/바꿈, 물려받는 부품, 새로 만들 것, 문항·별·점수·시간) ④ `cylinder-free` 안 견주기(선택지·추천, 그림이 있으면 경로) ⑤ 원주율·계산 ⑥ 영역 둘레(B — 도장·도전·시간·불러오기) ⑦ Build 차례 1 시안 목록(C) ⑧ Build 나누기·테스트 계획(D) ⑨ **사용자에게 물을 것**(번호, 선택지, 추천 — 6개 이하로 꼭 필요한 것만. 사용자는 초등 교사 — 기술 용어 없이) ⑩ 직접 본 것과 추정.
- `spec*.md`는 고치지 않는다(코디네이터가 결정 절과 2-3절에 옮긴다).

## 지킬 것

- **공개 저장소**: 교과서의 문장·그림·문제 수치를 옮기지 않는다(배우는 순서와 용어만 — 1-3절도 쪽 번호와 활동 종류만 적혀 있다). 예시 문제의 수는 새로 만든다.
- 작업 폴더 `.worktrees/cuboid` · 브랜치 `track/cuboid`(코디네이터가 `main`에 맞춰 둠). 결과 파일 하나만 쓴다(커밋은 코디네이터). 코드·다른 문서 수정 금지, 작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). **`npm install`·`npm ci`·내려받기 금지**(`node_modules`는 링크).
- 시제품·그림·측정은 scratchpad `plan-cylinder/`(경로는 프롬프트로)에만. 포트 **5371**(필요하면 5372). **서버를 내릴 때는 네가 띄운 PID만**(`pkill -f`·`killall` 금지). 5173·5183·5391·5392·5399는 다른 프로젝트·사용자 것 — 건드리지 않는다.
- 지금 다른 트랙에서 도는 일은 없다.
