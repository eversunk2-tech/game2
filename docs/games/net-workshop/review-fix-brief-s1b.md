# Review 서브에이전트 지침: S1 쌓기나무 검토 반영 확인 (트랙 "blocks")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-fix-brief-s1b.md](build-fix-brief-s1b.md)에 따라 고친 것을 **독립적으로** 확인하고, 지난 검토에서 통과한 것이 깨지지 않았는지 본다. Build와 분리된 검토자다.
- 트랙의 작업 폴더 안 `docs/games/net-workshop/review-blocks.md` **한 파일만** 고친다: 맨 아래에 `## 재검토 (S1b 수정 확인)` 절을 덧붙이고, 맨 위 "판정"·"검토일" 줄을 고친다. 앞 내용은 지우지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci` 금지.
- **트랙의 작업 폴더에서만** 일한다(코디네이터가 프롬프트로 알려 준다). `main` 체크아웃과 다른 트랙의 폴더는 건드리지 않는다(지침 파일을 읽는 것은 된다). 검증 파일·스크린샷은 정해 준 scratchpad 폴더에만. 개발 서버는 정해 준 포트만. e2e는 `--workers=4`.
- 옆 폴더 `review-s1/`에 지난 검토의 스크립트와 기준 빌드가 남아 있으면 **같은 스크립트로 다시 재서 지난 값과 나란히** 적는다(옛 복사본이 아니라 지금 작업 폴더를 새로 빌드한 것을 여는지 먼저 확인). 없으면 새로 짠다. Build의 scratchpad는 근거로 삼지 않는다.

## 기준

- `review-blocks.md`의 문제 표(S1-1 ~ S1-18)와 그 측정값(지난 값), "계획과 다른 점" ⑧
- [build-fix-brief-s1b.md](build-fix-brief-s1b.md)의 **사용자 결정 3가지**(= [spec-grade6.md](spec-grade6.md) 15-3. 트랙 폴더의 spec-grade6.md에는 아직 없으니 `main` 체크아웃의 것을 읽는다)
- [common-rules.md](common-rules.md) 1~8절(`main` 체크아웃의 것이 최신이다)

## 검토 대상

기준 커밋 `742805e`(첫 Build, 지난 검토 대상)와 트랙 브랜치의 마지막 커밋 사이의 변경 전부(`a3bff47`은 코디네이터가 review-blocks.md만 커밋한 것이다). 커밋 안 된 것이 있으면 그것도 보고 그 사실을 적는다. Build가 고쳐도 되는 파일은 build-fix-brief-s1b.md의 목록이다 — **전개도 공통 부품(`fold.js`·`geometry.js`·`view3d.js`·`free-board.js`·`play-*.js`·`orbit.js`·`logic.js`)이나 `net-workshop.spec.js`가 바뀌었으면 범위 위반**이다. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`를 보통과 글꼴 흉내(`E2E_WIDE_TEXT=font`)로 직접 실행(통과·실패·건너뜀). `git diff 742805e..HEAD -- tests/`로 **지워지거나 약해진 검사**가 없는지 — 별 기준이 바뀌어 고친 검사는 새 뜻(틀린 횟수)을 제대로 고정하는지.
2. **S1-1 (가장 중요)**: `blocks-count` — 시드 1,000개 이상에서 정답 자리 분포(지난 값: 셋째 95%, 첫째·넷째 0), "한 자리만 누르기" 네 가지 각각으로 만점이 되는 판의 비율(지난 값 82.5%), 보기 값의 크기 순위와 정답의 관계(가장 큰 값·가장 작은 값·가운데 값만 고르기로 맞히는 비율), 보기의 뜻(오개념 함정: 보이는 것만 센 수, 위에서 본 칸 수 등)이 살아 있는지, 보기에 같은 값·0 이하·말이 안 되는 값이 없는지. 저장소 코드가 아닌 **독립 계산**으로 정답을 다시 구해 견준다. 답하기 전 화면(글자·속성·순서)이 답과 엮이지 않는지.
3. **S1-2 별 기준**: `blocks-copy`(2문항)·`blocks-scene`(3문항)에서 틀린 답 0·1·2·3번으로 끝낸 판의 별(★3·★2·★1)과 결과 화면의 안내 문장을 직접 본다. 일어날 수 없는 것을 말하는 안내("한 번만 더 맞히면 별 2개" 따위)가 없는지. `blocks-hidden`·`blocks-count`·`blocks-where`의 별은 지난번과 같은지. **점수**: 기획서 문장과 engine.md 점수 표만 보고 짠 독립 계산 ↔ 엔진(무작위 여러 판, 나가기·새로 고침 포함) 어긋남 0, 일부러 틀려 이득 0, 화면 = 저장. 놀이터 11점 그대로.
4. **S1-3**: 같은 틀린 쌓기로 [확인하기]를 거듭(더블클릭·Enter 연타·터치 두 번) 눌러 틀림이 한 번만 세어지는지. 쌓기를 바꿨다가 같은 틀린 모양으로 되돌린 뒤 누르면 어떻게 세는지(의견). 맞는 쌓기의 거듭 누르기로 점수·진행이 두 번 되지 않는지.
5. **S1-4**: `blocks-where` — 시드 1,000개에서 네 문항의 정답 글자 분포, "지우기만으로 맞히는 기대 정답 수"(지난 값 2.08/4 → 찍기 1.0에 가까운지), 한 글자만 고르기의 만점 비율, 같은 정답이 연달아 나오는 가장 긴 줄.
6. **그 밖의 항목을 하나씩**: S1-5(파란 기둥 무늬 — 스크린샷을 직접 열어 층수가 바로 읽히는지, 조형물 셋이 색 없이도 구별되는지), S1-6(1366×680 `blocks-hidden` 예상 틀림 장면의 세로 여유: 보통 / 글꼴 흉내 / 글꼴 흉내 + 글자 110%), S1-7(폭 900~1100을 20px 간격 × 높이 768·680에서 쌓기나무와 조작 칸의 겹침 px — 지난 값 901~1,030px에서 64px), S1-8(버튼·방향키로 돌릴 때 알림의 글과 횟수 — 전개도 무대와 같은지, 너무 자주 읽히지 않는지), S1-9(까닭 문장·그림 이름을 시드 수백 개로 뽑아 어색한 조사·되풀이 0), S1-10(놀이터 머리와 작업 지시서 번호), S1-12(`blocks-scene` 보기 그림의 폭, 판 넘침 0), S1-15·16·17.
7. **사이트에 올라갔을 때**: 단계 지도의 차시 칩("쌓기나무 1차시"·"쌓기나무 2차시", 시간 칩), "6학년 2학기 · 공간과 입체" 안내, 놀이 방법의 쌓기나무 줄을 네 크기 스크린샷으로 직접 본다. **정육면체 차시의 칩("1차시")·예시 게임은 한 글자도 달라지지 않았는지**(기준 `3b48260` 빌드와 견줌). 엔진 변경(`app.js`·`base.css`)이 선택 값을 주지 않는 차시에 영향 0인지.
8. **깨지지 않았는가(지난 스크립트로 다시, 지난 값 → 지금 값)**: 누르기와 끌기 가르기(잘못 쌓임·잘못 돌아감 0), 누른 곳 = 독립 광선 계산, 깊이 순서 오류 0, 판정 전수 비교(262,144개) 어긋남 0, 답하기 전 정답 노출 0(멈춘 그림의 DOM, 돌리기 막힘), 세 크기 세로·가로 스크롤 0·판 넘침 0·잘린 버튼 0·머리와 매트 움직임 0, 48px, 키보드만으로 두 차시 끝까지, 정육면체 차시 불변(4단계 + 도전 2개 달라진 장면 0), 전개도 공통 부품 0줄, 콘솔 오류 0, 나간 뒤 리스너·타이머 0.
9. **범위·합치기**: 허용 파일 안인지. 같이 쓰는 파일(`main.js`, 엔진 `app.js`·`base.css`, `docs/engine.md`, `tests/unit/engine-ui.test.js`)에서 고친 곳의 줄 목록 — 직육면체 트랙(`track/cuboid`)의 마지막 커밋과 `git merge-tree`로 합쳐 보아 줄 단위 충돌이 있는지(읽기만, 실제로 합치지 않는다).
10. **새로 생긴 문제**, 사용자가 정해야 할 것(선택지와 추천).
