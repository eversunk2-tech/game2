# Review 서브에이전트 지침: c3 — 끌기 안내가 가끔 숨는 앱 문제 + "머무는 시간" 검사 (트랙 "c1")

## 역할과 범위

- 너는 **Review** 담당이다. Build가 [build-fix-brief-c3.md](build-fix-brief-c3.md)에 따라 고친 것을 **독립적으로** 확인한다. Build와 분리된 검토자다.
- 트랙의 작업 폴더 안 `docs/games/net-workshop/review-c1.md` **한 파일만** 고친다: 맨 아래에 `## 재검토 (c3: 끌기 안내 · 머무는 시간)` 절을 덧붙이고, 맨 위 판정 줄 아래에 c3 판정 한 줄을 더한다. 앞 내용은 지우지 않는다. 커밋하지 않는다.
- 코드·테스트·다른 문서를 고치지 않는다. 커밋·브랜치 바꾸기·작업 트리를 바꾸는 git 명령 금지(읽기용은 된다). `npm install`·`npm ci`·내려받기 금지.
- **트랙의 작업 폴더에서만** 일한다. 검증 파일·복사본은 정해 준 scratchpad 폴더에만. Build의 scratchpad는 근거로 삼지 않는다.

## 검토 대상

`4e7b216`(사이트에 올라간 것)과 `track/c1`의 마지막 커밋 사이의 변경 전부. **앱 코드는 `src/games/net-workshop/view3d.js`의 진행도 묶기(C3-1)와, Build가 "같은 꼴"로 보고한 줄만** 바뀌어야 한다. 검사 파일은 지침의 목록 안. Build의 최종 보고는 코디네이터가 요약해 전한다 — **확인 대상이지 근거가 아니다.**

## 확인할 것

1. **범위**: `git diff 4e7b216..HEAD --stat`과 `src/**`의 줄마다. 재현용 코드가 남지 않았는지. 영역 화면 트랙(B0a)이 고칠 검사(처음 화면·단계 지도·놀이 방법·게임 이름이 나오는 검사)를 건드리지 않았는지.
2. **C3-1 (앱)**: 원인 설명이 맞는지 직접 확인하고, **결정적 재현**(scratchpad 복사본에서 `requestAnimationFrame`의 첫 시각을 `start − 10ms`, 둘째를 `start + 0.5ms`로)에서 고치기 전 매번 "끌어서 돌려 봐요" 안내가 숨고 고친 뒤 0번 숨는지. 같은 꼴(시각 차이로 진행도를 구하면서 아래 한계가 없는 곳)을 `src/**`에서 직접 찾아 Build의 표와 견준다. **학생 화면 불변**: 기준 `4e7b216` 빌드와 견줘 정육면체·직육면체·쌓기나무 차시의 접기·펴기·힌트 장면(움직임이 끝난 뒤), 움직임 줄이기·`?fx=low`, 점수·기록 차이 0. 움직이는 도중의 모양이 달라지는 곳이 있으면(첫 프레임 등) 무엇이 어떻게.
3. **C3-2 (머무는 시간)**: 복사본의 앱에서 힌트의 반 접힘을 0·50ms로, 움직임 줄이기의 반 접힘을 0초로, 알림 시간을 300ms로 줄이면 새 단언이 실패하는지(정육면체·직육면체 모두), 앱 값 그대로면 CPU 4·8·12배 × `--repeat-each=10` 이상에서 통과하는지. 문턱이 앱의 값에서 나왔는지, 느린 기기에서 헛경보가 날 만큼 빠듯하지 않은지, 위 한계가 너무 넉넉해 "펴지지 않는" 회귀를 놓치지 않는지. 지켜보기가 누르기보다 먼저 시작되는지, 시각이 페이지 안의 것(`performance.now()`)인지.
4. **C3-3·C3-4**: 예산·기다림 제한 말고 바뀐 것이 없는지, 값이 알맞은지.
5. **C3-5 (드문 실패의 원인)**: Build가 밝힌 원인(또는 재현 못 함)을 직접 확인한다 — "마주 보는 면: 틀린 면은 제자리에서 흔들리고…"에서 면이 6px 넘게 움직이는 일이 재현되는지(CPU 느리게 하기, 재는 때 늦추기, 전체 파일 실행), 원인이 앱인지 검사인지. 앱이 면을 실제로 튀게 하는 것이면 그 모습(몇 px, 얼마 동안, 학생에게 보이는지)을 스크린샷·기록으로.
6. **전체 느리게 하기**: 지금 것의 복사본에서 `net-workshop.spec.js`·`net-workshop-cuboid.spec.js`·`net-workshop-free-finish.spec.js`를 4·8배로 한 번씩 — 값 실패 0.
7. **합칠 때**: `track/b0`·`track/blocks`의 지금 커밋과 `git merge-tree --write-tree`로 줄 충돌.
8. **테스트**: `npm test`, `npm run test:e2e -- --workers=4`, `E2E_WIDE_TEXT=font npm run test:e2e -- --workers=4`를 직접 실행. 다른 일꾼이 같은 때에 테스트를 돌린다 — 값이 어긋나는 실패는 부하 탓으로 넘기지 않는다.
9. **새로 생긴 문제**, 사용자가 정해야 할 것(C3-5가 학생에게 보이는 앱 문제라면 선택지와 추천).

## 형식과 끝나면

덧붙이는 절: 판정 줄(통과 = 반드시 수정 0건 / 수정 필요), 테스트 결과 표, C3-1 결정적 재현 전·후 표, 망가뜨린 앱 × 새 단언 표, 느리게 하기 결과 표, 학생 화면 불변 수치, 발견한 문제 표(심각도, 파일:줄, 재현 방법, 고칠 방향), 확인하지 못한 것.

최종 답변 **8줄 이하**: 판정, C3-1(재현 전·후, 같은 꼴, 화면 불변), C3-2(회귀를 잡는지·헛경보), C3-3·4, C3-5(원인), 테스트 숫자, 새 문제와 심각도별 개수, "반드시 수정" 목록(파일:줄), 합칠 때 부딪힐 곳, 확인하지 못한 것. 직접 잰 것과 추정을 구분한다.
